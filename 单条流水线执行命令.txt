单条流水线执行命令
=======================================================
用途：维护生产入口命令；分片/并行/合并由 YAML sharding 自动完成。
改批次：用 --source-name（+ 清洗时的 --source-dir），一般不用改 YAML 路径。
改并行度 / 卡号：改对应 pipelines/*.yaml 的 sharding。
执行顺序：1 清洗 → 2a/2b/2c 各模型独立识别 → 2d 聚合 → 2e 字准率 → 导出 xlsx（可选）。


-------------------------------------------------------

-------------------------------------------------------

2c. Kimi-Audio 全量识别（独立，vLLM HTTP；内部按时长桶 pad；不依赖 Qwen/SenseVoice）

# 前置：先启动 vLLM（另开终端，常驻）。两卡各起一份，不要 TP=2。
# YAML: pipelines/kimi_asr_batch.yaml（pad + 识别一条命令跑完）
# 产物: cleaned_<name> → kimi_asr_<name>.parquet
# 音频: 推理用 kimi_padded_16k；不改 resampled_16k / duration
#       pad 文件不进 Release / 评测集真值
# 并行：在途 HTTP ≈ 各副本 --max-num-seqs 之和
#       默认 2 shard × concurrency 4 = 8 路（两副本 × seqs=4）
# 单卡：把 sharding.shards / parallel_shards 改成 1，concurrency 对齐该副本 --max-num-seqs
# 不要 8 shard × 4 去打一台 seq=2 的服务
#       pad 且混合时长探针通过后，每卡 seqs 与 concurrency 可一起试到 8

CUDA_VISIBLE_DEVICES=4 \
vllm serve /data2/data-cp/zcl/models/Kimi-Audio-7B-Instruct \
  --host 0.0.0.0 \
  --port 5554 \
  --served-model-name kimi-audio \
  --tensor-parallel-size 1 \
  --trust-remote-code \
  --dtype bfloat16 \
  --max-model-len 4096 \
  --max-num-seqs 4 \
  --gpu-memory-utilization 0.90 \
  --no-enable-prefix-caching \
  --limit-mm-per-prompt '{"audio":1}'

换批次时改哪里（清单）
-------------------------------------------------------
[ ] 命令中的 --source-name / --source-dir
[ ] （可选）pipelines/qwen_asr_batch.yaml、sensevoice_asr_batch.yaml 的 gpus/shards
[ ] （可选）pipelines/kimi_asr_batch.yaml 的 sharding（默认 2 shard）；configs/asr/kimi.yaml 的 concurrency

[ ] （可选）KIMI_AUDIO_MODEL_PATH；先跑 scripts/probe_kimi_audio.py
[ ] （可选 GLM vLLM）GPU / 端口（占位 :5570，不要和 Qwen/Kimi 冲突）；GLM_ASR_MODEL=glm-asr

[ ] （可选 GLM vLLM）先跑 probe_glm_vllm.py：短 WAV、目录并发、--repeat 2（不要 --pad）

[ ] （外源金标）--external-gold / --aggregate-base / --label-col
[ ] 本文件中的模型环境变量（含 KIMI_ASR_API_BASE / KIMI_ASR_API_BASES / KIMI_ASR_MODEL / KIMI_AUDIO_MODEL_PATH / GLM_ASR_API_BASE / GLM_ASR_MODEL）
