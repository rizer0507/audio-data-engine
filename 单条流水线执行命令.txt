单条流水线执行命令
=======================================================
用途：维护生产入口命令；分片/并行/合并由 YAML sharding 自动完成。
改批次：用 --source-name（+ 清洗时的 --source-dir），一般不用改 YAML 路径。
改并行度 / 卡号：改对应 pipelines/*.yaml 的 sharding。
分拣默认：工序一③ = classify_dataset_five_class_v1（027）；legacy = asr_anomaly + selection_v3.0。
执行顺序：1 清洗 → 2 ASR（≥3 族双跑 + register）→ 3 prepare/attach → 分拣（内嵌按需噪声诊断）。
         噪声全量 sidecar 仅研究；聚合+字准（2d/2e）与 classify_dataset(v1) 仅为诊断 / legacy。
噪声速查：§2f-noise；五类入口：§2f-v3-027。

2f-noise. 噪声打分（DNSMOS）— 工序与步骤
-------------------------------------------------------
# 落点：工序一③（ASR attach 之后）。清洗①不跑 DNSMOS、不引入 VAD。

#   清洗 → 多族 ASR + prepare/attach
#     → ③′ diagnose_asr_anomaly（按需 DNSMOS，内嵌于分拣 YAML）
#     → ③ classify（五类或 selection_v3.0）
#
# 【路径 A · 生产主路径（推荐，无需单独命令）】
#   classify_dataset_five_class_v1.yaml
#     或 legacy classify_dataset_v3_asr_anomaly_noise.yaml
#   步骤：diagnose_asr_anomaly → classify
#   正常中文 → noise_diagnosis_status=not_required（不推理、不写假干净分）
#
# 【路径 B · 研究/历史全量（非默认）】
#   输入 cleaned_*；输出 quality_sidecar_*
#   分拣失败时禁止自动改跑本路径冒充修复
# audio-data pipeline run pipelines/audio_quality_sidecar.yaml `
#   --source-name 0914-mixed-30000 `
#   --config configs/quality/dnsmos_p835.yaml `
#   --force
# Linux:
# audio-data pipeline run pipelines/audio_quality_sidecar.yaml \
#   --source-name "$BATCH" --config configs/quality/dnsmos_p835.yaml --force
#
# 【执行前检查】
#   [ ] model_path ONNX 存在（缺文件 → 仅被触发子集 failed）
#   [ ] onnxruntime 或 pip install '.[dnsmos]'
#   [ ] resampled_16k 本机可读（路径在 /data2 须在可读机跑）
#   [ ] calibrated 仍为 false（听音校准前禁止改 true）

#   noise_diagnosis_status / dnsmos_sig|bak|ovrl / calibrated / noise_band
