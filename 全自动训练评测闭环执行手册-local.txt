全自动训练评测闭环执行手册（本地 Windows 版）
================================================================================
适用范围：
  A. 构建训练集并执行外部训练
  B. 构建/使用冻结评测集，对 baseline 与 candidate 自动评测并执行回归门禁

本手册是“单条流水线执行命令.txt”的闭环版，路径与 GPU 布局已调整为本地开发机
（D:/Work/...）。服务器生产环境请参考「全自动训练评测闭环执行手册.txt」。

核心原则：
  1. Parquet Manifest 是唯一真相源，XLSX 只用于人工审核。
  2. 每个流水线输出都会注册 Artifact ID；不要再人工寻找、复制、合并多个 XLSX。
  3. Dataset Release 一旦创建不可修改；标注或规则变化必须创建新 release_id。
  4. 评测与训练完全解耦：只要评测集与各模型推理结果 id 对齐即可；不必走 Model Registry。
  5. review 是明确的人工审批边界；未审核 hardcase/review_queue 不允许进入 Release。
  6. Qwen 生产识别默认通过独立 vLLM 服务调用；流水线进程不加载 Qwen GPU 模型。
     只有明确取消 QWEN_ASR_API_BASE 时，才回退到 qwen-asr 本地推理。
  7. SenseVoice 与 Kimi-Audio 本地模式均在 shard 进程内加载 GPU 模型（与 SenseVoice 相同
     并发模型）；Kimi 也可选 vLLM HTTP 模式，二者产物文件名不同，聚合时用对应 join 名。

================================================================================
四、使用金标评测集自动评测多模型（工序⑤，与训练解耦）
================================================================================

目标产物与手动「总表-字准率.xlsx」对齐：
  - 样本级：id / type / label(gold) / 各模型文本 / 错字少字多字 / CER / 字准率
  - 统计摘要 + 按 type 统计（总体字准率、平均字准率）
  - evaluation.json：各模型 corpus CER、分桶、金标覆盖率（可选配对门禁）

评测输入 Manifest 必须：
  1. 样本 id 全局唯一（错配直接失败）；
  2. labels.gold_text 尽量齐全（允许缺金标：只统计有金标子集，并在报告中注明）；
  3. labels.type（或 classification_bucket）用于分桶；
  4. 含 resampled_16k，供 vLLM 推理。

与④训练无依赖：只要「评测集」与「各模型推理 Manifest」id 对齐即可。
推荐把 summary / gold 注册为 eval_${BATCH}，再按别名独立跑批、聚拢、算字准。

五、（可选）把训练与评测串成 Task DAG

评测本身不依赖训练。仅当你希望「训练成功后再自动跑评测」时，才复制任务模板：

# PowerShell：Copy-Item tasks/train_and_evaluate.example.yaml "tasks/train_and_evaluate_${BATCH}.yaml"

必须修改模板中的：
  release ID
  recipe（本地示例：D:/Work/Qwen3-ASR-main/finetuning/qwen3_asr_sft.py）
  外部训练命令（本地示例：python D:/Work/Qwen3-ASR-main/finetuning/qwen3_asr_sft.py）
  candidate checkpoint / model ID（本地示例：D:/Work/Qwen3-ASR-main/data/outputs/...）
  评测节点：改为 --eval-name / --asr-run / eval_aggregate / eval_metric_pipeline
  （旧模板里的 evaluate_registered_models 为耦合入口，可替换）

执行：
audio-data task run "tasks/train_and_evaluate_${BATCH}.yaml"

查看状态：
audio-data task status "runs/tasks/<控制台打印的_task_id>"

Task 语义：
  - 节点按 depends_on 执行；检测重复 ID、未知依赖和依赖环；
  - 每节点日志在 runs/tasks/<task_id>/nodes/<node>/stdout.log|stderr.log；
  - 成功节点且声明输出仍存在时，重复执行会自动跳过；
  - 失败节点修复外部问题后，重新执行相同 YAML 即可续跑；
  - 修改 YAML 会得到新的 task_id，不会误用旧状态。

七、Qwen/Kimi vLLM 与 Kimi 本地加载运维
================================================================================

── Qwen / Kimi vLLM ─────────────────────────────────────────────────────────

1. 地址规范
  推荐：QWEN_ASR_API_BASE=http://host:port
  兼容：http://host:port/v1
  兼容：http://host:port/v1/audio/transcriptions
  不要写：http://host:port/v1/v1

2. 模型名
  批量 Qwen：请求里的 model 必须匹配该 vLLM 的 --served-model-name。
             默认读 configs/asr/qwen_asr.yaml；并发跑批时用
             export QWEN_ASR_MODEL=<served-model-name> 覆盖，勿改共享 yaml。
  Kimi：KIMI_ASR_MODEL 必须匹配 Kimi vLLM 的 --served-model-name。
  注册模型评测：served model 必须匹配对应 BASELINE_MODEL_ID/CANDIDATE_MODEL_ID。

3. 并发预算（本地单卡建议值）
  Qwen vLLM：parallel_shards(1～2) × concurrency(2～4)；vLLM 在 GPU 0、port 5559，
             --max-num-seqs 建议 ≥ 4。
  Kimi vLLM：parallel_shards(1～2) × concurrency(2～4)；vLLM 在 GPU 0、port 5554。
  SenseVoice 本地：GPU 0 × instances_per_gpu(1) = 1～2 shard，batch_size=16～32。
  Kimi 本地：GPU 0 × instances_per_gpu(1) = 1 shard，batch_size=1（一次一条；YAML 默认两卡时请改成 [0]）。
  出现 OOM、超时或服务排队时，先降低 concurrency / parallel_shards / batch_size。

4. 常见错误
  HTTP 404：检查 API_BASE 是否错误重复包含 /v1，以及 vLLM 是否提供 transcription 路由。
  HTTP 400：检查 model/served-model-name、language 和音频格式。
  HTTP 401/403：检查 API Key；无鉴权的本地 vLLM 可使用 dummy。
  HTTP 422：检查服务版本是否支持 audio transcription；客户端不会发送
             max_completion_tokens 等 Chat Completions 专用字段。
  请求超时：先查看 vLLM 日志和队列，再降低 shards/concurrency。
  空 text：使用同一音频直接 curl 探针；确认采样率、音频可解码和模型能力。

5. 缓存与重跑
  API_BASE、model、language、prompt 会参与缓存键。改变这些配置会生成新结果。
  服务端更换权重但仍沿用同一 served-model-name 时，客户端无法感知权重变化；此时必须
  同时升级 model/model_version 或用 --force 重跑，禁止复用旧缓存冒充新模型结果。

6. 安全停服
  等流水线退出并写完 Manifest/checkpoint 后再停止 vLLM。
  中途停服的样本会标记 failed；恢复服务后使用 --resume 续跑，不要删除已完成的 run root。

── Kimi-Audio 本地加载（kimi_audio_asr_batch）────────────────────────────────

1. 依赖与模型路径
  pip install -e ".[kimi-audio]"  # 含 kimia_infer（GitHub 源）
  KIMI_AUDIO_MODEL_PATH=D:/Work/models/Kimi-Audio-7B-Instruct（覆盖 configs/asr/kimi_audio.yaml）
  ASR 场景 load_detokenizer: false（默认已关闭），可显著节省显存。

2. 探针
  python scripts/probe_kimi_audio.py "$PROBE_WAV"
  python scripts/probe_kimi_audio.py "$SOURCE_DIR" --limit 8
  单文件和文件夹探针均为退出码 0 后，才跑 Parquet。

3. 并发预算
  官方 generate 一次一条。吞吐 = 进程数 = GPU 数。
  仓库默认 YAML 是两卡 A800（gpus [0,1]，shards=2）。Windows 单卡必须改成 gpus [0]、shards=1。
  inference_threads 保持 1；不要用 execution.workers 做 GPU 并发。

4. 常见错误
  ImportError kimia_infer：未安装 [kimi-audio] extra。
  FileNotFoundError 本地模型目录：检查 KIMI_AUDIO_MODEL_PATH。
  CUDA OOM：确认每卡只有 1 个进程。
  空 text：先用 scripts/probe_kimi_audio.py 对同一条 wav 复现。
  sharding 校验失败：parallel_shards 不能大于 GPU 槽位数（单卡却留着默认 2 shard 会直接失败）。

5. 缓存与重跑
  model_path、prompt、generation_kwargs 会参与 cache 键；改配置后需 --force 或清 cache。
  shard 结束后 release_asr_models 会释放进程内模型缓存；同一机器串行跑多模型时无需手工 kill GPU 进程。

6. vLLM 版 vs 本地版
  二者 operator、配置、产物文件名均不同，不可混用 join 名：
    kimi_asr_batch       → kimi_asr_<BATCH>       → --join-manifest kimi
    kimi_audio_asr_batch → kimi_audio_asr_<BATCH> → --join-manifest kimi_audio
