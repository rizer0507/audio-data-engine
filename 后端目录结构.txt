一、范围与阅读约定
本文件按当前工作区实际源码及现行文档整理，作为后续开发导航。
当前后端是 Python 3.10+ 的 CLI / Pipeline 数据引擎，包名 audio_engine，
命令入口为 audio-data -> audio_engine.cli.main:main。
当前未将 Web API、账号系统、数据库 ORM 或前端列为已实现模块。
039 文档描述独立标注平台与本引擎的交接契约，不表示本仓库已有平台后端。

第二节是项目总览；第三节完整列出自有源码、配置、流水线、脚本及测试文件。
第三节不展开运行数据、模型权重、第三方源码、缓存与 Python 字节码。
第四节中的 <BATCH>、<alias>、<version>、<run_id> 是运行产物命名模板，
不表示这些示例文件已存在。文件列表是本次快照，未来新增文件需同步维护。

四、业务数据与运行产物目录约定（模板，不是现存文件清单）

datasets/
├── stage1/
│   ├── cleaned/                    cleaned_<BATCH>.parquet
│   ├── asr/                        <alias>_asr_<BATCH>.parquet
│   ├── derived/                    聚合、分拣、金标回填等可复用产物
│   │                               classified_five_class_v3_<BATCH>.parquet
│   │                               classified_*_<BATCH>_with_gold.parquet
│   ├── review/
│   │   └── semantic_risk_transcripts/<BATCH>/
│   │       ├── queue.parquet        待标队列
│   │       ├── playlist.md          听音清单
│   │       └── wav/                 可选音频链接或副本
│   └── trainsets/<version>/        训练汇总版本及其产物
├── stage3/
│   ├── eval_sets/                  eval_<BATCH>.parquet
│   ├── asr/                        <alias>_asr_eval_<BATCH>.parquet
│   ├── derived/                    eval_aggregate_* / eval_metrics_*
│   └── reports/<eval_name>/        evaluation.json / evaluation.xlsx
└── manifests/                      旧扁平路径，只读兼容

data/
├── derived/                        处理生成的音频等派生资产
├── cache/                          可重建计算缓存
├── exports/                        XLSX 等交付物
└── catalog/                        不可变产物注册目录（默认）

runs/<run_id>/
├── config.yaml                     本次实际配置
├── manifest.parquet                运行输出或中间快照，视流水线而定
├── metrics.json                    运行指标
├── run.log                         运行日志
├── script_logs/                    自定义算子的结构化日志
└── reports/                        报告副本，视流水线而定
checkpoint、分片状态和 stage1 任务状态由对应执行器写入，具体文件名以实现为准。

边界：
1. 外部原始音频只读引用；resources/manifest.yaml 记录外部路径。
   根 README / 旧目录中的 data/raw/ 不是要求把生产音频迁入 Git 仓库。
2. Manifest 是数据集真相源；XLSX 是交付格式，runs 是执行痕迹。
3. ASR 结果昂贵，不能当临时缓存随意清理。
4. warehouse 冻结与 dataset_v3 Release 是不同业务概念；
   输出位置应遵守对应配置/调用参数，不能仅因名字近似而合并目录。
5. 外部训练框架和模型权重有自己的存储位置，本文件不虚构仓库内训练实现。

五、按开发任务定位修改位置

1. 增加音频处理能力
   operators/audio/ 或 operators/augmentation/ 实现算子；
   复用 core/operator.py，通过 registry 注册并在包初始化中导入；
   configs/ 放参数，pipelines/ 放组合，tests/ 验证输入输出与边界。

2. 增加 ASR 模型
   先看 operators/asr/base.py，再看对应模型及 vllm.py；
   参数放 configs/asr/，运行流程放 pipelines/；
   若接入 stage1 自动调度，还需对齐 core/stage1/adapters/ 与资源管理。

3. 调整现行五类分拣
   先读 docs/02-规范规则/数据挑选规则_v3.md；
   配置入口为 configs/selection/zh_asr_five_class_v3.yaml；
   流水线入口为 pipelines/classify_dataset_five_class_v3.yaml；
   规则实现在 core/selection_v3/，算子包装在 operators/quality/。
   当前业务名 v3 复用 five_class_v2_4_on_demand_acoustic.py 等工程实现，
   不能仅根据文件名中的 v2_4 判断它已过时。
   旧 selection_v3.0 与现行 selection_five_class_v3 不是同一套策略。

4. 修改断点恢复、重试、GPU 并发
   core/stage1/ 管理任务、进程、GPU 租约、调度和状态；
   样本流水线执行查看 core/pipeline.py、checkpoint.py、sharded_run.py；
   对应 tests/test_stage1_*.py、test_sharded_pipeline.py。

5. 修改人工听写或标注平台对接
   scripts/annotate_semantic_risk_transcripts.py 是现行 prepare / label / merge；
   core/annotation_v3/ 处理正式人审协议，勿把两种审核含义直接等同。
   对接规范看 039；(sample_id, original_audio_sha256) 为合并键。
   candidate_text 仅为参考；平台回传 gold_text、gold_kind、status 等字段；
   annotated 对应 speech + 非空文本，empty 对应 non_speech + 空文本，
   skipped 不写入 gold；回填不修改 category。
   平台 Task、播放器、Web API 属于独立项目开发范围。

6. 修改仓库冻结或训练汇总
   core/warehouse/、configs/warehouse/ 和 warehouse_* 流水线负责仓库；
   scripts/assemble_training_parquet.py、configs/trainsets/ 和
   pipelines/assemble_training_parquet.yaml 负责训练数据汇总；
   core/dataset_v3/ 负责数据集 Release；
   core/training.py 仅通过约定接口接入外部训练框架。

7. 修改评测和报告
   metrics/ 放指标能力，operators/quality/ 放指标及报告算子；
   configs/metrics/、configs/normalization/ 放口径；
   pipelines/eval_aggregate.yaml、eval_metric_pipeline.yaml 编排评测。
   评测不强依赖训练节点或 Model Registry，输入与金标须按身份对齐。

8. 修改命令行或新增配置
   cli/main.py 保持入口职责，业务逻辑尽量放既有 core / operators 模块；
   参数、流程分别放 configs / pipelines，避免硬编码某个批次路径；
   测试按现有 tests/test_*.py 风格组织，不要求先重构测试目录。

六、文档冲突与后续开发约定

- 现行五类默认入口以当前规则文档、配置和流水线交叉确认。
  README 和工序总览部分段落仍有 v2.2 / 旧 v3 描述，不能混用。
- 架构蓝图中的 data/batches、datasets/batches 等属于早期愿景；
  数据源登记采用 resources/manifest.yaml。

- 新功能优先沿用“CLI/任务入口 -> Pipeline -> Operator -> 核心能力
  -> Manifest/产物注册”的职责划分。
- 本文件仅新增开发文档，没有创建空目录、移动源码或修改业务逻辑。
