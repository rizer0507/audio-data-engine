工序总览原文：
--------------------------------------------------------------------------------
当前我的数据引擎工序是：
①数据清洗、落库流水线(data_cleaning_source_A.yaml) --------> ②同源多结果 ASR + 聚拢 + 字准：任意 `--asr-run` 别名识别（同 `--source-name`）→ `multi_asr_aggregate`（`--aggregate-base` + `--join-manifest`）→ `asr_metric_pipeline`（`--agreement-base`，vs_base agreement CER） -------> ③自动分拣 + 金标聚拢 +（可选）人工审核冻结 Dataset：classify_dataset → review export-gold →（可搁置）review export/import → release build --------> ④训练流水线(当前尚未实现，在另一套框架中，未集成进来)  --------> ⑤评测流水线（与④完全解耦）：`eval register` → 各模型独立 vLLM 跑批（`--eval-name` + `--asr-run`）→ `eval_aggregate`（按 id 对齐）→ `eval_metric_pipeline`（相对 gold_text 多模型字准 + 按 type 导出）

工序②要点：
- 同一 `--source-name` 下可多次跑任意模型/批次，用 `--asr-run <alias>` 区分产物（`{alias}_asr_<BATCH>.parquet` + transcript 键）
- 聚拢不绑模型清单：`--aggregate-base qwen1 --join-manifest qwen2 --join-manifest sensevoice1 ...`
- 字准：其余结果相对 base 算 agreement CER，并写出 `max_vs_base_agreement_cer`（工序②指标；工序③分拣不再依赖该 CER 进桶）

工序③要点：
- classify 使用 `configs/selection/zh_asr_v1.yaml`（`selection_zh_asr_v1_6` / `selection_v1.1`）：`type` + `decision` + `label` 三分开
- 分桶：`noise` / `voicemail` / `semantic_inversion` / `hallucination` / `qwen_missing` / `auto_gold` / `consensus_gold` / `hardcase`
- 一致度用 **transcript_similarity**（非字准率）；阈值 `0.95` / `0.90`；金标取 **medoid**（禁止随机）
- 模型族感知：同族多跑不算独立票；`semantic_inversion` 在相似度判断之前执行
- `audio-data review export-gold` 默认导出 `auto_gold` + `consensus_gold`
- 待审样本可搁置；`--allow-unresolved-review` 允许仅用已有金标冻结 Release
- `audio-data review export-summary`：导出全量汇总 xlsx，`type` 列=分拣桶
- 细则见 [数据挑选规则](../02-规范规则/数据挑选规则.md)

工序⑤要点：
- **与④训练无依赖**：只要评测集与各推理结果 id 对齐即可，不强制 Model Registry
- `audio-data eval register <summary|gold> --name eval_$BATCH` → 准入检查并落盘评测集快照
- 各权重独立起 vLLM，用 `--eval-name eval_$BATCH --asr-run <alias>` 跑批（例：`qwen` / `qwen-sft-epoch10` / `qwen-sft-epoch100`）
- `eval_aggregate`：评测集为底表，`--join-manifest` 左连接（允许推理侧多出 id；评测集缺 id 失败）
- `eval_metric_pipeline --eval-model ...`：相对 `gold_text` 算 CER/字准率，按 `type` 汇总，导出 evaluation.xlsx
- 若 summary 已含原模型文本，可只 join SFT 别名；`--eval-model` 选定报告维度
--------------------------------------------------------------------------------

全自动训练评测闭环执行手册（dev · 服务器真实执行版）
================================================================================
适用范围：
  A. 构建训练集并执行外部训练
  B. 构建/使用冻结评测集，对 baseline 与 candidate 自动评测并执行回归门禁

本手册依据服务器现场文档整理（tmp/0904 拷贝）：
  - 全自动训练评测闭环执行手册.txt
  - 文档.txt（单条流水线 / 安装 / vLLM 实开命令）
日常生产以本手册为准；旧「单条流水线执行命令」仍可用于单独排查清洗或 ASR。

核心原则：
  1. Parquet Manifest 是唯一真相源，XLSX 只用于人工审核。
  2. 每个流水线输出都会注册 Artifact ID；不要再人工寻找、复制、合并多个 XLSX。
  3. Dataset Release 一旦创建不可修改；标注或规则变化必须创建新 release_id。
  4. baseline/candidate 都使用 Model Registry ID，不在评测命令里直接填写 checkpoint。
  5. review 是明确的人工审批边界；未审核 hardcase/review_queue 不允许进入 Release。
  6. Qwen 生产识别默认通过独立 vLLM 服务调用；流水线进程不加载 Qwen GPU 模型。
     只有明确取消 QWEN_ASR_API_BASE 时，才回退到 qwen-asr 本地推理。
  7. SenseVoice 与 Kimi-Audio 本地模式均在 shard 进程内加载 GPU 模型（与 SenseVoice 相同
     并发模型）；Kimi 也可选 vLLM HTTP 模式，二者产物文件名不同，聚合时用对应 join 名。

四、使用冻结测试集自动评测新旧模型（工序⑤）

-------------------------------------------------------
11. 选择评测集并执行 baseline/candidate 评测
-------------------------------------------------------
# 默认示例使用同一 Release 的 test split。更严格的做法是长期维护独立 holdout Release。
#
# 重要：默认评测流水线会根据 Model Registry 中的 checkpoint 依次加载 baseline/candidate，
# 因此执行前必须取消批量建集阶段使用的 Qwen vLLM 环境变量：
#
#   unset QWEN_ASR_API_BASE QWEN_ASR_API_KEY QWEN_ASR_API_BASES
#
# 否则两个 inference step 都会被路由到同一个 vLLM 地址，而单模型 vLLM 服务不会按
# Registry checkpoint 自动换权重，可能导致新旧模型实际使用相同权重、评测结果无效。
# 本地评测还需要安装 `pip install -e ".[asr]"`，并确保两份 checkpoint 均可访问。

export EVAL_MANIFEST="$(audio-data release path "$RELEASE_ID" --split test)"
export EVAL_OUTPUT="data/evaluations/${RELEASE_ID}_${CANDIDATE_MODEL_ID}.parquet"

audio-data pipeline run pipelines/evaluate_registered_models.yaml

流水线自动完成：
  baseline 推理（transcript key=old_model）
  → 释放 baseline 模型和 GPU 缓存
  → candidate 推理（transcript key=new_model）
  → 与 gold_text 计算统一 CER
  → corpus CER + classification bucket 分桶
  → paired bootstrap 95% CI
  → overall/hardcase regression gate

输出：
  $EVAL_OUTPUT                         样本级结果 Manifest
  runs/<本次评测_run>/reports/evaluation.json

若门禁失败：
  流水线返回失败，但 evaluation.json 会保留；先检查 delta_cer、各 bucket 和 badcase，
  不要用 --force 或修改阈值绕过发布判断。

如评测数据规模必须使用 vLLM：
  1. 分别在不同端口启动 baseline 和 candidate vLLM，加载各自 checkpoint；
  2. --served-model-name 分别设置为 BASELINE_MODEL_ID 和 CANDIDATE_MODEL_ID；
  3. 复制 pipelines/evaluate_registered_models.yaml，为 baseline_inference 和
     candidate_inference 分别显式填写不同的 api_base；
  4. 不要只设置一个全局 QWEN_ASR_API_BASE；
  5. 分别用 /v1/models 和一条真实音频探针确认两个端口，再开始全量评测。

示例（复制后的 YAML 片段）：
  baseline_inference.params.api_base: http://127.0.0.1:5561
  candidate_inference.params.api_base: http://127.0.0.1:5562

由于 registered_model 会把请求中的 model 设置为 Registry ID，两个 vLLM 服务的
--served-model-name 必须与对应 Registry ID 完全一致，否则会收到 HTTP 404/400。

七、Qwen/Kimi vLLM 与 Kimi 本地加载运维
================================================================================

── Qwen / Kimi vLLM ─────────────────────────────────────────────────────────

1. 地址规范
  推荐：QWEN_ASR_API_BASE=http://host:port
  兼容：http://host:port/v1
  兼容：http://host:port/v1/audio/transcriptions
  不要写：http://host:port/v1/v1
  多实例：QWEN_ASR_API_BASES="http://127.0.0.1:5560/v1"（文档.txt）

2. 模型名
  批量 Qwen 建集：configs/asr/qwen_asr.yaml 的 model 必须匹配 Qwen
                 vLLM 的 --served-model-name（默认都是 qwen3-asr）。
  Kimi：KIMI_ASR_MODEL 必须匹配 Kimi vLLM 的 --served-model-name。
  注册模型评测：served model 必须匹配对应 BASELINE_MODEL_ID/CANDIDATE_MODEL_ID。

3. 并发预算（当前生产默认值）
  Qwen vLLM：parallel_shards(8) × concurrency(4) ≈ 32 路 HTTP；
             现场端口常见 5555 / 5559 / 5560 / 5563（按权重分开）。
  Kimi vLLM：port 5554 或 5561；--max-num-seqs 2～4。
  SenseVoice 本地：GPU 4、5 × instances_per_gpu(4) = 8 shard，batch_size=32。
  Kimi 本地：两卡 A800 × instances_per_gpu(1) = 2 shard，batch_size=1。
  出现 OOM、超时或服务排队时，先降低 concurrency / parallel_shards / batch_size。

4. 常见错误
  HTTP 404：检查 API_BASE 是否错误重复包含 /v1，以及 vLLM 是否提供 transcription 路由。
  HTTP 400：检查 model/served-model-name、language 和音频格式。
  HTTP 401/403：检查 API Key；无鉴权的本地 vLLM 可使用 dummy。
  HTTP 422：检查服务版本是否支持 audio transcription。
  请求超时：先查看 vLLM 日志和队列，再降低 shards/concurrency。
  空 text：使用同一音频直接 curl 探针。

5. 缓存与重跑
  API_BASE、model、language、prompt 会参与缓存键。改变这些配置会生成新结果。
  服务端更换权重但仍沿用同一 served-model-name 时，必须升级 model/model_version
  或用 --force 重跑，禁止复用旧缓存冒充新模型结果。

6. 安全停服
  等流水线退出并写完 Manifest/checkpoint 后再停止 vLLM。
  中途停服的样本会标记 failed；恢复服务后使用 --resume 续跑。

── Kimi-Audio 本地加载（kimi_audio_asr_batch）────────────────────────────────

1. 依赖与模型路径
  pip install -e ".[kimi-audio]"
  KIMI_AUDIO_MODEL_PATH=/data2/data-cp/models/kimi-audio
  ASR 场景 load_detokenizer: false（默认已关闭）。

2. 探针
  python scripts/probe_kimi_audio.py "$PROBE_WAV"
  python scripts/probe_kimi_audio.py "$SOURCE_DIR" --limit 8
  单文件和文件夹探针均为退出码 0 后，才跑 Parquet。

3. 并发预算
  官方 generate 一次一条。吞吐 = 进程数 = GPU 数。
  默认两卡 A800：gpus [0, 1]，instances_per_gpu=1，shards=2，batch_size=1。
  inference_threads 保持 1；不要用 execution.workers 做 GPU 并发。

4. 常见错误
  ImportError kimia_infer：未安装 [kimi-audio] extra。
  FileNotFoundError：检查 KIMI_AUDIO_MODEL_PATH。
  CUDA OOM：确认每卡只有 1 个进程。
  sharding 校验失败：parallel_shards 不能大于 GPU 槽位数。

5. vLLM 版 vs 本地版
  kimi_asr_batch       → kimi_asr_<BATCH>       → --join-manifest kimi
  kimi_audio_asr_batch → kimi_audio_asr_<BATCH> → --join-manifest kimi_audio
