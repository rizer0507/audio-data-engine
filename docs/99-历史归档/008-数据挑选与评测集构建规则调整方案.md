# 数据挑选与评测集构建规则调整方案

> 目标：在保留现有 `consensus_v1` 分拣能力的基础上，将当前“自动产金标”体系升级为“候选数据分拣 + 训练数据构建 + 固定评测集构建”三层体系。
>
> 适用项目：基于 `qwen3-asr-main` 二次开发的专属 ASR 训练框架。
>
> 建议版本：
>
> - 现行规则继续冻结：`selection_v1.1`
> - 新增分拣规则：`selection_v2.0`
> - 新增评测集构建规则：`eval_sampling_v1.0`
>
> 核心原则：**不要修改旧规则覆盖历史结果，而是新增版本。**

---

# 1. 调整结论

当前规则整体设计是合理的，以下能力建议保留：

1. `type / decision / gold_text` 三字段解耦。
2. 使用 `model_family`，同族多次推理不重复计票。
3. 使用 `transcript_similarity` 而不是错误地称为“字准率”。
4. 使用 medoid 选择共识文本，而不是随机选模型输出。
5. `semantic_inversion` 优先于普通文本相似度。
6. `auto_gold / consensus_gold / hardcase` 的整体思想。
7. 记录 `rule_version`、support models、similarity、review reason 等审计信息。

但是，当前体系仍然主要解决：

> “42 万条无人工金标数据中，哪些可以自动形成训练金标，哪些需要复核？”

它还没有完整解决：

> “如何从 42 万条数据中构建一个不会产生评测偏差、不会泄漏、能够稳定比较 Base / LoRA / Full SFT 的科学评测集？”

因此建议不要推翻现有引擎，而是在现有体系上增加两层：

```text
42万原始数据
    ↓
Layer 1：候选数据分拣
selection_v2.0
    ↓
Layer 2：用途分配
train / eval_core / eval_random / exclude
    ↓
Layer 3：人工金标与冻结
human_gold / silver / rejected
    ↓
正式 Dataset Release
```

# 2. 当前规则最需要修改的五个问题

## 2.1 `全部模型为空 → noise(auto_empty)` 风险过高

现行逻辑：

```text
损坏/时长≤0 或全部为空
    → noise
    → auto_empty
```

这里实际上混合了两类完全不同的数据：

### A. 物理无效数据

例如：

- 音频损坏
- 文件无法解码
- duration <= 0
- PCM/WAV 格式异常

这种数据可以直接：

```text
invalid_audio
decision = exclude
```

### B. 所有 ASR 都没有识别出文本

这不一定是 noise。

也可能是真实存在：

- 极短的“不”
- 很轻的“嗯”
- 弱发音“不需要”
- VAD 截断后的短音节
- 极低 SNR 的真实客户语音
- 模型共同漏识别

而这些恰好可能是当前业务最有价值的 badcase。

因此：

> “所有模型都为空”不能等价于“没有语音”。

### 调整方案

新增：

```text
invalid_audio
all_empty
```

规则：

```text
音频物理损坏 / duration <= 0
    → invalid_audio
    → exclude

所有模型输出为空
    → all_empty
    → model_review / manual_review
```

如果以后接入可靠的 VAD、speech probability、energy 或 no-speech classifier，再允许：

```text
all_empty
+ acoustic_no_speech_confidence >= threshold
    → confirmed_no_speech
    → auto_empty
```

在没有声学证据前，不建议仅靠多个 ASR 一致为空直接判定为空金标。

# 3. 调整 `hallucination` 与 `qwen_missing` 的判定顺序

现行顺序：

```text
semantic_inversion
→ qwen_missing
→ hallucination
```

这个顺序容易使部分 hallucination candidate 被提前吸收到 `qwen_missing`。

例如：

```text
qwen1       = ""
qwen2       = ""
sensevoice1 = "需要"
sensevoice2 = ""
```

根据现行规则：

```text
主族全空 + 其他非空
→ qwen_missing
```

但从风险分析角度，这条数据更值得优先进入：

```text
hallucination candidate
```

因为四个模型中 75% 为空，唯一非空文本又只来自单一模型族。

### 建议新顺序

```text
semantic_inversion
→ filler_confusion
→ hallucination
→ qwen_missing
```

即：

```text
空占比 >= 75%
AND 非空输出仅来自一个模型族
    → hallucination

否则：

主模型族全部为空
AND 其他模型族存在有效输出
    → qwen_missing
```

这样：

- “绝大多数模型认为没有文本”优先分析 hallucination；
- “Qwen 整体漏识别但其他模型族稳定识别”才进入 qwen_missing。

# 4. `type` 不应直接等价于真实错误类型

当前：

```text
type = semantic_inversion / hallucination / hardcase / ...
```

这些实际上是：

> 根据多模型输出推断出的“候选问题类型”。

例如：

```text
Qwen     = 不需要
SenseVoice = 需要
```

只能证明：

```text
两个模型族存在极性冲突
```

并不能在没有人工 Gold 的情况下证明：

```text
哪个模型发生了 semantic inversion
```

因此建议保留现有 `type` 字段以兼容现有代码，但是增加：

```text
error_type
error_source
```

其中：

## type

表示自动分拣得到的候选桶：

```text
semantic_inversion
hallucination
qwen_missing
hardcase
auto_gold
consensus_gold
...
```

## error_type

人工复核 / Gold 完成后，真正的问题类型：

```text
semantic_inversion
filler_confusion
noise_hallucination
crosstalk
deletion
insertion
substitution
numeric_error
entity_error
normal_easy
annotation_ambiguous
none
```

## error_source

问题真正来源：

```text
asr_acoustic_error
asr_generation_error
vad_segmentation
crosstalk_target_confusion
downstream_semantic_error
annotation_error
unknown
none
```

这样才能区分：

```text
候选原因 ≠ 最终错误归因
```

# 5. 增加 `filler_confusion` 候选桶

当前规则缺少一个本业务非常关键的候选类型：

```text
filler_confusion
```

需要重点覆盖：

```text
嗯 → 是
嗯 → 需要
嗯 → 有
啊 → 好的
哦 → 可以
```

以及：

```text
嗯……我不需要
```

这种包含停顿和最终否定表达的数据。

## 建议初步规则

维护两个词表：

```text
FILLER_WORDS
AFFIRMATIVE_WORDS
```

例如：

```text
FILLER_WORDS:
  嗯
  啊
  哦
  呃
  唔

AFFIRMATIVE_WORDS:
  是
  有
  要
  需要
  可以
  好
  好的
  愿意
```

当两个独立模型族之间出现：

```text
filler ↔ affirmative
```

冲突时：

```text
type = filler_confusion
decision = model_review
```

### 优先级

`semantic_inversion` 仍然高于 `filler_confusion`。

推荐：

```text
semantic_inversion
→ filler_confusion
→ hallucination
```

因为肯定 / 否定直接翻转风险最高。

---

# 6. `semantic_inversion` 从二值规则升级为 polarity

建议不要只维护简单：

```text
positive
negative
```

而是增加：

```text
semantic_polarity
```

取值：

```text
POSITIVE
NEGATIVE
NEUTRAL
MIXED
UNKNOWN
```

例如：

```text
需要
→ POSITIVE

不需要
→ NEGATIVE

嗯
→ NEUTRAL

嗯，我不需要
→ NEGATIVE 或 MIXED，具体由规则定义

不是不要，我是需要
→ MIXED

听不清
→ UNKNOWN
```

需要特别避免简单 substring 判断。

例如：

```text
“不需要”
```

同时包含：

```text
“不”
“需要”
```

如果只做关键词 contains，会产生错误。

`semantic_inversion` 的判定应该基于完整 polarity 解析结果：

```text
Family A = POSITIVE
Family B = NEGATIVE
    → semantic_inversion
```

而：

```text
NEUTRAL ↔ POSITIVE
    → filler_confusion / semantic_disagreement
```

不应统一塞入 semantic_inversion。

# 7. 新版推荐判定顺序

建议 `selection_v2.0` 使用以下顺序：

```text
文本标准化
    ↓
音频损坏 / duration <= 0？
    ├─ 是 → invalid_audio / exclude
    ↓
≥2 独立模型族命中 voicemail？
    ├─ 是 → voicemail
    ↓
所有模型输出为空？
    ├─ 是 → all_empty / review
    ↓
独立模型族 POSITIVE ↔ NEGATIVE？
    ├─ 是 → semantic_inversion
    ↓
独立模型族 FILLER/NEUTRAL ↔ AFFIRMATIVE？
    ├─ 是 → filler_confusion
    ↓
空输出占比 >= 75%
且非空输出仅来自单一模型族？
    ├─ 是 → hallucination
    ↓
主模型族全部为空
且其他模型族存在非空？
    ├─ 是 → qwen_missing
    ↓
全部非空
且 min_pairwise >= 0.95
且 semantic polarity 一致？
    ├─ 是 → auto_gold
    ↓
dominant cluster >= 75%
cluster 内 similarity >= 0.90
跨 >= 2 个独立模型族
semantic polarity 一致？
    ├─ 是 → consensus_gold
    ↓
hardcase
```

# 8. 新版分拣桶

| 优先级 | type | 含义 | 默认 decision |
|---:|---|---|---|
| 1 | `invalid_audio` | 文件损坏、duration<=0 等物理无效数据 | `exclude` |
| 2 | `voicemail` | 语音信箱 | 按现有策略 |
| 3 | `all_empty` | 所有 ASR 均为空，但尚未证明无语音 | `model_review` |
| 4 | `semantic_inversion` | 独立模型族肯定/否定极性冲突 | `model_review` |
| 5 | `filler_confusion` | 语气词与肯定词冲突 | `model_review` |
| 6 | `hallucination` | 大多数为空，非空只来自单一模型族 | `model_review` |
| 7 | `qwen_missing` | Qwen 主族整体为空、其他模型族有稳定文本 | `model_review` |
| 8 | `auto_gold` | 全模型高度一致 | `auto_accept` |
| 9 | `consensus_gold` | 跨模型族形成强共识 | `auto_accept` |
| 10 | `hardcase` | 无可靠共识 | `model_review` |

注意：

> `hallucination`、`semantic_inversion` 等在没有人工 Gold 之前，只表示候选桶，不代表已经确认存在对应 ASR 错误。

# 9. 增加 Dataset Role：分拣结果不能直接决定用途

建议新增字段：

```text
dataset_role
```

取值：

```text
train_candidate
eval_core_candidate
eval_random_candidate
replay_candidate
exclude
unassigned
```

同时增加：

```text
label_status
```

取值：

```text
unlabeled
silver
human_gold
external_gold
rejected
```

这样最终形成：

```text
type
    = 这条数据为什么被分到这里

decision
    = 下一步怎么处理

label_status
    = 当前标签可信度

dataset_role
    = 准备用到哪里

gold_text
    = 最终文本
```

四者不要混在一起。

# 10. 训练集与评测集必须使用不同的金标准入规则

这是本次调整最重要的一条。

## 10.1 训练集

训练数据允许：

```text
human_gold
external_gold
high-confidence silver
```

例如：

```text
auto_gold
consensus_gold
```

可以作为 replay / easy 样本进入训练。

## 10.2 正式评测集

正式 Eval：

```text
eval_core
eval_random
```

必须满足：

```text
label_status = human_gold
```

或经过明确验证的：

```text
label_status = external_gold
```

不建议：

```text
auto_gold
consensus_gold
```

直接作为最终 Test Gold。

如果某条 `auto_gold` 被抽入 Eval：

```text
auto_gold
    ↓
人工确认
    ↓
human_gold
    ↓
eval_core
```

原因是：

> 多模型一致只能说明模型共识高，不能证明它们没有共同犯错。

如果使用模型共识本身作为评测 Gold，会天然偏向这些模型，并低估共同错误。

# 11. 评测体系拆成两个固定数据集

不建议只维护一个 Evaluation Set。

至少拆成：

```text
eval_core_v001
eval_random_v001
```

---

## 11.1 eval_core_v001

用途：

> 专门检测本次 ASR 微调真正想解决的高风险业务问题。

建议第一版：

```text
总量约 2000
```

组成：

| 风险类型 | 数量 | 比例 |
|---|---:|---:|
| semantic_inversion | 500 | 25% |
| hallucination / noise / crosstalk | 500 | 25% |
| filler_confusion | 400 | 20% |
| normal_easy | 400 | 20% |
| qwen_missing / hardcase / 其他 | 200 | 10% |

所有样本：

```text
人工 Gold
```

并冻结版本：

```text
eval_core_v001
```

之后 LoRA、Full SFT、3K、5K、10K 等所有实验都使用同一版本。

---

## 11.2 eval_random_v001

用途：

> 检测模型在真实线上分布上有没有总体退化。

这部分不能从 hardcase 桶里抽。

必须：

```text
从 42 万原始数据中直接随机抽样
```

建议：

```text
1000 ~ 2000 条
```

然后统一人工 Gold。

它回答的问题是：

```text
高风险专项指标提升后，
真实整体分布 CER 是否变差？
```

### 非常重要

`eval_random` 必须在查看模型微调结果之前冻结。

否则会形成测试集适配。

# 13. 增加数据泄漏控制

评测集不能按照单条 utterance 简单 random split。

建议增加：

```text
group_id
```

优先级：

```text
call_id
conversation_id
customer_id_hash
speaker_id
```

至少做到：

> 同一通电话中的不同 utterance 不允许同时出现在 Train 和 Eval。

例如：

```text
call_001/utt_001 → train
call_001/utt_002 → eval
```

这种情况禁止。

应该：

```text
call_001/* → 全部属于同一个 split
```

# 14. 数据增强必须继承原始数据 split

例如：

```text
audio_001.wav
```

属于：

```text
train
```

那么：

```text
audio_001_snr10.wav
audio_001_speed09.wav
audio_001_reverb.wav
```

必须全部：

```text
train
```

不能让增强后的音频进入 Eval。

建议 Manifest 中保存：

```text
source_audio_id
augmentation_id
```

---

# 15. 增加去重约束

42 万条数据中应防止：

- 同一文件重复
- 同一录音不同路径
- 同一片段被多次切割
- 数据增强版本泄漏
- 高度重复模板语音

建议至少维护：

```text
audio_md5
source_audio_id
call_id
```

有能力后再增加：

```text
audio_fingerprint
```

进行近重复音频检测。

# 17. 新增评测集冻结机制

每次正式生成 Eval 后，形成：

```text
eval_core_v001
eval_random_v001
```

并保存：

```text
manifest
gold
sampling_config
rule_version
created_at
source_release
```

冻结后原则上禁止修改。

如果发现 Gold 错误或采样规则需要改变：

不要修改：

```text
eval_core_v001
```

而是生成：

```text
eval_core_v002
```

并记录：

```text
v001 → v002
修改了哪些数据
为什么修改
```

# 18. 不要让新模型参与重新定义旧 Eval

假设：

```text
EXP-002 = LoRA 模型
```

训练完成后发现一些新 badcase。

这些 badcase可以进入：

```text
badcase_pool_v002
train_v002
future_eval_v002
```

但不要回头根据 EXP-002 的表现修改：

```text
eval_core_v001
```

否则会造成：

```text
模型
    ↓
影响测试集
    ↓
测试集再评价该模型
```

形成实验污染。

# 19. 推荐增加“候选优先级”而不是只有桶

42 万数据规模较大，仅靠 bucket 不足以决定人工先标哪条。

可以增加：

```text
review_priority
```

例如：

```text
P0
P1
P2
```

推荐：

## P0

```text
semantic_inversion
filler_confusion
hallucination 中包含肯定业务词
```

## P1

```text
qwen_missing
all_empty
普通 hallucination
```

## P2

```text
hardcase
一般文本差异
```

进一步可以增加：

```text
risk_score
```

但第一版不建议构造过度复杂的神秘分数。

先使用可解释的规则优先级。

# 28. 最终建议

当前 `selection_v1.1` 不建议直接删除或修改。

建议：

```text
selection_v1.1
    = 历史稳定版本

selection_v2.0
    = 新候选分拣版本

eval_sampling_v1.0
    = 专门负责 Evaluation Set 构建
```

其中最关键的架构变化不是增加多少规则，而是：

```text
“模型共识”
不再等价于
“评测 Gold”
```

以及：

```text
“分拣桶”
不再等价于
“数据用途”
```

最终应该形成：

```text
候选分类
    ↓
用途分配
    ↓
标签可信度
    ↓
数据集冻结
    ↓
训练 / 评测
```

这会使后续所有 LoRA、Full SFT、数据扩量、Hard Negative、Noise Augmentation 实验都能够在同一个稳定实验体系中比较。
