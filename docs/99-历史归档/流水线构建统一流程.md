# 流水线构建统一流程

> 日期：2026-08-20
>
> 定位：**构建方法论**。以「数据入库统一化改造」为原型，抽象出一套可复用的流水线构建流程。将来新增任何流水线（清洗、标注、增广、导出…），都按本文步骤执行。

## 一、不变的执行模型

本工程所有流水线共享同一条执行链，**构建新流水线 = 向这条链上挂新算子 + 写一份 YAML**，不允许出现绕过 PipelineRunner 的独立链路：

```text
CLI (cli/main.py)
  → PipelineRunner (core/pipeline.py)
  → OperatorRegistry (core/registry.py)
  → Operator（样本级 BaseOperator / 集合级 ManifestOperator）
  → 产物：runs/<ts>_<name>/{manifest.parquet, config.yaml, metrics.json, run.log}
```

三个 CLI 入口最终都汇入 PipelineRunner：

| 命令 | 用途 | 内部路径 |
|------|------|----------|
| `audio-data pipeline run <yaml>` | 多步流水线 | `PipelineConfig.from_yaml` → `runner.run()` |
| `audio-data run <operator> -d <dataset>` | 单算子调试 | `runner.run_single_operator()` |
| `audio-data ingest <dir>` | 数据入库 | 内部构造单步 `ingest.scan` 流水线 → `runner.run()` |

**唯一真相源是 Manifest**：每一步的输入输出都是 Sample 集合，音频文件通过 `sample.audio[key]` 引用，不直接传递物理文件。

## 二、构建一条新流水线的六步流程

### Step 0：定义输入与输出（先想清楚再动手）

回答三个问题：

1. **输入是什么？**
   - 已有 manifest → YAML 里写 `input.manifest`
   - 外部物理目录（尚无 manifest）→ YAML 里写 `input.source_dir`，流水线第一步放 `ingest.scan`
2. **输出是什么逻辑资产？**（清洗后 manifest / 训练集 jsonl / 质检报告…）
3. **中间每一步的音频 key 链是什么？**（如 `raw → resampled_16k → denoised`）

### Step 1：盘点已有算子

```bash
audio-data operators
```

对照需求列出缺口。**能用已有算子组合解决的，不写新算子。**

### Step 2：为缺口算子选择类型

这是本次改造沉淀出的核心判断：

| 问题 | 选择 |
|------|------|
| 逻辑能表达为「一个 Sample 进、一个 Sample 出」吗？ | 能 → `BaseOperator`（样本级，自动获得 cache / skip / 血缘） |
| 需要创建、删除、合并样本，或依赖全集信息（去重、统计、采样）？ | 是 → `ManifestOperator`（集合级，如 `ingest.scan`） |

> 经验：绝大多数处理（转码、重采样、ASR、打分、打标）都是样本级；只有「入库、全局去重、集合筛选」这类操作才需要集合级。

### Step 3：实现算子

文件位置：`src/audio_engine/operators/<category>/<name>.py`，category 取 `ingest / audio / asr / quality / augmentation` 之一，或新建目录。

**样本级模板**（参考 `operators/audio/resample.py`）：

```python
from audio_engine.core.operator import BaseOperator, OperatorConfig
from audio_engine.core.registry import register_operator
from audio_engine.core.sample import Sample


@register_operator
class MyOperator(BaseOperator):
    name = "my_op"          # full_name = "<category>.<name>"
    version = "1.0.0"       # 改动逻辑必须升版本，否则 cache 不失效
    category = "audio"

    def _execute(self, sample: Sample, config: OperatorConfig) -> dict:
        input_key = config.params.get("input_audio_key", "raw")
        output_key = config.params.get("output_audio_key", "my_output")
        # ... 处理 sample.audio_path(input_key) ...
        return {
            "audio": {output_key: str(out_path)},   # 也可返回 transcripts / quality / labels
            "lineage_entry": {
                "operator": self.full_name,
                "version": self.version,
                "params": dict(config.params),
                "input_key": input_key,
                "output_key": output_key,
                "output_path": str(out_path),
            },
        }
```

**集合级模板**（参考 `operators/ingest/scan.py`）：

```python
from audio_engine.core.operator import ManifestOperator, OperatorConfig
from audio_engine.core.registry import register_operator
from audio_engine.core.sample import Sample


@register_operator
class MyManifestOperator(ManifestOperator):
    name = "my_op"
    version = "1.0.0"
    category = "ingest"

    def run(self, samples: list[Sample], config: OperatorConfig) -> list[Sample]:
        # 收到当前全量样本，返回更新后的全量样本
        # 新建的样本要手动 add_lineage + mark_completed（样本级算子由基类代劳）
        return samples
```

实现时的强制约定：

1. **幂等**：重复运行不产生重复样本 / 重复副作用（如 `ingest.scan` 按 sha256 去重）
2. **血缘**：所有产出必须写 `lineage_entry`，可追溯「谁、哪个版本、什么参数、产出了什么」
3. **状态**：完成要 `mark_completed`，失败由 runner 统一 `mark_failed`，不要吞异常
4. **只引用不搬迁**：外部物理文件只读，产出写 `data/derived/`，工程内只留逻辑索引

### Step 4：注册与接入

1. `@register_operator` 装饰算子类（模板里已含）
2. 新建 category 时，在 `src/audio_engine/operators/__init__.py` 加 import（否则不会触发注册）
3. （可选）常用算子在 `cli/main.py` 的 `_resolve_operator` 里加短名别名

### Step 5：编排 YAML

文件位置：`pipelines/<name>.yaml`。两种输入形态：

```yaml
# 形态一：从外部目录起步（入库 + 处理一条龙）
name: ingest_baseline
input:
  source_dir: D:/SharedAudio/vendor_20260815   # 只读扫描，不拷贝
pipeline:
  - name: ingest
    operator: ingest.scan
  - name: resample
    operator: audio.resample
    params: { sample_rate: 16000, input_audio_key: raw, output_audio_key: resampled_16k }
```

```yaml
# 形态二：从已有 manifest 起步
name: baseline_qwen
input:
  manifest: datasets/manifests/raw_20260820.parquet
pipeline:
  - name: resample
    operator: audio.resample
    params: { sample_rate: 16000, input_audio_key: raw, output_audio_key: resampled_16k }
  - name: qwen_asr
    operator: asr.qwen
    params: { input_audio_key: resampled_16k }
```

编排检查点：

- 每一步的 `input_audio_key` 必须是上游某步的 `output_audio_key`（或 `raw`），**key 链断裂是最常见错误**
- 需要筛选时用顶层 `filter`（pandas query 语法）
- ASR 等重算子放在 `quality.filter` 之后，先缩小样本集再跑贵的步骤

### Step 6：验证与验收

按本次改造的实际验证顺序：

1. **单测**：在 `tests/` 里为新算子写用例（用 `tmp_path` 生成音频，不依赖真实数据），跑 `python -m pytest tests/ -q` 全绿
2. **CLI 冒烟**：用临时目录 / 小数据集跑一次真实命令，确认端到端可用
3. **检查 run 产物**：`runs/<ts>_<name>/` 下四件套齐全，`metrics.json` 的 processed / failed 数字符合预期
4. **重跑验证幂等**：同命令再跑一次，应大量 cache_hit / skipped，样本数不变
5. **清理**冒烟测试产生的临时 run 目录

## 三、检查清单（构建完成前逐项过）

- [ ] 输入输出与音频 key 链在 Step 0 写清楚了
- [ ] 新算子类型选对了（样本级 / 集合级）
- [ ] `version` 有意义，逻辑变更会升版本
- [ ] lineage / status 完整，失败不吞异常
- [ ] 幂等：重跑不产生重复样本
- [ ] 注册链路通：`audio-data operators` 能列出新算子
- [ ] YAML 里 key 链无断裂
- [ ] 单测 + 冒烟 + 重跑三关都过
- [ ] 没有绕过 PipelineRunner 的独立脚本链路

## 四、实例回放：数据入库统一化（2026-08-20）

按上述流程回放本次改造，作为对照样例：

| 步骤 | 本次的具体做法 |
|------|----------------|
| Step 0 | 输入 = 外部物理目录；输出 = `datasets/manifests/*.parquet`；问题 = `ingest` 走 `Manifest.ingest()` 独立链路 |
| Step 1 | 盘点发现 registry 里没有入库算子 |
| Step 2 | 入库要「从无到有创建样本」，无法样本级表达 → 新增 `ManifestOperator` 基类 + 集合级算子 |
| Step 3 | 实现 `ingest.scan`：内部复用 `Manifest.ingest()` 扫描，按 sha256 去重保证幂等，逐样本写 lineage |
| Step 4 | `@register_operator` 注册；`operators/__init__.py` 加 `ingest`；CLI 加 `scan` 别名 |
| Step 5 | `PipelineConfig` 支持 `input.source_dir`；CLI `ingest` 命令改为内部构造单步流水线；示例 `pipelines/ingest_baseline.yaml` |
| Step 6 | 新增 `test_ingest_pipeline` 单测（7 个全过）→ 临时 wav 冒烟 CLI → 清理临时 run 目录 |

改造后所有入口统一：

```text
audio-data ingest <dir>        ─┐
audio-data pipeline run <yaml> ─┼→ PipelineRunner → OperatorRegistry → Operator
audio-data run <operator>      ─┘
```
