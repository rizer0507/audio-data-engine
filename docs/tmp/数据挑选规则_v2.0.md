# 数据挑选规则 v2.0（42 万条未金标 ASR 数据）

> 状态：建议实施版  
> 适用场景：金融贷款外呼 ASR 数据自动分拣、伪金标生成、人审队列生成、训练集/评测集候选构建  
> 目标模型：Qwen3-ASR 等 ASR 模型  
> 核心业务风险：短平快语句语义反转、否定词漏识别、人声串音、环境噪声、VAD 截断、语气词/脏话被错误“正向化”  
> 建议规则版本：`selection_v2.0`

---

## 1. 本次重构的核心结论

现有 `consensus_v1` 不建议推翻，以下设计继续保留：

1. `type / decision / gold_text` 分离；
2. 按 `model_family` 独立计票，避免同源模型重复投票；
3. 使用 medoid，而不是随机选一个模型输出作为标签；
4. 全流程保留 `rule_version`、支持模型、共识度等审计字段；
5. 文本一致度只叫 `transcript_similarity`，不叫 CER/字准率。

但在 42 万条全部未金标数据上，必须补齐四层能力：

1. **音频质量层**：不能再把“所有模型为空”等价成“噪声/空音频”；
2. **业务语义风险层**：否定词、意愿词、短句等必须先于相似度做硬拦截；
3. **伪金标置信等级层**：模型共识只能叫 pseudo gold，不能和人工金标混为一类；
4. **数据集治理层**：去重、训练/评测隔离、难例配额、人工抽检、版本冻结必须进入挑拣规则。

---

## 2. v2 的设计原则

### 2.1 “自动共识”不等于“真实金标”

任何仅由 ASR 模型互相投票产生的文本，都定义为：

- `pseudo_gold_high`
- `pseudo_gold_medium`

只有以下两类允许定义为真正的 `gold`：

- `human_gold`
- `trusted_external_gold`

因此建议新增：

```text
label_source
label_tier
is_human_verified
```

避免后续训练、评测、回溯时把“模型共识”误当成“人工真值”。

---

### 2.2 先做风险拦截，再做文本一致度

规则优先级必须满足：

```text
音频有效性
  > VAD/漏识别风险
  > 语义风险
  > 关键 token 冲突
  > 短句风险
  > 模型共识
  > 普通 hardcase
```

原因：一句较长文本即使只错一个“不”字，整体 `transcript_similarity` 仍可能很高，但业务语义已经完全反转。

因此：

> `similarity >= 0.95` 永远不能覆盖 `semantic_risk=true`。

---

### 2.3 42 万条数据不能只挑“最容易的一批”

如果训练集主要由多模型高度一致的数据组成，模型最终学到的大多仍是它本来就会的样本。

训练数据需要同时保留：

- 高质量普通样本；
- 否定/肯定意愿关键样本；
- 短句；
- VAD 边界截断；
- 串音；
- 环境噪声；
- 模糊发音；
- ASR family 间冲突样本；
- 经过人工修正的 hardcase。

---

现有字段继续保留：

| 字段 | 含义 |

## 4. 关键 token 与业务语义规则

### 4.1 关键否定 token

至少覆盖：

```text
不
不要
不用
不需要
没
没有
没要
没用
不是
不行
不考虑
不想
不办
不贷款
不缺
```

### 4.2 关键肯定/需求 token

至少覆盖：

```text
要
需要
有需要
要用
可以
考虑
想要
想办
缺
有需求
```

### 4.3 高风险短反馈 token

至少覆盖：

```text
嗯
嗯嗯
啊
有
是
对
好
不要
不用
没有
不需要
```

词表必须配置化，例如：

```text
configs/selection/semantic_lexicon_zh_v2.yaml
```

禁止把词表硬编码在 Python 逻辑内。

## 5. 文本标准化

用于模型间比较的文本执行：

1. Unicode 规范化；
2. 去除首尾空格；
3. 统一全半角；
4. 可选去除纯标点差异；
5. 数字表达按统一策略归一化；
6. 保留所有可能改变业务语义的词。

### 5.1 禁止在比较前删除以下内容

禁止为了提高 similarity 而删除：

- `不`
- `没`
- `要`
- `需要`
- `不用`
- `嗯`
- `有`
- 其他业务关键 token

文本清洗只能消除格式噪声，不能消除业务信息。

---

## 6. 音频预检层

### 6.1 `invalid_audio`

满足任一条件：

```text
无法解码
duration <= 0
采样数据损坏
音频文件为空
```

处理：

```text
type = invalid_audio
decision = exclude
label_tier = none
dataset_role = exclude
```

---

### 6.2 `true_silence`

不能再使用“所有 ASR 都为空”直接判定。

建议同时满足：

```text
全部模型族输出为空
AND
speech_ratio 极低
AND
无明显头尾语音能量
```

才允许：

```text
type = true_silence
decision = auto_empty
gold_text = ""
```

初始 `speech_ratio` 阈值可从 `0.05` 左右开始，但必须通过人工抽检校准。

---

### 6.3 `possible_vad_miss`

满足：

```text
全部/多数模型为空
BUT
VAD 或能量检测显示存在明显人声
```

或者：

```text
音频起始/结束边缘存在人声能量
AND
ASR 输出明显过短或为空
```

处理：

```text
type = possible_vad_miss
decision = model_review
label_tier = none
priority = P0
```

该桶是当前业务中必须新增的核心桶。

---

### 6.4 `overlap_crosstalk`

出现以下信号之一：

```text
重叠说话检测命中
串音检测命中
多个模型输出差异大且音频存在多人声
```

处理：

```text
type = overlap_crosstalk
decision = model_review
priority = P1
```

如果后续确认串音是业务真实场景，该桶应成为专项训练数据，而不是全部丢弃。

---

## 7. 短句规则

满足任一条件可标记：

```text
duration <= SHORT_AUDIO_SEC
OR
候选文本长度 <= SHORT_TEXT_CHAR
```

建议初始值：

```text
SHORT_AUDIO_SEC = 2.0
SHORT_TEXT_CHAR = 6
```

阈值必须配置化并通过样本分布调整。

### 7.1 短句禁止单纯依赖 similarity

例如：

```text
需要
不需要
```

编辑距离很小，但语义完全相反。

对于 `short_utterance=true`：

```text
只有跨模型族文本完全一致
或
语义类别一致 + 关键 token 一致
```

才允许进入 `pseudo_gold_high`。

否则：

```text
type = short_utterance_risk
decision = model_review
priority = P0/P1
```

---

## 8. 语义风险层

### 8.1 `semantic_inversion`

任意独立模型族之间出现：

```text
positive <-> negative
```

直接：

```text
type = semantic_inversion
decision = model_review
label_tier = none
priority = P0
```

### 8.2 v2 的重要变化

**禁止：**

```text
“因为 ≥2 个独立模型族形成多数，所以 semantic_inversion 自动接受”
```

金融外呼场景中，否定/肯定反转的业务损失远高于普通字符错误；多个模型可能存在共同偏置，因此不能仅靠多数票消除风险。

---

### 8.3 `critical_token_conflict`

如果不同模型族在以下 token 上存在“有/无”差异：

```text
不 / 没 / 要 / 需要 / 不用 / 不要 / 有 / 是 / 嗯
```

即使整体 similarity 很高，也进入：

```text
type = critical_token_conflict
decision = model_review
priority = P0
```

---

### 8.4 `semantic_sanitization`

针对“脏话、抱怨、拒绝语句被 ASR 美化成正向意愿”的问题，增加：

```text
semantic_sanitization_risk = true
```

触发条件可以来自：

- 不同模型族一方输出攻击/拒绝/粗口，一方输出正向需求；
- teacher ASR 与普通 ASR 的情绪/意愿极性明显冲突；
- 规则词典命中拒绝/粗口但最终候选被转成肯定意愿。

处理：

```text
type = semantic_sanitization
decision = model_review
priority = P0
```

---

## 9. 模型族共识计算

### 9.1 同族降权

继续执行：

```text
qwen1 + qwen2 != 2 个独立票
```

同一 family 先生成 family-level candidate，再进行跨 family 共识。

---

### 9.2 family-level candidate

同一个模型族存在多个输出时：

1. 计算族内相似度；
2. 选择族内 medoid；
3. 如果族内本身严重冲突，则标记：

```text
family_internal_conflict = true
```

该 family 不得作为高置信投票。

---

## 10. 伪金标分级

### 10.1 `pseudo_gold_high`

必须全部满足：

```text
audio_valid = true
存在有效人声
semantic_risk = false
critical_token_conflict = false
vad_edge_risk = false
family_internal_conflict = false
至少 2 个独立模型族形成一致 cluster
cluster 内 min_similarity >= 0.95
semantic_class 跨 family 一致
```

如果是短句，还必须：

```text
跨 family 文本完全一致
OR
关键 token 完全一致且语义一致
```

处理：

```text
type = pseudo_gold_high
decision = auto_accept
label_source = model_consensus
label_tier = pseudo_high
gold_text = cluster_medoid
```

注意：

> `pseudo_gold_high` 可以作为大规模训练数据来源，但不得直接进入正式评测集。

---

### 10.2 `pseudo_gold_medium`

满足：

```text
不存在 P0/P1 语义风险
dominant cluster 占模型输出 >= 75%
跨 >= 2 个独立模型族
cluster 内 min_similarity >= 0.90
semantic_class 一致
```

处理：

```text
type = pseudo_gold_medium
decision = model_review 或低权重训练候选
label_source = model_consensus
label_tier = pseudo_medium
```

建议不要默认与 `pseudo_gold_high` 同权训练。

---

## 11. `hallucination` 重构

旧逻辑中：

```text
空占比 >= 75%
且非空仅来自单族
```

可以继续作为“疑似 hallucination”的文本信号，但不能直接决定音频为空。

v2：

```text
多数模型为空
+ 单一 family 非空
```

之后必须看音频侧：

### 情况 A：无明显人声

```text
type = hallucination
decision = auto_empty 或 model_review
```

### 情况 B：存在明显人声

```text
type = model_missing_or_disagreement
decision = model_review
```

避免真实语音因为多个模型漏识别而被错误标成空。

---

## 12. `model_missing`

原来的 `qwen_missing` 建议泛化为：

```text
model_missing
```

并用字段记录：

```text
missing_family = qwen / sensevoice / other
```

判定：

```text
某 family 全空
其他至少一个独立 family 明确非空
音频侧检测到人声
```

处理：

```text
type = model_missing
decision = model_review
```

如果业务仍需要重点监控 Qwen，可通过：

```text
subtype = qwen_missing
```

保持统计兼容。

---

## 13. voicemail

原有“至少两个独立模型族命中 voicemail”逻辑可以保留。

建议增加：

```text
dataset_role = exclude_from_general_asr_train
```

除非你的线上场景本身需要专门识别语音信箱。

voicemail 不应与普通真人业务语音混合统计。

---

## 14. hardcase

满足以下任一情况且未命中更高优先级桶：

```text
无法形成稳定跨 family 共识
文本差异大
语义 unknown
模型族内部冲突
音频质量异常但无法确定类型
teacher ASR 与普通 ASR 持续冲突
```

处理：

```text
type = hardcase
decision = model_review
label_tier = none
```

---

## 15. 最终判定顺序（严格）

```text
0. 文件完整性检查
   → invalid_audio

1. 去重 / 近重复检测
   → duplicate

2. 音频侧检测
   → speech_ratio / noise / overlap / VAD edge

3. 全模型为空判断
   → 无人声证据 → true_silence
   → 有人声证据 → possible_vad_miss

4. voicemail
   → voicemail

5. 模型族内部一致性
   → family_internal_conflict

6. 业务语义风险
   → semantic_inversion
   → critical_token_conflict
   → semantic_sanitization

7. 短句风险
   → short_utterance_risk

8. 多数为空 / 单族非空
   → hallucination
   → model_missing

9. 严格跨 family 共识
   → pseudo_gold_high

10. dominant cluster 共识
   → pseudo_gold_medium

11. 其余
   → hardcase
```

## 16. 推荐分拣桶

| 优先级 | type | 主要含义 | decision | 可直接进训练 |
| ---: | --- | --- | --- | --- |
| P0 | `semantic_inversion` | 肯定/否定反转 | `model_review` | 否 |
| P0 | `critical_token_conflict` | 不/没/要/需要等冲突 | `model_review` | 否 |
| P0 | `possible_vad_miss` | 有人声但模型空/过短 | `model_review` | 否 |
| P0 | `semantic_sanitization` | 拒绝/脏话被正向化风险 | `model_review` | 否 |
| P1 | `short_utterance_risk` | 短句高语义敏感 | `model_review` | 否 |
| P1 | `overlap_crosstalk` | 串音/多人声 | `model_review` | 人审后可 |
| P1 | `model_missing` | 某 family 漏识别 | `model_review` | 人审后可 |
| P2 | `hallucination` | 单族疑似幻觉 | `model_review/auto_empty` | 视结果 |
| P2 | `hardcase` | 普通模型分歧 | `model_review` | 人审后可 |
| P3 | `pseudo_gold_medium` | 中等跨族共识 | `model_review/train_candidate` | 可低权重 |
| P4 | `pseudo_gold_high` | 高置信跨族共识 | `auto_accept` | 是 |
| P4 | `true_silence` | 高置信无语音 | `auto_empty` | 视训练目标 |
| P4 | `voicemail` | 语音信箱 | `auto_accept/review` | 通常隔离 |
| PX | `duplicate` | 重复数据 | `exclude/reference_only` | 仅保留代表样本 |
| PX | `invalid_audio` | 损坏数据 | `exclude` | 否 |

## 17. 42 万条数据的审核策略

不能对 42 万条全部人工打金标。

建议采用：

### 17.1 全量自动分拣

42 万条全部经过 v2 规则，得到所有桶的数量和比例。

必须输出：

```text
bucket_count
bucket_ratio
family_distribution
duration_distribution
semantic_distribution
```

---

### 17.2 优先人工审核 P0

优先顺序：

```text
semantic_inversion
critical_token_conflict
possible_vad_miss
semantic_sanitization
```

这些样本不仅用于修标签，也是后续专项 SFT/微调最有价值的数据。

---

### 17.3 P1/P2 分层抽样

根据：

```text
type
duration bucket
semantic_class
noise level
model family conflict
```

分层抽样，防止只审核某一种 hardcase。

---

### 17.4 pseudo_gold 必须抽检

即使 `pseudo_gold_high` 自动通过，也必须做随机人工抽检。

建议首轮至少：

```text
pseudo_gold_high：随机抽检 500~1000 条
pseudo_gold_medium：随机抽检 500~1000 条
true_silence：随机抽检 300~500 条
```

目标不是“做更多金标”，而是估计每个自动桶的真实误标率。

如果 `pseudo_gold_high` 中仍出现明显语义反转，应立即停止扩大自动接收，并回查规则。

---

## 18. 训练集构建规则

不要直接：

```text
所有 pseudo_gold_high → train
```

建议按数据价值进行采样。

训练集至少包含：

```text
普通干净语音
短句
negative intent
positive intent
关键 token
VAD 边界问题
噪声
串音
模糊发音
模型分歧后人工修正样本
```

### 推荐训练数据构成思想

不是固定比例，但可以从以下结构起步：

```text
60%~70% 高质量普通样本
20%~30% 人工确认 hardcase / 业务高风险样本
10% 左右噪声、串音、VAD、边界条件样本
```

之后根据评测集错误分布动态调整，而不是长期固定。

---

## 19. 评测集构建规则

正式评测集必须：

```text
100% human_gold 或 trusted_external_gold
```

禁止：

```text
pseudo_gold_high
pseudo_gold_medium
```

直接作为最终评测真值。

### 19.1 评测集必须覆盖

```text
normal_clean
short_utterance
semantic_inversion
negative_intent
positive_intent
critical_token
vad_miss
noise
overlap_crosstalk
ambiguous_pronunciation
```

### 19.2 评测集冻结

一旦进入正式评测 Release：

```text
audio_id
gold_text
type
subtype
speaker/call group
release_version
```

全部冻结。

后续训练数据不得与评测数据发生：

- `audio_id` 重复；
- 音频指纹近重复；
- 同一切片来源泄漏；
- 可识别的同通电话片段跨 train/eval 泄漏。

## 20. 去重规则

42 万条规模下必须加入去重。

至少做：

### L1：完全重复

```text
file hash / pcm hash
```

### L2：近重复

可使用：

```text
audio fingerprint
来源 call_id + 时间区间
相似音频 embedding
```

重复组只保留一个主要训练样本，其他记录：

```text
duplicate_group_id
duplicate_of
```

避免重复数据在训练中被异常放大，也避免训练/评测泄漏。

## 23. 与 v1 的兼容迁移

如果当前代码大量依赖旧 `type`，可以先不一次性改完。

建议第一阶段使用：

```text
type = 原有大类
subtype = v2 新类别
```

例如：

```text
type = noise
subtype = possible_vad_miss
```

或：

```text
type = hardcase
subtype = critical_token_conflict
```

稳定后再升级为完整 v2 `type`。

### 推荐映射

| v1 | v2 |
| --- | --- |
| `noise` | `invalid_audio` / `true_silence` / `possible_vad_miss` / `noise_only` |
| `semantic_inversion` | 保留，但禁止多数票自动接受 |
| `hallucination` | 保留，同时增加音频侧证据 |
| `qwen_missing` | `model_missing` + `subtype=qwen_missing` |
| `auto_gold` | `pseudo_gold_high` |
| `consensus_gold` | `pseudo_gold_medium` 或满足更严条件后升 `pseudo_gold_high` |
| `hardcase` | 保留，并拆分 subtype |
| `voicemail` | 保留 |

## 25. v2 上线前验收

上线前至少做一轮小规模校准集。

建议从现有数据分层抽取：

```text
2000~5000 条
```

人工确认以下内容：

```text
真实转写
是否有人声
是否存在 VAD 截断
是否串音
业务语义 positive/negative/neutral
是否关键 token 错误
```

用该校准集计算：

```text
每个 bucket precision
false_empty_rate
semantic_inversion recall
critical_token_conflict recall
pseudo_gold_high error rate
```

只有在确认自动桶质量达到可接受水平后，才把规则放到 42 万条全量数据上。

## 26. 最终原则

整个 v2 只遵循三个最高原则：

### 原则 1：高风险错误优先于字符级一致度

```text
语义正确 > 关键 token 正确 > 普通 CER
```

### 原则 2：模型共识只能产生伪金标

```text
model consensus ≠ human gold
```

### 原则 3：难例不是垃圾数据

```text
hardcase = 后续训练增益最高的数据池之一
```

因此最终体系不是：

```text
42 万条 → 挑出最干净的数据 → 训练
```

而应是：

```text
42 万条
  → 全量自动结构化分拣
  → 高置信伪标签池
  → 业务高风险难例池
  → 噪声/VAD/串音专项池
  → 人工金标核心池
  → 冻结评测集
  → 动态训练集
```

这才适合持续迭代 Qwen3-ASR 的数据闭环。
