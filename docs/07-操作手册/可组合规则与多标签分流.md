# 可组合规则与多标签分流（040）

> 代码交付：`selection_multi_tag_v1`。旧五类入口不变。默认 **已有证据模式**（不重跑 ASR、不强制声学）。  
> 需求：[040](../04-改进需求/已完成/040-可组合规则与多标签分流.md)

## 1. 生产打标（唯一编排入口）

```bash
audio-data pipeline run pipelines/tag_dataset_multi_tag_v1.yaml \
  --source-name "$BATCH" \
  --config configs/tagging/zh_asr_multi_tag_v1.yaml
```

- 输入优先：`datasets/stage1/derived/prepared_asr_v3_$BATCH.parquet`（可回退带 transcripts 的 classified_*）
- 输出：`datasets/stage1/derived/tagged_multi_tag_v1_$BATCH.parquet`
- 统计：`data/exports/summary_multi_tag_v1_$BATCH.xlsx`
- 工作区：`runs/tagging/$BATCH/selection_multi_tag_v1/`（`tag_state.json`、人工日志、cache、published 快照）

按需补算声学（显式启用）：

```bash
# 在额外 --config 覆盖 YAML 中写 evidence_mode: compute_acoustic
# 或经 tags run / 算子 params 传入 evidence_mode=compute_acoustic
```

断点续跑：同一 `work_root` 下传入算子参数 `resume_run_id=<上次 run_id>`（见 `runs/tagging/.../work/<run_id>/progress.json`）。恢复不会清空人工日志。

## 2. 配置与新增规则（无需改 Python）

主配置：`configs/tagging/zh_asr_multi_tag_v1.yaml`  
片段：`configs/tagging/fragments_v1.yaml`  
演示词表：`configs/tagging/lexicons/tag_1_patterns_v1.yaml`  
业务模板参考：`configs/tagging/templates/business_rules_v1.yaml`

1. 在 `tags:` 增加 `tag_id`（稳定 ID）
2. 在 `rules:` 增加 `rule_id` + 嵌套 `all` / `any` / `not` / `at_least` / `fragment` / `capability`
3. 需要正则时在 `lexicons:` 增加独立 YAML，条件里写 `capability: lexicon_match`
4. `audio-data tags validate -c <你的配置>` 通过后再跑 pipeline

`tag_1` 示例已内置：全族双跑成功 + 三族 stable_text + SenseVoice/GLM 无害等价 + 词表命中共同代表文本 + 整段单汉字 + Qwen 与之不等价。可与 `critical_short` 同时命中。

## 3. 管理 CLI（与 pipeline 共用服务层）

```bash
# 校验
audio-data tags validate -c configs/tagging/zh_asr_multi_tag_v1.yaml

# 预演（不写正式状态）
audio-data tags preview --batch "$BATCH" -c configs/tagging/zh_asr_multi_tag_v1.yaml

# 解释单样本
audio-data tags explain --batch "$BATCH" --sample-id <id> [--rule-id rule_tag_1_v1]

# 人工添加 / 移除（移除=撤人工添加+持续屏蔽）/ 恢复自动 / 只撤人工添加
audio-data tags add --batch "$BATCH" --sample-id <id> --tag-id tag_1 --sha256 <audio_sha> --reason "..."
audio-data tags remove --batch "$BATCH" --sample-id <id> --tag-id tag_1 --sha256 <audio_sha> --reason "..."
audio-data tags restore --batch "$BATCH" --sample-id <id> --tag-id tag_1 --sha256 <audio_sha>
audio-data tags retract-manual --batch "$BATCH" --sample-id <id> --tag-id tag_1 --sha256 <audio_sha>

# 筛选导出
audio-data tags export \
  --input datasets/stage1/derived/tagged_multi_tag_v1_$BATCH.parquet \
  --output data/exports/filter_$BATCH.parquet \
  --include-all tag_1 \
  --include-any critical_short
```

服务层旁路（逻辑与 pipeline 相同，生产仍以 pipeline 为准）：

```bash
audio-data tags run --batch "$BATCH" -c configs/tagging/zh_asr_multi_tag_v1.yaml
```

## 4. 样本字段与有效标签

- `labels.tags`：去重后的有效 tag_id 列表
- `labels.tagging`：`policy_version` / `snapshot_id` / `eval_status`（tagged|untagged|unresolved|not_evaluated）/ 规则覆盖率
- 有效标签 =（自动命中 ∪ 人工添加）− 人工屏蔽；多来源同 tag 只显示一次

## 5. 与旧五类 / 训练门禁

- 不覆盖旧 `category` / `risk_tag` / `noise_kind`
- 仅有 tag ≠ 人工金标 / 训练准入；训练抽取仍走现有完成门禁与排除契约

## 6. 环境限制

- **真实 Silero VAD / DNSMOS 推理**：本机交付以模拟适配器验证调度（零调用、共享去重、失败隔离）。服务器模型可用后再做真实声学 smoke，勿把模拟成功写成真实推理成功。
- 默认 `evidence_mode=existing`：缺声学证据的规则为 `unknown`，不伪造。
