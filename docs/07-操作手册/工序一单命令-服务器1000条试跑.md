# 工序一单命令：服务器 1000 条试跑操作手册

适用日期：2026-09-16；按当前 `stage1` CLI、runtime 配置和编排代码编写。以下命令在 **Linux 服务器 Bash** 执行。本文提供试跑步骤，尚未完成服务器实测。

目标：三家族各跑两路，生成 v2.2 Parquet、XLSX 和对账报告。首次只测试独立的 1000 条输入目录，不直接把完整数据源交给入口。

## 1. 拷贝代码并检查试跑前置条件

将当前开发代码完整拷贝到服务器项目目录，至少包含 `src/`、`configs/`、`pipelines/`、`resources/`、`scripts/`、`tests/`、`pyproject.toml` 和 README。保留服务器已有模型环境、权重和业务数据；不要将开发机的 `runs/`、测试生成的 catalog、历史产物或虚拟环境覆盖到服务器。

```bash
cd /data2/data-cp/lizi/audio-data-engine
# 激活以前能运行 audio-data 和 SenseVoice 的环境，再执行：
python -c "import sys; print(sys.executable)"
python -m pip install -e .
python -c "import audio_engine; print(audio_engine.__file__)"
audio-data stage1 run --help
audio-data stage1 retry --help
```

确认模块路径指向这次拷贝的代码。引擎环境还需要 `torch`、`funasr`、`modelscope`、`onnxruntime`、`librosa`、`openpyxl` 和 `rapidfuzz`，优先复用已跑通环境，不重新合并 Qwen、GLM 环境：

```bash
python -c "import torch, funasr, modelscope, onnxruntime, librosa, openpyxl, rapidfuzz; print('imports OK')"
```

缺依赖时在**引擎环境**按现有服务器安装方式补齐；有可用包源时可用 `python -m pip install -e '.[sensevoice,dnsmos]'`。GLM 保持原独立环境。所有后续命令从项目根目录执行。

**当前代码有一个已发现的试跑阻断项，先检查：**

```bash
python - <<'PY'
from audio_engine.core.stage1.reconcile import FIVE_CLASSES
expected = {'voicemail', 'semantic_risk', 'environment_noise', 'gold_candidate', 'hardcase'}
assert FIVE_CLASSES == expected, f'交付校验类别与 v2.2 不符，请先修复代码并重新拷贝：{FIVE_CLASSES}'
print('v2.2 校验类别一致')
PY
```

编写本手册时，`src/audio_engine/core/stage1/reconcile.py` 中仍为 `clear_semantic/environment_noise/human_noise/non_speech/foreign_language`，会拒绝合法的 v2.2 分类。若检查失败，先让开发端修复校验器及对应回归，再上传；不要把分类结果改成这套错误类别，也不要绕过对账。若包含 excluded 样本，还需核对 XLSX 空类别的 NaN 归一化，当前代码直接转字符串可能产生假差异。

另外，当前状态页的 ASR 总覆盖率按**已完成并登记的路数 / 6**计算，路内行数来自已落盘 Parquet；不能把它当作逐样本实时成功率。`--failed-only` 重置失败阶段后会重新调用该路流水线，不能据此保证只推理失败样本；本次应记录实际复用情况。以上是代码核对结论，不表示其他能力已通过现场验收。

## 2. 准备独立的 1000 条数据和服务器配置

### 2.1 设置本次变量

将下面所有“替换为……”改成实际值。GPU 必须是获授权的两张卡，不照抄历史卡号。

```bash
export ENGINE_PY="$(python -c 'import sys; print(sys.executable)')"
export AUTHORIZED_GPUS='替换为两个授权卡号，以逗号分隔'
export QWEN_VLLM='/替换为Qwen环境绝对路径/bin/vllm'
export DNSMOS_ONNX='/替换为DNSMOS绝对路径/sig_bak_ovr.onnx'
export ORIGINAL_SOURCE='/替换为原始音频目录'
export BATCH="stage1-smoke1000-$(date +%Y%m%d-%H%M%S)"
export SOURCE_DIR="/data2/data-cp/lizi/stage1-tests/${BATCH}/audio"
export RUNTIME_CFG="$PWD/configs/stage1/server-smoke1000.yaml"

nvidia-smi --query-gpu=index,uuid,name,memory.total,memory.used,utilization.gpu --format=csv
```

当前 ASR/分类产物按 batch 命名，首次试跑必须使用新 batch，避免同名历史结果污染。需要恢复时保留原 batch/job_id；若修改来源、权重或启动配置重新测试，使用新 batch。

Qwen 启动器路径可在原 Qwen 环境运行 `command -v vllm` 获取，然后回到引擎环境。SenseVoice 当前随 `engine_python` 执行。

### 2.2 如果已有恰好 1000 条的独立目录

直接把 `SOURCE_DIR` 改为该目录，继续 2.3。当前 `stage1 run` **没有 `--limit 1000`**，`--max-rows` 只控制 XLSX 分文件大小，不能限制输入数量。

如果需要从大目录抽取，下面脚本固定随机种子，复制 1000 个 WAV 并保留相对路径；不修改原始数据。首轮用带头 WAV，避免无头 PCM 采样率解释错误；原始 PCM 请先按真实采样率准备成 WAV，不要改扩展名冒充。

```bash
"$ENGINE_PY" - <<'PY'
import os, random, shutil, json
from pathlib import Path
src = Path(os.environ['ORIGINAL_SOURCE']).resolve(strict=True)
dst = Path(os.environ['SOURCE_DIR']).resolve()
assert src.is_dir()
assert dst != src and src not in dst.parents, '测试目录必须位于源目录之外'
assert not dst.exists(), '测试目录已存在，请换新 batch 或直接使用现有目录'
files = sorted(p for p in src.rglob('*') if p.is_file() and p.suffix.lower() == '.wav')
assert len(files) >= 1000, f'只有 {len(files)} 个 WAV'
chosen = random.Random(20260916).sample(files, 1000)
dst.mkdir(parents=True)
records = []
for p in chosen:
    rel = p.relative_to(src)
    target = dst / rel
    target.parent.mkdir(parents=True, exist_ok=True)
    shutil.copy2(p, target)
    records.append({'source': str(p), 'test_file': str(target)})
(dst.parent / 'sample_1000.json').write_text(json.dumps(records, ensure_ascii=False, indent=2), encoding='utf-8')
print('已复制 1000 个 WAV：', dst)
PY
```

验证文件数并挑选一个可解码、非空的探针：

```bash
export PROBE_AUDIO="$("$ENGINE_PY" - <<'PY'
import os
from pathlib import Path
import soundfile as sf
files = sorted(p for p in Path(os.environ['SOURCE_DIR']).rglob('*') if p.is_file())
assert len(files) == 1000, f'目录中应恰有1000个音频文件，当前{len(files)}个'
assert all(p.suffix.lower() == '.wav' for p in files), '首轮示例只接受 WAV'
for p in files:
    try:
        info = sf.info(str(p))
        if 1 <= info.duration <= 10:
            print(p.resolve())
            break
    except Exception:
        pass
else:
    raise RuntimeError('没有1～10秒可读WAV，请单独指定真实探针音频')
PY
)"
test -n "$PROBE_AUDIO" && test -f "$PROBE_AUDIO"
```

此处 1000 是原始输入文件数；清洗可能排除坏音频或去重，最终数目按 cleaned 对账，不能直接认定最终必须有 1000 条。

### 2.3 生成本机 runtime 配置

以下脚本保留模板中的三家族启动参数，只填现场值。**同时更新 DNSMOS 实际质量配置**：当前分类流水线读取 `configs/quality/dnsmos_p835.yaml`，仅填写 runtime 的 `onnx_path` 不足以改变评分路径。

```bash
"$ENGINE_PY" - <<'PY'
import os, shutil
from pathlib import Path
import yaml
cfg = yaml.safe_load(Path('configs/stage1/server.yaml').read_text(encoding='utf-8'))
tokens = [s.strip() for s in os.environ['AUTHORIZED_GPUS'].split(',')]
assert len(tokens) == 2 and all(s.isdigit() for s in tokens), '请填写两个授权物理卡号'
assert len(set(tokens)) == 2
for name in ('ENGINE_PY', 'QWEN_VLLM', 'DNSMOS_ONNX', 'PROBE_AUDIO'):
    assert Path(os.environ[name]).is_file(), f'{name} 路径不存在'
cfg['authorized_gpus'] = [int(s) for s in tokens]
cfg['authorized_gpu_uuids'] = None
cfg['engine_python'] = os.environ['ENGINE_PY']
cfg['families']['qwen']['vllm_bin'] = os.environ['QWEN_VLLM']
cfg['dnsmos']['onnx_path'] = os.environ['DNSMOS_ONNX']
cfg['probe']['audio_path'] = os.environ['PROBE_AUDIO']
cfg['scheduler']['dual_gpu'] = True
out = Path(os.environ['RUNTIME_CFG'])
out.write_text(yaml.safe_dump(cfg, allow_unicode=True, sort_keys=False), encoding='utf-8')
quality_path = Path('configs/quality/dnsmos_p835.yaml')
backup = quality_path.with_name(quality_path.name + '.before-smoke1000')
if not backup.exists():
    shutil.copy2(quality_path, backup)
quality = yaml.safe_load(quality_path.read_text(encoding='utf-8'))
quality['model_path'] = os.environ['DNSMOS_ONNX']
quality_path.write_text(yaml.safe_dump(quality, allow_unicode=True, sort_keys=False), encoding='utf-8')
print('runtime:', out)
print('DNSMOS model_path:', quality['model_path'])
PY

audio-data stage1 check-config --runtime-config "$RUNTIME_CFG"
"$ENGINE_PY" -c 'import os, onnxruntime as ort; ort.InferenceSession(os.environ["DNSMOS_ONNX"], providers=["CPUExecutionProvider"]); print("DNSMOS ONNX 加载成功")'
```

`check-config` 必须返回 `ok: true`；缺字段退出码为 2，路径错误为 3。它不能替代真实推理验证。核对 runtime 中模型权重、Qwen chat template、GLM 环境和端口是否仍与历史成功命令一致。DNSMOS 保持 `calibrated: false`，不要改动 v2.2 阈值。

## 3. 提交 1000 条试跑并查看进度

首次让编排器管理服务，不提前手工启动 Qwen/GLM，不加 `--attach-existing`。检查授权卡显存和 5555/5570 端口；发现已有进程时先确认归属，不能批量杀服务。0% GPU 利用率不代表显存空闲。

```bash
nvidia-smi
ss -ltnp '( sport = :5555 or sport = :5570 )'

export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1
mkdir -p /data2/data-cp/lizi/stage1-tests

audio-data stage1 run \
  --batch "$BATCH" --source "$SOURCE_DIR" \
  --model qwen=/data2/data-cp/zcl/models/Qwen3-ASR-1___7B \
  --model glm=/data2/data-cp/models/GLM-ASR-Nano-2512 \
  --model sensevoice=/data2/data-cp/xijujun/models/SenseVoiceSmall \
  --runtime-config "$RUNTIME_CFG" --gpus "$AUTHORIZED_GPUS"
```

若实际权重路径变化，同时修改 runtime 和命令。当前入口固定支持这三个家族，不增加 Kimi。输出中的 `submitted: true` 只表示已提交；记下真实 `job_id`：

```bash
export JOB_ID='替换为刚才返回的job_id'
export JOB_DIR="$PWD/runs/stage1/jobs/$JOB_ID"
printf 'export BATCH=%q\nexport JOB_ID=%q\nexport JOB_DIR=%q\n' "$BATCH" "$JOB_ID" "$JOB_DIR" > /data2/data-cp/lizi/stage1-tests/latest-smoke.env

audio-data stage1 status "$JOB_ID" --watch --interval 5
```

`Ctrl+C` 退出的是查看进度命令，不会取消后台任务。SSH 重连后激活同一引擎环境、回到项目根目录，执行：

```bash
source /data2/data-cp/lizi/stage1-tests/latest-smoke.env
audio-data stage1 status "$JOB_ID" --json
audio-data stage1 wait "$JOB_ID" --no-json
wait_rc=$?
printf 'wait退出码=%s\n' "$wait_rc"
```

`wait`：0 为正式对账成功，1 为失败/对账失败，3 为需人工介入；设置 `--timeout 秒数` 后超时为 2，超时不会取消工作。`status` 是查询命令，其退出码不表示任务成功。`--watch` 在需人工介入时可能继续等待，可退出后查日志。

本轮不需要 `--dry-run`：它会创建任务和快照但不做真实推理，故意不返回正式成功。若要演练，单独使用新 batch，勿混入这次正式试跑。

## 4. 失败排查和恢复

首先查看状态与对应阶段日志，不要直接重新提交同 batch，也不要在 worker 仍执行时反复 resume/retry。

```bash
audio-data stage1 status "$JOB_ID" --json
tail -n 100 "$JOB_DIR/worker.log"
find "$JOB_DIR/stages" -type f -name stderr.log -print
```

各阶段命令及标准输出位于 `stages/<阶段>/attempt_<次数>/command.json、stdout.log、stderr.log`；服务资料在 `serve/<家族>/`；底层流水线在 `pipeline_runs/`。优先检查失败阶段的最新 attempt。加载权重或整路尚未产出 Parquet 时，进度可能长时间不变；结合 GPU 和底层日志判断，不能仅凭 `stalled` 自动认定服务已死。

- **模型启动失败**：检查独立解释器、权重/模板、端口占用和显存。保留 GLM 的 FlashInfer 环境变量及启动参数。
- **一直等待 GPU**：检查授权卡显存和进程归属；不要手删仍有效的 GPU 租约，也不要终止其他用户进程。
- **DNSMOS unavailable**：查实际质量配置路径、ONNX 与音频是否可读；这是 v2.2 合法回退字段，但本次若要验证 DNSMOS 联合分支，应解决依赖问题再测试。
- **reconcile 报非法 category**：先检查第 1 节已知校验器问题，不能通过改结果或删除类别绕过。

修复外部故障、确认原 worker 已退出后，根据情况执行一条：

```bash
# 编排中断后的恢复
audio-data stage1 resume "$JOB_ID"

# GLM 第2路失败：只重置该范围内的失败阶段
audio-data stage1 retry "$JOB_ID" --family glm --run 2 --failed-only

# 仅导出或对账失败，保留 ASR
audio-data stage1 retry "$JOB_ID" --export-only
```

三条命令按故障选择，不要整段连续执行。恢复后再运行 `status`/`wait`。记录底层流水线是否复用成功样本；当前 CLI 不提供单样本选择参数。修复代码或修改配置后，不应默认旧检查点自动失效；涉及模型/规则变化用新 batch，涉及仅对账代码修复可采用 export-only 并重新核验结果。

## 5. 验收、取结果及回传问题

先保存最终状态和对账报告：

```bash
audio-data stage1 status "$JOB_ID" --json > "$JOB_DIR/final_status.json"
python -m json.tool "$JOB_DIR/reconcile.json"
python -m json.tool "$JOB_DIR/outputs.json"
```

默认主产物位置：

```text
data/exports/summary_five_class_v2_2_auto_noise_<BATCH>.xlsx
datasets/stage1/derived/classified_five_class_v2_2_auto_noise_<BATCH>.parquet
datasets/stage1/cleaned/cleaned_<BATCH>.parquet
datasets/stage1/asr/{qwen_1,qwen_2,glm_1,glm_2,sensevoice_1,sensevoice_2}_asr_<BATCH>.parquet
runs/stage1/jobs/<JOB_ID>/
```

1000 条通常只有一个 XLSX；实际位置以 `outputs.json` 为准。job 目录保存配置、身份、检查点及日志；主 Parquet/XLSX 在上面的全局目录，**仅复制 job 目录不会包含全部交付文件**。

检查：`batch_succeeded=true`、`reconcile.ok=true`，六路完整，XLSX 与 classified/cleaned 行数和样本集合一致。五类只能为 `voicemail/semantic_risk/environment_noise/gold_candidate/hardcase`；excluded 单独计数且有原因。若 cleaned 少于 1000，逐项核对清洗排除/去重，不能以分类对账通过代替源数据完整性审计。

本次建议记录：总耗时、每族双路耗时、两卡任务衔接、各路行数、五类计数、excluded 和 DNSMOS fallback 数。1000 条能验证流程，但不能证明大批稳定性、逐样本精准补跑或超过 20,000 行的分文件导出已通过验收。状态中的 `server_e2e_accepted=false` 是当前静态能力标记，不替代这次真实对账结果，也无需手改成 true。

需要回传排查时，至少带上 `final_status.json`、`state.json`、`reconcile.json`（若已生成）、`outputs.json`、`worker.log`、失败阶段的命令与最新日志，以及本次使用的 runtime 配置。成功时带回 XLSX 和权威 Parquet；需要追溯推理时再带六路 ASR、cleaned/prepared 和 run_identities。不要只回传终端最后一行错误。
