## 执行约定

先读 00、01，再执行具体阶段。各文档中的 MUST／必须为验收要求；示例地址、名称、端口和数据均为占位示例，不代表服务器已配置或已验证。

这些需求授权完成 Web 服务及插件层所必需的现有引擎适配；不要求重写现有执行器或标签规则。新增流水线和新增 tag 必须通过同一插件接口接入，不允许在 API、Worker 或页面中持续增加按业务名称分支的代码。

交互修订：source_id、connection_id 由后端自动生成并持久化，页面不要求手填。数据源用 batch 和服务器路径登记，模型连接用 provider、地址/端口和模型名登记。流水线插件与 tag 均提供“启用 / 归档”按钮，可恢复启用；按钮只修改管理状态，不修改规则、不触发推理、不删除历史结果。详见 01 的 4.4、02 的 2.2/3.1/4.2 和 03 的 5.3。

详情交互按最新版 06 简化：弹窗只展示名称、通俗解释和最近修改时间；编辑态只有一个解释文本框及保存/取消按钮，不修改名称、规则、参数或业务版本，不再设计高级编辑、技术详情或独立校验流程。涉及详情展示、在线编辑范围的旧约束以 06 为准；其余功能继续有效。

统一接口的权威定义在 01，HTTP 与任务状态的权威定义在 02，页面行为在 03，验收门槛在 04。历史文档与当前代码不一致时先核对实际实现；本次需求明确调整的 Web 接入边界以本文档组为准，既有业务规则不随意改动。
