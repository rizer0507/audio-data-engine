# 028 · 五分类自动噪声归类与互斥准入修复

> 后续增量修订：[029 · 五分类 v2.2 DNSMOS 联合判定修复](./029-五分类v2.2-DNSMOS联合判定修复.md)。029 仅增强 DNSMOS 联合证据，保留本文已实现的五分类主框架。

> 日期：2026-09-16  
> 状态：已实现并归档（2026-09-17；0914 全量影子需在服务器有 prepared ASR 与可读音频路径时执行）。
> 目标策略版本：`selection_five_class_v2_auto_noise`。  
> 目标入口：`pipelines/classify_dataset_five_class_v2_auto_noise.yaml`。  
> 输入前提：音频已经过上游 VAD；本项目不负责重新执行 VAD。  
> 关系：本文修订 [027 · 五类分拣重构正式需求](./027-五类分拣重构正式需求.md)，与本文冲突时以本文为准。

## 1. 我想做什么

修复当前五类分类中过度依赖人工听音、导致 `environment_noise` 长期为 0 的问题。在已经取得多个模型家族、每个家族两次 ASR 结果后，使用家族级稳定空/稳定有字证据、音频时长和音频能量自动完成五分类。

人工不再是噪声分类的前置条件。明确满足规则的背景噪声、人声噪声、静音和过短音频直接自动归入 `environment_noise`；只有模型结果不完整、家族内部不稳定、关键短应答存在误杀风险或声学指标处于阈值边界时，才进入 `hardcase` 并可附加人工复核动作。

分类完成后，每条成功进入分类器的样本必须恰好具有五个类别之一，不再输出 `category=null`、`manual_annotation` 类别、`pending_evidence` 或其他第六业务类别。

## 2. 本需求覆盖的旧规则

本文覆盖 027 及现行规则中以下条款：

- `environment_noise` 必须先有人听音确认才能入类。
- 全空、音量或 DNSMOS 只能产生人工任务，不能自动判噪声。
- 无法满足严格类别时可以输出 `manual_annotation + category=null`。
- `hardcase` 不能作为最终兜底类别。
- 金标候选必须至少三个稳定有字家族支持。
- 单家族有字、其他家族为空时必须等待人工判断目标语音。

本文保留以下原则：

- 一家族一票；同一家族双跑只验证稳定性，不能算两票。
- 推理失败、缺失、被排除不能冒充空转写。
- 语音信箱优先短路。
- 多家族明确语义正反冲突优先进入 `semantic_risk`。
- 原始转写、音频路径、音频哈希和分类证据必须可审计。
- 新策略和产物不得覆盖 `selection_five_class_v1` 历史结果。



## 3. 输入与运行边界



### 3.1 输入

- 使用 prepared ASR Manifest。
- 支持至少三个模型家族；优先兼容 Qwen、GLM、SenseVoice 三家族双跑。
- 每个家族默认两次独立推理。
- 音频已经过上游 VAD，本项目不重新切分音频，也不把“是否执行过 VAD”作为逐条分类门槛。
- 分类和需要读取音频的轻量声学计算必须在音频路径可读的服务器执行。
- Windows 只接收最终 Parquet/XLSX，不再承担读取 Linux 音频路径的噪声推理。



### 3.2 输出

目标产物：

```text
datasets/stage1/derived/classified_five_class_v2_auto_noise_<batch>.parquet
data/exports/summary_five_class_v2_auto_noise_<batch>-part-001.xlsx
data/exports/summary_five_class_v2_auto_noise_<batch>-part-002.xlsx
```

XLSX 超过 20,000 行时沿用现有自动分片机制。

### 3.3 五个且仅五个类别

`category` 只能取：

```text
voicemail
semantic_risk
environment_noise
gold_candidate
hardcase
```

技术上完全无法读取的 Manifest、结构损坏或无法建立样本身份对应关系，应使流水线明确失败并报告，不得写出伪造分类。只要样本成功进入分类决策，必须得到上述五类之一。

## 4. 统一前处理和家族状态



### 4.1 路次文本前处理

每一路 ASR 保留：

- `raw_text`：原始输出，只读。
- `body_text`：去除模型控制标签后的正文。
- `classify_text`：去除无意义标点、空白及已确认的完整提示词/热词回声后的分类文本。
- `route_status`：`success_text`、`success_empty`、`failed`、`missing` 或 `excluded`。

外语、完整提示词回声和完整热词回声可以从有效投票中排除，但不能转成 `success_empty`。

### 4.2 家族状态

对同一家族的两次推理归并为一个家族状态：

#### `stable_text`

- 两次推理均成功。
- 两次 `classify_text` 均非空。
- 文本相等或仅有经过现有容错规则确认的无害差异。
- 保存家族代表文本和两路支持证据。



#### `stable_empty`

- 两次推理均成功。
- 两次 `classify_text` 均为空。
- 空文本来源于真实成功空输出或仅含控制标签/标点的成功输出。
- 推理失败、缺失、外语排除、提示词回声排除均不能计为空。



#### `unstable`

- 两次推理一空一有字。
- 两次均有字但内容存在实质冲突。
- 只有一路成功，另一路失败、缺失或被排除。



#### `unavailable`

- 两路均失败、缺失或无法形成可用家族证据。

分类必须记录：

```text
stable_text_family_count
stable_empty_family_count
unstable_family_count
unavailable_family_count
family_state_by_name
family_representative_text
```



## 5. 轻量声学字段

DNSMOS 不再是自动噪声分类的唯一入口，也不要求人工听音后才能使用。服务器在分类前为每条音频计算以下低成本字段：

```text
duration_ms
rms_dbfs
peak_dbfs
non_silent_ratio
energy_state
energy_policy_version
```

`energy_state` 至少包含：

```text
too_short
inaudible
audible
borderline
failed
```

阈值必须配置化并记录版本，不能散落在代码中。建议新增：

```yaml
audio_energy:
  policy_version: audio_energy_v1
  min_duration_ms: <配置值>
  min_rms_dbfs: <配置值>
  min_peak_dbfs: <配置值>
  min_non_silent_ratio: <配置值>
  borderline_margin_db: <配置值>
```

阈值可以先采用工程默认值并通过批次统计持续调整，不要求先完成逐条人工听音才能启用。每次阈值修改必须提升策略版本并使分类缓存失效。

DNSMOS 的 `sig/bak/ovrl/noise_band` 可以作为补充证据和置信度信息，但不能阻塞能量规则，也不能覆盖家族投票结果。现有 `calibrated=false` 不得导致所有噪声候选退回人工。

## 6. 唯一决策顺序

所有样本严格按以下顺序判断，命中即结束：

```text
voicemail
  → semantic_risk
  → environment_noise
  → gold_candidate
  → hardcase
```

不得在多个主类之间重复计数。子类型和审核动作只能作为主类附属字段。

## 7. 五类准入规则



### 7.1 `voicemail`

任意一个未排除、成功有字的 ASR 路次命中现有语音信箱规则，即自动进入 `voicemail`。

准入条件：

1. 命中内容来自有效 `body_text/classify_text`。
2. 命中现有 `voicemail_patterns_v1.yaml` 中任一规则。
3. 不要求多个家族一致，不要求家族内部双跑稳定。

输出至少包含命中规则、family、run_id 和原文片段。命中后禁止进入后续四类。

### 7.2 `semantic_risk`

至少两个独立 `stable_text` 家族之间出现会改变业务含义的明确冲突，自动进入 `semantic_risk`。

准入范围：

- 肯定与否定冲突。
- 接受与拒绝冲突。
- 办理与取消冲突。
- 同一对象上的相反动作。
- 关键金额、数字、日期、对象或实体冲突。
- 多家族短应答极性相反。

禁止条件：

- 只有一个家族有字，其他家族为空。
- 只是少量无害字词差异。
- 不同文本讨论不同对象，不能形成同命题冲突。
- 纯标点、控制标签、提示词或热词回声。

子类型可以继续保留 `semantic_reversal`、`short_polarity_ambiguity` 等，但不能新增主类别。

### 7.3 `environment_noise`

`environment_noise` 完全自动判定，不以人工听音为准入条件。

#### A. 纯背景噪声

同时满足：

1. 所有可用模型家族均为 `stable_empty`。
2. 不存在 `stable_text`、`unstable` 或 `unavailable` 家族。
3. `energy_state=audible`。

输出：

```text
category=environment_noise
noise_kind=background
classification_source=auto_family_energy
classification_confidence=high
```



#### B. 人声噪声或串音

同时满足：

1. 至少两个独立家族为 `stable_empty`。
2. 恰好一个家族为 `stable_text`。
3. 没有其他 `unstable` 或 `unavailable` 家族。
4. `energy_state=audible`。
5. 唯一文本家族的内容未被另一个家族支持。
6. 唯一文本不是需要保守处理的关键短应答。

输出：

```text
category=environment_noise
noise_kind=human_noise
classification_source=auto_family_energy
classification_confidence=medium
```

如果已存在可信串音检测结果，可以将 `noise_kind` 细化为 `crosstalk`，但串音检测不是本需求首版的硬依赖。

#### C. 静音

同时满足：

1. 所有可用家族均为 `stable_empty`。
2. 不存在有字或不稳定家族。
3. `energy_state=inaudible`。

输出：

```text
category=environment_noise
noise_kind=silence
classification_confidence=high
```



#### D. 音频过短

满足：

1. `energy_state=too_short`。
2. 未提前命中语音信箱或语义风险。

输出：

```text
category=environment_noise
noise_kind=audio_too_short
classification_confidence=high
```



#### 禁止进入环境噪声

出现以下任一情况时不能自动进入 `environment_noise`：

- 至少两个家族支持相同有效目标文本。
- 至少两个家族存在明确语义冲突。
- 唯一有字家族内部双跑不稳定。
- 推理失败或缺失被错误计为空票。
- `energy_state=borderline/failed`。
- 唯一文本是“要/不要、需要/不需要、好/不好、可以/不可以”等关键短应答。

禁止条件命中但未进入其他前置类别时，最终进入 `hardcase`。

### 7.4 `gold_candidate`

同时满足：

1. 至少两个独立家族为 `stable_text`。
2. 至少两个家族代表文本相等或仅有已确认无害差异。
3. 没有其他稳定文本家族给出实质反对内容。
4. 未命中语音信箱、语义风险和环境噪声。
5. 家族内部双跑稳定。

一家族一票。资格判定与选文分离：从共同支持的家族代表文本中按现有可复现策略选文，不拼接新句，不使用同家族双跑增加票数。

三个家族中两个家族稳定支持同一文本、第三家族稳定为空时，可以进入 `gold_candidate`；第三家族稳定空作为审计信息，不自动否决多数家族共同文本。

### 7.5 `hardcase`

`hardcase` 是前四类均未命中后的唯一兜底类别。以下场景自动进入：

- 至少两个有字家族存在实质内容分歧，但不满足严格 `semantic_risk`。
- 家族内部双跑不稳定。
- 有字、空和失败/缺失家族混合，无法形成明确规则。
- 唯一有字家族是关键短应答，其他家族为空。
- `energy_state=borderline/failed`。
- 有效模型家族不足。
- 外语/回声排除后没有足够分类证据。
- 其他未命中前四类的样本。

输出必须包含具体 `hardcase_reason`，禁止只写笼统的 `fallback`。

人工复核只允许作为 `hardcase` 的附加动作：

```text
category=hardcase
needs_review=true|false
review_reason=<具体原因>
```

不得输出第六类别、`category=null` 或以 `manual_annotation` 替代业务分类。

### 8.1 新策略和配置

建议新增：


### 8.2 需要核查和修改的模块

- `src/audio_engine/core/selection_v3/types.py`：新规则版本、五类枚举和附属子类型。
- `config.py`：家族阈值、能量阈值和策略配置校验。
- `classify_text.py`：统一有效文本和空文本定义。
- `family_evidence.py` 或五类策略模块：构建四种家族状态。
- `five_class.py`：实现新的互斥决策顺序和五类兜底。
- `acoustic_evidence.py`：接入时长、RMS、peak、非静音占比和版本化证据。
- `src/audio_engine/operators/quality/`：新增或复用轻量音频能量算子。
- `result.py`：保证成功分类样本 `category` 必为五类之一。
- `review export-summary`：导出五类、噪声子类、家族计数和声学证据。
- source naming：新旧产物隔离，不能覆盖 v1。

可以根据实际代码结构调整文件位置，但不能同时维护两套互相冲突的家族状态定义。

### 8.3 服务器端完整流水线

目标执行链：

```text
服务器已有三家族双跑 ASR
  → prepare_dataset_v3
  → attach_asr_v3
  → audio_energy_v1
  → 可选 DNSMOS
  → selection_five_class_v2_auto_noise
  → classified Parquet
  → export-summary XLSX
```

目标命令：

```bash
audio-data pipeline run pipelines/classify_dataset_five_class_v2_auto_noise.yaml \
  --source-name "$BATCH" \
  --config configs/selection/zh_asr_five_class_v2_auto_noise.yaml \
  --force

  "datasets/stage1/derived/classified_five_class_v2_auto_noise_${BATCH}.parquet" \
  --output "data/exports/summary_five_class_v2_auto_noise_${BATCH}.xlsx" \
  --max-rows 20000
```

分类必须在音频路径可读的服务器运行。不得再采用“服务器 ASR → Windows 分类 → 服务器侧车 → Windows 重分类”的往返流程。

## 10. 自动化验收用例

至少覆盖以下测试：

1. 任意有效路次命中语音信箱，必须只输出 `voicemail`。
2. 两个稳定家族出现同命题肯否冲突，输出 `semantic_risk`。
3. 三个家族双跑全部成功空且有音量，输出 `environment_noise/background`。
4. 三个家族双跑全部成功空且无音量，输出 `environment_noise/silence`。
5. 音频低于最小时长，输出 `environment_noise/audio_too_short`。
6. 两个稳定空家族、一个稳定有字家族、有音量，输出 `environment_noise/human_noise`。
7. 上一用例中唯一文本为关键短应答，输出 `hardcase`。
8. 推理失败不能计入稳定空家族。
9. 两个稳定有字家族支持相同文本、第三家族稳定为空，输出 `gold_candidate`。
10. 两个稳定有字家族存在实质分歧但不构成严格正反，输出 `hardcase`。
11. 家族内部一空一有字，输出 `hardcase`。
12. 能量值位于阈值边界，输出 `hardcase` 并写明原因。
13. 任何成功分类样本的 `category` 都属于五类集合，禁止 null。
14. 五类集合互斥且总数等于输入成功分类样本数。
15. 同一输入、配置和策略版本重复运行结果完全一致。
16. v1 和 v2 产物路径、缓存和 lineage 互不覆盖。
17. 0914 三万条端到端运行能导出完整 XLSX，并报告五类数量和噪声子类数量。

不得将“真实批次 `environment_noise` 数量必须大于 0”作为无条件测试断言；但测试 fixture 必须包含并验证 background、human_noise、silence 和 audio_too_short 四种自动噪声路径。

## 11. 完成条件

- 新规则、配置、流水线、测试和文档全部落地。
- 现有 v1 测试保持通过；新 v2 测试独立覆盖。
- 服务器可用一条 pipeline 命令生成新策略 classified Parquet。
- `export-summary` 能生成含完整证据的 XLSX。
- 成功分类样本只存在五个类别且无空类别。
- 明确噪声无需人工听音；只有 `hardcase` 可以附加人工复核。
- 运行失败、模型缺失或音频不可读时明确报告，不伪造噪声结果。
- 更新 `docs/02-规范规则/`、`docs/03-流水线/`、`docs/07-操作手册/`、根目录 `单条流水线执行命令.txt` 和相关 dev/local 手册。
- 不覆盖历史分类、人工金标、审核包或 release。
- 不擅自提交、推送或清理用户已有未提交修改。
