你当前这版规则的方向是对的，但存在几个会直接影响自动挑选质量的问题：`hardcase` 和 `auto_gold` 边界不清；`review_queue` 本质上是处置状态而不是数据类型；`hallucination` 仅凭“Qwen 有、其他为空”无法确认幻觉；另外多处使用“随机挑一个模型文本”，会导致同一批数据重复运行得到不同结果。你当前规则见 。

我建议在**不大改现有体系**的情况下，改成下面这一版。

## 一、先把三个概念拆开

每条数据不要只有一个 `type`，至少保留：

| 字段         | 含义        | 示例                                                        |
| ---------- | --------- | --------------------------------------------------------- |
| `type`     | 这条数据是什么问题 | `auto_gold / hardcase / semantic_inversion`               |
| `decision` | 最终怎么处理    | `auto_accept / auto_empty / model_review / manual_review` |
| `label`    | 最终金标文本    | `"不需要"` / 空                                               |

例如：

```text
type = semantic_inversion
decision = manual_review
label = null
```

这样就不会再出现“hardcase 有时候自动、有时候人工”这种逻辑混乱。

# 二、一个非常重要的修改：不要再叫“字准率”

在挑选阶段你没有真正的人工金标，因此：

```text
Qwen1 vs Qwen2
Qwen1 vs SenseVoice
...
```

算出来的并不是“字准率”，而是**模型转写文本一致度**。

建议统一定义：

```text
similarity(A, B)
= 1 - edit_distance(A, B) / max(len(A), len(B))
```

范围：

```text
1.00    完全一致
0.95+   高度一致
0.90+   基本一致
0.70~0.90 有明显差异
<0.70   强冲突
```

推荐全局先只维护两个正式阈值：

```text
STRICT_THRESHOLD = 0.95
CONSENSUS_THRESHOLD = 0.90
```

你文档中 voicemail 的：

> 0.5～0.9 选择相近模型

这个范围太宽。

`0.5` 的文本已经可以完全不是同一句话了，绝对不应该自动生成金标。

# 三、推荐最终分类体系

我建议在现有 7 类基础上新增一个：

```text
consensus_gold
```

最终是 8 类。

| 优先级 | type                 | 核心含义               | 自动生成金标？   |
| --: | -------------------- | ------------------ | --------- |
|   1 | `noise`              | 全部模型为空             | 是，label为空 |
|   2 | `voicemail`          | 确认为语音信箱            | 条件允许      |
|   3 | `semantic_inversion` | 肯定/否定语义冲突          | 原则上否      |
|   4 | `hallucination`      | 某模型孤立产生文本          | 原则上否      |
|   5 | `review_queue`       | Qwen 与其他模型在有无语音上冲突 | 否         |
|   6 | `auto_gold`          | 所有模型高度一致           | 是         |
|   7 | `consensus_gold`     | 存在明显多数派            | 是         |
|   8 | `hardcase`           | 无法形成可靠多数           | 否         |

这个顺序很重要。

特别是：

> **semantic_inversion 必须在文本相似度判断之前执行。**

因为：

```text
我现在确实需要办理
我现在确实不需要办理
```

两句话可能字符相似度很高，但业务语义完全相反。

如果先判断 `similarity > 0.9`，有可能直接自动生成错误金标。

# 四、逐类修改后的规则

## 1. noise

你当前：

> 所有模型为空 → noise

这个规则可以保留。

但严格来说：

```text
所有模型为空 ≠ 一定是噪声
```

也可能是：

```text
纯静音
VAD漏切
极低音量
无法识别人声
```

因此从数据工程命名角度更推荐：

```text
non_speech
```

或者：

```text
all_empty
```

如果为了兼容现有工程继续叫 `noise` 也没问题。

规则：

```text
if 所有模型 normalized_text == "":
    type = noise
    decision = auto_empty
    label = ""
```

---

# 2. voicemail

不要只靠某一个模型命中正则就进入 voicemail。

否则：

```text
Qwen1：您好，您拨打的用户暂时无法接通
Qwen2：""
SV1：""
SV2：""
```

可能本身就是 Qwen 幻觉。

建议：

```text
至少两个独立来源支持 voicemail
```

如果现在是：

```text
Qwen1
Qwen2
SenseVoice1
SenseVoice2
```

要特别注意：

> Qwen1 + Qwen2 并不是两张完全独立的票。

因为同架构、同训练分布的模型错误高度相关。

更可靠的是：

```text
Qwen family + SenseVoice family
```

同时检测到语音信箱。

最终：

```text
至少两个模型族 → voicemail
只有单一模型族 → 不直接确认 voicemail
```

label 选择规则建议改成：

```text
similarity >= 0.95
    → 自动选择 consensus medoid

0.90 <= similarity < 0.95
    → 如果存在明显多数 cluster，自动选择 medoid

< 0.90
    → manual_review
```

不要再使用 `0.5`。

---

# 3. semantic_inversion

这是你整个 ASR 数据里**优先级最高的一类 hardcase**。

建议定义：

```text
positive:
需要
要
有需要
可以
愿意
考虑
...

negative:
不需要
不用
不要
没需要
不考虑
暂时不需要
...
```

这里 regex 一定要：

```text
negative 优先于 positive
```

否则：

```text
"不需要"
```

里面包含：

```text
"需要"
```

很容易被错误识别成 positive。

推荐规则：

```text
Qwen family = positive
SenseVoice family = negative
```

或者反过来：

```text
Qwen family = negative
SenseVoice family = positive
```

则：

```text
type = semantic_inversion
```

### 这里我不建议使用你原来的：

> 两个模型语义一致，就随机选择。

这个风险很高。

假设：

```text
Qwen1       需要
Qwen2       需要

SenseVoice1 不需要
SenseVoice2 不需要
```

表面是：

```text
2票 vs 2票
```

实际是：

```text
一个模型族 vs 一个模型族
```

根本没有多数。

应该：

```text
decision = model_review
```

如果你后面有第三种 ASR：

```text
Kimi-Audio
Whisper
商业ASR
```

就让第三模型裁决。

例如：

```text
Qwen       positive
SenseVoice negative
Kimi       negative
```

才可以：

```text
negative = 2 independent families

→ 自动接受 negative cluster
```

如果第三模型仍然模糊：

```text
manual_review
```

---

# 4. hallucination

你现在定义：

> Qwen 有输出，其他模型为空。

建议把名字实际理解成：

```text
hallucination_candidate
```

因为只根据 ASR 结果无法证明 Qwen 真的是幻觉。

例如：

```text
Qwen：不需要
SenseVoice：""
```

也有可能：

```text
SenseVoice 漏识别
```

而不是 Qwen 幻觉。

另外你现在：

> 超过两个模型包含两个为空 → 认为为空

如果你总共 4 个模型，这条规则不合理。

例如：

```text
Qwen1       不需要
Qwen2       不需要
SV1         ""
SV2         ""
```

这是：

```text
2 vs 2
```

不能因为两个为空，就把真实语音删除。

### 应该改成：

只有：

```text
3/4 或以上模型为空
```

而且非空结果：

```text
仅来自单一模型
```

才可以认为是强 hallucination candidate。

即：

```text
empty_count >= 75%
AND
non_empty_family_count == 1
```

然后最好还是：

```text
model_review
```

而不是直接删除。

如果第三模型也为空：

```text
→ auto_empty
```

---

# 5. review_queue

这个类建议实际改名：

```text
qwen_missing
```

或者：

```text
qwen_empty_conflict
```

因为 `review_queue` 是处理方式，不是数据特征。

例如：

```text
Qwen1       ""
Qwen2       ""
SenseVoice1 不需要
SenseVoice2 不需要
```

目前你的规则会：

```text
review_queue
```

这是合理的。

但：

```text
SenseVoice1 + SenseVoice2
```

其实仍然属于同一个模型族。

所以不能因为二者一致就自动认为：

```text
“不需要”是真实金标
```

建议：

```text
type = qwen_missing
decision = model_review
```

第三模型：

```text
第三模型 = 不需要
→ label = 不需要

第三模型 = ""
→ label = ""

第三模型也无法判断
→ manual_review
```

---

# 6. auto_gold

这里建议把你的：

> 随机选择一个转写文本

彻底删掉。

没有任何必要随机。

随机会导致：

```text
run1 → Qwen1文本
run2 → SenseVoice2文本
```

同一条音频生成不同金标，不利于复现。

### 推荐定义

所有模型非空，并且：

```text
min_pairwise_similarity >= 0.95
```

同时：

```text
semantic_class 一致
```

则：

```text
type = auto_gold
decision = auto_accept
```

label 不随机，而选择：

### consensus medoid

假设：

```text
A = 我不需要
B = 我现在不需要
C = 我不需要
D = 我不用
```

计算每条文本和其他文本的平均 similarity：

```text
score(A)
score(B)
score(C)
score(D)
```

选择：

```text
argmax(score)
```

作为 label。

本质上就是：

> 找到最接近所有模型“中心”的那个真实模型输出。

这比随机选可靠得多。

---

# 7. 新增 consensus_gold

这个类别非常有必要。

因为现实中大量数据都是：

```text
Qwen1       我不需要
Qwen2       我不需要
SenseVoice1 我不需要
SenseVoice2 我现在不需要
```

这种不应该：

```text
auto_gold
```

也完全没有必要：

```text
hardcase
```

可以定义：

```text
存在 >=75% 模型形成 cluster
cluster内部 similarity >= 0.90
跨 >=2 个模型族
semantic_class 一致
```

例如：

```text
Qwen1       不需要
Qwen2       不需要
SV1         不需要
SV2         不需要办理这个
```

三个模型高度一致：

```text
dominant_cluster = 3/4
```

则：

```text
type = consensus_gold
decision = auto_accept
label = medoid(cluster)
```

这个类别预计能替你挡掉相当一部分现在的人工审核数据。

---

# 8. hardcase

最后剩下的才是真正的 hardcase：

```text
所有模型都有输出
BUT
不存在 dominant cluster
AND
不是 semantic_inversion
AND
不是 voicemail
```

例如：

```text
Qwen1       我要办理
Qwen2       我要了解一下
SV1         我不办理
SV2         我知道了
```

没有可靠共识：

```text
type = hardcase
decision = model_review / manual_review
```

而不是简单定义：

```text
所有模型 CER < 0.95
```

# 五、最终推荐判定顺序

整个程序建议严格按这个顺序跑：

```text
文本标准化
     ↓
全部为空？
 ├─ YES → noise
 ↓ NO

是否可靠命中 voicemail？
 ├─ YES → voicemail
 ↓ NO

是否出现 positive / negative 语义冲突？
 ├─ YES → semantic_inversion
 ↓ NO

是否存在 空 / 非空冲突？
 ├─ Qwen空 + 其他非空
 │       → review_queue
 │
 ├─ Qwen非空 + 其他空
 │       → hallucination
 │
 └─ 只有单模型为空
         → 继续 consensus 判断
 ↓

全部文本 similarity >= 0.95？
 ├─ YES → auto_gold
 ↓ NO

是否存在 >=75% dominant cluster
AND similarity >= 0.90
AND 跨两个模型族？
 ├─ YES → consensus_gold
 ↓ NO

hardcase
```

# 六、尤其建议修改“两个模型一致”这个概念

假设现在就是：

```text
Qwen1
Qwen2
SenseVoice1
SenseVoice2
```

以后不要简单：

```text
2票 = 共识
```

应该引入：

```text
model_family
```

例如：

| model       | family     |
| ----------- | ---------- |
| qwen1       | qwen       |
| qwen2       | qwen       |
| sensevoice1 | sensevoice |
| sensevoice2 | sensevoice |

那么：

```text
Qwen1 + Qwen2
```

只能说明：

```text
Qwen family consensus
```

不能认为：

```text
两个独立模型确认
```

这对 `semantic_inversion` 和 `hallucination` 尤其重要。

## 我认为你当前方案最值得立即修改的 5 点

1. **取消所有“随机选择文本”**，统一改成 `medoid / 模型优先级`。
2. **没有人工 gold 时不要使用“字准率”概念**，统一叫 `transcript_similarity`。
3. `semantic_inversion` 必须在文本相似度判断之前执行。
4. `2 个模型一致` 不等于可靠多数，尤其 `Qwen1+Qwen2` 属于同模型族。
5. 新增 `consensus_gold`，把“3/4 模型高度一致”的样本从 hardcase 中释放出来。

这样最后体系会变得非常清晰：

```text
高置信一致
    auto_gold
        ↓
多数一致
    consensus_gold
        ↓
结构性特殊场景
    voicemail / noise
        ↓
模型冲突
    qwen_missing / hallucination
        ↓
高风险语义冲突
    semantic_inversion
        ↓
无法判断
    hardcase
        ↓
人工
```
