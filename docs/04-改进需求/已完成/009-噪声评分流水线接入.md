## 我想做什么

把已拷贝的 **DNSMOS P.835** 完整接入现行三大工序，使其：

1. 作为可复用的质量算子产出可审计指标；
2. 写入 Manifest，供分拣 / 金标分层 / 训练集配额消费；
3. 在「噪声被 ASR 幻觉成正向语义」等业务风险上提供**音频侧旁证**，而不是替代语义规则；
4. **全程不引入 VAD**。

## 1. 判定：应放在哪个工序的哪个引擎？

### 1.1 DNSMOS 是什么（能力边界）

DNSMOS P.835 是**非侵入式语音感知质量模型**，对单段音频给出：

| 分数 | 含义 | 对本业务的直觉 |
| --- | --- | --- |
| `SIG` | 语音失真/清晰度 | 人声是否糊、断、失真 |
| `BAK` | 背景噪声质量（越高越干净） | 环境噪声/底噪强弱 |
| `OVRL` | 整体主观质量 | 综合可听度 |

它**不做**：ASR、语义极性、否定词检测、串音说话人数、切分/端点检测。  
它**擅长**：量化「这段（已切好的）音频有多脏、语音本身有多糊」。

现有 `quality.snr` 是能量法近似 SNR，便宜但不稳；DNSMOS 更接近主观噪声/清晰度，适合作为正式 `noise_risk` 的生产者。两者可并存：SNR 作廉价对照，DNSMOS 作正式侧车特征。

### 1.2 落点判定（推荐架构）

```text
工序一
  ① 清洗落库（现有 data_cleaning_source_A）
       │  产出 cleaned_*（16k wav + probe）——输入已是上游切分段
       ▼
  ①′ 【新建】音频质量侧车  ← DNSMOS 主落点（无 VAD）
       │  quality.dnsmos（可选 quality.snr）
       │  写出 quality.dnsmos_* / noise_risk
       ▼
  ② 多 ASR + 聚拢 + agreement
       │
       ▼
  ③ 分拣  ← DNSMOS 主消费点
       │  读取 noise_risk / dnsmos_*
       │  影响：脏音频伪金标降档、幻觉旁证、人审优先级、全空样本的噪声倾向
       ▼
工序二（可选消费）
  release / dataset_builder：按 noise 层配额抽样训练
工序三（可选消费）
  eval 分桶：low_bak / noisy / high_ovrl 等切片报告
```

| 候选落点 | 判定 | 理由 |
| --- | --- | --- |
| 塞进 ① 清洗主 YAML | **不推荐默认开启** | 清洗是 CPU 分片高并发；DNSMOS 是 ONNX/GPU，混跑会拖慢清洗 |
| **①′ 独立侧车 pipeline** | **推荐** | 与 ASR 批跑同模式；可 GPU；产物 join 回 Manifest |
| 放进 ② ASR 算子内部 | 否 | 职责混杂；换模型时质量特征会丢 |
| 只放在 ③ classify 内联计算 | 否 | 分拣应只读特征；重推理应可复跑、可审计 |
| 工序二 / 工序三临时算 | 可作补算，非主路径 | 金标分拣已需要 `noise_risk` |

**引擎归属一句话**：

> **生产者**：工序一 · 质量侧车（`quality.dnsmos`）  
> **主消费者**：工序一 · 分拣引擎（优先 `selection_v2.0` 的 `noise_risk`；v1 若要消费可后续加读字段，非本需求阻塞）  
> **次消费者**：训练集配额、评测分桶  
> **明确排除**：任何 VAD / `speech_ratio` 生产与消费依赖

### 1.3 与现有字段的对齐（无 VAD）

| 字段 | 本需求 | 说明 |
| --- | --- | --- |
| `noise_risk` | **主生产者** | `BAK < T_bak` 或 `OVRL < T_ovrl` → `true`（阈值用校准集定） |
| `dnsmos_sig/bak/ovrl` | **写入** | 原始分，供分层与审计 |
| `quality.snr` | 可选对照 | 不替代 DNSMOS |
| `speech_ratio` / `vad_edge_risk` | **不写、不依赖** | 输入已是切分段；引擎不做端点检测 |
| `overlap_risk` | 不承诺 | 串音另开需求 |

> 在「不做 VAD」前提下：DNSMOS **不能**可靠区分「强噪声无人声」与「带噪真人声」——那是端点/人声检测的能力。本方案接受该边界：用 DNSMOS 做**噪声/清晰度风险**，用**多模型转写模式 + 语义规则**做幻觉与极性；全空样本以 `noise_risk` 做倾向加权，而不是假装能做人声有无判定。

## 2. 判定：指标如何服务金标与训练集？

### 2.1 写入 Manifest 的字段契约

```text
quality.dnsmos_sig      float
quality.dnsmos_bak      float
quality.dnsmos_ovrl     float
quality.dnsmos_model    str
quality.noise_risk      bool    # 由 BAK/OVRL 阈值推导
```

可选：`quality.snr`。

分拣侧：`selection_v2/audio_precheck` 已能读 `noise_risk`；**不要**为实现本需求去写 `speech_ratio`。

### 2.2 对金标（工序一 · ③）的作用

DNSMOS **不生成文本金标**，只改变「能不能自动信 / 要不要人审 / 脏音频怎么加权」：

| 场景 | 无 `noise_risk`（现状） | 有 DNSMOS 后 |
| --- | --- | --- |
| 全模型转写为空 | v1 → `noise`；v2 缺人声证据时偏保守 | `noise_risk=true` → 更倾向按噪声/空处理或降审优先级；**仍禁止**把「全空」与「漏识别」装成靠 DNSMOS 可分的两极（无 VAD 就不做该分流承诺） |
| 单族非空、其它空（疑似幻觉） | 几乎只靠文本规则 | 差 `BAK/OVRL` + 正向短句 → **强化幻觉人审旁证**；干净音频上的单族非空 → 更宜当「他模漏识/分歧」而非「噪声幻觉」 |
| 多模型高相似伪金标 | 可能在脏音频上「一致地错」 | `noise_risk=true` → 降 `pseudo_gold_high` 或强制 `model_review` |
| 人审 5% 预算 | 难按噪声难度分层 | 按 `BAK/OVRL` 分位数抽脏音频难例 |

**硬规则建议（写入分拣配置，阈值经校准集再定）：**

1. `noise_risk=true` 且存在 `semantic_risk` / `critical_token_conflict` → **禁止**自动接受，一律人审。  
2. `noise_risk=true` 且仅单族支持 medoid → 不得升 `pseudo_gold_high`。  
3. **不**引入基于 `speech_ratio` 的全空二分；不做 VAD 截断类桶的生产承诺。

### 2.3 对训练集（工序二）的作用

| 用途 | 怎么用 DNSMOS |
| --- | --- |
| **过滤极端垃圾** | `OVRL` 极低且多模型皆空 → `exclude` 候选（仍建议抽检） |
| **噪声配额** | `noise_risk=true` 且仍有可用文本/人工确认 → 进入真实场噪训练配额（约 10% 量级） |
| **难例加权** | 低 `SIG` + 短句/否定词 → 优先进人工修正后再进 train |
| **评测分层** | held-out 按 `BAK` 分层，避免只报干净 CER |
| **与合成噪区分** | DNSMOS 标真实场噪；`augmentation.add_noise` 另记账 |

```text
pseudo_gold_high  + noise_risk=false  → 可进 train（仍非真金标）
pseudo_gold_high  + noise_risk=true   → 降权或抽检后再进
pseudo_gold_medium + noise_risk=true  → 默认不进主训，进难例池
```

## 3. 判定：对当前业务场景有没有意义？

### 3.1 语义两极反转 —— 无直接意义

「不需要 ↔ 需要」是文本语义层问题。`noise_risk` 只做**人审加权**（脏 + 语义风险 → 必审），**不替代** `semantic_lexicon` / `semantic_inversion`。

### 3.2 噪声→正向幻觉 —— 有意义（旁证，非判官）

典型失败：底噪/忙音/无效段被某 ASR 听成「嗯」「好的」「需要」。

| 证据组合（无 VAD） | 解释 |
| --- | --- |
| 低 `BAK`/`OVRL` + 仅单模型输出正向短句 + 其它模型皆空 | **支持噪声幻觉旁证** → 人审 / 禁止自动金标 |
| 高 `OVRL` + 多模型一致正向 | 更像真说了正向话 |
| 中等质量 + 模型间严重分歧 | 走 hardcase / 人审，不单靠 DNSMOS 定案 |

单独 DNSMOS **不能**宣布「这是幻觉」——必须与**多模型空/非空模式** + 语义词典联判。本方案**明确不**用 VAD 做人声有无判决。

### 3.3 总评

| 目标 | DNSMOS 贡献 | 优先级 |
| --- | --- | --- |
| 填上 `noise_risk` 空壳 | 高 | P0 |
| 脏音频伪金标降档 / 人审分层 | 高 | P0 |
| 幻觉旁证（联用多模型模式） | 中高 | P0/P1 |
| 训练噪声配额与评测分桶 | 中高 | P1 |
| 语义两极反转直接判定 | **无** | — |
| 「有无人声」二分 | **不做**（无 VAD） | — |

侧车可与 ASR 并行启动（都只依赖 cleaned），**classify 前必须 merge** `dnsmos_*` / `noise_risk`。

### 4.3 算子设计约束

1. **Vendor 隔离**：DNSMOS 源码/权重放 `third_party/dnsmos/` 或可配置路径。  
2. **可复现**：`dnsmos_model` / 算子 version / 阈值版本写入 lineage。  
3. **缺权失败要明确**：禁止静默写默认分。  
4. **采样率**：优先吃 `resampled_16k`；若官方图要其它采样率，仅算子内临时重采样。  
5. **禁止**：依赖或写出 `speech_ratio` / `vad_*`；禁止在侧车 YAML 挂 `audio.vad`。

### 4.4 分拣消费规则（拟写入配置）

```text
noise_risk:
  bak_lt: <校准>
  ovrl_lt: <校准>

when noise_risk and (semantic_risk or critical_token_conflict):
  decision = manual_review

when noise_risk and single_family_medoid_only:
  forbid pseudo_gold_high

when suspected_hallucination_pattern:  # 单族非空 + 其它空 + 短正向
  if noise_risk:
    strengthen manual_review / hallucination-旁证
  # 不做 speech_ratio 分支
```

### 4.5 训练集 / 评测集消费规则

| 集合 | 规则草案 |
| --- | --- |
| train | 保留一定比例 `noise_risk=true` 且文本可用的样本；极低 OVRL + 全空可排除 |
| eval held-out | 按 `BAK` 三分位分层 |
| 人工 5% 预算 | 噪声高分位 ∩（短句 ∪ 语义风险 ∪ 单族非空）优先 |

### 4.6 验收标准

1. 侧车跑完后 `dnsmos_sig/bak/ovrl`、`noise_risk` 非空率达标（损坏样本除外）。  
2. 分拣能读到 `noise_risk`，脏+语义风险样本不再自动接受。  
3. ≥20 条「噪声被听成正向短句」与 ≥20 条「干净/较干净真正向」：旁证方向不系统性反号。  
4. 语义反转用例集上，开关 DNSMOS **文本规则结果不变**。  
5. 清洗主路径不被拖慢；**产物与配置中无 VAD / speech_ratio 依赖**。

## 5. 明确不做什么

1. 不引入、不恢复、不捆绑任何 VAD / `speech_ratio` / 端点检测。  
2. 不用 DNSMOS 替代 `semantic_inversion` / 关键 token 规则。  
3. 不承诺用 DNSMOS 单独完成「有人声 vs 无人声」二分。  
4. 不在本需求实现串音分离、去混响、DNSMOS 训练微调。  
5. 不默认对全库强行 GPU 重跑；支持按 batch / 子集调度。
