## 我想做什么

在**不推翻**现行 `consensus_v1` / `selection_v1.1` 的前提下，新增一套 `selection_v2.0` 分拣规则与实现，并把影响同步到**工序三评测**，整体升级为：

```text
工序一：音频有效性预检
  → 业务语义风险硬拦截
  → 伪金标分级（pseudo ≠ gold）
  → 人审路由 / 训练·评测候选构建 / 评测集冻结
工序三：仅消费冻结的 human/external 评测 Release
  → 注册门禁 → 独立跑批 → 聚合 → 按桶与业务风险出报告
```

目标场景：约 42 万条未金标金融贷款外呼 ASR 数据；目标模型以 Qwen3-ASR 为主。核心要堵住的业务风险是：短平快语句语义反转、否定词漏识别、人声串音、环境噪声、VAD 截断、语气词/脏话被错误「正向化」。

**原则：旧规则继续冻结；新版本并行落地，不覆盖历史分拣结果。工序三分拣桶与金标准入必须与 v2 字段语义对齐，禁止再把伪金标当正式评测真值。**

### 目标双路径（与现行架构对齐，收紧评测真值）

现行双路径图已写入 [工序总览](../../01-项目架构/工序总览.md)；v2 落地后语义如下（**两条都必须经清洗 + 多模型识别**，不能跳过 ASR）：

```text
【路径 A · 带金标外源数据】
  外源音频 + 金标 xlsx
    → 数据清洗流水线
    → 不同模型识别流水线
    → 分类分拣（注入外源金标，产生 type / 标签；label_tier=gold）
    → 冻结评测集 → 工序三

【路径 B · 不带金标数据】
  无金标音频
    → 数据清洗流水线
    → 不同模型识别流水线
    → 分类分拣（共识匹配伪金标，产生 type / 标签；label_tier=pseudo_*）
    → 人审 / 抽检升真金标（正式评测必经）
    → 冻结评测集 → 工序三
```

相对现行 v1.1：路径 A 基本保持；路径 B **禁止**再把 `pseudo_gold_*`（旧 `auto_gold` / `consensus_gold`）直接注册为正式评测真值。

## 数据从哪来、结果要什么

### 输入

- **路径 B**：约 42 万条未金标数据（本需求主场景）；须已完成多模型 ASR（至少跨 2 个独立 `model_family`）
- **路径 A**：带外源金标批次（可信外源可直接 `label_tier=gold` 进评测）
- 音频文件本身（需能做完整性 / VAD / 噪声 / 串音等侧车特征；首期可渐进接入）

### 输出

每条样本至少产出：

| 维度 | 字段（示例） | 说明 |
| --- | --- | --- |
| 分拣 | `type` / `subtype` / `decision` / `gold_text` | 主桶 + 兼容子类 + 动作 + 候选标签 |
| 标签可信度 | `label_source` / `label_tier` / `is_human_verified` | 区分 human/external/model_consensus |
| 音频侧 | `audio_valid` / `duration_ms` / `speech_ratio` / `vad_edge_risk` / `overlap_risk` / `noise_risk` | 不能再只靠「全模型为空」判噪声 |
| 语义侧 | `semantic_class` / `semantic_risk` / `critical_token_conflict` / `short_utterance` | 风险优先于 similarity |
| 共识审计 | 沿用 `rule_version` / `selected_model` / `support_*` / `consensus_score` / `min_similarity` 等 | 与 v1 审计字段兼容 |
| 数据用途 | `dataset_role` / `duplicate_group_id` | `train_candidate` / `eval_candidate` / `exclude` |

全量跑完后还要有分桶统计与监控指标（见下文验收）。

### 工序边界（避免把评测构建全塞进工序三）

| 大工序 | 本需求负责什么 |
| --- | --- |
| **工序一** | `selection_v2.0` 分拣、伪/真金标分级、人审、`dataset_role`、评测候选采样、**评测 Release 冻结**（`eval_core` / `eval_random` 等） |
| **工序三** | 对**已冻结**评测 Release 做注册门禁、推理、聚合、指标与报告；**不**再从 `auto_gold`/`pseudo_gold_*` 导出物直接当正式评测真值 |

评测集「怎么抽、怎么人审、怎么冻结」细则以 [008](./008-数据挑选与评测集构建规则调整方案.md) 为准；本需求补齐工序三侧必须跟着改的门禁与产物适配。

## 相对 v1.1 必须改掉的问题

### 1. 「全模型为空 ≠ 噪声 / 空音频」

**损坏检测本身已在工序一落地，不是 v2 新能力：**

| 阶段 | 现状 |
| --- | --- |
| ① 清洗 | `quality.probe` → `labels.broken`；`quality.filter` 要求 `broken != true and duration > 0`；`quality.select` 只保留 `audio_pass` 进 `cleaned_*` |
| ③ 分拣 | `selection_engine` 仍读 `broken` / `duration≤0`，但与「全模型为空」**合并**进同一桶 `noise` + `auto_empty` |

因此 v2 要改的不是「再加一遍 probe」，而是：

1. **分桶拆开**：损坏 vs 真空 vs 疑似漏收音，不再共用 `noise`；
2. **决策调整**：物理无效改为 `exclude`（不是 `auto_empty`）；全模型为空必须看人声证据，不能一律空金标；
3. **防御性兜底**：清洗已滤掉的损坏样本若仍进入分拣（旁路/外源/旧 manifest），仍映射到 `invalid_audio`，而不是混进噪声空标签。

| 条件 | type | decision |
| --- | --- | --- |
| 无法解码 / duration≤0 / 文件损坏（沿用既有 `broken` 等信号） | `invalid_audio` | `exclude` |
| 全族为空 **且** 人声证据极弱 | `true_silence` | `auto_empty` |
| 全族/多数为空 **但** 有明显人声或 VAD 边缘能量 | `possible_vad_miss` | `model_review`（P0） |

### 2. 语义风险不能被 similarity 覆盖

```text
similarity >= 0.95 永远不能覆盖 semantic_risk=true
```

禁止：因 ≥2 独立模型族多数票，就对 `semantic_inversion` 自动接受。

新增硬拦截桶（均为人审，默认不可进自动训练）：

- `semantic_inversion`（P0）
- `critical_token_conflict`（P0）
- `semantic_sanitization`（P0，脏话/拒绝被正向化）
- `short_utterance_risk`（P1，短句禁止单纯靠 similarity）

### 3. 模型共识只能叫伪金标

| 旧 type | 新 type | label_tier | 可否进正式评测集 |
| --- | --- | --- | --- |
| `auto_gold` | `pseudo_gold_high` | `pseudo_high` | **否** |
| `consensus_gold` | `pseudo_gold_medium`（或更严条件升 high） | `pseudo_medium` | **否** |

只有 `human_gold` / `trusted_external_gold` 才允许 `label_tier=gold`。

### 4. `qwen_missing` / `hallucination` 必须看音频侧

- `qwen_missing` → 泛化为 `model_missing`（`missing_family` + 可选 `subtype=qwen_missing`）
- 「多数空 + 单族非空」后：无人声 → `hallucination`；有人声 → `model_missing_or_disagreement` / `model_missing`，**禁止误标成空**

### 5. 42 万条不能只挑「最容易的一批」

训练集需按价值采样（干净普通 + 高风险难例 + 噪声/VAD/串音专项），评测集必须 100% 人工/可信外源金标并冻结防泄漏。去重（完全重复 + 近重复）进入挑拣流程。

## 业务规矩（摘要）

详细判定顺序、阈值、词表、分桶表以规则原文为准；落地时必须遵守：

### 判定优先级（严格）

```text
0 文件完整性兜底（复用①清洗的 broken/duration；非新建 probe）
   → invalid_audio / exclude
1 去重 / 近重复 → duplicate
2 音频侧特征 → speech_ratio / noise / overlap / VAD edge   ← 相对现行缺口较大
3 全模型为空 → true_silence | possible_vad_miss            ← 相对现行主改点
4 voicemail
5 族内一致性 → family_internal_conflict
6 语义风险 → inversion / critical_token / sanitization
7 短句风险 → short_utterance_risk
8 多数空/单族非空 → hallucination | model_missing
9 严格跨族共识 → pseudo_gold_high
10 dominant cluster → pseudo_gold_medium
11 其余 → hardcase
```

### 配置化（禁止硬编码词表与阈值）

建议新增：

```text
configs/selection/zh_asr_v2.yaml
configs/selection/semantic_lexicon_zh_v2.yaml
```

启动阈值（需首轮抽检校准，不是最终科学值）：

```yaml
rule_version: selection_v2.0
similarity:
  strict_threshold: 0.95
  consensus_threshold: 0.90
  dominant_cluster_ratio: 0.75
short_utterance:
  max_audio_sec: 2.0
  max_text_chars: 6
silence:
  max_speech_ratio: 0.05
consensus:
  min_family_count: 2
risk_gate:
  semantic_inversion_auto_accept: false
  critical_token_conflict_auto_accept: false
  vad_miss_auto_empty: false
```

### 文本标准化

比较前只清格式噪声（Unicode、全半角、可选纯标点、数字策略）；**禁止**为提高 similarity 删除「不/没/要/需要/嗯/有」等业务关键 token。

### v1 兼容迁移（第一阶段）

可先：

```text
type = 原有大类
subtype = v2 新类别
```

稳定后再切完整 v2 `type`。推荐映射见规则原文 §23。

### 实现结构（不要继续堆进单文件）

```text
quality.classify
  → audio_precheck
  → transcript_normalize
  → family_consensus
  → semantic_risk_gate
  → pseudo_label_engine
  → review_router
  → dataset_builder
```

引擎名建议新增 `consensus_v2` / `selection_v2.0`；默认生产仍可指向 v1，直到验收通过再切换。

## 工序三需要跟着改什么

现行工序三主路径（已落地）：

```text
eval register（summary_ / gold_ / classified_）
  → 各模型独立跑批
  → eval_aggregate
  → eval_metric_pipeline（vs gold_text，按 type 导出）
```

问题不在「跑批/聚合」骨架，而在：**注册进来的金标可信度**、**桶名/字段变化后的报告维度**、以及**冻结评测集与训练防泄漏**尚未成为硬门禁。

### 1. 评测集注册门禁（`eval register` / `eval check`）

现行可直接注册工序一 `gold_`（默认来自 `auto_gold` + `consensus_gold`）。v2 下这不再合法作为**正式评测真值**。

必须增加校验（正式评测 Release 路径）：

| 检查项 | 要求 |
| --- | --- |
| 金标来源 | `label_source ∈ {human, external}`，或 `label_tier = gold` |
| 人工确认 | `is_human_verified = true`（外源可信金标可按配置豁免，但必须显式标记 `trusted_external_gold`） |
| 禁止伪金标 | `label_tier ∈ {pseudo_high, pseudo_medium}` **拒绝注册为正式 eval** |
| 禁止未审风险桶当真值 | 仅有分拣 `type`、尚无人审修正的 `semantic_inversion` 等，不得直接当 eval gold |
| 字段齐全 | 每条具备稳定 `id` / `gold_text` / `type`（及过渡期 `subtype`）/ 音频键；建议带 `release_version` |
| 空金标策略 | `true_silence` 等允许空 `gold_text` 的样本，须有明确 `type` 与准入名单，不能 silently 混进普通 CER 主表 |

兼容策略：

- **正式评测**：只接受冻结的 `eval_*` Release（如 `eval_core_v001` / `eval_random_v001`），或已人审确认的 `classified_*` / 外源路径。
- **调试/冒烟**：若仍要用 `pseudo_gold_*` 做管道连通性测试，必须显式 flag（如 `--allow-pseudo-gold`），产物不得写入正式 `datasets/stage3/reports` 权威路径，或报告头标记 `eval_trust=pseudo_debug`。

### 2. 评测集形态：从「一个 gold_ 批」升级为「版本化双集」

与 008 / 规则原文 §19 对齐，工序三应能注册并并行评测至少两套冻结集：

| Release | 用途 | 金标 | 抽样来源（工序一产出） |
| --- | --- | --- | --- |
| `eval_core_vNNN` | 高风险业务问题专项 | 100% human / trusted external | 覆盖 `semantic_inversion`、`critical_token`、`short_utterance`、`vad_miss`、`noise`、`overlap_crosstalk`、正/负意愿、`normal_clean` 等 |
| `eval_random_vNNN` | 真实分布总体是否退化 | 100% human / trusted external | 从原始池随机，**不**从 hardcase 桶偏抽 |

要求：

- 名称带版本；`eval check` 能打印 `release_version`、样本量、`type` 分布、`label_tier` 分布。
- 冻结后 `gold_text` / `type` / `subtype` / call 分组字段只读；变更只能升 `vNNN+1`，禁止原地改正式集。
- 所有 Base / LoRA / Full SFT 实验对比**同一对** eval Release，禁止每次重抽。

### 3. 训练 ↔ 评测防泄漏（评测侧硬检查）

工序一负责构建时去重与隔离；工序三在 `eval check`（或评测前 gate）至少再验：

- 与当前/指定 `train_*` Release **无** `audio_id` 交集；
- 无同 `duplicate_group_id` 跨 train/eval；
- 尽可能检查同 `call_id` / 近重复指纹跨集合泄漏（能力可渐进，但接口先留上）。

失败则阻断正式评测报告产出。

### 4. 指标与报告适配新分拣桶

`eval_metric_pipeline` / `configs/metrics/model_eval.yaml` 需适配 v2：

| 现行 | v2 调整 |
| --- | --- |
| 按 `type` 导出子表 | 支持 v2 新桶名；过渡期同时认 `type` + `subtype` |
| `auto_gold` / `consensus_gold` / `noise` / `qwen_missing` 等旧名 | 映射或双读：`pseudo_gold_*`、`invalid_audio`/`true_silence`/`possible_vad_miss`、`model_missing` 等 |
| 主要看整体 CER | 正式报告至少按风险切片出表：短句、否定/肯定意愿、关键 token、VAD miss、串音、普通干净等（与规则 §19.1 覆盖对齐） |
| 空参考混进主 CER | `true_silence` / 允许空标样本单独切片或排除出主 CER，避免虚高/虚低 |

业务风险指标（NFR / FAR / NAHR / FAER 等）细则见 [007-评测指标进一步细分需求](./007-评测指标进一步细分需求.md)；**本需求不替代 007**，但要求工序三报告预留按 `type`/`semantic_class` 切片的扩展点，避免只改分拣却仍只出单一 CER。

### 5. 流水线 / CLI / 手册改动清单（工序三）

| 项 | 调整 |
| --- | --- |
| `audio-data eval register` | 正式模式校验 `label_tier` / `label_source` / `is_human_verified`；拒绝伪金标默认注册 |
| `audio-data eval check` | 增加金标可信度、版本、type 分布、与 train 防泄漏摘要 |
| `eval_aggregate.yaml` | 一般可保持 id 左连接语义；确认新字段透传不丢 |
| `eval_metric_pipeline.yaml` | 桶名映射、空标切片、风险覆盖表；报告元数据写 `eval_release` / `eval_trust` |
| `configs/metrics/model_eval.yaml` | `vs_gold` 保持；补充分组维度配置（type/subtype/semantic_class） |
| 旁路脚本 `run_eval_from_summary.py` 等 | 若 summary 含伪金标，启动 WARN；正式任务引导改用冻结 eval Release |
| 文档 | 更新 [评测流水线](../../03-流水线/评测流水线.md)、`手册/*/03-工序三-评测.txt`：场景 1 不再写「直接用 export-gold 的 auto/consensus 当正式评测」 |

### 6. 工序一 → 工序三交接契约

工序三只认以下输入为**正式评测集**：

```text
冻结 Eval Release
  ├── release_version
  ├── 每条：id, gold_text, type[, subtype], label_source, label_tier=gold,
  │         is_human_verified=true（或 trusted_external 豁免）
  └── 可选：semantic_class, dataset_role=eval_*, duplicate_group_id, call_id
```

工序一 `export-gold` 产出的 `pseudo_gold_*` 仅可用于训练候选 / 调试，**默认不进入**工序三正式 `eval register`。

## 分阶段落地建议

### Phase A · P0 规则引擎（先能分拣）

1. 新增 v2 配置与语义词表
2. 落地字段：`label_source` / `label_tier` / `is_human_verified` / `dataset_role` 等
3. 语义风险硬闸：`semantic_inversion` 禁止多数票自动接受；`critical_token_conflict`；短句规则
4. `auto_gold`/`consensus_gold` → `pseudo_gold_*`（或 subtype 过渡）
5. 将现行合并桶 `noise` 拆为 `invalid_audio`（复用已有 broken/duration）/ `true_silence` / `possible_vad_miss`；人声证据暂缺时，`possible_vad_miss` 宁可多进人审，禁止对「全模型为空」直接 `auto_empty`（物理损坏走 `exclude`，不再 `auto_empty`）
6. `qwen_missing` → `model_missing`；`hallucination` 与音频证据挂钩（无证据时偏 `model_review`）
7. CLI：`export-gold` / `export` 桶列表适配伪金标与新人审桶；统计报表输出各桶 count/ratio

### Phase B · 音频预检与人审抽样

1. 接入 `speech_ratio` / VAD edge / overlap / noise 特征（可先最小可用实现）
2. P0 全量进人审队列；P1/P2 分层抽样；`pseudo_gold_*` / `true_silence` 强制抽检配额（见规则 §17）
3. 输出抽检误标率：`pseudo_high_audit_error_rate`、`false_empty_rate`、`semantic_inversion_escape_rate`

### Phase C · 数据集治理 + 工序三正式评测闭环

1. L1 hash 去重 + L2 近重复（指纹 / call 时间窗 / embedding，可渐进）
2. `dataset_builder`：`train_candidate` / `eval_candidate`（或 `eval_core_candidate` / `eval_random_candidate`）/ `exclude`
3. 正式评测集：仅 human/external gold；Release 冻结；与训练防泄漏（audio_id、指纹、同 call 切片）
4. 训练集价值采样（非「全部 pseudo_gold_high → train」）
5. **工序三**：`eval register`/`eval check` 金标准入门禁；双集（core/random）版本化注册；指标按新桶与风险切片导出；手册与评测流水线文档改口

与 [008](./008-数据挑选与评测集构建规则调整方案.md) 中评测集分层（`eval_core` / `eval_random`）对齐时，以 008 为评测构建细则，以本需求 + v2 规则原文为分拣细则，以本节为工序三门禁与报告适配细则。
