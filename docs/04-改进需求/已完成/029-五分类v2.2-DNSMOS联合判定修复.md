# 029 · 五分类 v2.2 DNSMOS 联合判定修复

> 日期：2026-09-16  
> 状态：已实现并归档（2026-09-17；0914 全量影子需在服务器有 prepared ASR、可读音频与可选 DNSMOS 侧车时执行）。  
> 目标策略版本：`selection_five_class_v2_2_auto_noise`。  
> 基线版本：`selection_five_class_v2_auto_noise`（028，已实现）。  
> 目标入口：`pipelines/classify_dataset_five_class_v2_2_auto_noise.yaml`。  
> 改造性质：在 028 基础上增量修复 DNSMOS 证据融合，不重构五分类主框架。

## 1. 本次为什么修改

028 已完成以下核心能力：

- 使用 `stable_text / stable_empty / unstable / unavailable` 四种家族状态。
- 使用时长、RMS、peak、非静音占比判断 `too_short / inaudible / audible / borderline / failed`。
- 自动输出 `environment_noise` 的 `background / human_noise / silence / audio_too_short` 子类。
- 使用固定优先级完成 `voicemail → semantic_risk → environment_noise → gold_candidate → hardcase` 五分类。
- `hardcase` 是唯一业务兜底，人工复核只作为附加动作。

当前不足是：DNSMOS 虽然仍在流水线中运行，但 v2 分类器只把它写入 `acoustic_evidence.dnsmos_supplemental`，不参与类别和置信度判断。这样浪费了 DNSMOS 对语音信号质量、背景干扰和整体质量的辅助信息，也无法利用 DNSMOS 帮助处理能量临界、全家族空转写但音频可闻等样本。

v2.2 的目标是将以下三类证据联合使用：

```text
家族状态：是否存在稳定、可重复识别的内容
音频能量：是否有声音、是否静音、是否过短
DNSMOS：语音信号质量和背景干扰程度
```

DNSMOS 是联合证据之一，不是唯一噪声分类器，也不能单独判断目标说话人身份。

## 2. 与 028 的关系

本文只修订 028 中 DNSMOS 的角色及相关分支。以下内容保持不变：

- 五个业务类别不变：`voicemail / semantic_risk / environment_noise / gold_candidate / hardcase`。
- 决策顺序不变。
- 家族四态定义不变。
- 推理失败、缺失、外语/回声排除不得计为 `stable_empty`。
- `audio_too_short` 和明确 `silence` 不依赖 DNSMOS。
- 多家族稳定文本一致时不能因为 DNSMOS 低分改判为噪声。
- 关键短应答、家族不稳定和技术证据不足仍进入 `hardcase`。
- 分类必须在可读取音频的服务器执行，Windows 只接收最终 Parquet/XLSX。
- v1、v2、v2.2 的配置、缓存、lineage 和产物必须隔离。

本文新增或修改：

- DNSMOS 分数转换为版本化的判定状态，而不是只保存原始分数。
- DNSMOS 参与 `background / human_noise` 的置信度和矛盾判断。
- DNSMOS 可将部分 `energy_state=borderline` 样本从 hardcase 自动收敛到环境噪声。
- DNSMOS 可为可识别目标语音附加背景噪声质量标签，但不得改变其主类别。
- DNSMOS 不可用时保留 028 的兼容回退，不让整个批次退回人工。

## 4. DNSMOS 证据定义

### 4.1 原始字段

继续使用 DNSMOS P.835：

```text
dnsmos_sig
dnsmos_bak
dnsmos_ovrl
dnsmos_status
dnsmos_model_digest
dnsmos_preprocess_version
```

含义：

- `SIG`：语音信号听感质量。
- `BAK`：背景噪声听感质量。
- `OVRL`：整体听感质量。

这些分数不能单独证明是否存在目标说话人，也不能仅凭低分把稳定可识别语音改判为环境噪声。

### 4.2 派生判定状态

新增独立、版本化的 DNSMOS 决策配置，不复用含义模糊的 `calibrated` 布尔值：

```yaml
policy_version: dnsmos_decision_v2_2

thresholds:
  clean_bak: 3.5
  clean_ovrl: 3.2
  noisy_bak: 3.0
  noisy_ovrl: 2.8
  strong_sig: <配置值>
  weak_sig: <配置值>

decision:
  noisy_operator: or
  require_status_success: true
```

阈值默认可以复用现有 `dnsmos_p835.yaml` 的 BAK/OVRL 工程阈值，但必须复制到 v2.2 决策配置并单独版本化。SIG 阈值由实现根据现有批次分布给出工程默认值，不要求先人工听音才能启用；后续调整必须提升 `policy_version`。

派生字段：

```text
dnsmos_noise_state = noisy | moderate | clean | unavailable
dnsmos_speech_state = strong | weak | unknown | unavailable
dnsmos_decision_policy_version
```

判定原则：

- `dnsmos_status != success` 或分数缺失：`unavailable`。
- `BAK < noisy_bak` 或 `OVRL < noisy_ovrl`：`noise_state=noisy`。
- `BAK >= clean_bak` 且 `OVRL >= clean_ovrl`：`noise_state=clean`。
- 其余有效分数：`noise_state=moderate`。
- SIG 只形成语音质量提示，不单独证明有人声；`strong/weak` 阈值配置化。

## 5. DNSMOS 运行范围

当前 `quality.asr_anomaly_noise` 使用旧触发逻辑，不能直接代表 v2.2 的决策候选集。v2.2 必须新增或改造候选选择，使 DNSMOS 至少覆盖：

1. 全部家族 `stable_empty` 且能量为 `audible/borderline`。
2. 至少两个 `stable_empty`、恰好一个 `stable_text` 且能量为 `audible/borderline`。
3. 需要用 DNSMOS 标注背景质量的 `gold_candidate` 候选；若为节省计算，可仅在已有全量侧车时附加该标签，不得因此阻塞金标分类。

以下场景默认无需调用 DNSMOS：

- `energy_state=too_short`。
- 全家族稳定空且 `energy_state=inaudible`。
- 已命中语音信箱。
- 已形成明确多家族语义风险，且 DNSMOS 不影响主类。

实现可以选择：

- 按上述候选集按需评分；或
- 复用服务器已经生成的全量 DNSMOS sidecar。

无论采用哪种方式，都必须按 `sample_id + original_audio_sha256` 合并，禁止按行号合并。分类时优先复用同模型、同预处理版本、同音频哈希的已有分数，避免重复推理。

## 6. v2.2 联合判定规则

分类顺序继续保持：

```text
voicemail → semantic_risk → environment_noise → gold_candidate → hardcase
```

### 6.1 `audio_too_short`

保持 028：

```text
energy_state=too_short
且未先命中 voicemail / semantic_risk
→ environment_noise/audio_too_short
→ confidence=high
```

不要求 DNSMOS。

### 6.2 `silence`

保持 028：

```text
全部家族 stable_empty
+ energy_state=inaudible
→ environment_noise/silence
→ confidence=high
```

不要求 DNSMOS。即使已有 DNSMOS 分数，也不能用异常分数把静音改成人声噪声。

### 6.3 `background`

#### 高置信背景噪声

```text
全部家族 stable_empty
+ energy_state=audible
+ dnsmos_noise_state=noisy
→ environment_noise/background
→ confidence=high
→ classification_source=auto_family_energy_dnsmos
```

#### 中置信背景噪声

```text
全部家族 stable_empty
+ energy_state=audible
+ DNSMOS unavailable
→ environment_noise/background
→ confidence=medium
→ classification_source=auto_family_energy
```

这条保留 028 的兼容能力，DNSMOS 缺失不能导致明确全空有声样本全部退回 hardcase。

#### DNSMOS 与家族证据矛盾

```text
全部家族 stable_empty
+ energy_state=audible
+ dnsmos_noise_state=clean
+ dnsmos_speech_state=strong
→ hardcase
→ hardcase_reason=empty_asr_but_clean_strong_speech
```

该组合可能表示多个 ASR 同时漏识别了较清晰语音，不能强判为纯背景噪声。

如果 `noise_state=moderate`，默认仍归 `environment_noise/background`，置信度为 `medium`，同时保留 DNSMOS 状态供审计。

### 6.4 `human_noise`

基础家族条件保持 028：

```text
至少两个家族 stable_empty
+ 恰好一个家族 stable_text
+ 无 unstable/unavailable 家族
+ energy_state=audible
+ 唯一文本不是关键短应答
```

DNSMOS 融合：

- `noise_state=noisy`：`environment_noise/human_noise`，`confidence=high`。
- `noise_state=moderate/clean`：仍为 `environment_noise/human_noise`，`confidence=medium`。DNSMOS 无法判断说话人归属，不能因分数较好否决多家族空票证据。
- DNSMOS unavailable：保留 028 行为，`confidence=medium`。
- 已有可信 `human_crosstalk_confirmed=true`：子类细化为 `crosstalk`。

DNSMOS 只能增强背景干扰判断，不能把唯一文本解释成目标说话人或非目标说话人。

### 6.5 能量临界样本

新增自动收敛分支：

```text
全部家族 stable_empty
+ energy_state=borderline
+ dnsmos_noise_state=noisy
→ environment_noise/background
→ confidence=medium
```

```text
至少两个 stable_empty
+ 恰好一个 stable_text
+ 无 unstable/unavailable
+ 唯一文本非关键短应答
+ energy_state=borderline
+ dnsmos_noise_state=noisy
→ environment_noise/human_noise
→ confidence=medium
```

其他 `energy_state=borderline` 继续进入 `hardcase`。DNSMOS unavailable 不能自动消除 borderline 不确定性。

### 6.6 有效目标文本伴随背景噪声

当至少两个 `stable_text` 家族支持相同文本并满足 `gold_candidate` 时：

- 即使 `dnsmos_noise_state=noisy`，主类仍为 `gold_candidate`。
- 附加：

```text
quality_tag=background_noisy
background_quality_risk=true
classification_confidence=<保持金标规则结果，不因 DNSMOS 单独降为噪声>
```

低 BAK/OVRL 表示目标语音处在噪声环境中，不代表目标语音不存在。

### 6.7 hardcase

以下情况仍进入 `hardcase`：

- `energy_state=failed`。
- 家族内部不稳定或家族证据不足。
- 唯一文本为关键短应答。
- 多家族实质分歧但不满足严格语义风险。
- 能量 borderline 且 DNSMOS 不是 noisy 或不可用。
- 全家族空、有声，但 DNSMOS 显示 `clean + strong speech` 的矛盾组合。
- DNSMOS 分数不完整、模型错误或哈希不一致，同时现有能量/家族规则也无法独立定类。

DNSMOS 失败本身不能把原本已满足 028 强规则的样本强制改成 hardcase。

## 7. 置信度和证据来源

新增统一字段：

```text

classification_confidence
evidence_sources
dnsmos_noise_state
dnsmos_speech_state
dnsmos_decision_policy_version

```

`evidence_sources` 使用列表，例如：

```json

```

不得仅根据是否存在 DNSMOS 分数猜测规则是否真正消费了该证据。分类 trace 必须记录命中的规则分支、阈值版本和参与决策的实际字段。

## 8. 配置要求

v2.2 selection 配置在 v2 基础上增量增加：

```yaml
rule_version: selection_five_class_v2_2_auto_noise

dnsmos_decision:
  config_path: configs/quality/dnsmos_decision_v2_2.yaml
  enabled: true
  fallback_to_v2_rules: true
  resolve_borderline_when_noisy: true
  attach_gold_quality_tag: true
```

保留原有：

```yaml
audio_energy:
  config_path: configs/quality/audio_energy_v1.yaml
```

配置加载时必须校验：

- 阈值为有限数值且 clean 阈值不低于 noisy 阈值。
- `strong_sig > weak_sig`。
- 策略版本非空。
- 禁止开启 DNSMOS 决策却缺少配置文件。

## 11. 自动化验收用例

在 028 原有测试全部保留的基础上新增：

1. 全家族稳定空 + audible + DNSMOS noisy → `background/high`。
2. 全家族稳定空 + audible + DNSMOS unavailable → `background/medium`，保持 v2 回退。
3. 全家族稳定空 + audible + DNSMOS clean + strong speech → `hardcase/empty_asr_but_clean_strong_speech`。
4. 全家族稳定空 + audible + DNSMOS moderate → `background/medium`。
5. 全家族稳定空 + borderline + DNSMOS noisy → `background/medium`。
6. 全家族稳定空 + borderline + DNSMOS unavailable → `hardcase`。
7. 两个稳定空 + 一个稳定有字 + audible + DNSMOS noisy → `human_noise/high`。
8. 两个稳定空 + 一个稳定有字 + audible + DNSMOS clean → `human_noise/medium`。
9. 两个稳定空 + 一个稳定有字 + borderline + DNSMOS noisy → `human_noise/medium`。
10. 上述唯一文本为关键短应答时仍为 `hardcase`。
11. 两个以上稳定文本家族一致 + DNSMOS noisy → 仍为 `gold_candidate`，附 `quality_tag=background_noisy`。
12. 语音信箱或语义风险不能被 DNSMOS 改类。
13. `too_short` 和明确 `silence` 不依赖 DNSMOS。
14. DNSMOS failed/unsupported 不得伪造为 noisy。
15. 音频哈希不匹配必须失败或拒绝合并，不能消费错误侧车。
16. 相同输入、阈值版本和模型版本重复运行完全一致。
17. v1、v2、v2.2 的产物与缓存完全隔离。
18. v2 原有自动噪声测试继续通过，证明本次是增量修复而非规则重写。
19. export-summary 包含新增字段和统计。
20. 0914 影子运行报告 v2 与 v2.2 的类别迁移、置信度变化和 borderline 收敛数量。
