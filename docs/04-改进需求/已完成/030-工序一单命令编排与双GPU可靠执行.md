## 第二步：一条命令贯通工序一和完整交付

**要求**

提供以下拟议入口，`$AUTHORIZED_GPUS` 从部署配置取得，不预设具体编号：

```bash
audio-data stage1 run --batch example-30000 --source /data/audio/example \
  --model qwen=/data2/data-cp/zcl/models/Qwen3-ASR-1___7B \
  --model glm=/data2/data-cp/models/GLM-ASR-Nano-2512 \
  --model sensevoice=/data2/data-cp/xijujun/models/SenseVoiceSmall \
  --runtime-config configs/stage1/server.yaml --gpus "$AUTHORIZED_GPUS"
```

`source` 支持现有登记来源或本地源目录，`batch` 与来源分别保存。完整运行至少三个不同家族、每族两次真实独立推理；自动生成路次别名和身份，不能复制第一次结果或跨路命中缓存冒充第二次。

自动执行：**预检/冻结输入 → 来源登记与清洗 → 三族双跑 → artifact/run identity 登记 → prepare_dataset_v3 → attach_asr_v3 → v2.2 能量、DNSMOS 候选、分类 → export-summary → 对账交付**。复用现有流水线和 catalog，不要求用户逐路改 YAML，不新增 VAD。

提交返回 `job_id`、状态入口和输出目录；后台执行不受 SSH 断开影响。source、权重内容摘要、解码/提示词、规则及代码版本留档。重复提交不得重复占卡或覆盖结果，不同配置必须隔离。正式成功须同时满足：

- 计划内所有必要 ASR 路次补齐，按 `sample_id + original_audio_sha256` 对齐；源文件到 cleaned 的排除/去重有记录，cleaned 到 classified/excluded 无丢失、重复。
- 固定 `selection_five_class_v2_2_auto_noise`，分类顺序及家族四态沿用现行规则；五类互斥，excluded 可空类别但必须有原因。失败不能填成稳定空，也不能删掉失败家族凑足三族。
- DNSMOS 只评分候选或复用合规证据；unavailable 按 v2.2 审计回退，不能伪造 noisy，也不切换旧版 pipeline。该合法回退与 ASR 路次缺失分别统计。
- 交付权威 classified Parquet、**全部 XLSX 分文件**（沿用每份 20,000 行机制，不截断）、ASR/cleaned/prepared 及能量/DNSMOS 证据、配置身份快照、失败/排除清单和产物校验索引。XLSX 与 Parquet 的样本集合、分类及关键证据一致。

各 job/结果修订独立保存，不覆盖历史 v1/v2 或 release。完整分类可包含 hardcase；工序一完成不自动等于金标审核完成或 `publish_status=pass`。

**验收**：小批次一条命令生成完整产物；相同证据与现有 v2.2 分类结果一致；超过 20,000 行的导出逐条对账；缺路、错哈希、重复键均阻止正式成功。

## 第三步：失败隔离、有限重试和精准补跑

**要求**

持久化 job、阶段、family、run、shard/sample、attempt 状态及成功检查点。瞬时故障默认最多重试两次并退避；确定性配置错误直接报告，连续故障熔断。OOM 可降低并发或分片大小，不能静默更换权重、精度或解码语义。

GLM 第二路失败时，Qwen、SenseVoice 及其他可执行分片继续；所有独立工作完成后，仅剩失败项进入 `needs_attention`，依赖阶段标记 blocked。**缺路未补齐，不发布正式完整结果**；运行故障清单与业务 hardcase 复核清单分开。

```bash
audio-data stage1 resume <job_id>
audio-data stage1 retry <job_id> --family glm --run 2 --failed-only
```

只补失败/缺失样本，成功结果校验后复用；真实 execution/attempt 与合并产物来源可追溯，遵守现有 identity 契约。补齐自动解锁后续阶段，导出失败只恢复导出。缓存须识别权重内容和输入变化。

成功分片原子落盘、单写者锁、过期 worker 写入隔离；SSH 断开继续，进程崩溃/服务器重启后可恢复，先核对存活 worker 和已提交产物，防止重复执行及覆盖。取消保存检查点并释放自有资源。重试次数跨重启保留，等待命令区分成功、需介入、失败和取消的退出状态。

**验收**：注入单路服务崩溃，其他家族继续；耗尽重试后精准补跑可完成交付；模拟编排中断、损坏产物和导出失败，确认成功结果不丢、不重复提交。

## 第四步：两张授权 GPU 动态接续任务

**要求**

附件中多张卡 GPU-Util 为 0 但显存占用约 75～79 GiB，因此**利用率低不能作为空闲判据**。以授权 UUID、显存预算、进程归属和资源租约共同决定准入；采集失败标记 unknown，其他人的进程不抢占、不终止。

当前 Qwen、GLM 均以 `tensor-parallel-size=1` 运行，优先按单卡实例调度。GLM 的 0.90 与 Qwen 的 0.5 是已用配置，不应在同一卡同时套用并假设能容纳。默认每卡一个重型实例；SenseVoice 多 worker 的整体显存和吞吐须实测后配置。

- 两卡可跑不同家族，也可用独立实例分担同家族的路次/未开始分片；按剩余音频时长、吞吐和加载成本排队。
- 同模型分片和第二路优先复用驻留实例，减少加载；分片不宜过大，空闲卡可领取尾部待执行工作。
- CPU 解码/I/O 有界预取；重试退避释放 GPU；旧实例退出并释放显存后再启动下一家族。多批提交也必须共享资源锁。
- 默认 5 秒采集。存在兼容就绪任务且资源已释放时，领取延迟 P95 ≤10 秒；模型加载/探针单独计时，不承诺零加载时间。

**验收**：以同一输入和解码配置对比串行基线，报告总耗时、两卡忙碌率、加载时间、空闲原因和调度延迟；一张卡受占用或故障时，另一张继续兼容任务。实际吞吐提升以服务器测量为准。
