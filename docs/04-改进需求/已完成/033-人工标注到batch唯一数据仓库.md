日期：2026-09-17。状态：已实现（单元测试通过；服务器大 batch 端到端人审未跑）。

## 1. 本次要完成什么

在现有分类分拣之后，补上“导出人工标注 → 回填校验 → 冻结入仓”的流水线，使一个 batch 最终只对应一个可追溯的数据仓库。这里的 batch 是工序一的数据批次，不是训练 mini-batch。

本次只实现到数据仓库。训练标签如何生成、跨仓抽取、训练集版本发布和一键训练后续再做；第 5 节只约定接口方向，不作为本次实现任务。不增加标注平台、数据库服务、自动配比推荐等功能。

与 [032 设计](./032-工序一标注到Qwen3-ASR训练数据流水线设计.md) 的关系：本文是当前阶段的收敛需求；032 的多格式接入、联合配额、训练编排等不作为本期前置条件。涉及 batch 唯一仓库和标签来源待定的地方，以本文为准。

## 2. 在当前项目中从哪里接入

- 分类入口已有 `scripts/classify_asr_to_xlsx.py`，默认生成 `datasets/stage1/derived/classified_five_class_v2_2_auto_noise_<batch>.parquet` 及分类 XLSX。以分类 Manifest 为入仓源，XLSX 用于人工操作，不能仅凭 Excel 文件名确定归属。
- `src/audio_engine/cli/main.py` 已有 `review export/import --protocol v3`；`core/annotation_v3/` 已有标注包、原始 `.meta.json` 身份校验、初审/复审/裁决和导入记录。应复用这些能力。分类汇总 XLSX 不能未经适配直接当作 v3 标注包导入。
- `Sample/Manifest` 已保存音频、转写、分类和 lineage，`core/catalog.py` 已有产物登记。入仓继续使用这些结构，不另建一套样本格式。
- 当前缺口是：batch 与分类快照的绑定、整批人工处理完成检查、唯一仓库冻结及登记。现有 `dataset_v3/release.py` 面向训练/评测集合发布，不能直接把它当作 batch 数据仓库。

现行类别为 `gold_candidate / semantic_risk / hardcase / voicemail / environment_noise`。分类字段采用 `labels.category`，细分 `type` 不等于类别；仓库与标注流程不能写死五个分支。

## 3. 最小流水线



### 第一步：生成该 batch 的人工标注包

指定 batch 和对应分类 Manifest，固化输入摘要及样本清单，再复用 v3 导出标注包。保留 `sample_id`、音频身份、原分类、来源、队列及版本信息，供人工听音和回填。批次绑定应进入随包保存的元数据，并在导入时核验。

覆盖该 batch 的全部分类样本，允许分包、分次标注，但不能只导出默认审核队列中的部分样本后就认为整批已处理。重复执行不得覆盖人工已填写的文件。

### 第二步：人工标注并回填

人工确认分类、填写或修正转写，也可以明确标记无法辨认、无效、无语音等结果。沿用现有标注状态与必要的复审/裁决要求，不新加一套审核等级。

- 原自动分类保留。人工改类另存 `reviewed_category`；未改类时使用原类别，类别值由配置校验，增减类别无需重写入仓逻辑。
- 回填按 batch、样本 ID 和音频身份关联，禁止按 Excel 行号关联；非本批样本、篡改身份、重复冲突、缺失元数据必须报错。
- 沿用 `gold_text` 等现有人工结果字段存储，不在此决定未来训练 `label` 的选取规则，也不把自动候选转写直接认作人工金标。
- 空白表示未完成；确认无语音沿用 `__EMPTY__`，不能把未标注或听不清转换为空转写。
- 允许多次回填完成整批；保留每次标注包、导入结果及错误清单。错误数据不得绕过校验进入正式仓库。



### 第三步：校验并冻结唯一仓库

人工工序完成后，一条生产流水线命令完成最终回填校验、整批检查、落仓和登记。导出标注包是另一条命令；两者之间保留人工操作，不把人工环节宣称为自动完成。

冻结条件：样本与分类快照逐条对应，数量一致、身份不重复；全部样本已有明确人工处理结果，所需复审已完成，没有 pending、未解决冲突或导入错误。无效、拒绝、听不清的样本也保留在仓库中并记录原因，供追溯，不因此成为可训练样本。保留的有效音频引用必须可解析并有内容摘要；音频缺失只有被明确确认为无效并排除时才能保留记录，不能默默跳过。

## 4. 仓库唯一性与最小产物

**一个 batch 只能登记一个正式 warehouse_id；一个仓库只能属于一个 batch。** 多个 ASR 运行、标注包、流水线重试都不能生成第二个正式仓库。batch 是稳定业务身份，不用一次运行的时间戳或配置摘要代替。

建议新增 `datasets/stage1/warehouses/<batch>/`，最小产物为：

- `manifest.parquet`：完整样本、原分类与人工修正分类、人工标注结果、处理状态，以及原来源路径和音频引用。
- `warehouse.json`：warehouse_id、batch、冻结时间、输入分类文件及摘要、标注记录引用及摘要、Manifest 摘要、分类规则/标注配置版本、按最终类别和人工处理结果统计的数量。

标注证据沿用 `datasets/stage1/review/`，正式仓库引用的证据必须保留且不可被覆盖。原音频不重复复制进仓库，但记录选定音频键、路径和摘要，后续消费校验内容是否变化。沿用 catalog 登记，补充 batch 唯一绑定检查。

同 batch、同输入及同人工结果再次执行，校验后返回原仓库；内容变化则报错，禁止覆盖或自动创建另一个仓库。发布先在临时目录完整校验，再原子提交；同 batch 并发发布也只能成功登记一次，失败重试不能留下可被消费的半成品。

首版不提供冻结后修改或多版本仓库功能。发现错误需明确报错，后续单独设计修订规则，不能偷偷改变已冻结数据。**仓库与训练集版本是不同对象：多次抽取产生的是训练集新版本，不是同 batch 的新仓库。**

## 5. 为后续抽取与训练保留的约定（本期不实现）

- 可从一个或多个 batch 仓库抽取。每条入选样本明确指向唯一的仓库、batch 和样本 ID；跨仓重复音频需识别，并显式决定保留来源，不能重复计数或丢失来源。
- 抽取配方支持人为指定仓库、类别和各自样本数；可选择任意类别组合，不硬编码五类、固定比例或现有四训练池。预留手工 ID 清单与带种子的随机抽取方式，后续策略可扩展。数量不足报缺口，不静默补其他类别或重复样本。
- 抽取结果固定为不可覆盖的训练集版本，保存配方、种子、仓库摘要及入选清单。分类、数量、来源用于单独的溯源文件，不放入模型训练字段。
- 训练文件每条只保留一个音频路径和一个转写字段。用户所说的 `label` 是概念名称；本地 `Qwen3-ASR-main/finetuning/qwen3_asr_sft.py` 当前实际读取 `audio`、`text`，后续按接入的官方训练代码确定字段和文本格式。本期不开发训练文本生成逻辑，也不提前绑定 `gold_text` 或任一 ASR 输出为训练标签来源。
- 权重记录必须关联固定训练集版本及摘要、基础模型和训练方式。展示区分 LoRA 与全量 SFT；技术记录可分别保存训练任务 `sft` 与参数更新方式 `lora/full`，因为 LoRA 也可用于 SFT。



## 6. 验收标准

1. 一个小 batch 经导出、人工回填和冻结后，得到唯一仓库；任一样本能追溯到原分类快照、音频及人工记录。
2. 分包回填不会丢失其他样本；未完成、冲突、身份错误或缺少必要复审时不能冻结；明确拒绝/无效记录保留且不被当作训练标签。
3. 同输入重跑返回原仓库；同 batch 换内容及并发发布不能生成第二个仓库或覆盖原数据；发布失败可安全重试。
4. 配置增加一个类别后，导出、人工回填和入仓统计仍可完成，不需改底层分支。
5. 本期不抽取训练集、不启动训练；交付标注包导出和回填入仓的生产命令、操作说明及上述关键测试结果。
