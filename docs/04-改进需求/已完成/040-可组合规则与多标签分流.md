## 1. 目标与必须交付的行为

把已完成多模型家族 ASR 的数据分流，改造成「计算可复用证据 → 独立判断各条规则 → 命中就添加对应 tag」。同一条数据可以同时拥有多个 tag，标签支持添加、移除、恢复和按组合筛选。

这里的「满足一个要求就打 tag」指：**满足任意一条完整标签规则，就获得该规则对应的 tag；规则内部可以要求多个条件同时成立。** 例如 tag_1 的四个条件全部成立才打 tag_1；命中 tag_1 后继续判断 tag_2、tag_3，不因先命中而结束。

新规则完全建立在当前程序已有的文本清洗、家族证据、一致性、语义判断与声学检测能力之上。把这些能力拆成可重复调用的组件，用户通过组合条件定义标签，不必为每个标签重新写一条流水线。

本需求改变的是业务规则之间的互斥和优先级。模型结果有效性、清洗、一致性判断、已有阈值以及人工金标和训练准入的要求继续沿用当前实现。新增「只有单字」等条件须明确定义，不能顺便改变旧指标口径。

## 2. 当前程序实际依赖哪些能力

以下根据当前配置和代码核对，区分「现有计算能力」与「本需求新增的组合和管理能力」。

### 2.1 多模型结果与家族证据

- 配置家族及双跑路次的对齐、运行成功/失败/缺失状态；当前默认 Qwen、GLM、SenseVoice 三家族六路，家族集合由配置决定。
- 每路原始转写、最终可比文本、清空原因及是否可参与投票。
- 家族四态：`stable_text`、`stable_empty`、`unstable`、`unavailable`，以及稳定家族数、否定票数和代表文本。
- 「原生空」「清洗后空」「失败或缺失」分别保留，不能互相冒充。

### 2.2 文本清洗与有效性处理

- 控制标签、标点、字符规范化与当前中文可比文本策略。
- 外语、提示词回声、热词回声等处理，以及回声匹配所依赖的外部配置。
- 超长转写、转写语速防护等已有有效性判断。
- 保留 `raw_text` 与 `classify_text` 的区别；不能把清洗后结果当成原始输出。

### 2.3 正则与外部词表

- 语音信箱正则已由 `configs/selection/voicemail_patterns_v1.yaml` 外部维护，当前在成功路次的原始文本上匹配。
- 极性/语义词表来自 `configs/selection/semantic_lexicon_zh_v3.yaml`；关键短应答名单位于当前 selection 配置。
- 本需求把外部词表匹配扩展为通用条件，并补充词表版本、命中位置和匹配范围。

### 2.4 文本关系与语义判断

- 家族内稳定性、家族间一致/无害等价、有效非空文本之间的实质分歧。
- 极性相反、关键短应答实质歧义、稳定同文支持及现有候选选文逻辑。
- 文本长度、汉字数、音频时长和语速等基础特征可复用；「整段只有一个汉字」作为本需求新增的显式条件。
- 「不一致」不自动等于「语义相反」；空、失败和缺失不自动构成语义冲突。

### 2.5 声学证据

- Silero VAD：是否有人声、语音占比及检测状态。
- `audio_energy`：当前静默判断使用混合声道前的全声道采样值严格全零；低能量不能替代严格全零。
- DNSMOS：保留 SIG/BAK/OVRL 和计算状态；当前 v3 业务判断只使用 SIG 低档，沿用现有 `weak_sig` 配置和边界比较方式。
- EfficientAT 在仓库中属于可选/历史能力，已退出当前默认主路径。本需求不默认引入新模型。

### 2.6 还有哪些配套依赖

样本身份、音频可读性、物理有效性、数据源/批次、模型及配置版本、证据复用和导出审计共同决定结果是否可信。它们需要保留，但「输入体检」「证据计算」「业务标签规则」「下游训练准入」应分别承担各自职责。

当前的 `route_asr_queue()` 会在命中语音信箱后直接返回，并从 A—E 中选一个计算队列；后续 VAD/energy/DNSMOS 候选范围也依赖该队列。因此，不能仅把最终 `category` 改成列表：还必须拆开提前返回的条件判断，并重建声学依赖规划。

## 3. 可重复调用的五组能力

实现必须覆盖以下五组能力。**这里的 A—E 是能力分组，与当前程序互斥的 ASR 队列 A—E 无关。** 每组内部可有多个独立函数/算子，不限制整个系统只能有五个函数。

- **A：ASR 与文本证据。** 读取已有识别结果，应用当前清洗策略，生成家族状态、代表文本、原生空/清洗空及有效路次；不在打标签时重跑 ASR。
- **B：外部词表与正则匹配。** 指定词表、文本来源、家族/路次范围及任一/全部匹配方式，返回匹配结论和证据。
- **C：文本特征与关系判断。** 提供单字、长度、一致/不一致、极性、关键短应答和现有候选条件；一致性直接复用当前有效实现。
- **D：人声与物理声音证据。** 独立提供 VAD 与严格全零检测；二者按规则需要分别调用，不强制绑定运行。
- **E：DNSMOS 质量证据。** 独立评分，依当前配置生成 SIG 低档等条件；原始分数与阈值解释分开保存。

每个组件都应能独立调用，也能被多个规则共享。组件输出至少包含值、状态、输入指纹、能力版本、配置摘要和错误原因，不直接修改业务标签。

### 「正确率规则保持不变」的约束

复用当前生产路径实际使用的判断函数和配置，不能把配置中出现的所有相似度阈值都当成当前分支正在使用的阈值。当前五类路径家族稳定性使用 `build_family_states()` 及无害等价/语义冲突检查，应保持其实际语义。

多模型一致性是识别证据，不能直接宣称是真实正确率。存在外源金标时，CER/字准率继续使用既有指标引擎；无金标时不得新增未经依据的「正确率」数值。实施时须用固定样例核对抽取前后原子判断结果一致。

## 4. 规则如何自由组合

### 4.1 标签和规则的关系

标签包含稳定的 `tag_id`、显示名称、业务解释和启用状态；规则包含稳定的 `rule_id`、版本、所产生的 tag 及完整条件。名称可以改，ID 不随显示名称改变。

一条规则可以由多个条件组合；多条规则可以产生同一个 tag。一个样本的同一个 tag 只显示一次，但所有命中来源都要保留。一条来源消失，其他来源仍成立时，标签应继续存在。

支持如下条件组合，第一版即需要支持嵌套：

- `all`：全部成立（AND）。
- `any`：至少一个成立（OR）。
- `not`：条件取反（NOT）。
- 家族集合上的 `all` / `any` / `at_least(n)`：例如至少两个家族稳定有字。

条件可以保存为有名称、带版本的复用片段。例如「全部配置家族双跑成功」「SenseVoice 与 GLM 稳定同文」可直接被多个规则引用；片段变更应形成新版本并展示影响范围。拒绝循环引用；第一版规则条件读取证据或片段，不读取本轮刚生成的标签，避免执行顺序影响结果。

### 4.2 tag_1 的完整解释

将用户例子定义为以下四组条件同时成立：

1. 当前配置的全部家族双跑成功；SenseVoice、GLM、Qwen 都为 `stable_text`，具备有效非空代表文本。沿用当前稳定性判断，不降低要求。
2. SenseVoice/GLM 的共同代表文本命中外部维护的 `tag_1` 正则词表。
3. 该共同代表文本清洗后整段恰好为一个汉字，不含额外数字或其他字符。
4. SenseVoice 与 GLM 按当前无害等价规则一致；Qwen 与它们按同一规则不一致。

这里明确选择「匹配和单字都针对 SenseVoice/GLM 共同代表文本」。后续规则也可以选择任一路原始文本、指定家族代表文本等来源，但必须明确写出来源，不能隐式换字段。

概念表达如下，**仅是需求示意，不是当前可执行配置**：

```text
tag_1 = all(
  全部配置家族双跑成功,
  SenseVoice / GLM / Qwen 均稳定有字,
  等价(SenseVoice代表文本, GLM代表文本),
  正则命中(词表tag_1, SenseVoice代表文本),
  整段单汉字(SenseVoice代表文本),
  not(等价(Qwen代表文本, SenseVoice代表文本))
)
```

示例：SenseVoice 双跑「好/好」、GLM 双跑「好/好」、Qwen 双跑「要/要」，词表含 `^好$` 时，命中 tag_1；若还满足另一条「关键短应答」规则，同时保留另一个 tag。

若 Qwen 是双跑空、族内不稳定或失败，不得利用 `not(一致)` 自动命中本规则。如需标出「两族同文而 Qwen 稳定空」，另设一条明确要求 `Qwen.state=stable_empty` 的规则。

### 4.3 外部词表维护

复用当前 YAML 词表维护方式，通用词表支持独立文件、词条 ID、正则/字面词条类型、匹配模式（search/fullmatch）、flags、版本及内容哈希。语音信箱迁移模板保持当前原始文本匹配范围和方式。

每个匹配条件显式指定文本字段、家族/路次范围、任一或全部命中方式。同一规则中多个文本条件默认绑定同一选定文本；如有意分别匹配不同路次，必须显式声明，避免「一条文本命中正则，另一条文本满足单字」的误拼接。

启动前校验路径、词表结构和全部正则；无效正则不得默默视为未命中。单次运行固定词表快照，运行过程中编辑文件只影响下一次运行。给复杂正则设置可执行的超时或复杂度限制，异常保留原因。

## 5. 命中状态、执行顺序与成本

### 5.1 规则判断三态

每条规则的结果为 `matched`、`not_matched` 或 `unknown`。证据另记 `success`、`not_computed`、`not_required`、`failed`、`missing` 等计算状态。

- `matched` 才产生自动标签；`not_matched` 是证据足够且条件不成立。
- `unknown` 表示当前无法判断，记录缺少或失败的依赖；不能当成 false 后再用 NOT 变成 true。
- AND 中有 false 即 false，全部 true 才 true，其余 unknown；OR 中有 true 即 true，全部 false 才 false，其余 unknown；NOT unknown 仍为 unknown。
- 失败只影响依赖该证据的规则，不阻断可以独立判断的其他标签。

「ASR 已跑完」与「每一路都成功」要区分。缺路文件、重复样本 ID、错批次等契约错误在入口体检报错；单样本某路运行失败仍保留记录，不能删除或伪装为空。失败状态本身是可判断的事实，例如 `family_state=unavailable` 可以正常命中诊断规则；依赖其不存在文本的比较则为 unknown。

### 5.2 业务规则无优先级，计算仍有依赖

每条启用规则都要得到判断结果；配置顺序只影响展示，不影响标签集合。允许在一条 AND 规则内部用便宜条件短路，不得因一条规则命中而跳过其他规则。

执行器先计算已有 ASR/文本证据，判断便宜条件，再对仍可能成立的规则收集声学依赖，取样本集合的并集执行。多个规则共用同一音频、模型和参数时，VAD、energy、DNSMOS 各算一次。新增纯文本标签不应触发声学计算。

当前「语音信箱命中就不跑声学」是旧互斥流程的优化，不再作为全局限制。若同一样本还可能命中依赖 DNSMOS 的另一个 tag，应继续收集其必要证据；若其他规则均无需声学，则仍不计算。

支持「只使用已有证据」和「按需补算声学」两种模式。已有证据模式下缺少证据返回 unknown；补算模式只补本次启用规则真正需要的声学证据。两者都不启动 ASR。

### 5.3 复用、版本与重算

证据缓存按输入内容、音频表示/预处理、模型版本和计算参数识别，不能仅按 batch 或文件路径复用。声学评分和阈值判定分开缓存，修改阈值只重判，不必重跑评分。

只改正则词表、规则组合或标签名称时，复用仍有效的 ASR/声学证据。清洗或家族判断版本变更须重算受影响的文本证据及下游规则；VAD 参数变更只使相应 VAD 证据及依赖它的结果失效。

具备持久化进度、幂等恢复及原子发布；可复用 [038](./038-工序一后置五类分拣断点续跑.md) 的设计，但其仍未实现，不能写成已具备。实施时可抽出共享底座，不要求先完成旧五类入口的全部改造。

## 6. 多标签如何添加、去除与恢复

### 6.1 标签来源与有效集合

分别维护「自动命中来源」「人工添加」「人工屏蔽」，不要只存一个可覆盖的字符串数组。有效标签为：

```text
有效标签 =（当前自动命中标签 ∪ 人工添加标签）－ 人工屏蔽标签
```

同一标签可同时有多条自动规则来源和人工来源。标签管理操作作用于 `(batch_id, Sample.id, tag_id)`；同时校验样本音频身份，避免同 ID 换音频后错用人工操作。

### 6.2 必须区分的管理动作

- **添加标签**：写入人工添加来源；重复操作不产生重复标签。
- **移除标签**：移除人工添加来源并创建该样本/标签的人工屏蔽记录；默认持续生效，规则重跑不能自动加回。底层自动命中证据继续保留。
- **取消人工添加**：只撤销人工来源；仍存在自动命中时标签继续显示，操作结果应说明。
- **恢复自动管理**：撤销屏蔽，依据当前自动结果重新决定是否显示；不会凭空创建人工来源。
- **重新人工添加被屏蔽标签**：显式撤销对应屏蔽后再添加，避免产生互相矛盾的状态。
- **停用规则**：新快照不再保留该规则的自动来源，保留人工标签、其他规则来源和历史快照；展示受影响数量。
- **停用/归档标签定义**：阻止后续自动及人工新增，新有效视图不显示该标签；保留全部历史与屏蔽记录，允许恢复。停用标签时其关联规则停止参与打标。

人工操作记录操作者、时间、理由和操作前后状态，支持按明确样本列表或筛选快照批量执行。第一版提供程序/CLI 接口即可，Web 管理界面可后续扩展。

### 6.3 规则变更后的对账

完整成功重跑后，以新规则快照替换该范围的旧自动来源，已不命中的自动标签自动退出；人工添加和屏蔽不被覆盖。规则从命中变成 unknown 时，新视图不继续把旧标签当成已确认，旧结论只作为历史记录展示。

局部重算只对明确的样本和规则范围对账，不能删除未执行规则的来源。未执行规则若版本或输入已变，应标记旧来源为 stale，不纳入当前已确认有效标签。运行中断不发布半套结果；并发人工修改不得被旧作业快照覆盖，使用操作日志或版本校验合并。

## 7. 输入、输出与筛选

### 7.1 输入

沿用现有 cleaned / prepared_asr 底表、各路识别结果、家族配置及可读音频。优先读取已完成模型结果；既有 VAD/energy/DNSMOS 证据通过指纹校验后可复用。规则所需的家族名称不存在时配置校验失败，不能静默映射为其他模型。

规则定义、复用条件片段、词表及人工操作记录均需版本化。数据规模不预设，至少覆盖当前万级批次。

### 7.2 输出

新增独立版本 `selection_multi_tag_v1`，实现以下目标产物；这些是待开发契约，不是现成功能：

- `datasets/stage1/derived/tagged_multi_tag_v1_${BATCH}.parquet`：全量样本及排序、去重后的有效 tags，保持一条样本一行。
- 同版本规则结果明细：以样本 × 规则为粒度，保存三态结论、条件证据、命中词条、家族/路次/文本来源、声学状态、版本与原因。
- 持久化标签来源、人工操作日志与证据缓存；可作为批次唯一数据仓库的版本化附属产物，不另建重复音频仓库。
- `data/exports/summary_multi_tag_v1_${BATCH}.xlsx`：样本列表、每标签去重样本数、标签重叠情况、未命中/无法判断数量及失败依赖统计。重叠明细可按需选择标签计算，避免标签多时全组合膨胀。

标签总次数允许大于样本数。每条样本评估状态定义为：有至少一个有效标签 → tagged；无有效标签且存在 unknown/stale → unresolved；无有效标签且全部启用规则已确定判断完成 → untagged。untagged 中另记「全部不命中」或「命中但被人工屏蔽」等原因。无启用规则且无有效人工标签时单列 not_evaluated，不计入 untagged。

输入唯一有效样本数应等于上述状态数量之和。已有标签的样本也可能有其他 unresolved 规则，须另报规则判断覆盖率，不能因已打一个标签就宣称全部判断完成。

支持按「包含全部指定标签」「包含任一标签」「排除指定标签」、规则 unknown/证据失败以及人工屏蔽记录筛选。按多个 tag 汇总导出时以样本身份去重；同一音频跨批次的去重继续遵守既有音频身份约定。

### 7.3 操作体验

统一脚本/CLI 实现，至少支持：规则与词表校验、预演、按 batch 打标签、按指定规则/样本增量重算、查看单样本命中原因、人工增删恢复、标签组合筛选导出。

预演展示新增/退出/屏蔽的标签数和预计需补算的声学样本数，不写正式标签状态。已有证据不足时明确哪些结果仍未知；不能把估算写成最终命中数。生产入口和参数要求见第 12 节，实现后提供实测可执行命令。

## 8. 与现有五类、人审和训练流程的关系

新模式是独立的多标签判断入口，旧五类及其历史产物保留可复现。多标签模式不以旧 `category` 或旧唯一队列作为是否运行某条规则的前提，也不覆盖旧 `category`、`risk_tag`、`noise_kind`。

迁移时从现行程序抽取原子条件，并提供语音信箱、疑似 Qwen 幻觉、人声噪声、极性冲突、关键短应答歧义、静默、非静默背景噪声和 gold 候选等规则模板。保留各规则自身明文的成功态、否定票、语义与声学约束；取消仅因「前面已经命中」造成的隐式排除。业务条件中明确存在的 `not` 仍需保留，例如关键短应答分支明确排除已构成极性相反的情况。

旧 hardcase 是顺序决策后的剩余集合，不能直接复制成普通标签并宣称含义相同。新模式以 untagged/unresolved 表达覆盖情况；族内不稳定、家族不可用等可各自定义诊断标签。若业务需要「未命中任何业务规则」标签，使用独立收尾规则，基于指定业务规则集合的确定结果求补集，不能按排列顺序判断，也不能把 unknown 当未命中。

仅有 tag 不等于人工金标、人工类别或训练准入。人工类别、标注状态与训练排除条件继续执行当前仓库契约；按 tag 抽取训练样本仍须经过现有人工完成、拒绝/排除、数据身份与去重等门禁。下游暂时只能接收单类时使用显式配置、单独版本化的适配策略，不把隐藏优先级重新写回多标签引擎。

## 9. 怎么才算满意（验收场景）

1. **无顺序依赖**：同一样本同时满足两条规则时获得两个标签；打乱规则排列后标签集合、证据结论保持一致。
2. **示例成立**：SenseVoice/GLM 稳定「好」，Qwen 稳定「要」，词表 `^好$` 时得到 tag_1；「好啊」不满足单字；Qwen 稳定「好」不满足分歧。
3. **失败不冒充不一致**：Qwen 单路失败、全失败或稳定空均不命中上述 tag_1；另设稳定空规则时只按其明文条件判断。
4. **组合与三态**：嵌套 AND/OR/NOT 和至少 N 家族成立可运行；NOT unknown 不产出标签；错误规则、未知能力/家族、循环片段和非法正则在正式执行前报错。
5. **准确性口径不漂移**：固定样例中清洗、家族四态、无害等价、极性及声学阈值判断与当前实际函数一致；保留原始空和清洗空差异。
6. **声学按需共享**：纯文本规则调用声学次数为零；两条规则共用 VAD 时每个相同输入只算一次；信箱命中后其他依赖声学的规则仍可完成判断。
7. **故障隔离**：DNSMOS 失败只让依赖它的规则无法判断，独立文本标签正常生成；严格全零和低能量不会混淆。
8. **外部词表可重跑**：修改词表形成新快照，只重判受影响规则；已有有效 ASR 和声学模型推理不重跑，导出能够追溯词条和版本。
9. **人工移除持续生效**：移除自动标签后重跑仍不显示；恢复自动管理后按当前规则恢复；重复添加/移除幂等，多来源同 tag 不重复。
10. **自动来源正确对账**：规则不再命中、被停用或变成 unknown 时，新快照不保留其旧确认来源；其他规则来源及人工来源独立保留；局部运行不误删范围外结果。
11. **统计和导出去重**：一行样本可带多个标签，分标签计数允许重叠，合并导出不重复样本；样本状态数量守恒，unknown 单列。
12. **可恢复和兼容**：中断恢复复用有效证据，未完成作业不发布正式快照；并发人工操作不丢失；旧五类回放与原产物保持可用，训练门禁不因增加标签被绕过。
