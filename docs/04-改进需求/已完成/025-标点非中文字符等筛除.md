## 0. 用户原话（需求真相源）

1. 全面检查当前标点符号存在的问题，以及 SenseVoice 存在 `<||>`（即 `<|…|>` 控制标签）的问题。
2. 分类分拣的前提是所有非中文字符全部被筛除，即非中文字符不参与数据分类分拣。
3. 当前 GLM 和 SenseVoice 容易出现非中文字符；只要出现非中文字符，均将该路转写视为空（人声噪声，或该模型家族没听清楚）。无论哪个模型家族，转写与提示词完全一致、或与热词完全一致，也视为转写为空（人声串音或背景噪声导致的回声/幻觉）。

实施时若与用户原话冲突：**停下来问用户，不要自行改需求含义。**

## 1. 目标与结论

源音频按中文业务通话处理。分类、共识、语义核验、选文和语速栏，都必须先得到一路**只含中文分类字符**的文本；标点、FunASR 控制标签、拉丁字母和其他文字体系不能进投票。

GLM / SenseVoice 吐出英文、混语或控制标签，不表示音频里真的在说外语，也不给该路一张「译文语义票」。该路按空处理：家族没听清，或把噪声/串音编成了字。

模型把解码提示词或热词表原样吐出来，同样按空处理：这是提示词回声，不是用户说了那句话。

空路不等于 `non_speech` 金标。六路变空之后，仍走 023/024 已有的语音存在性 / 噪声诊断缺口，不能直接标噪声或放进训练集。

本需求优先于 022/024 中「外语译文可参与已核验语义票」「混语保留拉丁片段」的分类口径。023 的噪声触发仍看**筛除前**的正文快照，否则英文被置空后 `non_chinese_transcript` 永远不会发生。

## 2. 当前事实：标点、`<|…|>`、非中文和回声分别卡在哪

以下是编写时对仓库的核对，实施前须再读实际代码与未提交 diff，不能只抄本节。

### 2.1 标点：比较层在剥，状态层没剥干净

分拣里现在有三套相近但不相同的「去标点」：

| 位置 | 实际行为 | 问题 |
| --- | --- | --- |
| `selection_v3/text.py` 的 `comparison_text` | 去控制标签 + NFKC + 配置/默认标点表 + 去空白 | 默认表是手写字符集，漏「」『』～•￥#%*+= 以及多数 Unicode `P*`/`S*` |
| `selection_v3/text_tolerance.py` 的 `comparison_form` | 同上，默认表多了 `—－-…` | 与 `text.py` 默认表不一致；022/024 走这里，生产 `classifier.py` 走 `text.py` |
| `metrics/normalization.py` 的 `normalize_text` | `unicodedata.category` 以 `P` 开头的都删 | 评测比分拣更干净；分拣没用这套 |
| `operators/quality/normalize_transcripts.py` | 评测/字准才挂；会整句 blank 热词 | **`classify_dataset_v3` 不跑它** |

生产 `classify_run_status`（`input_contract.py`）只看 `raw_text` 是否字面为空。SenseVoice 常见 `<|zh|><|NEUTRAL|><|Speech|><|withitn|>。`：原串非空 → `success_text`，比较文本去标签去标点后变成 `""`。024 已写过：第 3 行四路空、SenseVoice 两路「控制标签 + `.`」被打成 `language_unverified`。022 的 `content_language` / `has_lexical_content` 修了影子路径，**生产 `selection_v3.0` 的 `family_evidence.py` 仍用旧状态机**。

语言检测也不统一：`detect_language()` 在保留标点的 `transcript_text` 上跑，单独一个 `.` 是 `unknown` 而不是 `empty`；`content_language()` 先抽词汇再判语言。分类若混用两套，纯标点会继续进跨语言 hold。

句边语气词（啊/呀/呢）在 024 里可以不拆开业务等价；那是语义层。本需求的标点筛除不得顺手删「不/没/好/行/嗯」。

### 2.2 SenseVoice `<|…|>`：021 只修了分拣候选，ASR 落盘仍脏

用户说的 `<||>` 就是 FunASR 控制字段，例如 `<|zh|>`、`<|NEUTRAL|>`、`<|Speech|>`、`<|withitn|>`，以及空标签 `<||>`。不是音频清洗漏了尖括号。

021 已说明两条口径打架：

- `parse_sensevoice_text` **只删白名单**；`withitn` / `woitn` / `EMO_UNKNOWN` / 新标签留在 `transcripts.*.text`。
- `clean_control_tags` / 022 候选正文删**全部** `<\|…\|>`。
- 生产 v3.0 选文仍可能把 `medoid.raw_text` 写给人看。

对 025 的直接影响：

1. 分类若读 `text` 而不是统一 `clean_control_tags`，标签字符会进语言检测、语速字数、是否非空。
2. 全文只剩标签时必须是空路，不能把 `<|withitn|>` 当一句话。
3. 正则 `<\|.*?\|>` 能删 `<||>`；残缺形 `<EMO_UNKNOW>|` 要靠 `_LOOSE_EMO_TAG_RE`。未闭合的 `<|zh` 不按控制标签删，以免误伤普通 `<`。
4. **不要**为去标签重跑 SenseVoice。`extra.raw_text` 已够离线重写。① `data_cleaning_source_A` 无转写，禁止把本项塞进 pcm/resample。

021 继续负责 ASR 落盘 `text` 白名单；025 不替代 021，但分类路径必须在 021 未完成时也能剥掉全部控制标签。

### 2.3 非中文：GLM/SenseVoice 仍在参与分类

023 本地 0908 影子：非中文话语 7,025 条。024 语言 hold 18,042 里，去掉六路空之后仍有大量 en/mixed/其他文字。现行处理是：

- 生产 v3.0：GLM 非中文不进中文选文，但英文路次仍可能把样本打进 hold / 语速隔离，而不是先置空。
- 022：`char_comparable=false`，译文可走跨语言语义核验。
- 024：外语核验后可贡献语义证据，不能当中文逐字票；空路与有字路冲突保持 U。
- 018 语速栏按字符/秒。非中文长篇会把 GLM 打进 `speech_rate_quarantine`（024 记过仅 GLM 语速隔离 1,368 条）。那些字往往不是中文口语。

用户现在的规则更硬：**出现非中文词汇（拉丁/其他文字体系）→ 该路分类视为空**，不再拿「删掉英文后剩下的汉字」去凑中文共识，也不再给该路语义票。混语 `你好 hello` 整路空，不是变成 `你好`。

这与 023「数字、电话、中文语境产品缩写不触发噪声评分」不矛盾：023 看的是筛除前快照；025 决定的是分类投票用不用这路字。

### 2.4 提示词/热词回声：评测有、分拣无

整句精确命中则置空，已经存在于**评测归一化**，没有接到分拣：

- `configs/normalization/blank_exact_qwen_v1.yaml`：Qwen 把 `vocabulary:` 整表吐出后，去标点等于  
  `没有暂时不用不需要谢谢不可以啊不用我不需要不要不用不需要` → 置空。
- `rewrite_plain_transcript_entry` 只在 `normalize_transcripts` 里调用。
- `pipelines/classify_dataset_v3*.yaml` 没有这一步。
- Qwen 配置 `context: "vocabulary:没有，暂时不用，…"` 仍在 `configs/asr/qwen_asr.yaml`。
- Kimi 默认提示词是 `请撰写这段语音：`（`configs/asr/kimi.yaml`）。GLM 配置目前没有写死 prompt，但算子指纹含 `prompt`，批次若传了就必须纳入回声表。
- SenseVoice 通常无自然语言 prompt，但仍有控制标签回声，归 2.2。

「和热词完全一致」必须是**整路正文 = 提示词全文，或 = 热词表拼接/整表 dump**，不能是「正文等于词表里的某一个词」。否则真实短句「不需要」「没有」会被清掉。现网 `blank_exact_qwen_v1` 已经是整表一句，不是逐词。

## 4. 业务规矩：字符类、置空、回声

### 4.1 处理顺序（每路独立，先审计后分类）

```text
raw_text（只读）
  → 剥离全部控制标签 / 残缺 EMO 标签     → body_no_tag
  → 提示词/热词整句精确命中？            → 是则 success_empty（prompt_echo / hotword_echo）
  → 去空白与全部标点/符号                 → body_no_punct
  → 纯空                                 → success_empty（punctuation_or_tag_only）
  → 仍含拉丁或其他文字体系字母？         → success_empty（non_chinese_discarded）
  → 只保留中文分类字符                   → classify_text
  → classify_text 为空                   → success_empty
  → 否则 success_text，仅 classify_text 进入分拣
```

`transcript_text`（候选/人审可见）= `body_no_tag` 再 strip，**可以保留中文标点**，但禁止残留 `<|…|>`。若该路已因回声/非中文置空，候选不得再选用这一路。

### 4.2 什么算中文分类字符

参与 `classify_text` 的字符仅限：

1. CJK 统一汉字及扩展（含简繁）。繁体可继续走现有安全一对照简，但比较键里必须是汉字。
2. 阿拉伯数字 `0-9` 及 NFKC 后的全角数字。电话、金额、验证码是业务槽位，**不因出现数字而整路置空**，数字也**不从分类键里删掉**。

「所有非中文字符都筛除」在本需求中的操作定义是：标点/符号/空白/控制标签/拉丁/其他文字**不得进入分类比较**；其中拉丁和其他文字体系一旦出现，整路作空。数字按槽位保留。若用户要求数字也删或数字也整路作空，先问再改，不要 silently 改槽位。

语气词「嗯啊好行」是汉字，不是非中文，不能为了扩大空路把它们清掉。023 已禁止把真实短反馈当空。

### 4.3 什么出现就把整路当空

在标签剥离之后、进入投票之前，下列任一成立则该路 `classify_text=""`，状态 `success_empty`，并记下原因（可多选，同路只空一次）：

| 原因码 | 条件 | 业务解释 |
| --- | --- | --- |
| `control_tag_only` | 去标签后无词汇 | 标签不是转写 |
| `punctuation_or_symbol_only` | 去标签去标点后无词汇 | `.`、`。`、`…` 不是转写 |
| `non_chinese_discarded` | 去标签去标点后仍有拉丁/假名/西里尔/阿拉伯文等字母 | GLM/SenseVoice 没听清或把噪声编成外语 |
| `prompt_echo` | 规范化后全文等于该路实际 prompt/context | 提示词回声 |
| `hotword_echo` | 规范化后全文等于热词整表 dump 或配置的整句热词条目 | 热词表回声 |

混语：`你好 hello`、`OK 好的` 只要还剩拉丁字母，整路空，不留「好的」去投票。  
英文整句：`Please leave a message` → 空。  
中文加电话：`回拨13812345678` → 保留。  
中文加产品缩写：`转IVR` 是否整路空，见 4.4。

置空是**路次**行为。其他家族仍是正常中文时，样本继续用那些中文路分类；不要因为 GLM 英文就给整条打 `language_unverified`。这正是把非中文从分拣前提里拿掉的目的。

### 4.4 缩写、NFKC、未知符号

- 先 NFKC，再判拉丁。全角 `Ｈｅｌｌｏ` 按英文置空。
- 中文语境里 2～6 个大写字母缩写（IVR、OK、VIP）**不单独**作为 `non_chinese_discarded` 的充分条件，以免「转IVR」被误杀。无汉字、只剩拉丁缩写 → 仍整路空。
- 连续 ≥3 个拉丁字母且构成外语词（leave/message/hello）→ 整路空，即使旁边有汉字。
- Unicode 类别 `P*`（标点）、`S*`（符号）、`Z*`（分隔）一律不进 `classify_text`。不要只维护一份易漏的手写标点表；手写表最多作补充。
- emoji、装饰符号、货币符号：剥离；若剥完没有汉字或数字 → 空。
- `unknown` 短串（既无汉字也无拉丁）→ 空，不再变成跨语言 hold。

### 4.5 提示词 / 热词「完全一致」

比较双方都走同一套：去控制标签 + NFKC + 去标点空白（热词匹配阶段**还不必**因拉丁置空，否则英文 prompt 永远对不上）。然后：

1. **提示词：** 该路实际使用的 `prompt` / `context` 全文（含 Qwen 的 `vocabulary:…` 整串，比较时去掉 `vocabulary:` 前缀）。空 prompt 不做回声。
2. **热词整表：** 词表全部条目按同一规范化后按配置顺序拼接成一句，全文相等才空。Qwen 现网那句必须继续命中。
3. **热词条目：** 仅配置里显式列出的**整句**条目（如评测 `贷款审批` 那种字段名），不是词表里每个「不需要」。
4. 所有已配置家族都做，不限 Qwen。Kimi `请撰写这段语音：` 必须覆盖。
5. 子串包含不算。`暂时不需要谢谢` 不是整表 dump，不得因含「不需要」清空。
6. 命中后 `raw_text` 仍保留；只改分类用文本和空路原因。

热词表从该批次真实 ASR 配置读取（Qwen `context`、评测 `blank_exact_*.yaml`、以及 selection 配置可追加的 echo 列表）。缺文件不能静默当成没有回声规则；缺则失败或显式 `echo_list_missing`，由配置决定，但不得用空列表假装已防护。

### 4.6 明确不做

- 不改音频，不重切，不重跑 ASR。
- 不把空路直接映射为 `noise` / `non_speech` / 训练负例，除非 023/024 的独立音频证据已经成立。
- 不删除汉字否定词、应答词。
- 不把外语译回中文再投票。
- 不覆盖旧 classified / 审核包 / release。
- 不为了本需求打开全量 DNSMOS。
- 不把 021 未完成当成 025 可以偷懒的理由：分类侧必须先干净。

## 7. 我怎么才算满意
