# 027 · 五类分拣重构正式需求

> 日期：2026-09-15  
> 状态：已实现并归档（2026-09-17；全量业务听音验收未宣称完成）。  
> 策略版本：`selection_five_class_v1`。  
> 正式入口：`pipelines/classify_dataset_five_class_v1.yaml`。  
> legacy 回退：`pipelines/classify_dataset_v3_asr_anomaly_noise.yaml` + `selection_v3.0`。

## 1. 目标与需求优先级

重构当前 ASR 数据分拣流程：先排除外语、热词回声和模型提示词回声，再将有效样本严格分入五个业务类别；无法自动定类的样本直接形成可执行的人工标注任务，不设待处理类别或等待补证据的中间队列。

本需求是本轮用户规则的最终版本，优先于 [026 早期方案](./026-五类分拣收敛与严格语义风险方案.md) 及 020～025 中与本文冲突的条款。明确废止以下旧口径：

- 外语、热词回声、提示词回声按成功空转写参与分类。
- 语音信箱必须多家族命中或经过上下文核验才能隔离。
- 未满足类别条件时输出 `pending_evidence`、待处理、未分类待核验等任务状态。
- 旧语义风险标签命中即可直接决定 `semantic_risk` 主类。
- 要求所有配置家族均有有效转写才能成为金标候选；新口径为至少三个合格家族，同时不得忽略其他有效反对证据。

本次重构明确允许修改 `src/audio_engine/core/selection_v3/` 及必要的算子、结果契约、审核包、导入与数据集消费者。工程组织遵循 [流水线构建执行手册](../../07-操作手册/流水线构建-AI执行手册.md)，其中历史业务默认不得覆盖本文最终规则。

## 2. 当前问题与改造范围

基于本轮已检查代码和配置：

- 当前已有中文前处理模块，但 `SelectionV3Config` 默认 `classify_text_policy=legacy`，0914 三族配置未启用中文前处理。
- 现有 `semantic_risk.py` 使用全路文本和宽词汇规则，可将未知文本与肯定句分歧判为幻觉，缺少独立家族身份与声学约束。
- 当前主分类器的风险分支早于语音信箱，信箱要求多个稳定家族命中。
- 现有容错选文是确定性距离排序，不是 Qwen 加权随机。
- 当前噪声算子采用未校准 DNSMOS，不能直接证明串音、目标语音不存在或肯否幻觉。

Cursor 开始实施时应重新核查当前工作区，不把以上快照当作永远准确的事实。

范围：复用已有音频和多家族 ASR，改造分拣及必要下游接口；不为文本规则重跑 GPU ASR，不覆盖原始转写、人工金标、历史审核包或 release，不修改与需求无关的 ASR 配置。

## 3. 输入、终态与输出契约



### 3.1 输入

- 使用现有 prepared ASR Sample/Manifest，优先兼容 `0914-mixed-30000` 三族双跑。
- 按真实配置识别 family/run_id，不硬编码为八路或四族。
- 音频引用沿用 Sample 中的原始/规范化音频路径及哈希。
- 获取每一路实际使用的热词、prompt、context、内置提示词模板及来源版本；不能仅使用当前配置猜测历史批次实际提示词。



### 3.2 五个业务类别

- `voicemail`：语音信箱，含当前正则覆盖的电话助手等内容。
- `gold_candidate`：抽查型金标候选。
- `semantic_risk`：严格语义风险。
- `hardcase`：多家族实质高分歧。
- `environment_noise`：有声学依据的环境噪声/串音。



### 3.3 样本级分拣出口

分拣结束时，每条输入必须恰好进入以下一个出口：

1. `excluded`：全部路次被前置规则排除，不进业务分类和人工标注队列。
2. `classified`：已赋予上述五类之一；可同时携带抽查或逐条人工标注任务。
3. `manual_annotation`：尚不能严格赋予五类之一，但已立即创建人工标注任务，任务信息齐全。

第三种是可直接执行的人工工作出口，不是第六业务类，不是待处理池。此时允许 `category=null`，但必须有具体 `annotation_task_id`、任务类型、音频引用、证据和需要回答的问题。禁止只输出 null 类别而不创建任务。

样本守恒：`输入数 = excluded 数 + classified 数 + manual_annotation 数`，三个集合按 sample_id 互斥。已分类样本的审核任务是附属记录，不重复计算样本。

不得导出 `pending_evidence`、`calibration_hold`、待模型补跑、待噪声评分等业务出口。模型/评分失败不能伪造证据；未能自动完成分类的样本直接送标。致命输入契约错误允许流水线明确失败并报告，不得伪造“全部成功”。

## 4. 强制执行顺序

```text
ASR 聚合及身份检查
  → 逐路前置过滤：外语 / 热词全文回声 / 模型提示词全文回声
  → 全部路次被排除？是：excluded，结束
  → 对未被排除路次执行现有语音信箱正则
  → 任意一路命中？是：voicemail，结束
  → 有效中文比较文本与家族证据
  → 按需声学诊断（失败或无证据不等待）
  → 严格 semantic_risk：②幻觉 → ③短音频不可辨 → ①反转
  → 已确认 environment_noise
  → gold_candidate
  → hardcase
  → 其余直接 manual_annotation
```

前置过滤和信箱命中完成前，不得调用样本噪声评分或提前触发其他类别。全路排除及信箱样本均应短路结束。被排除路次可以保留只读审计信息，但不能参与后续特征或触发器。

## 5. 逐路前置过滤



### 5.1 文本视图

- `raw_text`：原始转写，只读。
- `body_text`：剥离全部控制标签后的正文，用于前置匹配及信箱正则。
- `classify_text`：通过前置过滤后去标点、空白等的比较文本。
- `route_disposition=eligible/excluded/failed/missing`：明确区分排除和技术失败；真实成功空输出属于 eligible，其内容状态另记为空。
- `exclusion_reasons`：允许多个原因，但每路只计一次排除。

NFKC、控制标签剥离、标点和空白规范化必须共享实现。排除路次不得通过 raw_text、旧 comparison_text、备用代表或回退选文重新进入决策。

### 5.2 外语

- 存在拉丁或其他非汉字文字内容，整路排除；中外混语同样整路排除。
- 不保留混语里的中文片段凑共识，不保留大写缩写豁免。
- 汉字含简繁及支持的 CJK 扩展；数字按既有业务槽位保留，不视为外语。标点、符号和控制标签不构成外语。
- 记录 `foreign_transcript`。



### 5.3 热词全文回声

- 转写规范化全文等于该路实际热词全文、整表规范化拼接或明确配置的整表序列化形式，整路排除。
- 仅按已知格式去除 `vocabulary:` 等包装，不做任意子串删减。
- 不做子串或模糊匹配；“暂时不需要谢谢”不能因为含“不需要”被排除。
- 正常业务单词与热词表中的某个词相等，不视为整表回声。即使热词表只有一个正常应答词，也不得仅据此误杀该应答；必须有明确的完整回声形式依据。
- 记录 `hotword_echo`。



### 5.4 模型提示词全文回声

- 转写规范化全文等于该模型该路实际内置提示词、prompt、context 或指令正文，整路排除。
- 覆盖本批次所有模型家族，不限于 Qwen。
- 记录 `prompt_echo`，并保存匹配来源及指纹。
- 从 ASR 算子默认模板、批次配置和可用运行元数据建立可追溯的匹配表；不臆造未知内置提示词。
- 历史来源缺失且无法恢复时记录缺口，不能把“没拿到匹配表”冒充“已验证无回声”。受影响且无法可靠过滤的样本直接人工标注；若配置已明确无提示词/热词，则不属于缺失。



### 5.5 过滤后行为

- 外语/回声排除不等于成功空转写，不等于无语音，不等于噪声，不产生 presence conflict。
- 其他未排除家族继续分类；排除不额外增加金标门槛，但也不计支持票。
- 所有配置路次均因上述规则排除，样本 `excluded`，不创建人工任务。
- “部分排除 + 其余失败/缺失”不是全部被前置排除；没有其他合法分类证据时直接人工转写。
- 控制标签/标点独占造成的真实空文本，不自动视为上述三种排除，仍按实际空输出处理。



## 6. 家族证据及通用约束

- 一家族一票；双跑只验证稳定性，不重复投票和抽样。
- 保留每族可用路次、排除路次、失败路次、代表文本和稳定性证据。
- 双跑语义冲突则族内不稳定；只有明确无害字符差异可以视为语义稳定。
- 对配置要求双跑的家族，只剩一条有效路时不能当作已验证稳定的支持家族；该路若提出实质反对内容仍不能被忽略。
- 风险和共识必须保存跨族证据对，禁止直接对全路字符串集合判风险。
- “不知道、嗯、啊、未知语义”不能推导成噪声、肯定或否定。



## 7. 五类规则



### 7.1 voicemail

对所有通过前置过滤的路次，用当前 `voicemail_patterns_v1.yaml` 的完整规则集匹配 body_text 及适配的规范化文本。

任意一路命中即进入，无家族数量、稳定性、上下文或听音门槛。现有宽正则同样生效，不擅自加严、删除或缩小规则范围。

输出命中规则 ID/内容、run_id、family 和原文片段。立即结束，禁止进入其他四类及其人工任务队列。本文不要求为信箱创建逐条标注任务。

### 7.2 gold_candidate

必须同时满足：

1. 至少三个独立、合格、稳定家族有有效中文代表文本。
2. 代表文本两两相等或差异全部明确无害，不使用链式等价合并。
3. 否定、动作、对象、时间、数字、实体和陈述/疑问一致。
4. 未排除的其他中文路次没有实质反对内容、族内肯否冲突或真实空/有字冲突。
5. 不存在需要进一步判定的实际语义或声学疑点。

允许相同称呼位置的“你/您”；“呢/啊”等只允许在确证不改变疑问、请求和肯否时容忍，不全局删除。“需要吗/需要啊”“需要/不需要”不能容错通过。

短句不额外排除；全族一致“不需要”可入。仅模型失败或外语/回声排除不构成反对票，三个合格家族已经成立时不因这些缺口单独送标。

资格判定与选文分离：在合格等价家族代表中加权随机选完整文本，默认 Qwen=2、其他每族=1。三族均合格时为 50%/25%/25%；同族双跑不加权，不拼接新句，不生成新文本。

用固定 seed、sample_id、策略版本生成稳定哈希抽样值；候选排序固定，避免进程随机 hash、分片或输入顺序改变结果。保存家族、run_id、权重、抽样值及版本。

输出抽查任务。批次抽查接纳与逐条人工核验分开，不能把未逐条听音的样本标为 `is_human_verified=true`。发现语义级错误时，受影响规则批次转逐条标注。

### 7.3 semantic_risk

只有三种子类。通用短句标签、旧 false_affirmation/filler_affirmation/rejection_sanitization 标签不能直接赋予主类。宽触发只生成具体人工问题，不能降低下列准入条件。

#### ① semantic_reversal：语义反转

- 不同家族分别稳定输出明确正向和明确负向。
- 主语/动作、对象、时间、条件对齐，差异为否定或明确互斥表达。
- 排除疑问、引用、假设、双重否定、自我纠正及不同对象。
- 自动模板必须完整匹配并定位冲突片段；复杂句不能仅凭全文正负词命中入类。

“我需要这个服务/我不需要这个服务”可入；“不需要贷款/需要保险”“不知道/好的”不可入。文本证据可证明模型输出反转，不代表已判定哪一族正确。

输出 `semantic_risk + semantic_reversal`，创建人工判定正确转写任务。

#### ② hallucinated_assertion：模型幻觉肯定/否定

- 一个家族真实稳定为空或非语音事件，另一独立家族稳定输出明确业务肯定/否定。
- 外语/回声排除绝不能充当空输出家族。
- 音频核验确认目标语音不支持该肯否内容，实际来源为背景噪声、串音或无语音。
- 已排除真实短应答被空输出家族漏识别。

核验依据可以是已存在人工标注或经过校准的独立声学核验；目前未具备时直接人工语义/听音标注，不能用未校准 DNSMOS 替代。人工回填确认后正式赋予此子类。

输出 `semantic_risk + hallucinated_assertion`，标注有效语音或无有效目标语音。

#### ③ short_polarity_ambiguity：短音频肯否不可辨

- 所有有效家族代表文本的最大汉字数 ≤4，不取最短一路；数字槽位继续检查，不能因不计汉字数而忽略其内容。
- 至少一个家族命中“需要/不需要、要/不要、用/不用”等完整应答模板。
- 跨家族存在同一命题肯否冲突，或短应答与真实空输出冲突。
- 音频核验确认真实语音存在，关键否定音节过轻、截断或被掩盖，无法可靠确定肯否。

全族一致短句、普通听不清、单纯音频短均不可入。无需另加未经确认的硬时长准入阈值；音频长度与 VAD 片段作证据，不使用 padding 后时长判断。

输出 `semantic_risk + short_polarity_ambiguity`，标注可辨内容和不可辨位置，不强选肯否标签。

子类冲突时②优先于③优先于①；主子类唯一，可附其他证据。疑点存在但缺乏正式条件，直接人工标注，不阻塞等待新模型结果。

### 7.4 hardcase

- 至少两个未排除的独立家族存在实质分歧。
- 分歧涉及主要内容、动作、对象、实体，或大量非无害编辑；无法形成可靠转写，或存在稳定家族与多数家族显著冲突。
- 未满足严格风险条件，未确认环境噪声。
- 实现必须提供可审计的分歧片段/槽位；字符距离只作辅助，不能单凭相似度低就归类。

少量未确认等价字符、失败、有效家族不足、全空输出不能单独入类。不得作为所有剩余样本的兜底。输出 `hardcase` 并直接创建人工转写任务；有肯否疑点时附加语义问题。

### 7.5 environment_noise

- 经校准声学诊断或人工听音确认主要为环境背景音/串音，缺少可可靠转写的目标语音。
- 全空、外语/回声排除、低 DNSMOS、VAD 未检出均不能单独决定入类。
- 背景嘈杂但目标语音清楚不入类。
- 满足幻觉②时主类归 semantic_risk，噪声仅为附属属性。

输出 `environment_noise`，属性为 background/crosstalk/mixed；记录可辨目标语音或无有效目标语音。DNSMOS 提供质量证据，不能独自判定目标说话人归属或串音内容。

## 8. 直接人工标注与回填闭环

仅对通过前置排除、未命中信箱且无法自动完成严格判定的样本，立即生成任务：

- 少量字符分歧或家族不足：`transcribe`。
- 疑似肯否风险：`resolve_semantics`，必要时同时转写。
- 真实全空、空/有字冲突、疑似串音：`verify_target_speech`。
- 音频损坏/不可辨：允许标注 `invalid_audio/unintelligible`，不强行伪造文本或噪声类别。

任务包必须携带 sample_id、可用音频引用、原始多族转写、逐路排除理由、冲突片段、明确问题、已存在声学证据。排除原文可供审计查看，但不得预先作为投票或正确答案。

同一样本多个问题合并为一个标注任务，防止重复听音。导入应幂等，不重复创建任务，不因再次分拣覆盖人工答案。

回填可输出正确转写、是否存在目标语音、语义子类、噪声属性、不可辨片段。人工纠正得到的金标记录到现有人工 gold 契约，不必强改为“多模型高一致”的 gold_candidate。历史 high-disagreement 可保留为样本来源属性。不能要求所有人工完成样本最终强塞入某一自动业务类别。

## 9. 噪声诊断调整

- 删除新策略中“外语转写触发评分”的决策用途；外语已经退出，不得绕回噪声流程。
- 仅对未排除、非信箱样本中的真实空/有字冲突、肯否短句冲突、显式非语音事件和可信串音信号按需诊断。
- 不全量强制评分；未触发评分不影响正常高一致金标资格。
- 存在待核验的真实冲突时，不能仅因缺评分把样本送入金标；直接人工任务。
- DNSMOS 模型缺失、失败、未校准均不得解释为噪声。保留错误并送标，不输出等待评分队列。
- 缓存包括音频哈希、模型/预处理版本；新策略版本需要参与分类缓存失效，不能复用旧分类标签。



## 10. 工程改造与交付



### 10.1 优先核查的模块

- `selection_v3/classify_text.py`、`input_contract.py`：独立 excluded 路次契约、统一前处理。
- `family_evidence.py`、`consensus.py`：一族一票和剩余证据完整性。
- `classifier.py` 及其他策略分发：前置排除和信箱优先短路。
- `semantic_risk.py`：新严格谓词模块或策略分支，禁止沿用旧标签直接定类。
- `noise_trigger.py`、`acoustic_evidence.py`、质量算子：删除排除路次触发链，补人工出口。
- `gold_select.py`：资格判断后的加权可复现选文。
- `result.py`、`types.py`、`review_router.py`、annotation_v3 和 dataset_v3 消费者：五类、排除、直接人工任务及回填。

## 11. 自动化验收用例

以下必须同时覆盖单元及必要的端到端路径，重点验证真实失败模式和出口契约：

1. 外文、混语、大写缩写含外文路次被排除，不变成成功空票。
2. 去标签、标点、空白后精确等于提示词/整表热词可排除；正常单个“不需要”及部分匹配不误杀。
3. 被排除路次包含信箱关键词，不能触发信箱；另一有效路次命中则触发。
4. 全路排除输出 excluded，零分类、零噪声调用、零人工任务。
5. 部分排除、其余失败不冒充全路排除，直接人工任务。
6. 任一有效路次信箱命中，即使其他族肯否冲突、噪声或高分歧，也只能输出 voicemail；零后续噪声调用、零其他类任务。
7. 现有宽信箱正则任一路命中仍生效，不新增多族门槛。
8. 三个稳定家族一致、第四族外语/回声排除，可入金标；只剩两个支持家族则人工转写。
9. 三个稳定家族一致，另一路有效中文明确反对，不能忽略反对后选金标。
10. “你好/您好”允许；“需要吗/需要啊”“需要/不需要”不容错。
11. 同族双跑正反不自动判跨族反转；跨族同命题稳定正反可判①。
12. “不知道/好的”“嗯/好”“不需要贷款/需要保险”不自动判风险①②。
13. 外语排除族与肯定族并存不能触发空/有字幻觉；真实空族与肯定族无音频证据时直接人工。
14. 已核验背景噪声幻觉判②；真实短应答但某族漏识别不判②。
15. 全族一致“不需要”不判③；最大代表长度超过四汉字不能用最短一路判③。
16. 满足短应答冲突且关键否定音节不可辨判③；一般听不清不判③。
17. 噪声低分、全空、VAD 未检出不能单独判环境噪声；评分失败不产生待处理池。
18. 实质多族分歧归 hardcase；家族不足或少量未解释字符差异直接人工，不滥入 hardcase。
19. 同 seed/样本/版本加权选文可复现，不受分片、顺序、双跑数影响；抽样区间严格对应配置权重，Qwen 不合格不得获选。
20. 输出仅五种业务类别，三个出口互斥且 ID 守恒；所有 manual_annotation 均有可执行任务，禁止裸 null 结果。
21. 标注任务幂等导出/导入，不能覆盖人标；无效/不可辨允许完成，不能强行制造文本。
22. 新旧缓存和产物隔离，legacy 回退仍可复现。



## 12. 验证交付与完成条件

- 先运行相关规则与契约测试，再跑小规模端到端 fixture，覆盖前置排除、信箱短路、五类及人工出口。
- 环境和输入可用时，复用已有 ASR 跑 0914 新策略影子，对照旧结果；不为完成报告重跑 ASR。
- 报告输入总数、三出口数、五类数、逐路排除原因、人工任务数/类型、风险子类数、评分调用与失败数、旧新迁移。
- 人工任务较多时应定位主要原因并检查是否有实现缺陷或无谓重复；不能通过放宽风险、噪声或 hardcase 条件来减少人工量。
- 规则测试通过不等于声学精度验收。未听音、缺校准或缺模型必须如实报告，不能声称风险精确率或噪声精度已达标。
- 自动化可完成的代码、配置、测试、任务导出/回填及文档应完整交付；需要人工事实判断的样本以可执行任务完成分流，不以“等待补证据”结束流水线。
