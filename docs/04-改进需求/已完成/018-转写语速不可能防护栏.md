## 1. 当前事实（结论）

### 1.1 脏数据是真的，但不是「真人口语一万字」

本机 `prepared_asr_v3_0908-30000` 抽查（2026-09-10）：

| 项 | 事实 |
| --- | --- |
| 比较文本 ≥1 万字的样本 | ≈ **613**（相关路由 ≈951） |
| 主要来源 | **几乎全是** `glm-asr-1` / `glm-asr-2`（Qwen 仅偶发） |
| 音频时长 | 中位约 **3.1s**（短片段） |
| 字率 | 中位约 **4400 字/秒**，极端可到十万级 |
| 文本形态 | 英文套话 / 假「speech transcript」长文，如 `The following is a transcription of the speech...` |

结论：表里的「超长转写」是 **ASR 跑飞/幻觉**，不是清洗漏掉的长音频。

### 1.2 现行①清洗做了什么、没做什么

`data_cleaning_source_A` 文件头写死：

> **只做音频质量，不做标注决策**

实际 DAG：

```text
ingest → pcm_to_wav → resample_16k → probe(broken) → filter(duration>0) → select(audio_pass)
```

| 有 | 无 |
| --- | --- |
| 解码失败 → `broken` | VAD / 静音检测（设计上不做） |
| `duration > 0` | **任何 transcript / 语速 / chars_per_sec** |
| 仅 `audio_pass` 进 `cleaned_*` | ASR 幻觉、超长文本、多模型一致性 |

DNSMOS 也不在清洗主路径（侧车，见 009 / 016）。

### 1.3 为什么没有「人类语速不可能」防护栏？（根因，不是漏写一行 filter）

**主因：时序。** ①清洗发生在多 ASR **之前**，当时没有转写，算不出 `len(text) / duration`。

```text
① cleaned_*（仅音频）
  → ② 多 ASR
  → prepare / attach_asr / quality_sidecar
  → ③ classify_dataset_v3   ← 这里才同时有 duration + 各路 transcript
```

**其它设计原因：**

| 原因 | 证据 / 含义 |
| --- | --- |
| 职责边界刻意收窄 | 清洗文档与 YAML：「只做音频质量，不做标注决策」 |
| 「空白」只等于 `duration==0` | 不做 VAD；人声有无留给后段规则 |
| 挑选规则未定义字率栏 | v3 有空转写 / 族不稳定 / 语义冲突等桶，**没有** max chars/sec |
| 幻觉靠「空 vs 非空 / 族共识」间接打 | 多族若共识同一段胡话，仍可能进 `pseudo_high`（字率漏洞） |

因此：**不是清洗引擎「忘了写语速 filter」，而是①层按设计根本看不到 ASR 文本。**  
若把防护硬塞进①音频清洗，会破坏边界，且对已跑完清洗、事后 GLM 跑飞的批次**拦不住**。

### 1.4 与「重构清洗引擎」的关系（本需求口径）

用户诉求是：在质量链路里**标出并剔除**语速不可能的数据。  
本需求接受该诉求，但**纠正落点**：

- **不要**重构① `pcm → resample → probe → audio_pass` 去算语速。
- **要**扩展工序一的「数据质量防护」：在 **ASR 附着之后、分拣自动放行之前** 增加可配置的字率栏，打标 + 禁止进伪金标/自动训练池。
- 若产品语言仍称「清洗引擎」，指的是 **Manifest 质量算子体系 / 工序一质量闸门**，不是狭义音频清洗 DAG。

## 2. 我想做什么

增加一道**物理不可能语速**防护：

1. 对每条样本、每一路（或每族代表）转写，计算  
   `chars_per_sec = len(comparison_text) / duration_sec`（`duration<=0` 已由既有 invalid 路径处理）。
2. 超过可配置上限 → 打标（如 `implausible_speech_rate` / risk tag），并在分拣中：
   - **不得**进入 `pseudo_high` / `pseudo_medium` 自动训练池；
   - 默认进 `manual_review`（或显式 `exclude`，由配置二选一，须写清默认）。
3. 单路超限 vs 多路同时超限的行为可配置（例如：仅单路 GLM 跑飞 → 该路作废/族不稳定；多路共识超长胡话 → 整样本审查）。
4. 与 `short_utterance` **正交**：现有是「太短」；本栏是「相对时长太长」。
5. 顺带服务 [017](./017-v3分拣加速.md) / [019](../已完成/019-Levenshtein原生加速.md)：超长对在编辑距离前短路（即便已用 `rapidfuzz`，调用次数与极端长度仍值得省；**语义裁决以本需求为准**）。

推荐落点（按优先级）：

| 优先级 | 落点 | 作用 |
| --- | --- | --- |
| P0 | `classify_dataset_v3` 规则最前段 | 已有 duration + 全路文本；直接改桶，防伪高 |
| P1 | attach 后写诊断字段 / 轻量 sidecar | 如 `max_chars_per_sec`、`implausible_routes`；**裁决仍在 classify**（类比 DNSMOS→risk） |
| 不做 | 改①音频清洗 YAML 依赖 ASR | 时序不可能；破坏「只做音频」契约 |

可选增强（非必须）：ASR batch 出口写 `text_len` / 告警 metrics，便于早发现某模型系统性跑飞（如本批 GLM）。

## 3. 数据从哪来、结果要什么

- **输入**：已有 `duration` 的样本 + 各路 ASR transcript（典型：`prepared_asr_v3_*` 进入 classify；或 attach 完成后的等价表）。
- **输出**：
  - 样本级标签 / type / decision（或 risk_tags）标明语速不可能；
  - 分拣报告 / metrics 中有计数（如 `implausible_speech_rate_count`、按模型/族分布）；
  - 自动训练候选中**不再出现**这类样本。
- **规模**：`0908-30000` 已证明约 2% 量级可中招；其它批次比例可能不同。

## 4. 业务上有哪些规矩

1. **阈值可配置、可校准**：须给出初始默认（例如中文场景先用偏严上限，再按听审池校准）；禁止魔法数写死在无文档处。
2. **比较文本口径**与 v3 一致：用 `comparison_text`（或明确写 raw）；空文本不走本栏。
3. **不误伤正常长句**：长音频 + 合理字率应放行；只打「相对时长不可能」。
4. **不替代**现有 `family_unstable` / `speech_presence_disagreement` / `semantic_risk`；本栏是物理先验。
5. **默认剔除自动池**：进审查或 exclude；**禁止**静默当 `pseudo_high`。
6. **文档必须写清**：语速栏在 **ASR 之后的质量闸门 / 分拣**，不在①音频清洗；避免以后再提「清洗漏了语速」。
7. 与 [017](./017-v3分拣加速.md) / [019](../已完成/019-Levenshtein原生加速.md)：允许对超限文本跳过或限制编辑距离比较，但分桶结果须与「先裁决再加速」一致（019 已换 `rapidfuzz`，本栏仍先短路）。
