### 1.2 semantic_risk 过宽的代码原因

[semantic_risk.py](../../../src/audio_engine/core/selection_v3/semantic_risk.py)存在以下条件：

- `false_affirmation`：一条 positive 与一条 unknown 等非肯定文本并存，即可能触发；没有要求后者确实是噪声，也没有要求音频证据。
- `filler_affirmation`：语气词与肯定词并存即触发；真实“嗯/好”差异不能直接证明幻觉。
- `negation_flip`：按全文正负词汇判定，没有充分约束两段文本是否在谈同一动作、对象、时间和否定范围。
- `classifier.py`向风险模块传入全部有效路次文本。风险模块不接收家族身份，因此单一家族双跑的差异也可能触发主类，不能保证是独立家族间分歧。
- 主分类器只要命中 `SEMANTIC_RISK_TAGS` 就提前返回，早于语音信箱和后续共识。集合包含反转、幻觉肯定、语气词肯定、拒绝美化四种标签。

需要纠正一个可能的误解：当前短句配置为音频 2 秒、文本 6 字，但 `short_utterance` 标签本身不在 `SEMANTIC_RISK_TAGS` 中。短音频混入风险池，不能简单归因于“短句直接入类”，应检查同条触发的肯定/否定规则。

### 1.3 噪声、选文和语音信箱现状

- [噪声触发器](../../../src/audio_engine/core/selection_v3/noise_trigger.py)主要针对全族无有效转写或出现非中文正文。一个家族空、另一个家族中文肯定的样本不一定触发评分，存在诊断缺口。
- [噪声算子](../../../src/audio_engine/operators/quality/asr_anomaly_noise.py)当前强制未校准模式，并拒绝 `calibrated=true`；[DNSMOS 配置](../../../configs/quality/dnsmos_p835.yaml)也为未校准。不能将“评分成功”当成“已证实环境噪声”，更不能据此认定串音或幻觉。
- [已有容错选文](../../../src/audio_engine/core/selection_v3/gold_select.py)使用平均距离、相同文本支持数、家族顺序确定性选文，并非 Qwen 加权随机。生产主分类器还有自己的共识选文路径，新方案应统一出口。
- [现有语音信箱正则](../../../configs/selection/voicemail_patterns_v1.yaml)同时包含电话助手、无法接通、IVR、转接等。当前主分类器要求至少两个稳定家族且各自双路命中。本文保留这套业务覆盖范围，主类统一叫“语音信箱”，不再拆分助手类别。

以上为静态代码与配置检查结论，不代表已测得最近三万条各类误报数量。

## 2. 目标输出：只保留五个业务主类

1. `gold_candidate`：简单抽查即可决定是否接纳的高一致候选。
2. `semantic_risk`：严格限定的语义风险，子类只有 `semantic_reversal`、`hallucinated_assertion`、`short_polarity_ambiguity`。
3. `hardcase`：多家族文本或语义高度不一致，无法形成可靠共识。
4. `environment_noise`：环境背景音、人声串音等有音频证据的噪声样本。
5. `voicemail`：现有正则覆盖的语音信箱、电话助手等。

不把失败重试、证据缺失、家族不完整再做成业务类别。另设 `processing_status=ready/pending_evidence/retry/excluded`；未满足任何类别条件时 `category=null`，留在待处理清单。它不是第六类，也不能为了凑满五类而塞进 hardcase 或噪声。

样本守恒口径：五类已判定样本 + 未定类待处理/失败/无效样本 = 输入样本，按 ID 去重且互斥。允许严格规则暂时无法定类，禁止静默丢弃。

## 3. 统一前处理与家族证据

### 3.1 新流水线顺序

音频清洗 → 多模型 ASR → 聚合与身份校验 → **全部路次文本前处理** → 家族内稳定性与家族间证据 → 按候选触发声学诊断 → 五类判定 → 选文/抽查/严格复核。

每路保留三个文本字段：

- `raw_text`：原始输出，只读。
- `display_text`：去控制标签，供复核看，允许中文标点。
- `classify_text`：统一比较文本，所有共识、风险、长度和选文资格只读这一字段。

处理顺序：保留去标签正文快照 → NFKC → 提示词/热词整表精确匹配 → 去标点、符号、空白 → 外文检测 → 输出汉字和业务数字。空路同时记录 `empty_reason`。

新策略采用严格外文口径：出现拉丁或其他非汉字文字则整路置空，混语不保留其中中文来凑共识；包括现有大写缩写例外，需在新版本显式关闭。数字保留为金额、号码等槽位，这是沿用 025 的明确业务例外；数字差异不能当无害字符。短句长度只数汉字，同时保留数字槽位冲突判断。

注意：`不/没/无/别/未/好/行/嗯` 不属于要清除的字符。“不需要”命中热词表中的一个词不能置空，只允许全文提示词或整表回声命中。语言判别、噪声触发继续能读取筛除前快照；纯外文置空不等于实际无语音。

### 3.2 一家族一票

- 同家族双跑用于判断稳定性，不增加独立票数。
- 每族保留 `stable_text/stable_empty/unstable/failed` 等证据状态；失败和清洗置空都不能冒充“模型识别为噪声”。
- 风险判断要求记录具体的跨家族证据对及对齐片段，不再把六路字符串混在一起触发标签。
- 默认高一致金标要求至少三个独立家族，并且所有配置家族均完整、族内稳定、族间通过等价检查。缺一个家族不能降低分母自动过关。
- 同族两路只在无害字符上不同可视为语义稳定；否定、数字或关键实体不同则不稳定。

## 4. 五类的严格规则

### 4.1 gold_candidate：高一致、只容忍明确无害差异

必须同时满足：

1. 第 3.2 节的完整性与家族数要求成立，所有家族均有有效中文转写。
2. 所有家族代表文本两两等价，不能用链式聚类把 A≈B、B≈C、A≠C 合成一簇。
3. 每个差异都被白名单解释：例如相同称呼位置“你/您”；句末“呢/啊”仅在陈述/疑问性质、请求意图和语气不变时允许。不能全局删除“呢/啊”，也不能将“需要吗/需要啊”判成相同肯定。
4. 否定范围、动作、对象、时间、金额、号码、关键实体、陈述/疑问全部一致；不使用单纯相似度阈值覆盖这些约束。
5. 不存在未解决的空/有字、音频归属或疑似幻觉证据；未命中语音信箱及严格风险规则。

初始建议：允许的无害编辑数不超过 2 且不超过较长文本长度的 10%（向上取整，至少允许 1）；这是待校准上限，白名单是必要条件。超限不自动判语义风险，保留一般分歧证据。

**加权随机选文：** 资格判定结束后再抽家族，建议 Qwen 权重 2，其他各 1；三族时概率为 50%/25%/25%。每族先固定一个合格代表，防止双跑翻倍。只从等价候选中抽取，不拼接或生成新句子。保存家族、run_id、权重、抽样值及策略版本。

采用可复现的伪随机：用固定种子、sample_id、策略版本生成稳定 SHA-256 值，按排序后的家族累计权重区间抽样。同一输入与版本不因分片、输入顺序或重跑而换标签。Qwen 不合格时不能凭权重获选；完整性未满足时整个样本不进入此类。

本类先为 `audit_pending`。抽查通过后可按项目约定接纳为批次金标，但未逐条听音的样本不能写 `is_human_verified=true`，需保留 `batch_audit_passed` 与模型选文来源。

### 4.2 semantic_risk：三个严格子类

统一原则：**候选触发与正式入类分开**。宽规则只触发补证据；只有以下某个完整谓词成立才入类。没有证据时返回待处理，不拿 unknown 充当否定、噪声或反转。文本只能证明模型输出互相矛盾，不能单独证明真实音频里的“不”过轻或模型确实幻觉。

#### ① semantic_reversal：同一命题正反冲突

全部满足：

- 两个不同家族各自稳定输出明确正向与明确负向。
- 对齐后主语、动作、对象、时间、条件及其他业务槽位一致；差异定位在否定表达或明确互斥动作上。
- 使用完整短语和否定作用域匹配，不按“含需要/含不”判断；疑问、引用、假设、双重否定、转述、自我纠正先判不确定。
- 对齐模板覆盖不了的复杂句只作候选，需结构化复核或听音确认命题关系后入类。

正例：“我需要这个服务”与“我不需要这个服务”。反例：“不需要贷款”与“需要保险”是对象不同；“不知道”与“好的”没有相同命题；所有家族都说“不是不需要”没有跨族冲突。

#### ② hallucinated_assertion：噪声/串音上的肯定或否定幻觉

此处按需求覆盖肯定和否定，中文展示可写“模型幻觉肯定/否定”。全部满足：

- 至少一个家族双路稳定为空或输出显式非语音事件；保留来源。因外文/回声而置空只能算待核实的空路证据。
- 另一独立家族稳定输出明确业务肯定或否定，不是孤立“啊/嗯”，也不是含肯定词的长段无关内容。
- 对同一音频片段完成独立声学核验：存在噪声/串音，且目标说话人的可懂语音不能支持该肯定/否定。初期以听音为准，后续只有经过校准的核验器才可替代。
- 核验结果明确排除“目标说话人确实说了短句，只是某家族漏识别”。

“一族空、一族需要”只触发诊断，不足以正式入类。DNSMOS 低分也不能单独证明幻觉；如果是目标说话人的真实肯定，即使背景很吵，也不属于本子类。

#### ③ short_polarity_ambiguity：短片段中否定词不可判定

全部满足：

- 所有有效家族代表文本的最大汉字数 ≤4，而不是取最短一条；至少一个家族命中完整的“需要/不需要、要/不要、用/不用”等版本化应答模板。
- 不同家族存在同一命题正负分歧，或稳定短应答与稳定空路分歧；全族一致“不需要”不能仅因短而入风险类。
- 原始有效语音段较短，初始诊断参考值为 ≤1.5 秒，需校准；采用原始音频/VAD 有效片段，不能用模型 padding 后时长。
- 听音或已校准局部核验明确表明“不”等关键音节微弱、截断或被掩盖，无法可靠确定肯否。只有短、只有听不清、只有识别不一致都不够。

若听音清楚、只是模型正反不一，归①；若已证实只有噪声/串音并产生肯否转写，归②；若真实语音存在但关键否定音节无法判定，归③。允许保留多项证据标签，但主子类仅一个，按②→③→①选择最具体证据解释。

### 4.3 hardcase：高度不一致

至少两个可用独立家族输出有实质差异，且不能通过无害编辑等价检查，并满足以下任一项：

- 主要动作、对象、实体或内容主题不同，无法组成可靠文本共识。
- 无唯一占优等价簇，或某个家族稳定输出与其他家族大幅冲突。
- 初始字符距离参考：至少一对稳定家族代表归一化编辑距离 ≥0.30，并有非白名单差异；阈值需结合长度校准，不能覆盖已命中的严格风险规则。

单一家族失败、全族为空、仅一处不在白名单中的近义表达，不直接归 hardcase。前两者补证据，后者先扩展等价核验。宁可暂不定类，也不把 hardcase 做成所有剩余样本的垃圾桶。

### 4.4 environment_noise：音频证据决定

进入条件：经校准声学诊断或听音确认以环境背景音、人声串音为主，缺少可可靠转写的目标语音，或目标语音被严重掩盖；并且不满足②的具体肯否幻觉条件。

保留 `noise_kind=background/crosstalk/mixed` 作为属性。可懂、归属明确的目标语音不能仅因低分被移到噪声类。全空转写、非中文转写、低 DNSMOS、VAD 无检出单独都不充分。

诊断组合：DNSMOS SIG/BAK/OVRL 提供质量证据，VAD 提供语音片段信息，串音需要重叠说话/来源归属证据或听音。当前仓库的评分不能直接承担完整串音与目标说话人归属判断。

### 4.5 voicemail：沿用现有正则覆盖

使用现有正则，至少两个稳定家族各双路命中，匹配对象为通过前处理的有效文本。命中词、正则 ID、家族与 run_id 全部保留；“我是机主”“人工服务”等宽表达保持既有覆盖，但作为抽查重点，不宣称正则等于声学确认。

在结构化语义判断前隔离此类，避免自动播报里的“需要/不需要”进入业务意图风险池。只有一个家族命中则不立即隔离，继续核验。

## 5. 决策顺序与噪声诊断补齐

正式顺序：技术有效性 → 统一文本前处理 → 家族证据 → 高置信语音信箱 → 严格语义风险②/③/① → 已证实环境噪声 → 高一致金标候选 → 高分歧 hardcase → 未定类待补证据。

各类证据可先并行计算，最终仅提交一个主类。处理状态独立保存。对疑似风险尚待音频核验的样本，不得跳过未解决证据直接接纳金标。

扩展现有按需诊断触发项：

- 保留筛除前非中文、全族无有效转写。
- 新增跨家族空/有字且有明确肯否。
- 新增 ≤4 字应答模板的跨族肯否分歧。
- 新增稳定语音存在性冲突、显式非语音事件及可信串音信号。

不要求全量重跑 DNSMOS。缓存键包含音频哈希、模型版本和预处理版本。评分失败进入 `pending_evidence` 或重试；缺评分不解释为噪声。新校准策略需要独立版本及实现，不能只把当前配置改成 true 绕过算子限制。

## 7. 验证与验收

### 7.1 必须覆盖的规则案例

- 标签与标点独占的输出变空；中英混语整路空；数字槽位保留；“不需要”不被热词单项误杀。
- 家族仅“你好/您好”无害不同可入金标候选；“需要吗/需要啊”“需要/不需要”不能靠字符容错过关。
- 同一家族一正一负、其他家族未知，不自动判跨族反转。
- “不知道/好的”“嗯/好”不自动判幻觉肯定；两家族同命题稳定正反可判①。
- 一族空、一族“需要”，无声学核验时未定类；证实噪声幻觉后判②；证实真实短应答后排除②。
- 全族一致“不需要”不因 ≤4 字入风险；短音频只是“喂/谁啊”不入③。
- 短音频关键“不”不可判定且符合跨族条件时判③；有长转写家族时不能取最短一路冒充短句。
- 全空但未评分不定噪声；纯背景噪声获确认后归环境噪声；目标语音清楚且低分不自动归噪声。
- 多族语音助手匹配优先隔离；正则命中证据完整。
- 固定种子选文可复现、分片顺序不影响结果、同族双跑不增权、Qwen 权重只改变合格候选中的抽样概率。
- 每条仅一个主类，待处理不丢失，旧产物不被覆盖。

### 7.2 听音校准与报告

从旧风险类、旧金标类、空/有字冲突、短句、噪声及语音信箱分别分层抽取；校准集与最终验收集按音频身份隔离。新风险类在首轮影子中全部听音复核，存在争议时由第二人复核，不能凭规则自身输出当真值。

验收重点是每个子类的精确率，不追求风险类数量。建议目标：独立验收集各子类精确率的单侧 95% 置信下界 ≥95%；少样本类别标为证据不足。例如某子类 59 条独立样本零误报，精确率单侧精确二项下界约为 95%，不能用三五条零误报宣称高精度。全部命中与已证实真风险分别计数，报告灰区和不确定复核结果。

金标候选按家族选文、长度、差异类型分层抽查，首轮建议至少 300 条；发现语义级错误则暂停该规则批次接纳并修正规则。样本量不够时全检。零误报也不是绝对正确证明，需报告样本量及误差上界。

交付影子报告应包含：五类数量、未定类数量及原因、旧新迁移、风险逐子类误报、金标语义错误、噪声判定精度、噪声评分调用数和缓存命中。召回只在人工标注的对照样本上估计，不能以类别缩水比例代替。
