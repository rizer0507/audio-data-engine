---

## 1. 我想做什么

工序一里，多模型家族识别（默认 Qwen / GLM / SenseVoice，每族 `--asr-run` 双跑）已经跑完之后，我需要一个**统一入口脚本（或 CLI）**，从「已有六路 ASR 结果」开始，严格复用当前工序一③使用的分类引擎（五类 v2.2 + `audio_energy` + DNSMOS 联合判定），最终交付一份**完整分类 XLSX**。

它应当默认「本 batch 的多家族识别结果已经存在」；若有缺失，必须**按家族、按路次**把缺什么说清楚，而不是只抛一个含糊路径错误后退出。

## 2. 数据从哪来、结果要什么

### 2.1 输入（我怎么传）


| 参数                          | 含义                    | 约定                                                           |
| --------------------------- | --------------------- | ------------------------------------------------------------ |
| `--batch` / `--source-name` | 与各家族推理时传入的同一 batch    | 校验规则同现有 `validate_source_name`                               |
| 家族与双跑别名                     | 推理时各路 `--asr-run` 的别名 | 必须逐字一致（含下划线/横线）                                              |
| cleaned 底表                  | 该 batch 的完整清洗底表       | 默认 `datasets/stage1/cleaned/cleaned_${BATCH}.parquet`        |
| ASR 目录                      | 六路结果所在目录              | 默认 `datasets/stage1/asr/`，文件名 `{alias}_asr_${BATCH}.parquet` |


**别名解析优先级（实现时必须写死）：**

1. 命令行显式传入的家族双跑映射（推荐形态：`--family qwen=qwen_1,qwen_2`，可重复三次）；或等价的 `--asr-run` 列表若采用更贴近推理命令的写法。
2. 若存在批次 dataset 配置（如 `configs/datasets/zh_asr_v3_<batch>.yaml` 的 `model_families`），从其读取。
3. 若以上皆无：回落到工序一 stage1 固定别名（与 `cache_policy.FAMILY_RUN_ALIASES` 一致）：

```text
qwen:       qwen_1, qwen_2
glm:        glm_1, glm_2
sensevoice: sensevoice_1, sensevoice_2
```

历史批次（如 `qwen-basr-1`）**不得静默猜测**；没有配置/显式映射时，按缺失报错并提示如何传入。

### 2.2 前置存在性检查（必须详细）

启动分类引擎前，先做一次只读体检，失败时**非零退出**，报告至少包含：

1. **cleaned 底表**：路径、是否存在、是否为空、是否每条有 `original_audio_sha256`、`resampled_16k` 是否可读（抽样或全量按现有契约）。
2. **按家族汇总的 ASR 路次**：对每个期望家族列出两路别名，分别标注「存在 / 缺失」及期望路径。
3. **缺失摘要**：例如「家族 glm 整族缺失（glm_1、glm_2 均不存在）」「家族 qwen 缺第二路 qwen_2」。
4. **不要**在缺路时仍进入聚合/分类（避免半套结果被当成完整交付）。

示例期望报错形态（文案可微调，信息量不可降）：

```text
错误: batch=demo-batch 分类前置检查失败，缺少以下 ASR 结果：
  [qwen] qwen_1     OK   datasets/stage1/asr/qwen_1_asr_demo-batch.parquet
  [qwen] qwen_2     缺失 datasets/stage1/asr/qwen_2_asr_demo-batch.parquet
  [glm]  glm_1      OK   ...
  [glm]  glm_2      OK   ...
  [sensevoice] sensevoice_1 缺失 ...
  [sensevoice] sensevoice_2 缺失 ...
摘要: 缺失家族 sensevoice（两路皆无）；家族 qwen 缺路次 qwen_2。
请确认推理时 --source-name/--batch 与 --asr-run 是否与上表别名逐字一致。
```

### 2.3 输出（我要什么）

严格走工序一同一套引擎语义，得到**一份完整分类 XLSX**：


| 项    | 要求                                                                                                                  |
| ---- | ------------------------------------------------------------------------------------------------------------------- |
| 引擎   | 五类 v2.2：`audio_energy` → `dnsmos_v2_2_candidates` → `classify`（`selection_five_class_v2_2_auto_noise`）              |
| 业务五类 | `voicemail` / `semantic_risk` / `environment_noise` / `gold_candidate` / `hardcase`；`excluded` 保留原因，不是第六业务类         |
| 工作簿  | 至少含「分类统计」+「分类明细」；明细列契约对齐正式 `review export-summary`（含六路文本、家族四态、能量、DNSMOS、原因等）                                        |
| 默认路径 | 建议与正式交付对齐：`data/exports/summary_five_class_v2_2_auto_noise_${BATCH}.xlsx`（若实现选择兼容旧脚本名，须在帮助与手册中写清，并可用 `--output` 覆盖） |
| 行数守恒 | 相对 cleaned 底表 ID + 原音频哈希守恒；分类桶齐全                                                                                    |
| 原子写入 | 成功对账后再替换目标文件；默认不覆盖已有输出，除非显式 `--overwrite`                                                                           |


**可选增强（本需求鼓励，不阻塞最小交付）：**  
同时落盘正式中间表 `datasets/stage1/derived/classified_five_class_v2_2_auto_noise_${BATCH}.parquet`，便于后续 `review export-summary` 复跑与训评衔接。若不落盘，须在文档标明「仅交付 XLSX、不写正式 classified parquet」。

## 3. 业务上有哪些规矩

1. **深度贴合工序一**：起点是「多家族 ASR 完成之后」；禁止在本入口内启动 vLLM / SenseVoice / 任何 ASR pipeline。
2. **双跑必须纳入**：每个家族两路 `--asr-run` 都要参与聚合与投票；同族最多一票的引擎规则不得绕过。
3. **三族为默认契约**：与 stage1 一致时为 Qwen + GLM + SenseVoice；规则模板仍以 `qwen` 为 `target_family`，三族中须含 qwen。若未来扩展第四族，不在本需求强制范围。
4. **不伪造正式身份**：本入口可以完成分类交付；不自动 `register-asr-run`、不做 reservation/release。需要正式发布时仍走原流程。
5. **与现有脚本关系**：仓库已有 `scripts/classify_asr_to_xlsx.py`。本需求优先**收敛为统一入口**（增强该脚本，和/或增加 `audio-data stage1 classify` / 等价 CLI 并复用同一实现），避免再出现第三套半兼容路径。
6. **产物命名**：正式 stem / XLSX 命名不得与 v2 / v1 / legacy v3 互相覆盖。

```bash
# 工序一固定别名（stage1 双跑后最常见）

# 或未来 CLI：

# 历史/手工双跑别名

  --batch "$BATCH" \
  --source-dir "$SOURCE_DIR" \

  --family glm=glm-base-1,glm-base-2 \
  --family sensevoice=sv-base-1,sv-base-2
```
