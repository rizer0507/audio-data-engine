## 1. 我想做什么

把 v3 输入契约从：

```text
恰好 4 个模型族 × 每族 2 跑 = 8 路（缺一不可）
```

改为：

```text
N 个模型族（N ≥ 3）× 每族 2 跑 = 2N 路（配置声明多少就校验多少）
```

清洗与分拣主路径在只具备三族（或三族以上）时仍走：

```text
prepare_dataset_v3
  → ASR（已声明各族双跑）+ register-asr-run
  → attach_asr_v3
  → audio_quality_sidecar
  → classify_dataset_v3
  → …
```

**四族八路仍是推荐上限配置之一**，但不再是进入 v3 的最低门票。

## 2. 数据从哪来、结果要什么

### 2.1 最低合法输入

| 项 | 要求 |
| --- | --- |
| 模型族数 `N` | **≥ 3**（含 `target_family`） |
| 每族跑数 | 仍为 **2**（同族双跑只计一票的规则不变） |
| 总 ASR 路数 | **恰好 2N**（配置声明与落盘/register 一致） |
| teacher | 默认 = `model_families \ {target_family}`，即 **N−1** 个 teacher；三族时 teacher=2，四族时 teacher=3 |
| 底表 / 侧车 | 与 014 相同：`cleaned_*`（或等价）、DNSMOS 侧车可按环境跑 |

### 2.2 对 `0908-30000` 的期望

在别名与 catalog 按 014 对齐后，下列三族六路即为合法 v3 输入，**不要求补 Kimi**：

- `qwen`：`qwen_1` / `qwen_2`（或映射后的 `qwen3-asr-1` / `qwen3-asr-2`）
- `glm`：`glm_1` / `glm_2`
- `sensevoice`：`sensevoice_1` / `sensevoice_2`

产出：`classified_v3_0908-30000.parquet` 等，与四族批次同一套字段语义（共识比例相对「已配置族数」归一，而不是写死 `/4`）。

### 2.3 非法输入（仍须 fail-fast）

- `N < 3`
- 某族不是恰好 2 跑、别名跨族重复、缺 register / 缺 digest
- 配置声明了某族但缺 parquet（或反过来多出路未声明）
- 用「少一路就当三族」的静默裁剪——必须以配置显式声明参与家族

## 3. 业务规矩

1. **下限 3 族，不设必须 4 族**；允许 3、4、或经批准的更多族（若实现上暂只测到 4，文档写清上限与扩展点）。
2. **每族双跑不变**：同族两次推理用于不稳定性，最多计一票。
3. **全量共识 / pseudo_high**：条件从「四个家族全部 stable」改为「**配置内全部 N 个家族**全部 stable，且共同簇覆盖全部 2N 路」。
4. **teacher 共识**：阈值与计数相对「当前 teacher 集合」计算，禁止写死「必须 3 个 teacher」。
5. **字段命名**：`support_ratio_of_4` 等写死「4」的对外字段须改为与配置族数无关的名字（如 `support_ratio`），或保留旧名但语义改为 `support / N` 并在 lineage 标注 `configured_family_count=N`（二选一，实施时定一种并做兼容说明）。
6. **缺族不等于失败样本**：批次级缺族（没跑 Kimi）是配置问题；样本级某路 `failed`/`missing` 仍走现有 `inference_incomplete` 等逻辑。
7. **不回退 v1**：三族场景必须能走 v3；禁止「不够四族就改 classify_dataset v1」作为正式口径（与 014 一致）。
8. **伪标签 / 正式 eval 门禁**：012-B/C 关于 noisy/unknown、抽检、formal eval 拒伪金标的规则保留；仅放宽家族数量，不放宽质量与人审门禁。

## 4. 需要改动的工程点（实施对照）

> 下列为已知硬编码位置，实施时以仓库检索为准，补测覆盖三族与四族。

| 位置 | 现状 | 目标 |
| --- | --- | --- |
| `selection_v3/config.py` `validate_family_config` | `len(model_families) != 4` 直接报错；`teacher_families` 必须恰好 3；`runs` 必须恰好 8 | `N >= 3`；每族 2 跑；`len(teacher_families) == N - 1`；`len(runs) == 2N` |
| `operators/quality/attach_asr_v3.py` | `len(cfg.runs) != 8` | `len(cfg.runs) == 2 * N` |
| `aggregate_manifests` / input_contract | 文案与报告按八路 | 按配置期望路数报告 |
| `consensus.py` / `classifier.py` | `support_ratio_of_4`、全四族文案 | 相对 `configured_family_count` |
| `configs/datasets/zh_asr_v3.yaml`、`configs/selection/zh_asr_v3.yaml` | 示例四族八路 | 保留四族示例；增加**三族合法示例**（可另存 `zh_asr_v3_three_family.yaml` 或同文件注释示例） |
| 手册 / 014 / 工序总览 | 「必须八路」「补 Kimi」 | 改为「≥3 族双跑；四族为可选增强」 |
| 单测 | 多假设 4×2 | 增补 `N=3` 契约通过用例 + `N=2` 失败用例；四族回归不破 |

### 4.1 teacher / target 约定（三族默认）

推荐默认（与现网批次对齐）：

```yaml
target_family: qwen
model_families:
  qwen: [qwen_1, qwen_2]
  glm: [glm_1, glm_2]
  sensevoice: [sensevoice_1, sensevoice_2]
teacher_families: [glm, sensevoice]
expected_runs_per_family: 2
```

若某批次以其它族为 target，须显式改配置；teacher 始终为「非 target 的已配置族」。

### 4.2 与 014 的关系

| 014 原表述 | 本需求修订后 |
| --- | --- |
| 必须补 Kimi 才能进 v3 | **不必须**；三族合法即可 classify_v3 |
| 默认链画成「八路 ASR」 | 改为「**已声明各族双跑（≥3 族）**」 |
| 缺 Kimi 列为 P0 数据缺口 | 降为**可选增强**；P0 改为别名对齐、register、cleaned/侧车 |

014 中「别名契约 / catalog / DNSMOS / 手册切默认」仍有效。

## 5. 我怎么才算满意

1. 仅配置三族六路时，`attach_asr_v3` + `classify_dataset_v3` **可跑通**；配置两族时 **明确失败**。
2. 四族八路既有路径回归通过，行为与放宽前一致（除文档文案）。
3. `0908-30000` 在完成别名/register/底表后，**无需 Kimi** 即可产出 `classified_v3_*`。
4. 文档与手册不再写「v3 必须四家族/八路」；改为「≥3 族双跑；推荐可上四族」。
5. pseudo_high / 全量共识判定使用「配置内全族」，三族全同意时可按规则出候选（质量/审计门禁仍生效）。
