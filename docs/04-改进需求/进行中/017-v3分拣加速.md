> 状态：**进行中（部分落地）** — P0 编辑距离已由 [019](../已完成/019-Levenshtein原生加速.md) 交付；并发 / checkpoint / 内存结构仍待做。  
> 日期：2026-09-10  
> 触发：本机 `0908-30000`（3 万条）跑 `classify_dataset_v3` 时，单核 CPU 打满、约 3GB 内存、十余分钟仍无中间进度；manifest 算子一次吃完整批，体感「卡住」。万级～十万级批次下分拣墙钟成为 v3 默认路径瓶颈（侧车加速见 [016](./016-质量侧车多进程并发.md)）。  
> 前置 / 关联：分拣语义由 [012-B](../已完成/012-B-质量与分拣.md) / [013](../已完成/013-v3实现审计与代码修订交付.md) / [014](./014-分拣生产默认切换至v3.md) / [015](./015-v3分拣支持三族及以上.md) 落地；引擎并发能力见 [001](../已完成/001-数据清洗并发改进.md)；编辑距离热路径见 [019](../已完成/019-Levenshtein原生加速.md)；语速短路见 [018](./018-转写语速不可能防护栏.md)。

## 1. 当前事实（结论）

**慢的是分拣本身，不是侧车。** 立项时是「单核 + 纯 Python 编辑距离」；**编辑距离已换 `rapidfuzz`（019）**，余下瓶颈主要是 **Manifest 整批串行 + 无进度 / 宽表拷贝**。

立项实测（2026-09-10，`0908-30000`）与落地后对照：

| 项 | 立项时 | 当前（019 后） |
| --- | --- | --- |
| 流水线 | `pipelines/classify_dataset_v3.yaml` → `quality.classify` | 同左 |
| 执行形态 | **ManifestOperator** 整批一次跑完（`_run_manifest_step`） | **仍同左**（待本需求 P0 并发） |
| 并发 | `executor: sequential`，`workers: 1` | **仍同左** |
| 进度 | 中途无日志、无分片 checkpoint | **仍同左** |
| 热路径 | `_levenshtein` 纯 Python DP | **`rapidfuzz` C++**（见 [019](../已完成/019-Levenshtein原生加速.md)；本机热路径约 847×） |
| 前置开销 | 全量 deep copy + 侧车 join + 宽表 DataFrame | **仍同左**（待 P1） |
| 资源画像 | 约 1 核打满、内存约 3GB | 编辑距离不再是主拖累；整批仍单核跑完 |

相对 v1 表达式分拣，v3 每条要：三族（或更多）× 双跑证据、族内稳定性、教师共识、语义冲突、多轮 `text_similarity`。规模到 3 万～10 万时，**仅靠串行执行模型**仍可能墙钟偏长；编辑距离项已不再是「纯 Python 双循环」卡点。

目标路径不变：

```text
prepared_asr_v3_* + quality_sidecar_*
  → classify_dataset_v3（本需求：显著加速）
  → classified_v3_*
```

## 3. 数据从哪来、结果要什么

- **输入**：`prepared_asr_v3_<BATCH>.parquet`（含 N≥3 族、每族 2 跑）+ 可选 `quality_sidecar_<BATCH>.parquet`。
- **输出**：`classified_v3_<BATCH>.parquet`，字段与现契约一致（桶、决策、reason、gold/伪标签相关 labels、lineage 等）。
- **规模**：试点 3 万（`0908-30000`）；目标场景可达十万级。不清楚精确上限时，以「同机对比串行有可见数量级或接近线性的加速，且结果一致」验收。

---

## 4. 业务上有哪些规矩

1. **结果可复现 / 可对照**：同一配置、同一输入下，加速后与「串行 + 旧实现」对同一样本的分桶结果一致；相似度浮点若因库实现有差分，须证明**不改变**任何样本的桶与 decision（或文档给出容差与抽检方案）。
2. **合并契约不变**：质量侧车只按 ID + 原音频哈希 join。
3. **失败隔离**：单条异常不得污染整批；`fail_fast` 语义与引擎一致。
4. **资源可控**：默认 workers 不得无脑打满内存（每进程若复制大对象会爆）；文档给推荐区间与「内存不够就降 workers / 改分片」。
5. **Windows**：注意 spawn 开销；若 `process` 实测不如预期，验收里写明并允许切 `thread` 或「分片多进程」等价路径，但默认一条 `pipeline run` 应明显快于今日串行。
