## 1. 为什么现在还在走 v1

不是工程没做完，而是 **012 把「工程落地」和「生产默认切换」拆开了**：

| 事实 | 含义 |
| --- | --- |
| `prepare_dataset_v3` / `attach_asr_v3` / `audio_quality_sidecar` / `classify_dataset_v3` / `review --protocol v3` / `build_dataset_v3` 已齐 | v3 **能跑** |
| 工序总览、挑选规则、手册、`classify_dataset.yaml` 仍写「默认 selection_v1.1」 | 操作与文档 **仍教 v1** |
| 012-E 写明：人工听审、伪标签抽检、`business_risk` 阈值未校准前「不得切换生产默认」 | 上一轮验收门禁把默认钉在 v1 |
| 本机批次（如 `0908-30000`）只有三族六路 ASR、无 Kimi、无 catalog 登记、无 cleaned/侧车 | **012 原文曾要求四族**；经 [015](./015-v3分拣支持三族及以上.md) 后三族合法，但仍须别名对齐、register、cleaned/侧车后才能 `classify_v3`。临时用 v1 仅作诊断，不得当正式分拣 |

因此此前操作指南给的是「本机可立刻跑通」的 v1 后段，不是业务上认可的最终分拣口径。

**本需求的决策**：分拣口径以 v3 为准；缺数据/缺权重就补齐或明确降级策略，而不是退回 v1。

---

## 2. 我想做什么

把工序一「清洗后 → 多 ASR → 分拣」的**默认分拣流程固定为 v3**：

```text
cleaned_*（或等价底表）
  → prepare_dataset_v3
  → ASR（已声明各族双跑，族数 N≥3，见 015）+ artifact register-asr-run
  → attach_asr_v3
  → audio_quality_sidecar（DNSMOS）
  → classify_dataset_v3
  →（可选）review --protocol v3 / audit-pseudo
  → build_dataset_v3 / Release
```

不再推荐、不再默认：

```text
multi_asr_aggregate → asr_metric_pipeline → classify_dataset（v1）
```

v1 聚合+字准链路可保留为「模型间一致度诊断」旁路，**不得**再作为金标/分桶生产入口。

## 3. 数据从哪来、结果要什么

### 3.1 输入（新批次标准）

- 已清洗底表：`datasets/stage1/cleaned/cleaned_<BATCH>.parquet`（含可读 `resampled_16k` 或可解析音频资产）
- **已声明各族双跑 ASR**（N≥3，共 2N 路 parquet），且已 `artifact register-asr-run` 写入 catalog；四族八路为推荐增强，非门票
- 质量侧车：`quality_sidecar_<BATCH>.parquet`（DNSMOS；未校准前 `noise_risk`/`noise_band` 可为 unknown，但侧车须跑通）
- 配置：`configs/datasets/zh_asr_v3.yaml` 或三族示例 `zh_asr_v3_three_family.yaml`（`runs` 条数 = 2N）、对应 `configs/selection/*.yaml`

### 3.2 针对存量批次 `0908-30000` 的缺口（必须纳入本需求交付）

| 缺口 | 现状 | 要求 |
| --- | --- | --- |
| Kimi 双跑 | 无 | **按 [015](./015-v3分拣支持三族及以上.md) 不强制**；三族六路即可进 v3。Kimi 为可选第四族增强 |
| 别名契约 | 现有 `qwen3-asr-1`、`glm-asr-1`、`sensevoice-asr-1` 等 | 与 v3 配置 `qwen_1`/`glm_1`/`sensevoice_1`… **对齐**（见 §5.2）；参与家族数 ≥3 即可 |
| cleaned 底表 | 本地无 `cleaned_0908-30000` | 从 ASR 嵌套音频重建底表，或从源机拷贝 cleaned；`prepare_v3` 禁止空底表硬跑 |
| catalog | 基本为空 | **已声明各族**全部 register（三族六路即可），禁止裸路径冒充契约 |
| DNSMOS | 本机无 ONNX / 音频路径在 `/data2` | 权重到位 + 在**可读音频**环境跑侧车；或定义「远端算侧车、本机只 classify」的交接物 |
| 噪声校准 | `calibrated: false` | 分拣可进审；**禁止**把 unknown 噪声当已校准去自动进伪标签训练池（012-B 约束保留） |

### 3.3 输出

- `datasets/stage1/derived/prepared_v3_<BATCH>.parquet`
- `datasets/stage1/derived/prepared_asr_v3_<BATCH>.parquet`
- `datasets/stage1/derived/quality_sidecar_<BATCH>.parquet`
- `datasets/stage1/derived/classified_v3_<BATCH>.parquet`（**唯一默认分拣产物**）
- 人审/构建按 v3 协议导出；**不得**再写默认 `classified_<BATCH>.parquet`（无 `_v3_`）作为新批次主产物

## 4. 业务规矩（硬约束）

1. **家族契约（经 015 修订）**：配置声明 **N≥3** 个模型族、每族恰好 2 跑（共 2N 路）；缺声明族或路数不符则 `attach_asr_v3` / `classify_dataset_v3` 失败。**禁止**因不够四族而静默降级到 v1；四族为可选增强而非门票。
2. **不覆盖旧产物**：v3 继续写 `classified_v3_*`；历史 `classified_*`（v1）只读复现。
3. **分拣默认入口**：手册、工序总览、命令台账、一键脚本中的「工序一③」一律改为 `classify_dataset_v3`；`classify_dataset.yaml`（v1）标注为 **legacy / 复现 only**。
4. **质量侧车必跑**：DNSMOS 进入默认链路；`calibrated: false` 时允许分拣与送审，但伪高置信自动放行训练集仍按 012-B/C 阻断。
5. **不做 VAD**：继续禁止引入端点检测；噪声只认 DNSMOS→`noise_risk`/`noise_band`。
6. **伪标签 / 正式 eval**：正式评测集仍须人审或可信外源金标；伪金标不得冒充 formal eval（012 既有门禁保留）。
7. **业务门禁阈值**：`business_risk_v1.yaml` 中 null 阈值可继续 `needs_review`，**不阻塞**「分拣默认切 v3」；阻塞的是「宣称业务回归 pass / 自动发布」而非「跑 classify_v3」。
