# 038 · 工序一后置五类分拣断点续跑

> 日期：2026-09-24  
> 状态：需求待实现（**尚未落地，勿当现行功能**）  
> 触发：手册 [`手册/dev/05-一条命令多步骤.txt`](../../../手册/dev/05-一条命令多步骤.txt) §2 的后置分类命令  
> `python scripts/classify_asr_to_xlsx.py --batch "$BATCH" --energy-workers 32`  
> （及等价 `audio-data stage1 classify`）当前**整批临时目录一把跑完**，中断后临时态丢弃，只能 `--overwrite` 整批重来；万级样本上 Silero/energy/DNSMOS 按需子集仍可能跑很久，断线/杀进程代价过大。  
> 基线入口：[031](./031-工序一后置统一分类分拣入口.md) + [037](./037-按需声学五类分拣重构.md)（现行默认 **五类 v3 / 按需声学**）。  
> 正式规范（分类条件/顺序，**本需求不得改规则**）：[数据挑选规则_v3](../../02-规范规则/数据挑选规则_v3.md)。  
> 目标：给后置分类入口增加**可断点继续**能力；不改变五类判定语义；不重跑 ASR。

---

## 1. 我想做什么

给「六路 ASR 已齐 → 一键五类分拣 → XLSX」这条生产入口加上**断点续跑**：

- SSH / VS Code 断开、进程被杀、机器重启后，用同一命令（或明确的 `--resume`）能从上次进度接着算；
- 已算完且仍有效的声学证据与分类中间结果**不重算**；
- 最终仍原子写出正式 `summary_five_class_v3_*.xlsx` 与 `classified_five_class_v3_*.parquet`（legacy stem 同理）；
- **不改**五类 v3 分类条件与按需声学顺序；不启动 ASR；不伪造 register / reservation / release。

当前痛点（实现现状，供对照）：

```text
整批读入 → 临时目录内：聚合 → asr_route → silero → energy → dnsmos → classify
         → 结束才原子写正式产物 → TemporaryDirectory 删除
中断 = 全部中间进度丢失；再跑只能 --overwrite 整批重来
```

期望（概念，具体落盘形态由实现定，但须满足验收）：

```text
持久化 work/checkpoint（按 batch + rule_version 隔离）
  → 各步可增量：跳过已成功样本 / 已完成步骤
  → 续跑同一命令或 --resume
  → 全部完成后原子发布正式产物
  → 可选清理 checkpoint；失败可审计
```

## 2. 数据从哪来、结果要什么

### 输入（与现行后置入口相同）

- `datasets/stage1/cleaned/cleaned_${BATCH}.parquet`
- 六路（或多路配置）`datasets/stage1/asr/{alias}_asr_${BATCH}.parquet`
- 默认规则：`selection_five_class_v3`；兼容 `v2_4_on_demand_acoustic` / `v2_3_min_acoustic` / `v2_2_auto_noise`
- 本机可读 `audio.resampled_16k`

### 正式产物（成功结束时，与现行一致）

| 产物 | 默认路径（v3） |
| --- | --- |
| XLSX | `data/exports/summary_five_class_v3_${BATCH}.xlsx` |
| classified | `datasets/stage1/derived/classified_five_class_v3_${BATCH}.parquet` |

### 新增：续跑用中间态（不得冒充正式产物）

- 须落在**固定、可发现**的路径（建议示例，实现可微调但须文档写死）：  
  `datasets/stage1/derived/classify_ckpt_${rule_stem}_${BATCH}/`  
  或 `runs/classify_post_asr/${BATCH}_${rule_stem}/`
- 目录内至少能回答：当前跑到哪一步、哪些 sample 已完成哪类证据、规则版本/配置摘要、上次更新时间
- **禁止**把半成品写成正式 `classified_five_class_v3_*` / `summary_five_class_v3_*` 文件名（除非整批对账通过后的原子发布）

### 规模

服务器常见数千～数万条；续跑价值主要在按需 Silero / energy / DNSMOS 与整批 classify 的耗时上。

## 3. 业务上有哪些规矩

### 3.1 续跑语义

1. **默认可续跑**：同一 `batch` + 同一 `--rule-version`（及影响证据的关键参数，如家族别名解析结果、DNSMOS/Silero 配置摘要）下，再次执行应优先接着算，而不是静默整批重来。  
2. **显式整批重来**：保留 `--overwrite`；清理正式产物**并**清理对应 checkpoint 后重跑（或提供 `--restart` 等价语义，实现二选一写清）。  
3. **正式产物已存在且未 `--overwrite`**：行为与现行一致——拒绝覆盖并提示；**不要**在正式产物已完整存在时又偷偷改写。  
4. **配置漂移拒绝盲续**：若 checkpoint 记录的 `rule_version` / selection 摘要 / 家族别名集合与本次命令不一致 → **非零退出并说明**，要求 `--overwrite`/`--restart` 或对齐参数；禁止混用旧证据做出新规则结论。  
5. **样本集合变化**：cleaned / 六路 ASR 相对 checkpoint 的 id 集合或 `original_audio_sha256` 对账失败 → 拒绝盲续或提供明确「作废 checkpoint」路径；不得静默少样/多样交差。

### 3.2 哪些可以跳过（须正确）

| 步骤 | 续跑期望 |
| --- | --- |
| 前置体检 / 聚合六路 | 可快速重做；或缓存聚合表但须与 ASR 指纹一致 |
| ASR 预分流 | 可缓存每条 `asr_route`；输入转写未变则跳过 |
| Silero 按需 | 仅对仍 `required` 且尚未成功的候选计算；已成功或 `not_required` 跳过 |
| energy 按需 | 同上（仅 B∩VAD 无人声） |
| DNSMOS 按需 | 同上；已有同 hash 有效分数可继续复用 sidecar（现行能力保留） |
| classify | 可在证据齐全后整批或按条重算；**不得**在声学未齐时写出假类别 |

失败样本：记 status/errors，不伪造成功 VAD/energy/SIG；续跑应对「上次 failed」可重试，对「上次 success」默认不重算。

### 3.3 进度与日志（纠正「假全量」观感）

- 进度打印须区分：**应算条数 / 本轮新算 / 跳过(已完成) / 跳过(not_required)**，禁止只打 `energy n/total` 让人以为在全量算波形。  
- 结束摘要（及 XLSX 统计表）保留并诚实反映：Silero/energy/DNSMOS **按需调用数**、本轮实际新算数、从 checkpoint 复用数。

### 3.4 明确不做

- 不改五类 v3 / 简版 0922 分类条件与按需顺序。  
- 不重跑 ASR，不启模型服务。  
- 不做跨机器分布式调度（单机断点即可）。  
- 不把 `stage1 run` 全链路 resume 与本需求混为一谈；本需求只覆盖**后置** `classify_asr_to_xlsx` / `stage1 classify`。  
- 不要求 Windows 本地跑声学；服务器执行、本机收表即可。

## 4. 我怎么才算满意

1. **中断可续**：故意在 Silero 或 energy 中途杀进程 → 再跑同一命令（或文档写明的 resume 用法）→ 已成功样本不重算波形，最终正式产物行数 = cleaned 有效条数，五类互斥成立。  
2. **配置隔离**：先用 `v3` 跑一半，再改 `--rule-version v2_2_auto_noise` 续同 batch → 必须失败提示，不得混用。  
3. **正式产物契约**：成功结束前，磁盘上没有半套 `classified_five_class_v3_*` 被当成完成态；成功后原子出现完整 XLSX + parquet。  
4. **`--overwrite` / 重启**：能清掉 checkpoint + 正式产物后整批重来。  
5. **脚本与 CLI 同一实现**：`scripts/classify_asr_to_xlsx.py` 与 `audio-data stage1 classify` 行为一致。  
6. **单测**：至少覆盖「假中断后 resume 跳过已算」「配置漂移拒绝」「正式产物已存在拒绝」；不依赖真 GPU ASR。  
7. **文档**：更新 `手册/dev/05-一条命令多步骤.txt` §2、`docs/07-操作手册/已有六路ASR一键分类导出.md`，写清续跑命令、checkpoint 路径、何时必须 `--overwrite`。  
8. **不做规则回退**：默认仍为五类 v3；本需求只加工程续跑，不改 `数据挑选规则_v3.md` 条件。

## 5. 建议实现方向（供 AI 选型，可微调）

以下不是强制 API，但是验收友好的默认：

1. **持久 workdir**：按 `batch + rule_stem` 固定目录，进程结束不删；内存 TemporaryDirectory 改为「可恢复会话目录」。  
2. **分步 manifest**：例如 `01_aggregated.parquet`、`02_routed.parquet`、`03_silero.parquet`、`04_energy.parquet`、`05_dnsmos.parquet`、`06_classified.parquet`，每步结束原子替换；或单文件 + `labels`/`quality` 增量写 + `checkpoint.json`（步骤名、指纹、计数）。  
3. **样本级跳过键**：`sample_id` + `original_audio_sha256` + 算子版本/配置 digest；命中且状态 success/`not_required` 则 skip。  
4. **CLI**：  
   - 默认：有合法 checkpoint 则 resume；  
   - `--overwrite`：删正式产物并重启；  
   - 可选 `--restart-checkpoint` / `--no-resume` 若需要更细控制。  
5. **与 017**：本需求是后置入口的实用 checkpoint；不必一次做完全局分拣加速框架，但设计时避免把 checkpoint 写死成无法扩展的临时脚本私货。
