# 039 · 语音标注平台 · 上游交接契约

> **文档性质**：本仓库（`audio-data-engine`）作为**标注平台的上游**，说明我们产出什么、交给标注平台什么、双方如何对齐、对方要用哪些字段、对方应回传什么供我们回填。  
> **不是**：标注平台怎么建、用什么技术栈、API/UI 怎么实现。交互样稿仅作对方产品参考，见文末索引。  
> **状态**：契约 / 先验；待标池「标准导出包」命令可后补，现行等价逻辑已在 CLI `prepare` 中。

---

## 1. 双方边界（一句话）

| 谁 | 负责 |
|----|------|
| **本仓库（上游）** | 五分类完成后，筛出 `semantic_risk`，打包**待标池**（元数据 + 可听 wav）；拿到标注结果后按主键 **merge 回填** `gold_*`，得到 `*_with_gold.parquet`，供训练汇总等下游使用。 |
| **标注平台（下游独立项目）** | 导入待标池 → 切 Task → 听写/复核 → **导出 annotations 兼容表**。不改五类、不跑 ASR、不做账号体系（人员认领在平台外约定）。 |

```text
本仓库工序一
  classified_*_{BATCH}.parquet
        │  本仓库：筛 semantic_risk + 解析 wav + 写身份字段
        ▼
  【交给标注平台】待标池包 pool_package/
        │  标注平台：导入 / 切 Task / 听写 / 复核
        ▼
  【标注平台交回】annotations.parquet（或 JSONL）
        │  本仓库：merge（sample_id + original_audio_sha256）
        ▼
  classified_*_{BATCH}_with_gold.parquet
        │
        ▼
  训练汇总等（036 等，与平台无关）
```

现行 CLI 三段与边界对应关系：

| CLI | 归属 |
|-----|------|
| `prepare` | **本仓库**（待标池真相源逻辑） |
| `label` | 将被标注平台替代；契约仍以 CLI 写出的 annotations 为准 |
| `merge` | **本仓库**（消费平台导回的表） |

## 2. 本仓库已经产出什么（标注平台的上游原料）

### 2.1 分类 Manifest（池子的母表）

工序一五类分拣完成后的 parquet，例如：

```text
datasets/stage1/derived/classified_five_class_v3_{BATCH}.parquet
```

（legacy stem 可能不同；以实际跑出来的文件为准。）

对标注有关的事实：

- 每条样本有稳定身份：`id`（即 `sample_id`）+ `original_audio_sha256`（见 §4）。
- 业务类在 `labels.category`（兼容读 `labels.type`）。
- **`semantic_risk`**：机转冲突/风险类，**禁止**当金标自动用，必须人工听写补 `gold_text`。
- 机转选文常在 `labels.candidate_text`（给标注员**只读参考**，不是答案）。
- 听音文件路径在 `audio.*` / `source_path`（解析顺序见 §3.2）。

### 2.2 现行 CLI 工作目录（等价「半成品池」）

`prepare` 默认写出：

```text
datasets/stage1/review/semantic_risk_transcripts/{BATCH}/
  queue.parquet      # 待标队列（字段见 §3.3）
  playlist.md        # 人类可读清单
  wav/               # 可选：序号软链/副本
```

这就是标注平台应消费内容的**当前实现形态**。标准化「zip/目录导入包」可在此之上封装，字段不得少于 `queue.parquet` 的契约列。

### 2.3 本仓库最终要的东西（平台做完之后）

不是平台内部的 Task 进度，而是：

1. **annotations 表**（§5）——能被 `merge` 读入；  
2. merge 后的 **`classified_*_{BATCH}_with_gold.parquet`** ——未标行不变，`category` 不变，命中行写入 `gold_text` 等。

## 3. 交给标注平台的是什么

### 3.1 交付物定义：**待标池包**

一次交付对应一个 `batch`（或明确的 pool 版本），内容为：

| 交付件 | 作用 | 标注平台必须 |
|--------|------|----------------|
| 样本元数据表（`queue` / `items`） | 告诉平台「标哪些、顺序、身份、参考文」 | **必用** |
| wav 文件（包内或可解析路径） | 听音 | **必用**（缺文件的行应可识别） |
| 批次元数据（batch 名、来源 classified 路径、条数） | 溯源与导回时填 `batch` | 必用 |

推荐目录（与未来 `export-pool` 对齐；今日可用 `prepare` 产物手工等价）：

```text
pool_{batch}/
  manifest.json       # 批次元信息（可后补；最小可只有 batch 名）
  items.parquet       # = 契约化的 queue（列见 §3.3）
  wav/
    00001_<sample_id>.wav
    ...
```

### 3.2 本仓库如何从分类表抽出池（平台不需要再实现筛选逻辑，但需理解）

1. 读分类 Manifest。  
2. **只收** `labels.category == "semantic_risk"`（无 category 时兼容 `type`）。  
3. 按 `sample_id` **稳定排序**，赋 `queue_index`（从 1 起）。  
4. 解析听音路径，优先级：  
   `audio.resampled_16k` → `pcm_wav` → `pcm_to_wav` → `raw` → `pcm_wav_path` → 若 `source_path` 为音频后缀则用之。  
5. 写入 `original_audio_sha256`（§4）。  
6. `candidate_text` ← `labels.candidate_text`。

平台侧：**不要重新发明五分类**；假定进入包内的行已经是 `semantic_risk`。若收到其它 category，应拒绝或隔离并告警。

### 3.3 元数据表字段（交给平台的列契约）

与现行 `queue.parquet` 对齐；平台导入后这些列要能原样出现在导回的 annotations 里（至少主键与参考列）。

| 字段 | 本仓库是否写出 | 标注平台怎么用 |
|------|----------------|----------------|
| `sample_id` | ✓ | 样本主键之一；展示/跳转；**导回必带** |
| `original_audio_sha256` | ✓ | 样本主键之二；**导回必带**；不可丢、不可改 |
| `batch` | ✓ | 批次；导回必带 |
| `category` | ✓ 固定 `semantic_risk` | 校验用；**禁止改成别的类再导回当事实** |
| `queue_index` | ✓ 全池顺序 | 切 Task、进度、展示序号；导回建议保留 |
| `wav_path` / 包内相对路径 | ✓ | 绑定播放器；导回可写平台路径或原路径 |
| `candidate_text` | ✓ 可空 | UI「生产环境转写」**只读参考，勿默认当金标** |
| `source_path` | ✓ 可空 | 排障 |
| `selected_family` | ✓ 可空 | 可选展示 |
| `duration` | ✓ 可空 | 可选展示 |
| `status`（队列侧） | prepare 时多为 `pending` | 平台自己的完成态以标注结果为准，勿与导回 `status` 混淆 |

**本仓库当前不交付、平台 UI 可有的字段：**

| 字段 | 说明 |
|------|------|
| `previous_text`（上一句） | 样稿有此栏；**现行 prepare 不产出**。平台显示「（无）」即可；将来上游补齐再写入导入表。 |

### 3.4 音频

- 优先 16 kHz wav（`resampled_16k`）。  
- 交付方式：包内 `wav/` 副本或软链；或可解析的绝对路径（平台部署机必须读得到）。  
- 命名习惯：`{queue_index:05d}_{sample_id}.wav`（便于人工点播，非合并键）。

### 3.5 本仓库**不**交给平台的东西

- 完整六路 ASR 明细（除非未来明确加列）  
- 五分类规则引擎 / DNSMOS 等侧车  
- 账号、Task 分配名单（外部分配）  
- 训练配比、warehouse 冻结流程

## 4. 对齐规则（双方必须一致）

### 4.1 合并主键（硬约束）

```text
(sample_id, original_audio_sha256)
```

- 禁止只按文件名、行号、Task 内序号回填。  
- `original_audio_sha256` 在本仓库的取值：优先 `labels`/`quality` 的 `original_audio_sha256` / `source_audio_sha256` / `raw_audio_sha256`，否则退回样本 `sha256`。  
- 导回时若 sha 与分类表不一致 → merge **失败或计入 mismatch 报告**，不得 silently 写入。

### 4.2 类别边界

- 池内样本业务类保持 `semantic_risk`。  
- 人工只补转写（及无语音判定），**不**通过本听写通道改 `category`。  
- 「不作训练 / 语音信箱」等若写成金标文本，是**文本内容约定**，类别清洗发生在本仓库训练汇总（036），不是平台改类。

### 4.3 完成态语义（导回时本仓库认什么）

| 导回 `status` | 本仓库 merge | 含义 |
|---------------|--------------|------|
| `annotated` | ✓ 写入 | 有语音；`gold_kind=speech`，`gold_text` 非空（业务上应有字） |
| `empty` | ✓ 写入 | 确认无语音；`gold_kind=non_speech`，`gold_text=""` |
| `skipped` | ✗ 忽略 | 未完成；下次还可标 |
| 其它 / 缺省 | ✗ | 不写 gold |

对应决策字段习惯：`decision ∈ {accept, empty, skip}`。

### 4.4 机转文 vs 人工文

| 字段 | 谁产生 | 对齐约定 |
|------|--------|----------|
| `candidate_text` / 平台展示的「生产环境转写」 | 上游 | 只读；导回可带回，merge **不**把它当成 `gold_text` |
| `gold_text` | 标注平台 | 听写结果；merge 写入 labels |

### 4.5 协议标记（导回后本仓库写入 labels）

平台导出本身带 annotations 列即可；merge 时本仓库会写（平台导出可用不同 `label_source` 字符串，便于区分 CLI/Web）：

| labels | 约定 |
|--------|------|
| `gold_text` / `gold_kind` | 来自 annotations |
| `annotation_state` | `annotated` |
| `annotator_id` / `annotated_at` | 来自 annotations |
| `label_source` | CLI：`human_transcript_cli`；Web 建议：`human_transcript_web` |
| `transcript_annotation_protocol` | CLI：`semantic_risk_cli_v1`；Web 建议：`semantic_risk_web_v1` |
| `is_human_verified` | `true`（听写台确认 ≠ 正式双审金标） |
| `label` | 有语音时同步为 `gold_text` |
| `category` | **不修改** |

平台扩展列（`task_id` / `uncertain` / `reviewed` 等）**允许出现在导回表**；现行 merge **可忽略**，不冲突即可。

## 5. 标注平台导回给我们的是什么

### 5.1 文件

优先：`annotations.parquet`（也接受 JSONL，列同名）。

交回方式：文件拷回本仓库工作目录，或 `--annotations` 指向平台导出路径。

### 5.2 列（兼容现行 CLI；平台可多列不可少主键与 gold）

| 列 | 必填 | 说明 |
|----|------|------|
| `sample_id` | ✓ | |
| `original_audio_sha256` | ✓ | |
| `batch` | ✓ | 与待标池一致 |
| `category` | 建议 | `semantic_risk` |
| `queue_index` | 建议 | |
| `wav_path` | 建议 | |
| `candidate_text` | 建议 | 回传参考文 |
| `gold_text` | ✓* | `empty` 时为 `""` |
| `gold_kind` | ✓* | `speech` \| `non_speech` |
| `decision` | 建议 | `accept` \| `empty` \| `skip` |
| `status` | ✓ | `annotated` \| `empty` \| `skipped` |
| `annotator_id` | 建议 | 外部分配的人名/工号字符串即可 |
| `annotated_at` | 建议 | UTC ISO8601 |
| `task_id` / `uncertain` / `reviewed` / … | 否 | 平台自用；merge 可忽略 |

\*对 `status∈{annotated,empty}` 的行必填语义正确；`skipped` 行 gold 可空。

### 5.3 本仓库如何消费

```bash
python scripts/annotate_semantic_risk_transcripts.py merge \
  --batch "$BATCH" \
  --annotations /path/to/exported_annotations.parquet \
  --overwrite
```

产出：

```text
datasets/stage1/derived/classified_*_{BATCH}_with_gold.parquet
*.merge_report.json   # applied / sha256_mismatches / orphans 等
```

## 6. 标注平台「拿到之后要用哪些」（消费清单）

按优先级，对方实现导入与标注页时**必须消费**：

1. **`sample_id` + `original_audio_sha256`** — 全程携带，导回原样还回。  
2. **wav** — 绑定每条样本的可播放文件。  
3. **`queue_index`** — 全池顺序；切 Task 时保持升序子集，禁止打乱全局序。  
4. **`candidate_text`** — 展示为生产/机转参考。  
5. **`batch` / `category`** — 校验与导回。  

**建议消费：**

6. `duration` / `source_path` / `selected_family` — 展示与排障。  

**可空、勿阻塞：**

7. `previous_text` — 上游未提供则显示占位。  

**不必消费（本仓库未作为听写输入交付）：**

- 完整 transcripts 多路原文、quality 侧车、lineage 细节（除非未来扩展导入列）。

Task 切分、复核抽检、无登录等是平台内部产品行为；**唯一与上游对齐的硬接口**是：导入字段守恒 + 导回 annotations 契约 + 合并键。

## 9. 对齐验收（联调用）

1. 本仓库 `prepare`（或等价导出）条数 ≈ 分类表中 `semantic_risk` 计数。  
2. 平台导回表含全部已完成样本的主键与 `status∈{annotated,empty}`。  
3. `merge` 报告：`sha256_mismatches=0`，`applied` = 有效标注条数。  
4. 抽查：有标注行 `labels.gold_text` 正确；无标注行与原 classified 一致；**所有行 `category` 未变**。
