## 1. 目标与范围

建立统一的 tag 规则库，让用户能清楚回答：**这个 tag 是什么意思、什么条件会命中、依赖什么数据、当前使用哪个版本。** 每条完整业务规则对应明确的 tag，同一样本可以命中多个 tag。

采用 **“一 tag 一定义文件 + 运行配置显式选用 + 自动生成可读目录”**，接入现有 040 多标签引擎。本期交付定义库、加载与校验、查看和文档生成、历史快照、配置迁移及测试。管理界面可后续扩展，已有原子判断和训练准入语义沿用现行实现。

## 2. 当前基础与缺口

目前 `configs/tagging/` 已有标签、可组合规则、公共条件片段和独立词表；[配置加载器](../../../src/audio_engine/core/tagging/config.py) 从运行配置中的 `tags`、`rules` 组装现有引擎配置，已有校验、预演和单样本解释能力。

缺口是定义散落在不同运行配置中，没有目录加载和统一可读总览。当前 `TagDef` 没有定义版本字段，运行记录的配置路径／摘要也不足以独立还原当时的全部定义；这些属于本次待实现能力。开工时与当前代码复核。

## 3. 定义库与加载契约

以下为目标目录示意：

```text
configs/tagging/
  library/                       # Tag 定义库
    tag_1.yaml                   # 一个文件收齐一个 tag 的说明及规则
    critical_short.yaml
  fragments_v1.yaml              # 公共条件片段，供规则复用
  lexicons/                      # 词表、正则
  zh_asr_multi_tag_v1.yaml        # 选择本次使用哪些 tag，以及运行参数
```

定义文件是唯一维护入口，文件名对应 `tag_id`。每个文件只能定义一个 tag，内部使用 `rules` 列表收齐对应规则；每条规则只能产生本文件的 tag。允许多个规则产生同一 tag，保留逐规则三态与来源，任一规则命中即可产生该自动标签，有效 tag 去重。

运行配置显式选择 `tag_id` 和定义版本，并保留 `selection_config`、证据模式和运行参数；新增库文件不会自动参与所有批次。库模式下空选择、未知 ID、版本不匹配、选用停用／归档项均明确报错，不隐式启用全库。

公共片段是规则内部可复用条件，词表是匹配数据，均不自动代表 tag。复用当前 `all / any / not / at_least`、能力及 `text_binding` 语义，保留共享引用，避免复制阈值和词表。

兼容旧内联 `tags/rules` 配置；迁移后的生产配置改为引用定义库。新旧来源同时定义同一 ID 时拒绝覆盖。统一并文档化路径解析规则，使库文件、公共片段和词表引用不依赖偶然的启动目录。

## 4. 每个 tag 必须说清什么

- **身份与含义**：稳定 `tag_id`、中文名称、业务定义、版本、启用／归档状态；改显示名称不改变 ID。
- **完整规则**：`rule_id`、组合条件、阈值及比较边界、文本来源、家族／路次范围、成功态和排除条件，避免只写“模型不一致”等模糊描述。
- **依赖**：引用的公共条件、词表及版本；是否需要声学证据。
- **例子**：命中、不命中，以及证据不足时无法判断的例子。

沿用既有 `tag_id`、`rule_id` 和条件含义。新增必要的定义版本、业务说明和例子字段，给出完整 YAML 示例及字段说明；引用已有阈值时写清出处及比较方式。命中例子是规则示例，不能宣称为未做过的真实模型验证。

## 5. 可读目录与历史追溯

扩展现有 `audio-data tags` 管理入口，提供全库列表、单 tag 详情以及定义文档生成／过期检查。由同一加载器生成 [目标文档位置](../../02-规范规则/) 下的 `tag规则库.md`，稳定排序，包含启用／停用／归档项、版本、定义文件链接、完整规则和例子。详情展开公共条件并提供词表内容／来源入口；涉及运行参数时标明依赖，并可结合指定策略查看有效值。

生成和查看定义无需执行 ASR 或声学模型；生成文档标记为派生产物，修改定义后可一条命令更新，检查模式能发现过期。复用现有 `tags validate / preview / explain`，使库加载与正式打标使用相同校验及解释逻辑。

每次运行持久化所选定义、规则、递归公共条件、词表内容及匹配参数、有效 selection／声学配置的完整快照和内容摘要，并随现有发布机制绑定结果。不能只保存可变文件路径和哈希；单条命中来源必须可定位到当时的定义版本及快照。

规则或依赖改变后更新版本并改变有效内容摘要；断点恢复校验定义摘要和既有输入身份，发生变化时拒绝混用旧进度，提示新运行／重算。停用或归档保留历史；历史数据缺少快照时据实提示无法完整还原，不用当前定义冒充历史定义。

保留多标签独立判断、`matched / not_matched / unknown`、命中证据和人工添加／屏蔽语义。迁移及重跑不清空人工状态；局部重算保留范围外来源，变为 unknown 的规则不能继续保留其旧自动确定结论。不得因整理定义库自动重跑 ASR 或强制补算声学。

## 7. 验收标准

- 能从一个统一入口列出全部 tag，并看懂其定义、完整条件、例子、版本和状态。
- 组合已有能力新增 tag 时，主要新增定义文件并选入运行配置；无需复制流水线或修改 Python。
- 重复 tag／rule ID、规则与文件 tag 不一致、缺失／循环引用、非法正则和规则、版本不匹配在运行前报错，错误能定位文件和条目。
- 新库启用后产生的历史命中结果可追溯到实际使用的 tag 定义、规则版本及证据；人工标签来源保持可区分。

使用固定离线证据验证，不要求运行全量昂贵推理。自动化测试至少覆盖：

1. 同一批证据迁移前后的逐规则三态、命中来源和有效 tags 一致；包括多规则同 tag、多 tag 重叠、规则顺序变化及人工添加／屏蔽。
2. 新文件未选入时不影响打标；显式选入、停用／归档、空清单、版本错误和新旧 ID 冲突按契约处理。
3. 定义／公共条件片段／词表实际内容变化能改变相关有效摘要；旧快照仍可查看，恢复时拒绝定义漂移；未变化时正常续跑。
4. 总览与源定义一致，可查看所有状态和完整条件；重复生成稳定，过期检查有效，查看和生成过程中没有 ASR／声学调用。
5. 现有相关回归通过；片段样本的 ID、父源血缘和人工记录不因定义库迁移丢失。041 尚未具备的能力明确列出，不能虚构闭环已验收。
