## 0. 一句话结论

这次失败不是「音频太难」，而是流水线把**未校准、模型分歧、内容敏感、推理异常**统一变成了逐条人工盲标，同时导出筛选有明确缺陷，发布前置条件也未满足。重构必须先暴露批次阻断、机器修可修问题、保留完整证据，再按用途和预算派发人工。

本需求以 0908-30000 为冻结回放集；验收同时要求**功能回归**与**业务收益材料**。功能通过 ≠ 业务完成。

## 2. 我想做什么

将分拣从「发现风险就全量送人工盲标」重构为：

1. **先判断批次是否可用**（诊断 / 校准小批 / 生产加工 / 发布四级权限分离）；
2. **机器修复可修问题**（路次重试、异常路次隔离、重算有效家族）；
3. **完整计算证据再处置**（可解析样本不得因首风险丢失候选）；
4. **按用途和人工预算派发**（盲审金标 ≠ 训练候选校对 ≠ 语音存在性确认）；
5. **修正导出与身份契约**（筛选交集、拆包 meta、导入拒错版）。

同时保留：关键语义保护、人工金标真实性、数据隔离与防泄漏、评测集独立。

## 3. 数据从哪来、结果要什么

### 3.1 输入

- 已切分音频 manifest（①清洗后）；
- ≥3 模型家族及各自运行证据（`prepared_asr_v3_*` / attach 契约）；
- DNSMOS 分数与质量策略（侧车；区分未校准 / 失败 / 不支持 / 真噪声）；
- 来源与分组元数据（call / speaker / source index）；
- 已有人工标注（可复用须绑定音频+标注范围）；
- **目标用途**与**人工预算**（配置或 CLI）；
- 回放集：`0908-30000` 原始快照（classified / exports / meta）只读保留。

### 3.2 输出（必须分开落盘）

| 产物 | 落点 | 内容 |
| --- | --- | --- |
| 批次可用性报告 | `runs/<run_id>/reports/batch_availability.json` | 契约、运行健康、校准状态、治理/发布阻断、预估人工负载 |
| 逐条证据 manifest | `datasets/stage1/derived/evidence_v3_<BATCH>.*` | 全部风险、路次有效性、家族、候选簇、处置、规则版本 |
| 处置后 classified | `datasets/stage1/derived/classified_v3_<BATCH>.*` | 与现字段兼容 + 新 disposition / 阻断层级；影子跑不覆盖旧文件 |
| 人工派发包 | `data/exports/` | 按用途/优先级/预算拆包；每包独立 `.meta.json` |
| backlog | `datasets/stage1/derived/review_backlog_<BATCH>.*` | 未选入本轮的待办；不得静默放行 |
| 结果报告 | `runs/<run_id>/reports/sort_outcome.json` | 守恒、迁移矩阵、发布量、阻断项、人工预估 |
| 跨批复盘 | `docs/08-分析报告/` | 方法与收益，不进现行规范 |

manifest 继续作为业务真相源。

### 3.3 互斥处置枚举（`disposition`）

实现时统一写入 labels；与可重叠的 `risk_tags` / `type`（主因）并存。

| disposition | 含义 | 典型下一动作 |
| --- | --- | --- |
| `machine_retry` | 推理不完整 / 路次失败可重试 | 有限重试，记次数与终态 |
| `route_quarantine` | 单路异常（幻觉语速等），样本仍可能可用 | 隔离该路，重算有效家族 |
| `calibration_hold` | 质量未校准等批次级阻断落到样本 | 进校准计划，不生成转写任务 |
| `governance_hold` | 缺分组/防泄漏证据 | 补来源后重冻分配 |
| `audio_exclude` | 物理音频无效等充分证据 | 排除；需说明证据 |
| `presence_confirm` | 全空或空/非空混合 | 先判 speech/non_speech/uncertain |
| `voicemail_isolation` | 留言候选 | 隔离队列 |
| `pseudo_pending_audit` | 高置信伪标签待抽审 | `pseudo_audit` |
| `train_assisted_correction` | 有候选的训练校对 | assisted 工作流（非盲金标） |
| `human_blind_label` | 正式盲审 / 评测金标 | blind + 所需双审 |
| `content_complexity_sample` | 同文但内容复杂/敏感 | 按用途抽审，非「模型冲突」 |
| `backlog` | 超预算未派发 | 持久化待办 |

守恒：**每条样本恰好一个 disposition**；报告须解释 `review_queue` 计数与 `decision` 计数的历史差异。

## 4. 业务上有哪些规矩

### 4.1 批次门禁（四级权限）

| 权限 | 允许 | 禁止 |
| --- | --- | --- |
| 诊断分拣 | 证据计算、报告、影子处置 | 大规模生产派发、宣称可发布 |
| 校准任务 | 显式小批盲审/听音 | 把全量 unknown 当转写任务 |
| 生产人工加工 | 预算内按用途派发 | 绕过治理与关键语义保护 |
| 发布 | 治理通过 + 抽审通过 + 评测独立 | 零错误样本冒充总体零风险 |

**批次级可见阻断（任一触发则不得全量生产派发）：**

1. 全量（或超过配置比例）质量 `unknown` / 未校准；
2. 质量版本不一致；
3. 来源/分组缺失 → `governance_hold`；
4. 某一路系统性失败（失败率超阈）；
5. 自动候选为零且未声明「仅诊断」；
6. 预估人工负载（唯一音频 × 审次 × 假设秒数）超过配置预算。

质量状态至少四态：**未校准 / 评分失败 / 评分不支持 / 实际高噪声**。不得都压成 `audio_quality_risk` 转写任务。  
`calibrated: false` **禁止**改 true 伪造校准。未校准 → `calibration_hold` + 校准计划。

缺分组：保留 `governance_hold`；补关联后重新冻结并验无泄漏；禁止虚构 speaker/call ID。

### 4.2 证据与处置拆开

1. 先算：路次状态、家族稳定性、语义差异、全部候选簇、质量证据。  
2. 再定：主因 `type`、全部 `risk_tags`、阻断层级、`disposition`、下一动作。  
3. 可解析样本：**禁止**因首个风险 return 而丢候选簇。  
4. 物理无效或无法解析：允许不算完整共识，但必须写 `evidence_gap_reason`。  
5. 家族计票独立；同族双跑≠两票；家族数随配置（N≥3），不强制补第四族。

每条至少保存：主因、全触发规则、阻断层级、触发路次与差异片段、候选文本与支持家族、机器补救历史、下一动作、规则/词表/输入摘要哈希。

### 4.3 语义风险重定义

| 概念 | 定义 | 处置 |
| --- | --- | --- |
| 模型间冲突 | **比较文本实质不同**且存在可解释的肯否翻转 / 关键金额号码差 / 确认的存在性高风险差 | 可上 P0；记录双方文本与跨度 |
| 内容复杂/敏感 | 单句内含复杂肯否或敏感材料，**但各路比较文本相同** | `content_complexity_sample`；按用途抽审，**不得**标模型间冲突或同族 `unstable_semantic` |
| 语气/礼貌差异 | 「嗯」「啊」「好」增删、重复词、ASR 控制标签 | 不得无条件等同肯否反转 |

硬约束：

- 相同比较文本 → **不得**产生模型间冲突或同族语义不稳；
- 不通过统一删除「嗯/啊/不」达到表面一致；保留 `raw_text`；
- 短句规则按校准确定；记录触发是**时长**还是**路次文本长度**；单个异常短输出不得无解释改变整条容差。

回归锚点（复盘）：88 条六路一致样本冲突标记须消失；「不需要/需要」类真实差异仍命中。

### 4.4 路次先修，避免整条误排除

1. 失败/缺失路次：按错误类型有限重试（最大次数、退避、终态入证据）。  
2. 超长幻觉 / 不可能语速：优先 `route_quarantine`，保留原文，重算有效家族（演进 018：从「整条 exclude」改为「路次隔离」；整条 exclude 仅当物理无效或隔离后仍不可用）。  
3. 有效独立家族不足：转 `machine_retry` / 暂存，**禁止**降低家族门槛静默放行。  
4. 全空 / 空非空混合：`presence_confirm`；需人工时先判 speech/non_speech/uncertain，再对 speech 转写。无音频证据不得用多数空文本自动空金标。引擎仍不做 VAD。  
5. 噪声/文本阈值版本化，须校准支持。

### 4.5 按用途与成本派发

用途（互斥任务目的，可与 disposition 映射）：

1. 独立质量校准  
2. 正式评测金标（盲审 + 所需双审）  
3. 伪标签抽审  
4. 训练候选校对（**assisted correction**，可见候选；不得冒充独立盲标）  
5. 高价值 Qwen 错误修复  
6. 语音存在性确认  

新增 **assisted correction** 工作流：何时可见候选、可编辑字段、`label_source` 标记；当前 `candidate_check` 要求已有初审——不能只改导出视图宣称支持首轮低成本校对。

人工预算（可配置）：

- `max_unique_audio` / `max_review_jobs` / `max_reviewer_minutes`；
- 预估含初审、复审、仲裁储备；无实测秒数时配置显式假设，试标后更新；
- **P0 不得静默绕过预算**；无法覆盖 → 告警 + 分期 + backlog；
- 同 `original_audio_sha256` + 同语音范围 + 同规范版本可建复用关系；冲突标签不自动传播；双审仍须独立人员；评测分组不去重串集。

### 4.6 导出与身份契约

1. `priorities` 与 `queues` **同时给出时取交集**。  
2. 无 priority 的 `pseudo_audit`：通过明确任务模式（如 `--task-mode pseudo_audit` 或只传 queues 且 priorities 为空的专用路径），**不得**作为「匹配任意 queue 即忽略 priority」的通用例外。  
3. 导出前校验：实际行的 priority/queue 与声明一致；否则失败。  
4. 每包：独立 `queue_id`、`revision`、样本集合摘要、行数、双审数、配套 meta；原生按优先级/用途/预算拆包。  
5. 导入：拒缺失/不匹配 meta、重复冲突、过期版本；不覆盖已有标注。  
6. 原始错误包只读保留用于追溯；新包用新 revision。

### 4.7 校准、发布与性能

- 先冻结独立校准/评测分组，再调阈值。  
- 分别测：高置信转写错误、关键语义错误、全空误判、噪声层风险、来源偏差。  
- 预先指定抽样设计、样本量、错误率上界；禁止看完结果改标准。  
- 发布：治理通过 + 伪标签抽审通过 + 评测金标独立。  
- 复用既有 ASR/DNSMOS；避免为改规则重跑全模型。与 016/017 协同保留缓存、断点、进度。性能优化不能代替规则修复。  
- 未确定验收策略时只允许**影子运行**。

## 6. 我怎么才算满意

### A. 功能验收（必须自动化或可脚本复现）

1. **守恒**：本批 30,000 条，每条恰好一个 disposition；风险标签可重叠；报告解释 queue 与 decision 计数差异。  
2. **导出交集**：P0+manual_review → **9,915** 且 P1=0；P1 独立 → **16,156**；pseudo_audit 无优先级行为有单独测试。  
3. **未校准**：全量 DNSMOS success 但未校准 → 报告 30,000 未校准；**不**生成 30,000 条质量失败转写任务；**不**伪造已校准。  
4. **治理**：全量 governance_hold → 发布阻断可见；显式小批校准可跑；人工标签不绕过治理。  
5. **同文语义**：复盘 88 条六路一致 → 模型间冲突标记消失；「不需要/需要」仍命中；语气/数字/重复/复杂肯否有回归。  
6. **质量反事实隔离**：4,971 基线可复现；乐观 2,634 **禁止**记为已发布训练数据。  
7. **路次幻觉**：任一路超长 → 路次异常处理；剩余家族不足仍阻断；有重试上限。  
8. **候选保留**：人工/暂存分支保留证据；正式盲包仍不可见答案；assisted 不进盲审统计。  
9. **预算**：派发不超过配置；双审计入；未选入 backlog；同音频复用可追溯、冲突不传播。  
10. **包身份**：每拆包 meta 匹配；错版本/错集合/重复冲突导入失败，保留原标注。

### B. 业务验收材料（门禁）

在冻结同一批次上提交：

- 旧→新 类别/队列/disposition 迁移矩阵；
- 人工唯一音频数、审核次数、人工分钟（试标实测）；
- 待处理积压、实际发布量、错误率（独立抽审，分关键语义/来源/质量层）；
- 在**不降低发布质量门槛**下证明人工成本下降且产生可用训练数据；  
  **只减少导出、不减少总待办 = 未完成**。

版本化验收策略须含：最低可用发布量、人工预算、错误率上限。若仍为零发布或预算不可达 → 验收失败并写明阻断。

**禁止**预先承诺「只需标 N 条」或「90% 自动通过」——缺乏听音校准时给这类指标会重复本次设计错误。
