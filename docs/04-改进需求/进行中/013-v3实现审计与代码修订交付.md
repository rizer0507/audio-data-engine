# 013：v3 实现审计与代码修订交付

日期：2026-09-10。依据：012 母需求及当前实际执行链。

交付边界：本次审计发现的核心执行链与门禁问题已落实代码修改。用户已明确接手测试，最终修改后不再执行完整测试或生产验收。本文件不是测试通过证明；012 母文档保持不变。

## 1. 审计结论

原实现不能仅凭 A～E 模块存在或已有单测通过判定满足 012。主要问题是评测抽样口径偏差、伪标签放行缺少独立抽检证据、人工审核边界不完整，以及发布门禁只消费点估计。以下为修订后的实现约束。

## 2. 输入、身份和隔离

- `prepare_dataset_v3` 默认消费完整音频底表，先冻结样本、音频哈希、泄漏组及用途；不能先按 ASR 结果删样本。
- 新增 `quality.attach_asr_v3` 和 `pipelines/attach_asr_v3.yaml`，将八个已登记的 ASR Manifest 左连接到冻结底表。
- 严格四家族、每家族两次识别。八个 transcript key、family、run_id 必须对应；不能用部分 `runs` 缩减检查范围。
- 接入时校验 artifact 内容、真实 execution_id、checkpoint/decode/prompt/input_audio 摘要、输入音频键和执行时间。同一产物或同一家族同一次执行不能冒充两次结果；独立执行允许使用相同模型参数。
- `artifact register-asr-run` 登记已有识别产物及用户提供的真实执行元信息，不重新识别，不推测执行身份。输入音频摘要按完整底表的 `id → original_audio_sha256` 计算。
- 缺失识别行保留为 `missing`；`text=null`、pending/running 不等于成功空输出。左连接的多余 ID 留下报告。
- 仅有 source_snapshot_id 不能证明通话隔离；不确定近重复必须隔离。通话、来源及文件/PCM 哈希的各有效字段均参与连通分组。
- 构建时拒绝重复 ID、冻结名单外 ID、变化的音频哈希；旧 reservation 缺少新增音频哈希证据时需生成新的版本。

主要代码：`core/selection_v3/{config,input_contract}.py`、`core/dataset_v3/{grouping,reservation}.py`、`operators/quality/attach_asr_v3.py`。

## 3. 分拣与噪声

- 未人工确认的 `gold_text` 为 null，不能写成已确认的空标签。
- 原始识别文本优先于展示清洗文本参与风险判定，保留否定、语气词和数字差异；负向片段外还有肯定内容时判为 mixed，未识别语义不默认为 neutral。
- 质量侧车拒绝重复键、缺失哈希及同 ID 不同音频；不能因错误 join 消费其他音频的噪声结果。
- DNSMOS 改为非 personalized P.835 逐窗校准、一秒滑窗、短音频重复扩展及内部重采样。版本为 `p835_official_nonpersonalized_v2`，旧分数不可直接作为新版本分数重算风险。
- 模型评分缓存与风险阈值计算分开；质量输出记录策略摘要，阈值变化不能沿用旧审计范围。
- 权重缺失报错；默认 `calibrated: false`，噪声等级仍为 unknown，不能将其自动放入伪标签训练池。

DNSMOS 算法依据：[Microsoft 官方实现](https://github.com/microsoft/DNS-Challenge/blob/master/DNSMOS/dnsmos_local.py)。真实音频分数一致性、速度和业务阈值由后续验收确认。

## 4. 标注与抽检

- 二审和抽检视图不显示模型候选；候选核对须已有首审记录，仲裁只消费冲突状态。
- 完成 speech/non_speech 标注必须填写 speech_scope、human_semantic、human_noise、human_crosstalk；non_speech 还须明确事件标签与空文本。
- 噪声、串音、事件标签和错误标签的不同也构成复核冲突。空标签必须双审，仲裁人必须独立于前两位标注人。
- 完成后的标注不能被普通导入覆盖；导入校验失败的诊断产物不能进入正式金标链。
- 导入必须保留原始 `.meta.json`，校验导出成员和不可编辑字段。队列 ID 包含内容身份；再次导出不会覆盖已填写的包。
- 普通单审样本按来源、类型、噪声和时长分层抽检；出现关键差异锁定该层并扩检，正式发布检查最低 10% 抽检覆盖。
- `has_formal_gold_evidence` 统一用于审计、构建及 v3 评测就绪检查，不能仅凭 `is_human_verified=true` 或 `second_review` 字符串放行。

### 伪标签独立审计

1. 运行 `review plan-audit-pseudo`，在标注前冻结完整候选范围、总体抽检及各保护层名单。
2. 从输出 Manifest 仅导出 `pseudo_audit` 队列；未抽中的候选保留在 `pseudo_audit_pool`。
3. 独立双审后运行 `review audit-pseudo --audit-plan <冻结计划>`。未完成人工标注的抽中条目必须阻塞，不得换样补足成功数。
4. 无预冻结计划的调用只生成诊断，不得通过；阈值配置变化须新建计划。
5. 审计报告绑定候选文本、音频、八路身份、噪声证据、规则、隔离版本和人工标注摘要。
6. 只有报告范围内且内容不变的候选能够得到放行戳。Release 再次校验报告及每个伪标签成员；`auto_accept` 或布尔标签不能替代报告。

主要代码：`core/annotation_v3/`、`core/dataset_v3/{audit,audit_plan}.py`。

## 5. 抽样与 Release

- eval_random 按原始样本抽取，同组多条允许入选；整组仍不进入 train/dev。补样仅消费冻结候补顺序且不得侵犯已分配的其他用途。
- non_speech 优先进入对应核心评测层，不因空文本长度被误分为 filler。
- Qwen 纠错池不能因为任意模型的错误标签直接认定 Qwen 错误。
- 训练四池随机抽样不满足交叉约束时，联合求解池配额、肯定/否定/有噪语音下限、伪标签/非语音上限、通话上限及去重约束；无可行解时保持阻塞。
- 任一配额不足或最大比例超限都阻止正式发布。`fail_on_shortfall=false` 不能绕过正式发布门禁。
- 同一 Release ID 的写入互斥；运行诊断放在 Release 目录外。常规异常撤销本次发布文件和注册记录。
- 幂等比较覆盖配置、Parquet、JSONL 和审计/采样/泄漏报告；命中前复核现有文件及目录注册记录。改变内容必须换 Release ID。
- 未选中的源条目写入 excluded，避免守恒统计丢失。输入顺序统一排序，避免分片顺序影响产物。

主要代码：`core/dataset_v3/{sampling,quota_solver,release}.py`。

## 6. 业务评测及执行入口

- 新增正式入口 `pipelines/eval_metrics_v3.yaml`，不复用旧评测流水线的全文热词置空步骤。
- 校验冻结 Release 成员、音频和 gold；失败/缺失预测不能当空文本。业务 CER 从实际参考与识别文本计算，不盲信过期的预计算 CER 字段。
- 主指标与 CER、肯定保留率、NSHR 的保护判断均消费组级配对置信区间；缺少有效分母、分组、区间或未知语义门限不能通过。
- eval_core 与 eval_random 分别判断；第三个参与比较的模型缺失结果时，不得被基线/候选的通过状态覆盖。
- `fail_on_business_gate=true` 时，needs_review 和 diagnostic_only 同样不能作为成功发布。
- TaskNode 支持 `waiting_exit_codes: [75]`。`review check-v3 --queue-meta ...` 未完成人审时返回 75，DAG 记录 waiting_review 并停止下游；拒收及已完成的不可用标注作为已完成排除结果，最终配额由 build 决定。

完整代码入口顺序：

```text
prepare_dataset_v3（完整底表、冻结用途）
→ register-asr-run × 8（已有结果和真实执行信息）
→ attach_asr_v3（严格接入八路产物）
→ audio_quality_sidecar + classify_dataset_v3
→ 人工队列 / plan-audit-pseudo / 双审 / audit-pseudo
→ build_dataset_v3（显式 reservation + audit_report）
→ 固定 Release 上识别
→ eval_metrics_v3
```

## 7. 交给使用者的配置项

- 填写八条真实 `runs` 身份及 artifact_id；提供可用的原始音频、通话/来源映射。
- 配置 DNSMOS 权重并完成人工校准，默认不自动改为 calibrated。
- 人审包填写新增必填项，导入时保留配套 metadata；历史仅有布尔金标标记的数据需补齐证据。
- 构建指定 release_id、reservation_path、audit_report_path；正式比较固定 baseline/candidate 别名和校准后的门限。
- 安装 DNSMOS 可选依赖时包含 librosa；旧评分、旧 reservation、旧审核包不能冒充新增契约产物。

代码交付与测试验收分开：本轮后续未执行测试、真实模型全量跑批、人工听审或生产切换。以上操作由用户自行执行，不将修改前或中途的测试结果作为最终版本验收结果。
