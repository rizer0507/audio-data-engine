## 1. 我想做什么

写一条**可复现的汇总入口**（脚本 + 可选 pipeline YAML），让我：

1. 指定**多个 batch** 及其分类/标注后的 parquet；
2. 指定要从中抽取的**数据类别**（五类中的任意子集）；
3. 合并成**一个完整、带固定版本号**的训练候选 parquet；
4. 对 `semantic_risk` 中人工标成「不做训练 / 不作训练语音信箱」等样本做清洗，**统一划入** `hardcase`；
5. 合并结束后输出**完整明细与汇总统计**，能一眼看清每个版本里有什么。

```text
batch_A parquet（含标注） ─┐
batch_B parquet（含标注） ─┼─→ 指定类别 + 清洗规则
batch_C parquet（含标注） ─┘
                              ↓
                    trainset_<version>.parquet
                    trainset_<version>.summary.json / .md
                    （明细：按 batch × category × 清洗动作）
```

## 2. 数据从哪来、结果要什么

### 2.1 输入


| 项    | 约定                                                                                   |
| ---- | ------------------------------------------------------------------------------------ |
| 主输入  | 每个 batch 一份 Manifest parquet（优先 `classified_*_${BATCH}_with_gold.parquet`；也可显式传任意路径） |
| 批次列表 | CLI / 配方 YAML 显式列出；禁止靠扫目录「猜」哪些 batch 进本版本                                            |
| 类别列表 | 显式列出要纳入的 `labels.category`（兼容顶层/`type` 回退读取，但**写入与统计以** `category` **为准**）           |
| 类别字段 | 清洗前读取：人工纠正优先 `reviewed_category`（若有）→ 否则 `labels.category` → 否则 `type`               |
| 训练文本 | 有 `labels.gold_text`（或约定的人工字段）的优先；本期**不强制**全员有金标，但汇总报告必须标明「有/无人工文本」条数                |


默认路径习惯（可覆盖）：

```text
datasets/stage1/derived/classified_five_class_v2_3_min_acoustic_${BATCH}_with_gold.parquet
# legacy 可改 stem，例如 classified_five_class_v2_2_auto_noise_${BATCH}_with_gold.parquet
```

### 2.2 输出（一个训练集版本一套产物）

建议落点：`datasets/stage1/trainsets/<trainset_version>/`


| 产物                       | 用途                                                |
| ------------------------ | ------------------------------------------------- |
| `manifest.parquet`       | 合并后的完整样本（真相源）                                     |
| `recipe.yaml`（或 `.json`） | 本版本配方：batch 列表、路径摘要、所选类别、清洗规则版本、生成时间、输入文件 SHA256  |
| `summary.json`           | 机器可读统计                                            |
| `summary.md`             | 人类可读明细总览（合并完成后必须完整展示）                             |
| `lineage.json`（可选但建议）    | 每条样本 → 来源 batch、源 parquet、原 category、清洗后 category |


**版本不可覆盖**：同名 `trainset_version` 已存在则失败，除非显式 `--overwrite`（默认关闭）。版本名由用户指定（如 `zh_asr_mix_20260921_v001`），脚本不得用「当前时间戳」冒充业务版本号（时间戳可进 lineage 元数据）。

### 2.3 规模

不清楚最终条数；实现不得写死总量上限。数量不足时按配方报告缺口，**不静默用其他类别填充**。

## 3. 业务规矩

### 3.1 多 batch 组装

1. 训练集从**多个 batch** 的 parquet 汇总而来。
2. 每个训练集必须绑定一个**固定版本**（`trainset_version`）。
3. 配方 =「哪些 batch + 每个/全局选哪些类别 + 清洗规则版本」；同一配方 + 同一输入摘要应可复现同一 Manifest（稳定排序：先 batch 顺序，再 `sample_id`）。
4. **跨 batch 同** `sample_id`：不得静默覆盖。默认策略：
  - 以 `(source_batch, sample_id)` 为行唯一键写入；  
  - 若检测到跨 batch 音频身份相同（如 `original_audio_sha256` 相同），写入 `summary` 的重复告警清单，并支持配置：`keep_first` / `fail`（首版默认 `fail` 更安全，或至少强制打印告警且 recipe 记录策略）。

### 3.2 `semantic_risk`「不做训练」清洗（硬规则）

在 `semantic_risk`（清洗前类别）中，人工标注文本若命中「不做训练」类标记，**不得进入训练正样本类别语义**，统一改写为：

```text
training_category / labels.category（写入策略见下） = hardcase
```

首版匹配规则（大小写不敏感；去首尾空白后整串或明显前缀等价均可，但必须版本化）：


| 标注文本示例                  | 动作                                                      |
| ----------------------- | ------------------------------------------------------- |
| `不做训练`                  | → `hardcase`，记录 `clean_reason=exclude_from_training`    |
| `不作训练`                  | 同上（容错异体）                                                |
| `不作训练语音信箱` / `不做训练语音信箱` | → `hardcase`，记录 `clean_reason=exclude_voicemail_marked` |
| 仅包含上述短语、无有效听写正文         | 同上；**不要**把这些短语当作 `gold_text` 训练目标                       |


实现建议：

- 保留原始人工字段到 `labels.annotation_raw_text` 或 `labels.gold_text_raw`；  
- 清洗后：`labels.gold_text` 置空或置约定占位（需在 recipe 写死一种，禁止半空半留）；  
- 另写 `labels.training_category=hardcase`，并写 `labels.category_before_clean`；  
- **是否同时改写** `labels.category`：首版建议**同时改写**为 `hardcase`（便于下游只看 `category`），并在 summary 中单独统计「由清洗划入 hardcase」条数。

匹配表放入小配置（如 `configs/selection/training_exclude_markers_v1.yaml`），禁止只硬编码在脚本里无法改版本。

### 3.3 类别选择

- 用户可指定例如：`gold_candidate,semantic_risk,hardcase`（不含 `voicemail` / `environment_noise` 等）。  
- 清洗**先于**类别过滤：先判定「不做训练 → hardcase」，再按「清洗后类别」决定是否入选。  
  - 例：配方只要 `semantic_risk`，某条原 `semantic_risk` 被洗成 `hardcase` → **不进入**本版本（并在 summary 记 `dropped_after_clean`）。  
  - 例：配方含 `hardcase`，上述样本 → **进入**，并在明细标清洗来源。

### 3.4 合并后必须完整展示的明细

`summary.md` / 控制台收尾打印至少包含：

1. **版本号**、生成时间、规则/清洗配置版本
2. **输入表**：每个 batch 的路径、文件 SHA256、原始行数
3. **按 batch × 清洗后 category** 的入选条数、时长合计（有 `duration` 则汇总）
4. **清洗动作统计**：不做训练 → hardcase 条数；其中「语音信箱标记」条数
5. **有/无** `gold_text` 条数（按清洗后类别）
6. **告警**：跨 batch 重复音频、缺音频引用、类别字段缺失、未识别的「不做训练」近义写法（可选：近义只告警不自动洗）
7. **抽样明细表**（全量可落到旁路 csv/parquet）：`sample_id, batch, category_before, category_after, clean_reason, has_gold_text`

「完整显示」= 统计 + 可追溯明细文件，不只是一行 total。

## 4. 现状澄清：分类脚本对「语音信箱」的筛选逻辑（及是否金标）

### 4.1 现行逻辑（v2.3 / 与 v2、v2.2 共用命中函数）

生产五分类（含 `selection_five_class_v2_3_min_acoustic`）对 voicemail 的判定是：

```text
任意一条「合格 route」的 ASR 文本
  （body_text / classify_text / transcript_text）
命中 voicemail 正则库
  → 立刻 category=voicemail（短路径，优先于 semantic_risk / noise / gold）
```

- 正则库：`configs/selection/voicemail_patterns_v1.yaml`（「语音信箱」「请留言」「通话已转至」「无法接通」「请按N」等模板）。  
- 命中函数：`_voicemail_hit`（`five_class.py` 等，v2.3 复用）。  
- v2.3 增量：若同时声学状态为 silence / non_speech，仅打 `needs_review` + `review_reason=voicemail_acoustic_contradiction`，**不降级、不改类**。  
- 决策：`decision=exclude`，`review_queue=voicemail_isolation`；这是**自动规则隔离**，不是人工金标。

### 4.2 这是不是「金标」？

**不是。**


| 维度    | 结论                                                                               |
| ----- | -------------------------------------------------------------------------------- |
| 依据    | ASR 转写上的**模板正则**，不是人工听音确认                                                        |
| 假阳性   | ASR 把正常通话听成「留言/转接」类词 → 误进 `voicemail`                                            |
| 假阴性   | 真实语音信箱但 ASR 未写出库内短语 → 落入 `semantic_risk` / `hardcase` 等                          |
| 与人工关系 | `semantic_risk` 听写里出现「不作训练语音信箱」正是在补「自动漏检/误检」的人工裁决                                |
| 训练含义  | 自动 `voicemail` **不能**当作可训练金标文本来源；是否纳入训练需另订配方（032 亦约定 voicemail 仅在业务需要且文本可靠时谨慎纳入） |


因此：本需求的「不作训练语音信箱 → hardcase」是**标注侧清洗**，与分类器自动 `voicemail` 桶是两条线；汇总时不要假设「所有语音信箱都已在 `voicemail` 类」。

```bash
  --version zh_asr_mix_20260921_v001 \
```

