# 012 · 四家族双跑分拣、噪声评分与人工金标数据集闭环

> 状态：待实现。本文定义目标行为，不表示现有能力已经满足。
> 版本：`selection_v3.0` / `annotation_v3.0` / `dataset_policy_v3.0` / `business_metrics_v1.0`。
> 输入：Kimi-ASR、GLM-ASR、SenseVoice、Qwen-ASR 四个家族，每家族两份全量识别结果；微调对象为 Qwen-ASR。
> 实施范围：工序一的分拣、音频质量、人工标注、数据集构建，以及工序三的准入和指标适配。复用现有执行引擎、ASR、Catalog、审核与 Release 能力。
> 本需求统一承接进行中 007、008、009 的相关目标，取代其与本文冲突的设计；v1/v2 保留用于复现。不得直接覆盖旧分拣产物。

## 1. 目标与硬约束

交付可复现链路：

```text
数据源快照 + 音频分组/查重 + 八路 ASR
  → DNSMOS 独立评分
  → 四家族状态与业务风险分析
  → 候选分类 + Qwen 纠错价值 + 人审队列
  → 人工听审 / 双审 / 仲裁 / 伪标签抽检
  → train / dev / eval_core / eval_random 独立冻结
  → Qwen Base / LoRA / Full SFT 在相同评测集上的 CER + 业务风险指标
```

必须满足：

1. 同家族两次推理用于发现不稳定性，最多计一票；四家族也可能共同出错，共识不等于真实标签。
2. Qwen 不担任金标基准，不享有投票加权；Kimi、GLM、SenseVoice 是三个辅助家族，不预设某一个绝对正确。
3. 任何一路出现业务语义冲突都须保留，禁止用族内 medoid 或多数票掩盖。
4. 正式评测仅用经验证的人工/外源金标；伪标签只允许进入通过抽检门禁的训练子集。
5. 输入已是上游切分段，不新增、不调用、不依赖 VAD；不生产 `speech_ratio` / `vad_edge_risk`。
6. DNSMOS 只衡量音频质量，不能判定无人声、串音、说话人归属或语义正确性。
7. 原始音频与八路原文只读；禁止自动拼接多个转写创造标签，禁止将“不”“嗯”等关键内容清空。
8. 所有阈值、词表、配额、审核规则版本化；校准未通过时允许分拣和送审，禁止自动发布伪标签训练集。

## 3. 输入契约与八路对齐

### 3.1 显式家族配置

```yaml
engine: consensus_v3
rule_version: selection_v3.0
target_family: qwen
model_families:
  kimi: [kimi_1, kimi_2]
  glm: [glm_1, glm_2]
  sensevoice: [sensevoice_1, sensevoice_2]
  qwen: [qwen_1, qwen_2]
teacher_families: [kimi, glm, sensevoice]
expected_runs_per_family: 2
```

别名可配置，不从文件名前缀猜家族。Kimi 本地/vLLM 两种运行方式仍属于同一 Kimi 家族。

每份结果登记：`run_id`、`family`、`model/checkpoint_digest`、`decode_config_digest`、`prompt_digest`、`input_audio_digest`、`input_audio_key`、`created_at`。同一产物复制两次不得算“双跑”；两次真实独立执行即使参数和文本完全相同也可接收。

每条音频必须有稳定 ID、原始路径、`sha256`、`duration`、`source_snapshot_id`、`source_audio_id`、分组字段。兼容旧 ID，但跨源必须使用带来源命名空间的唯一键。

### 3.2 状态不能与文本混淆

每一路显式区分：`success_text`、`success_empty`、`failed`、`missing`。

- 以音频快照为底表对齐八路，校验 ID、原音频哈希及血缘；不同推理音频变体通过原音频血缘关联，不比较 pad 文件与原文件哈希相等。
- 重复 ID、家族配置重复、相同 ID 对应不同原音频：整批 fail-fast。
- 推理侧额外 ID 输出报告；正式八路快照禁止混入其他数据源。
- 单条 missing/failed 保留为 `inference_incomplete`，生成补跑清单，不当作空转写，不进自动伪标签。
- 守恒报告：输入数 = 物理无效数 + 推理不完整数 + 可分类数；质量评分失败另列交叉统计。
- 质量侧车和所有聚合字段必须按 ID + 原音频哈希连接，禁止按行位置连接。

## 4. DNSMOS 质量侧车

新增 `quality.dnsmos` 与 `pipelines/audio_quality_sidecar.yaml`，输入未 pad 的 `resampled_16k`，与 ASR 独立执行，分拣前合并。

输出：

```text
quality.dnsmos_sig / dnsmos_bak / dnsmos_ovrl
quality.dnsmos_status = success | failed | unsupported
quality.dnsmos_model_digest / dnsmos_preprocess_version
quality.noise_band = clean | moderate | noisy | unknown
quality.noise_risk = true | false | null
quality.quality_policy_version
```

实现要求：

- 封装外部 DNSMOS P.835 的固定版本与模型文件，不修改其他环境的源码；缓存含音频、模型、预处理版本。
- 按固定官方实现处理短片段、窗口和聚合；短于窗口时的重复/补齐只在推理内部进行，记录策略，不改变原音频或时长。
- 缺模型文件/配置错误在启动时失败；单条推理失败保留错误，`noise_band=unknown`，不得写默认干净分。
- 单独持久化 SIG/BAK/OVRL；噪声阈值变更只重算风险，不重跑模型。
- `noise_risk = (BAK < T_bak) OR (OVRL < T_ovrl)`；任一分数无效或缺失时为 `null`。clean/moderate/noisy 的有序阈值也必须显式配置。
- 阈值在独立人工校准池上按原始时长、录音来源验证，保存配置和混淆统计；未校准可输出分数，但风险为 unknown。
- `noisy/unknown` 均禁止自动进入高置信伪标签；不删除有语音的噪声难例，优先听审。
- 全部 ASR 为空，即使 BAK/OVRL 很低，也不得自动标空。干净高分也不构成人声或正确转写证明。

## 5. 家族状态与共识

### 5.1 两套文本用途

- `raw_text` 永久保留。
- `comparison_text` 仅做 Unicode、全半角、空白、配置允许的标点归一化；保留否定、语气词、脏话、重复反馈和关键数字。
- 中文数字、金额、日期允许附加规范化实体用于比较，不覆盖原文，不默认把模糊表达归并为相同。
- 文本相似度：`1 - levenshtein(a,b) / max(len(a),len(b))`；双空相似度可定义为 1，但空输出不参与文本伪标签投票。
- 业务极性是当前片段可观察表达，不推断完整客户意愿；上下文不足时标 unknown。

### 5.2 家族状态

按以下顺序，每家族只取一个状态：

1. `incomplete`：任一路 failed/missing。
2. `stable_empty`：两路均成功且为空。
3. `unstable_presence`：一路成功空、另一路成功非空。
4. `unstable_semantic`：两路出现极性、关键 token/实体、语气词正向化或拒绝美化冲突。
5. `stable_text`：两路非空、无上述风险、相似度 ≥ `family_threshold`；短句必须 comparison_text 完全一致。
6. `unstable_text`：其余。

初始配置：`family_threshold=0.98`；短句为原时长 ≤2 秒或任一路非空文本 ≤6 字。阈值需校准。

`stable_text` 才能提供文本票，每家族一票。其他状态用于风险分析，不计正票；支持率分母始终是配置中的四个家族，不随弃权减少。两条转写选 medoid 平分时按固定 run_id 排序，且保留双方。

### 5.3 跨家族共识

- cluster 必须满足成员两两相似度门槛，不允许 A≈B、B≈C、A≠C 的传递连接冒充全体一致。
- 计算 `support_family_count`、`support_ratio_of_4`、`teacher_support_count`、`min_similarity`。
- 候选文本从获支持家族的真实输出取 family-balanced medoid；每家族总权重相同，并列按 family/run_id 排序。
- 簇内一致度同时核验支持家族的两路原始 comparison_text，不能只检查代表文本。
- 多个最大簇并列且文本不同，标 `consensus_ambiguous`，送审，不用字典序宣称唯一共识。
- 三个 teacher 同意、Qwen 不同，只能判 Qwen 纠错候选，不能自动认定 teacher 正确。

## 6. 风险标签、主类别与 Qwen 纠错价值

### 6.1 先计算全部风险标签

`risk_tags` 多选，基于全部八路有效原文计算；不能先丢弃不稳定家族。

- `negation_flip`：明确肯定与明确否定冲突，如“需要/不需要”。
- `false_affirmation_candidate`：非肯定表达与肯定表达冲突。
- `filler_affirmation`：“嗯/啊/哦/呃”等与“需要/可以/是/有/好的”等冲突。
- `rejection_sanitization`：拒绝、抱怨、粗口与肯定表达冲突。
- `critical_token_conflict`：否定、意愿词、数字/金额/日期等关键内容有无或值冲突。
- `presence_conflict`：成功空与成功非空并存。
- `short_utterance`、`family_instability`、`noisy_audio`、`quality_unknown`。
- `crosstalk_suspected`：仅来自人工/可信外部特征；ASR 分歧本身不能确认串音。

极性取 `positive/negative/neutral/mixed/unknown`。最长短语匹配与否定作用域优先；“不是不要”“不是不需要”等复杂表达无法可靠解析时设 mixed/unknown 并送审。禁止简单 contains“需要”就判 positive。跨家族共识不能消除同家族内部风险。

### 6.2 主类别：先计算风险，再按顺序取一个 type

1. `invalid_audio`：无法解码或时长无效 → exclude。
2. `inference_incomplete`：八路未完成 → retry；仅在补跑失败经批准后进入人工可标队列。
3. `semantic_risk`：命中 negation_flip / false_affirmation_candidate / filler_affirmation / rejection_sanitization → manual_review，P0。
4. `critical_content_risk`：关键 token/实体冲突，或 mixed 表达无法解析 → manual_review，P0。
5. `all_empty_unverified`：八路成功空 → manual_review，P1；禁止自动空标。
6. `speech_presence_disagreement`：成功空与非空混合 → manual_review，P0（非空含肯定词）或 P1。
7. `voicemail_candidate`：至少两个稳定家族、各自两路命中语音信箱规则，且前面风险未命中 → 专项隔离队列，P2；不进入普通伪标签池。
8. `qwen_correction_candidate`：三个 teacher 均稳定并形成相似度 ≥0.98 的共识，而 Qwen 不稳定或任一路与该共识低于门槛 → manual_review，P1。
9. `family_unstable`：任一家族不稳定 → manual_review，P1。
10. `audio_quality_risk`：DNSMOS noisy/unknown，或有可信串音风险 → manual_review，P1。
11. `pseudo_high`：满足 §6.3 → audit_pending；抽检放行后 auto_accept。
12. `pseudo_medium`：至少三稳定家族形成 ≥0.95 共识，剩余家族未触发前述风险，但不满足 high → manual_review，P2；首版不直接进入训练。
13. `hardcase`：其余，包括 2:2、两个家族支持、无唯一共识 → manual_review，P2。

`type` 只描述候选原因，人工导入后保留，不改成 `human_gold`。真实错误归因另写 `verified_error_tags`。

Qwen 价值字段与 type 并存，避免 Qwen 难例被高优先级桶覆盖：

```text
qwen_status / teacher_consensus_status
qwen_vs_teacher_similarity_1 / qwen_vs_teacher_similarity_2
qwen_risk_tags / qwen_correction_candidate
qwen_verified_error_1 / qwen_verified_error_2  # 仅人工真值后计算
```

Qwen 两路与 teacher 的比较只命名为 agreement，不当作真实准确率。人工发现四家族共同错误也应进入 Qwen 纠错池。

### 6.3 pseudo_high 候选与自动训练准入

1. 八路均成功非空，四个家族全部 stable_text。
2. 四家族共同簇覆盖全部八路，最小相似度 ≥0.98；短句全部八路 comparison_text 完全一致。
3. 八路关键 token/实体一致，极性相容；mixed 或检测到语义风险禁止通过。普通不含意愿词的中性陈述可通过，不强制命中肯定/否定词。
4. DNSMOS 成功、noise_band 为 clean/moderate；无已知串音风险。
以上四项决定 `type=pseudo_high`，与数据用途、审计是否完成无关；避免 eval 保留样本因用途不同被错误归为 hardcase。自动训练准入另须同时满足：

5. 不在 eval/dev/校准保留组内，无数据治理隔离标记。
6. 对应规则版本、模型组合和质量分层通过 §8 抽检门禁；此前保持 audit_pending。

写 `candidate_text`、`label_tier=pseudo_high`、`label_source=model_consensus`，不写 `is_human_verified=true`，不将 candidate_text 冒充最终人工 gold_text。

## 7. 人工标注契约

### 7.1 必填字段

```text
sample_id / original_audio_sha256 / queue_id / queue_revision
annotation_state = pending | annotated | second_review | conflict | adjudicated | rejected
gold_kind = speech | non_speech | unintelligible | ambiguous_target | invalid
gold_text = null | "" | 非空文本
speech_scope = target | background_only | mixed | none | unknown
human_semantic = positive | negative | neutral | mixed | unknown | not_applicable
human_noise = clean | moderate | noisy | unknown
human_crosstalk = true | false | unknown
verified_error_tags[]
annotator_id / reviewer_id / adjudicator_id / timestamps / annotation_revision
```

- `null` 表示未完成/无法确认；`""` 只表示人工确认的非语音空真值，两者不可互换。
- speech 要求非空逐字转写；保留“嗯、啊、不、没”、口吃和实际拒绝，不润色、不补全、不根据业务意愿改词。
- non_speech 要求 `gold_text=""`、明确音频事件标签（静音/环境声/音乐/忙音等）及人工确认；不填“噪声”作为识别目标文本。
- 听到人声但听不清，标 unintelligible，不标空；能听到多个说话人但无法确定目标，标 ambiguous_target，不猜金标。
- 标注协议固定目标：优先按来源提供的客户声道/角色标记；缺少角色证据且多人声时不得凭文本推断客户。背景人声不能作为 non_speech；是否训练为空取决于另行明确的目标说话人抑制任务，首版隔离。
- 混合语音仍可可靠确认目标且完整转写时，允许 speech + human_crosstalk=true。局部不可辨认片段首版不导出完整句训练标签。
- 可信外源按同一字段契约导入，记录供应方、标注协议、版本和验收记录；普通 xlsx 上传不自动授予 trusted_external。

### 7.2 听审流程

1. 一审先听未 pad 原音频，填写独立转写与标签，再显示匿名、随机顺序的候选供核对；顺序种子可追溯。
2. 正式 eval 全量、P0、所有拟采用空金标及高置信伪标签抽检样本必须由不同标注员独立双审；二审看不到一审答案或家族名。
3. 两审在关键词、转写、gold_kind、目标说话人或极性上不同，进入第三人仲裁；无法裁定则 rejected/隔离。
4. 其他训练人审样本单审后按来源与风险分层复核至少 10%；发现关键错误则扩大该层复核。
5. 只有通过规定审核级别的样本写 `label_tier=gold`、`label_source=human`、`is_human_verified=true`；不允许操作员用一个 accepted 绕过二审。
6. 导入校验队列、样本、哈希、标注员与 revision；拒绝未知/重复 ID、旧版覆盖、不可编辑列改动。部分导入只推进已完成样本，其余保持 pending。
7. 每次导入写新 annotation artifact，不改原八路转写、不覆盖历史分类；人工标签升级不触发重新分配 eval 到 train。

首版用独立 XLSX/JSONL 审核包与已有人工工具完成，不要求开发完整标注 Web 平台。盲审包不包含可直接看到的模型答案；需要候选核对时提供独立的后续视图。

## 8. 审核预算与伪标签放行

- P0 全部进入待审队列；标注预算不足时按优先级选批，未审部分留池，不因积压放宽自动准入。
- P1 内优先：Qwen 存在肯定幻觉候选、teacher 一致/Qwen 错、短否定句、全空、噪声与串音。
- P2 按来源、时长、质量、家族状态分层选取；每层使用稳定种子和组内去冗余，不能只挑最长或最容易的文本。
- 首轮校准池目标 3000 条，可配置 2000～5000，来源只能是开发池；用途 `calibration`，不进入正式评测。词表、DNSMOS 阈值、相似度阈值只在该池调节。
- 规则冻结后从拟自动接受的训练候选中另抽独立审计样本：每个生产批次均匀随机抽至少 500 个不同泄漏组，每组随机一条；该统计明确命名为“组均衡误标率”，不冒充按音频条数加权的总体错误率。不得用调阈值的校准样本自证质量。
- 初始自动发布门禁：总体组均衡文本错误率 Wilson 95% 区间上界 ≤1%；关键语义错误观测数必须为 0；短句、否定、肯定、moderate 质量等受保护层各随机抽至少 200 个独立组、每组一条，层内上界 ≤2%。文本错误指 comparison_text 与人工转写不一致，关键语义错误另计。
- Wilson 使用双侧 95% 区间的上端点（z=1.96）。各层分别报告 n、错误数、区间、种子；重叠审核记录可复用，但不得将加抽层直接混入总体样本计算错误率。不足样本数的层全量人工确认或保持不放行；如需联合置信结论另配置多重比较校正，不宣称这些单独区间具有联合 95% 置信度。
- 发现关键语义误标立即停止相关层伪标签发布，回查规则，生成新版本后重新独立抽检。禁止回写修改已冻结 Release。
- 每次新增来源、改变八路模型/提示词/预处理、修改规则或噪声阈值，重新获得对应范围的审计证据。抽检门禁是工程验收标准，不代表总体绝对无误。

## 9. 数据隔离：先保留评测，再采训练

### 9.1 泄漏组

按以下关系建无向图并取连通分量为 `leakage_group_id`：

- 同 `call_id/conversation_id`；有可靠客户/说话人标识时按配置并入同组。
- 同 `source_audio_id` 的切片、增强版本。
- 相同文件哈希或规范化解码 PCM 哈希。
- 已确认近重复指纹关系；保存算法、阈值与匹配证据。

分组字段必须从来源索引解析，不能盲猜文件名前缀。缺来源/通话映射的样本可分拣和人审，但进入治理隔离池；首版不得发布到声称无通话泄漏的正式训练/评测组合。元数据补齐后再解锁。

相同内容去重在训练中只保留代表，不删除历史记录；随机评测按原始目标分布采样，允许相同内容保留出现频次，但推断时按泄漏组处理相关性。近重复不确定匹配先隔离确认，不以相同文本判音频重复。

### 9.2 固定分配顺序

1. 冻结原始输入快照、原始 ID 列表、分组映射与目标分布定义。
2. 在查看模型错误和调整分拣规则前，按原始样本 ID 等概率随机选 `eval_random`，锁定其全部泄漏组；种子和完整候补序列固化。
3. 从剩余组预留 `eval_core_reserve`（默认按组哈希 15%）；其余为开发池。专项集只从该 reserve 选取，避免边挑训练边反向挪评测。
4. 开发池中独立预留 calibration 和 dev 组，剩余才是 train pool。默认 dev 占开发池组数 10%，calibration 按目标条数逐组选取。
5. 规则与质量阈值只用 calibration，模型/训练参数只用 dev。专项集构建规则冻结后才在 eval_core_reserve 分拣、抽样、听审。
6. 所有未入选的 eval 保留组仍禁止进入当轮 train/dev/calibration；禁止因难标、空标、Qwen 已识别正确而回流。

如历史模型结果已被查看，记录评测设计形成时间与已使用信息；不宣称历史数据是从未观察的独立测试。新微调结果不得参与修改已冻结评测集。

## 10. 评测集构建与冻结

### 10.1 eval_random_v001

- 目标 2000 条，均匀抽自原始片段总体，不能先按 ASR 是否非空、噪声分数、共识、类别或 Qwen 错误筛选。
- 保留真实出现的语气词、噪声、空片段与重复频次；整组锁定但只审核入选片段。
- 解码失败、无法确定真值等样本记录为不可评估，报告原始入选数、有效数、排除原因；不悄悄换成容易样本。
- 如补量，只按冻结候补顺序补，并保留初始样本队列的覆盖率统计；报告指标适用范围是可评估子集，不能冒充全体原始分布。

### 10.2 eval_core_v001

默认 2000 条，按人工最终属性形成互斥主层，按以下顺序归层：

1. 明确否定/拒绝：500。
2. 纯语气词/中性短反馈：300。
3. 人工确认无人声（含环境噪声、忙音、静音）：300。
4. 含可辨目标语音的噪声/串音：300。
5. 明确肯定：300。
6. 其他普通语音和难例：300。

跨层属性仍以多标签保留，例如带噪否定句属于第 1 层，同时进入 noisy 切片。初始候选按 v3 风险标签过采样，人工属性确定后补齐；不得按微调模型表现补样。

每层覆盖来源和原时长；否定层覆盖“不需要/不用/不要/没有/不是”等不同表达，不能全是同一句。teacher 同意/Qwen 不同的难例与四家族一致的普通样本都要覆盖。报告注明专项集非自然分布，不能与 random 简单平均成线上指标。

### 10.3 通用门禁

- 两套 eval 必须 100% 完成双审/仲裁或等价外源验收；有 speech 与 confirmed non_speech 的空真值。
- `unintelligible/ambiguous_target` 单独存弃权集合，报告覆盖率，不作为空金标计算。
- eval_core 与 eval_random 组间无交集；与 train/dev/calibration 也无 ID、文件/PCM 哈希、源音频、通话或已确认近重复组交集。
- 配额不足输出 shortfall，正式构建失败；明确修改配额需新配置版本，不能自动重复样本凑数。
- 冻结音频引用及内容哈希、人工真值、全部标签、抽样名单、分组映射和版本；后续修标生成新版本。
- 训练新增数据也要检查已冻结 eval 的全体保留组，不能只检查最终入选 ID。

## 11. Qwen 训练集与 dev

### 11.1 准入与目标文本

- 人工/可信外源 speech：以 gold_text 为训练目标。
- 通过独立抽检的 pseudo_high：以 candidate_text 为训练目标，保留伪标签身份；不写入 human gold。
- pseudo_medium、未审风险样本、缺失推理且未完成人工例外审核、不可辨/目标不明：不进入训练。
- 人工 non_speech：仅训练适配器经测试支持空转写目标后加入，仍包含必要的模型任务模板与结束 token；否则形成独立待接入清单，禁止改成“噪声”或静默丢弃。
- dev 仅使用开发保留组中的人工/可信外源金标，含业务风险和自然样本两种统计视图；不使用正式 eval 选 epoch 或调参数。

### 11.2 默认配额

训练目标条数 `train_size` 必填，首轮建议 10000；采用四个互斥池，按顺序归池：

1. **40% Qwen 已确认错误修正**：人工真值证明 Qwen 任一路关键或普通转写错误，优先语义、语气词正向化、噪声幻觉。
2. **20% 其他人工高风险样本**：不属于第 1 池的短句、否定、噪声、串音等；保留 Qwen 已识别正确的风险样本，避免只学“全部否定”。
3. **20% 人工普通样本**：不属于前两池，覆盖肯定、否定、中性和正常长句。
4. **20% 审计通过的 pseudo_high**：普通能力保持；排除已入前三池者。

全体再施加交叉约束：肯定与否定语音各 ≥15%；可辨带噪/串音语音 ≥10%；non_speech ≤10%；pseudo_high ≤20%。这些是首版可修改实验配方，不是效果保证。各百分比以最终训练条数为分母，辅助报告音频小时分布。

按 source、时长、语义、质量层做确定性配额分配；无放回、每个 exact duplicate 仅一份，默认同通话最多 3 条。优先满足硬隔离与标签门禁，再满足配额；不足输出缺口，不自动复制、降低金标等级或超额填伪标签。

v3 首版通过配额控制，不假定训练框架支持 sample_weight；扩展权重必须由适配器显式声明支持并验收。增广只对 train 执行，继承原组和 split，单独记录增强比例。

## 13. 业务评测与回归门禁

扩展统一 MetricRunner；每个指标必须输出 `numerator/denominator/value/eligible_count/excluded_count`，分母为 0 输出 null，禁止记为 0%。

以下为本项目 v1 指标定义，语义判定器须版本化并用人工标注校准：

- **CER**：仅 gold_kind=speech 的可评估样本，`sum(S+D+I)/sum(reference_length)`；同时报 S/D/I 率。non_speech 单独统计，不混入主 CER。
- **NFR**：人工明确 negative 样本中，输出被判 positive 的条数 / 人工明确 negative 样本数。
- **FAR**：人工明确无肯定的样本（negative、neutral、确认 non_speech）中，输出被判 positive 的条数 / 这些样本总数。mixed/unknown 不进分母。
- **NAHR**：人工 non_speech 且音频事件含环境噪声/忙音/音乐的样本中，输出被判 positive 的条数 / 此类样本数；纯静音单独报同口径切片。
- **FAER**：人工确认纯语气词/中性短反馈的样本中，输出被判 positive 的条数 / 此类样本数；不把“嗯，我不需要”当纯语气词。
- **NSHR**：全部人工 non_speech 中，输出任意非空文本的条数 / 人工 non_speech 样本数。
- **肯定保留率**：人工明确 positive 中输出仍为 positive 的条数 / 人工 positive 样本数，防止通过全部输出空/否定降低风险指标。
- **推理失败率**：失败或缺失预测数 / 应预测样本数；与真实 success_empty 分开。

输出 mixed/unknown 的预测不算已确认 positive，但单独报语义不可判率与“unknown 全算风险”的保守上界；正式提升结论须完成影响结论的模糊样本裁定或满足预设不可判门禁，禁止通过让判定器认不出文本降低风险率。

正式比较要求固定样本上预测齐全；任一模型 failed/missing 可以出诊断报告，但发布门禁为 incomplete，不按模型分别删样本或将失败填空。配对置信区间按 leakage_group 重采样，防止同一电话多片段虚增统计量。

报告分别展示 eval_core、eval_random，总体及否定/肯定/语气词/短句/噪声/串音/来源切片；Base 和每个微调权重使用相同解码设置。每个权重固定一个主评测运行，第二次仅报告稳定性，不能择优挑运行。

发布门禁配置包括：主业务指标、最小有意义改善量、CER/肯定保留率/NSHR 非劣容忍度、置信水平、最低分母、最大语义不可判率。初版不硬编码未经业务校准的增益阈值；缺配置或样本不足返回 needs_review，不自动 pass。仅主指标满足改善且保护指标未退化才可 pass。

## 15. 验收用例

### 15.1 判定正确性

- 四家族双跑均为“我不需要”：短句完全一致且质量/审计通过 → pseudo_high，仍不得正式 eval。
- 三个 teacher 都“我不需要”，Qwen 两路“我需要”：semantic_risk + qwen_correction_candidate，必须人审。
- Qwen 两路分别“需要/不需要”，其余六路一致“需要”：P0，不能丢弃 Qwen 负向输出后自动接受。
- 七路“需要”、一路“不需要”：P0，不按 7:1 自动收。
- 六路“嗯”、两路“需要”：filler_affirmation，P0。
- 一路“别再打电话”、其他输出肯定：拒绝美化风险，P0。
- 八路都成功空，无论 DNSMOS 高低：all_empty_unverified，必须人审。
- 七路空、一路“好的”：presence_conflict，P0；人工 non_speech 后才能作为空目标。
- 一路失败、七路空：inference_incomplete，不能当作八路空。
- 三 teacher 仅普通字词一致、Qwen 错字：无语义风险时 qwen_correction_candidate。
- 家族内部一空一非空：unstable_presence，不算稳定文本票。
- 2:2 或相似度传递链：不得自动伪标签。
- 四家族高一致但 DNSMOS noisy/unknown：送审，不自动收；八路一致也能被抽检发现共同错误。
- 双重否定、数字金额冲突、背景人声、语音信箱与语义风险同时命中均有独立测试。

### 15.2 标注与数据安全

- accepted non_speech 空字符串可完整经过审核、Release、支持空目标的训练导出及 eval；pending/null 和 unintelligible 不得通过。
- 一审填完不等于双审完成；同标注员自审、冲突未仲裁、旧 revision 导入均被拒绝。
- 人工导入保留原 type/risk_tags/八路原文；人审 gold 与 candidate_text 独立。
- 不同路径相同音频、同通话、同源切片、增强、已确认近重复跨集合均阻断发布。
- eval 保留但未入选的同组样本也不得进入训练；缺 group 元数据不能静默退回按 ID 随机拆分。
- 随机集名单不因 ASR、DNSMOS、分类或新模型结果变化；所有排除可追溯。
- 输出配额不足、审计失败、标注未完成时不得宣称生成正式 Release。
- 同输入、配置、版本、seed 在不同顺序/分片/续跑下得到相同分类、采样 ID 与内容摘要。
- 重复发布幂等；同 ID 不同内容先失败，不覆盖既有文件。

### 15.3 指标与工程

- CER、NFR、FAR、NAHR、FAER、NSHR、肯定保留率分别有可人工核算的分子分母测试；零分母 null、失败预测 incomplete。
- 全输出空不会通过肯定保留率；未知极性不能制造虚假的低风险通过。
- DNSMOS 以固定真实 WAV 验证原始分数与所固定官方实现一致（容差配置），覆盖短片段、采样率、失败隔离和缓存失效；不得用 mock 宣称模型评分验收通过。
- 质量特征传到分拣后，noisy 开关确实改变自动接收决策；任何高相似度仍不能覆盖 P0。
- 单元测试覆盖纯逻辑；离线集成验证八路聚合→分类→双审导入→冻结→多模型报告；最后在目标机器逐级 1k/10k/全量验证吞吐、内存、守恒与恢复，报告实际测得数据。
- 回归现有 v1/v2、独立 ASR 和外源金标路径。更新 docs 索引、工序总览、规则规范、执行手册及命令台账，注明 v3 生产切换门禁；未通过人工校准不得修改生产默认。

## 16. 实施顺序

1. **A：契约与隔离**——八路身份、空/失败区分、分组、评测预留与 immutable artifact。
2. **B：质量与分拣**——DNSMOS、四家族状态、全八路风险、Qwen 价值、v3 分类，先只输出候选。
3. **C：人审**——空金标、盲审、双审、仲裁、revision、独立抽检门禁。
4. **D：数据集**——人工校准、固定双评测集、dev、训练配额、跨集防泄漏、原子 Release。
5. **E：评测与切换**——业务指标、固定权重比较、集成/规模验证，证据通过后切生产默认。

每阶段分别提供实现清单、测试结果和剩余阻塞；工程完成与人工数据验收完成分开记录。
