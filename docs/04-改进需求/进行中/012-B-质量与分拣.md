## 1. 目标与硬约束（母文档 §1，全局适用）

交付可复现链路：

```text
数据源快照 + 音频分组/查重 + 八路 ASR
  → DNSMOS 独立评分
  → 四家族状态与业务风险分析
  → 候选分类 + Qwen 纠错价值 + 人审队列
  → 人工听审 / 双审 / 仲裁 / 伪标签抽检
  → train / dev / eval_core / eval_random 独立冻结
  → Qwen Base / LoRA / Full SFT 在相同评测集上的 CER + 业务风险指标
```

必须满足：

1. 同家族两次推理用于发现不稳定性，最多计一票；四家族也可能共同出错，共识不等于真实标签。
2. Qwen 不担任金标基准，不享有投票加权；Kimi、GLM、SenseVoice 是三个辅助家族，不预设某一个绝对正确。
3. 任何一路出现业务语义冲突都须保留，禁止用族内 medoid 或多数票掩盖。
4. 正式评测仅用经验证的人工/外源金标；伪标签只允许进入通过抽检门禁的训练子集。
5. 输入已是上游切分段，不新增、不调用、不依赖 VAD；不生产 `speech_ratio` / `vad_edge_risk`。
6. DNSMOS 只衡量音频质量，不能判定无人声、串音、说话人归属或语义正确性。
7. 原始音频与八路原文只读；禁止自动拼接多个转写创造标签，禁止将“不”“嗯”等关键内容清空。
8. 所有阈值、词表、配额、审核规则版本化；校准未通过时允许分拣和送审，禁止自动发布伪标签训练集。

## 3. DNSMOS 质量侧车（母文档 §4 全文）

新增 `quality.dnsmos` 与 `pipelines/audio_quality_sidecar.yaml`，输入未 pad 的 `resampled_16k`，与 ASR 独立执行，分拣前合并。

输出：

```text
quality.dnsmos_sig / dnsmos_bak / dnsmos_ovrl
quality.dnsmos_status = success | failed | unsupported
quality.dnsmos_model_digest / dnsmos_preprocess_version
quality.noise_band = clean | moderate | noisy | unknown
quality.noise_risk = true | false | null
quality.quality_policy_version
```

实现要求：

- 封装外部 DNSMOS P.835 的固定版本与模型文件，不修改其他环境的源码；缓存含音频、模型、预处理版本。
- 按固定官方实现处理短片段、窗口和聚合；短于窗口时的重复/补齐只在推理内部进行，记录策略，不改变原音频或时长。
- 缺模型文件/配置错误在启动时失败；单条推理失败保留错误，`noise_band=unknown`，不得写默认干净分。
- 单独持久化 SIG/BAK/OVRL；噪声阈值变更只重算风险，不重跑模型。
- `noise_risk = (BAK < T_bak) OR (OVRL < T_ovrl)`；任一分数无效或缺失时为 `null`。clean/moderate/noisy 的有序阈值也必须显式配置。
- 阈值在独立人工校准池上按原始时长、录音来源验证，保存配置和混淆统计；未校准可输出分数，但风险为 unknown。
- `noisy/unknown` 均禁止自动进入高置信伪标签；不删除有语音的噪声难例，优先听审。
- 全部 ASR 为空，即使 BAK/OVRL 很低，也不得自动标空。干净高分也不构成人声或正确转写证明。

## 4. 家族状态与共识（母文档 §5 全文）

### 4.1 两套文本用途

- `raw_text` 永久保留。
- `comparison_text` 仅做 Unicode、全半角、空白、配置允许的标点归一化；保留否定、语气词、脏话、重复反馈和关键数字。
- 中文数字、金额、日期允许附加规范化实体用于比较，不覆盖原文，不默认把模糊表达归并为相同。
- 文本相似度：`1 - levenshtein(a,b) / max(len(a),len(b))`；双空相似度可定义为 1，但空输出不参与文本伪标签投票。
- 业务极性是当前片段可观察表达，不推断完整客户意愿；上下文不足时标 unknown。

### 4.2 家族状态

按以下顺序，每家族只取一个状态：

1. `incomplete`：任一路 failed/missing。
2. `stable_empty`：两路均成功且为空。
3. `unstable_presence`：一路成功空、另一路成功非空。
4. `unstable_semantic`：两路出现极性、关键 token/实体、语气词正向化或拒绝美化冲突。
5. `stable_text`：两路非空、无上述风险、相似度 ≥ `family_threshold`；短句必须 comparison_text 完全一致。
6. `unstable_text`：其余。

初始配置：`family_threshold=0.98`；短句为原时长 ≤2 秒或任一路非空文本 ≤6 字。阈值需校准。

`stable_text` 才能提供文本票，每家族一票。其他状态用于风险分析，不计正票；支持率分母始终是配置中的四个家族，不随弃权减少。两条转写选 medoid 平分时按固定 run_id 排序，且保留双方。

### 4.3 跨家族共识

- cluster 必须满足成员两两相似度门槛，不允许 A≈B、B≈C、A≠C 的传递连接冒充全体一致。
- 计算 `support_family_count`、`support_ratio_of_4`、`teacher_support_count`、`min_similarity`。
- 候选文本从获支持家族的真实输出取 family-balanced medoid；每家族总权重相同，并列按 family/run_id 排序。
- 簇内一致度同时核验支持家族的两路原始 comparison_text，不能只检查代表文本。
- 多个最大簇并列且文本不同，标 `consensus_ambiguous`，送审，不用字典序宣称唯一共识。
- 三个 teacher 同意、Qwen 不同，只能判 Qwen 纠错候选，不能自动认定 teacher 正确。

## 5. 风险标签、主类别与 Qwen 纠错价值（母文档 §6 全文）

### 5.1 先计算全部风险标签

`risk_tags` 多选，基于全部八路有效原文计算；不能先丢弃不稳定家族。

- `negation_flip`：明确肯定与明确否定冲突，如“需要/不需要”。
- `false_affirmation_candidate`：非肯定表达与肯定表达冲突。
- `filler_affirmation`：“嗯/啊/哦/呃”等与“需要/可以/是/有/好的”等冲突。
- `rejection_sanitization`：拒绝、抱怨、粗口与肯定表达冲突。
- `critical_token_conflict`：否定、意愿词、数字/金额/日期等关键内容有无或值冲突。
- `presence_conflict`：成功空与成功非空并存。
- `short_utterance`、`family_instability`、`noisy_audio`、`quality_unknown`。
- `crosstalk_suspected`：仅来自人工/可信外部特征；ASR 分歧本身不能确认串音。

极性取 `positive/negative/neutral/mixed/unknown`。最长短语匹配与否定作用域优先；“不是不要”“不是不需要”等复杂表达无法可靠解析时设 mixed/unknown 并送审。禁止简单 contains“需要”就判 positive。跨家族共识不能消除同家族内部风险。

### 5.2 主类别：先计算风险，再按顺序取一个 type

1. `invalid_audio`：无法解码或时长无效 → exclude。
2. `inference_incomplete`：八路未完成 → retry；仅在补跑失败经批准后进入人工可标队列。
3. `semantic_risk`：命中 negation_flip / false_affirmation_candidate / filler_affirmation / rejection_sanitization → manual_review，P0。
4. `critical_content_risk`：关键 token/实体冲突，或 mixed 表达无法解析 → manual_review，P0。
5. `all_empty_unverified`：八路成功空 → manual_review，P1；禁止自动空标。
6. `speech_presence_disagreement`：成功空与非空混合 → manual_review，P0（非空含肯定词）或 P1。
7. `voicemail_candidate`：至少两个稳定家族、各自两路命中语音信箱规则，且前面风险未命中 → 专项隔离队列，P2；不进入普通伪标签池。
8. `qwen_correction_candidate`：三个 teacher 均稳定并形成相似度 ≥0.98 的共识，而 Qwen 不稳定或任一路与该共识低于门槛 → manual_review，P1。
9. `family_unstable`：任一家族不稳定 → manual_review，P1。
10. `audio_quality_risk`：DNSMOS noisy/unknown，或有可信串音风险 → manual_review，P1。
11. `pseudo_high`：满足 §5.3（母文档 §6.3） → audit_pending；抽检放行后 auto_accept。
12. `pseudo_medium`：至少三稳定家族形成 ≥0.95 共识，剩余家族未触发前述风险，但不满足 high → manual_review，P2；首版不直接进入训练。
13. `hardcase`：其余，包括 2:2、两个家族支持、无唯一共识 → manual_review，P2。

`type` 只描述候选原因，人工导入后保留，不改成 `human_gold`。真实错误归因另写 `verified_error_tags`。

Qwen 价值字段与 type 并存，避免 Qwen 难例被高优先级桶覆盖：

```text
qwen_status / teacher_consensus_status
qwen_vs_teacher_similarity_1 / qwen_vs_teacher_similarity_2
qwen_risk_tags / qwen_correction_candidate
qwen_verified_error_1 / qwen_verified_error_2  # 仅人工真值后计算
```

Qwen 两路与 teacher 的比较只命名为 agreement，不当作真实准确率。人工发现四家族共同错误也应进入 Qwen 纠错池。

### 5.3 pseudo_high 候选与自动训练准入

1. 八路均成功非空，四个家族全部 stable_text。
2. 四家族共同簇覆盖全部八路，最小相似度 ≥0.98；短句全部八路 comparison_text 完全一致。
3. 八路关键 token/实体一致，极性相容；mixed 或检测到语义风险禁止通过。普通不含意愿词的中性陈述可通过，不强制命中肯定/否定词。
4. DNSMOS 成功、noise_band 为 clean/moderate；无已知串音风险。
以上四项决定 `type=pseudo_high`，与数据用途、审计是否完成无关；避免 eval 保留样本因用途不同被错误归为 hardcase。自动训练准入另须同时满足：

5. 不在 eval/dev/校准保留组内，无数据治理隔离标记。
6. 对应规则版本、模型组合和质量分层通过 §8（见 [012-C](./012-C-人工审核与伪标签门禁.md)）抽检门禁；此前保持 audit_pending。

写 `candidate_text`、`label_tier=pseudo_high`、`label_source=model_consensus`，不写 `is_human_verified=true`，不将 candidate_text 冒充最终人工 gold_text。

## 7. 验收用例：判定正确性（母文档 §15.1 全文）

- 四家族双跑均为“我不需要”：短句完全一致且质量/审计通过 → pseudo_high，仍不得正式 eval。
- 三个 teacher 都“我不需要”，Qwen 两路“我需要”：semantic_risk + qwen_correction_candidate，必须人审。
- Qwen 两路分别“需要/不需要”，其余六路一致“需要”：P0，不能丢弃 Qwen 负向输出后自动接受。
- 七路“需要”、一路“不需要”：P0，不按 7:1 自动收。
- 六路“嗯”、两路“需要”：filler_affirmation，P0。
- 一路“别再打电话”、其他输出肯定：拒绝美化风险，P0。
- 八路都成功空，无论 DNSMOS 高低：all_empty_unverified，必须人审。
- 七路空、一路“好的”：presence_conflict，P0；人工 non_speech 后才能作为空目标。
- 一路失败、七路空：inference_incomplete，不能当作八路空。
- 三 teacher 仅普通字词一致、Qwen 错字：无语义风险时 qwen_correction_candidate。
- 家族内部一空一非空：unstable_presence，不算稳定文本票。
- 2:2 或相似度传递链：不得自动伪标签。
- 四家族高一致但 DNSMOS noisy/unknown：送审，不自动收；八路一致也能被抽检发现共同错误。
- 双重否定、数字金额冲突、背景人声、语音信箱与语义风险同时命中均有独立测试。
