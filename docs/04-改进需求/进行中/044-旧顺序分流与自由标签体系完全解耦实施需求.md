## 1. 目标与“完全解耦”的验收含义

本次范围是**端到端业务依赖解耦**，覆盖输入发现、配置校验、证据计算、规则判断、状态持久化、缓存恢复、结果发布、人工审核、仓库冻结和训练数据构建。

两套模式允许使用同一份音频、原始 ASR 产物、版本固定的中性算法、模型评分缓存及共同治理契约。必须满足以下边界：

1. 自由标签模式不读取旧分流策略、阈值、默认值、类别、队列或候选门控作为运行前提或隐含判断依据。
2. 旧模式不读取自由标签规则、标签集合、人工 tag 操作或 tag 消费策略决定旧分类结果。
3. 各自的业务配置、状态、发布指针、checkpoint、审核任务和结果投影相互隔离。
4. 共用组件不包含旧五类业务规则，不通过回调、默认参数、包装器或动态导入反向调用任一业务分流体系。
5. 两套体系的人工金标、训练准入和数据治理继续遵循明确的共同契约；这些契约必须与旧自动分类策略区分开来。
6. 新模式可以在没有旧 selection 配置、旧分类产物以及旧业务分类器可用的环境中启动、校验并完成运行。
7. 两套结果都能追溯到自己的实际生效配置、证据和快照，不能依靠当前可变文件还原历史。

仅将类名、目录或 YAML 改名，复制一份包含旧业务策略的完整 Selection 配置，或者把旧 `category` 转成 tags 列表，均不满足本需求。

## 4. 目标架构与依赖方向

建议按以下方向落地，具体模块名称可结合现有工程调整：

```text
原始音频 / ASR / 来源身份
             ↓
中性输入契约 + 版本化文本工具 + 中性模型计算 / 证据存储
             ↓                            ↓
旧分流策略与旧候选计划                 自由 tag 策略与依赖并集计划
             ↓                            ↓
旧唯一分类与旧下游投影                 多 tag 结果与独立下游消费策略
             └───────────┬────────────────┘
                         ↓
              独立于自动分流的共同治理契约
```

### 4.1 中性公共层

可建立 `core/evidence/` 或职责等价的模块，承载：

- 音频与 ASR 输入契约、状态解析、内容身份、片段血缘。
- 显式参数化、版本化的文本清洗、无害等价与家族证据构造。
- VAD、energy、DNSMOS 的评分接口、模型调用、缓存与证据数据结构。
- 通用字符统计、三态/数据类型、可辨性证据等基础能力。

禁止将旧 A—E 队列、唯一 category、旧 gold 选择、旧训练配额或旧业务阈值带入公共层。旧配置对象不能成为公共 API 的必要参数。

旧模式可通过兼容包装调用公共组件，固定旧版本和显式参数；tag 模式从自身配置调用公共组件。新增算法版本必须由各自配置显式选择，不得替换共享默认值而同时改变两个模式。

### 4.2 依赖约束

- `core/tagging/` 及 tag 正式计算适配器的业务依赖闭包不得引用 `core/selection_engine.py`、`core/selection_v2/`、`core/selection_v3/` 的业务实现或旧分类/候选算子。
- 公共证据层不反向依赖 tagging 或 selection 的业务层。
- 旧 selector 不依赖 tagging 的规则、tag 状态和消费策略。
- 存量迁移工具可读取旧配置/产物，但应位于隔离的迁移边界；tag 核心加载器不能默认导入迁移器。
- 算子注册、包初始化和 CLI 启动应保证旧模块缺失或旧配置不可用不会阻断新模式，反向同理。

必须增加直接及传递依赖检查，防止通过“公共 facade 包一层旧实现”绕过以上约束。

## 5. 自由标签独立配置与规则语义

### 5.1 独立配置

新正式运行配置不得再含运行期有效的 `selection_config`，也不得引用 `configs/selection/` 下可变业务配置或词表。

必须独立显式描述：

- 家族与路次映射、家族顺序、预期路次数、路次状态及排除策略。
- 文本清洗策略/版本、标点和数字保留、回声与控制标签处理。
- 家族稳定性、代表文本和无害等价策略及版本。
- 关键短应答目录、语义/极性判定与词表。
- 声学模型与预处理配置、VAD/energy 参数、DNSMOS 评分参数。
- tag 业务阈值与比较边界，例如 SIG 低档阈值；模型评分与业务阈值分开。
- 定义库、显式选中 tags、片段、词表、证据模式、工作区和发布策略。

通用模型配置可放在中性目录。业务词表与阈值由各自模式独立维护；初始化时可以复制当前有效内容，运行时不再跟随旧文件变更。

纯文本规则的 validate、list、show、docs、preview 和实际运行不要求声学依赖或本地声学模型存在。仅对当前操作实际需要的能力校验运行条件。

旧 tag 配置中的 `selection_config` 应由显式迁移命令转换为独立配置与依赖快照。新核心遇到旧 schema 应说明迁移方式，不得自动加载旧 selection 继续运行。

### 5.2 现有规则保留与缺陷修正

- 继续支持规则组合、家族量化、文本绑定、多规则同 tag、多 tag 重叠及人工来源。
- 保留 matched / not_matched / unknown；NOT unknown 仍为 unknown；失败、缺失、清洗空和真实空不能混淆。
- “全部家族成功”“指定三族稳定”等条件只在规则明确声明时生效，不能成为所有 tag 的隐藏全局门禁。
- 信箱命中不阻断其他 tag 的声学取证，旧类别与队列不参与规则判断。
- 每个语义能力独立返回自己的结论、证据和缺失依赖。可同时满足多个能力，不经旧唯一 risk subtype 筛选。
- 正式短极性歧义能力应传入完整可辨性/人工证据；缺证据按三态契约处理，不隐式当作确认不存在。
- 支持的每个文本策略均验证 comparison_text/classify_text/代表文本一致性；不支持的策略在配置加载时拒绝，禁止把有字成功路次误判成 stable_empty。
- 043 的路次范围、单汉字定义及关键词原文匹配口径保持不变；“全部家族”改从独立 tag evidence 配置取得。单字分支按用户后续确认的版本 2：仅 Qwen 须为单汉字，SV/GLM 不限长度，Qwen 与至少一方不等价即可。

迁移基线应固定当前合法配置与离线证据，逐规则比较三态、命中来源和有效 tags。明确缺陷修复另列预期差异，不能把所有行为漂移归为“解耦需要”。

## 6. 中性证据、候选计划与真实补算

### 6.1 证据与调度隔离

一份证据至少绑定：样本与音频内容身份、音频表示/预处理摘要、路次/模型、模型版本或可靠标识、计算参数摘要、能力版本、计算状态、值、错误及来源。

ASR 证据还须区分原始文本、清洗文本、运行状态、排除原因与路次映射。任何会参与判断的内容必须进入相应证据身份。

- 已成功的证据记录不可被旧队列或新 tag 计划覆写为空。
- `not_required` 表示**某一消费者本次的调度决定**，不作为共享音频证据的事实状态。
- 中性证据可记录 success/failed/missing/not_computed 等真实计算状态；读取旧 not_required 时仅能解释为未提供有效证据。
- 旧模式按自己的候选计划生成兼容视图；tag 模式按各条未决规则收集依赖并集。两者均不改写对方视图或共享事实。
- 现有 `sample.quality` 可保留为兼容投影；自由标签不得继续把无来源、会被门控覆写的裸字段当权威共享证据。
- 旧产物已经丢失的评分不能凭空恢复，只能标明缺失、导入可信侧车或按需重新计算。

对同音频、同模型、同参数的依赖并集去重；参数或模型版本不同则不复用。评分缓存不包括 tag 业务阈值，修改阈值应重判而不重跑评分。

### 6.2 正式计算适配器

生产 pipeline 和 CLI 服务层必须使用同一可执行的真实声学适配层，直接调用中性 VAD/energy/DNSMOS 计算接口，不借旧分类器或 A—E 队列驱动评分。

- existing：不启动模型；缺证据为 unknown，明确列出依赖。
- compute_acoustic：只补启用规则仍可能需要的证据；纯文本规则零声学调用。
- 缺运行依赖、模型或参数时给出可定位错误/能力失败；不得静默退回 passthrough 冒充已计算。
- 单项声学失败只影响相关规则，不影响独立文本 tag；保持样本与错误可追溯。
- planned、模型实际调用、缓存复用、成功和失败分开统计。实际模型调用不得用“调用过空 adapter”计数。
- 预演只规划，不执行推理；补算不启动 ASR。

允许通过注入 mock scorer 验证正式 adapter 的调度与失败路径；交付时清楚区分该验证与真实模型 smoke。

## 7. 状态、缓存、快照与双层恢复

### 7.1 独立状态与身份

旧分类状态和新 tag 自动/人工状态按 mode、batch、policy/schema 分开。人工记录必须绑定稳定样本/片段与音频身份，不能只凭 sample_id 跨音频复用。

保留人工添加、持续屏蔽、恢复、撤销、多来源去重、停用/归档及局部重算契约。迁移不能清空人工记录，也不能把相同 ID 的不同音频当成同一样本。

每次运行保存完整有效配置和递归依赖内容，至少覆盖：家族/路次、文本/等价/语义策略、阈值、模型/预处理参数、tag 定义/版本、规则/片段、词表/匹配参数、证据输入身份、人工状态版本和解释所需来源。

快照必须自足且不可变；路径只是来源说明，不能替代内容。历史缺数据时据实说明不可完整还原。

### 7.2 Tag service 恢复

- completed 记录绑定样本输入、定义、证据及相关状态版本。
- 恢复时还原已计算的规则结果、自动来源和样本输出，不能仅跳过 ID 并复制原始输入。
- 定义、证据、音频/路次或人工状态漂移时拒绝不安全恢复并提示新 run/明确重算；不得混合不同版本结果。
- 允许重算时只复用仍有效的模型证据；自动来源重新对账，人工状态按独立版本合并。
- 当前证据变 unknown 或规则停用后，不保留旧自动确认来源；局部执行保留范围外仍有效来源。

### 7.3 Pipeline checkpoint

在恢复 complete checkpoint **之前**计算并校验实际依赖摘要。可以扩展算子 fingerprint/dependency hook；不能只修改 tag service 而留下 pipeline 旁路。

指纹覆盖外部配置/片段/词表内容、实际使用的证据字段和人工 tag 状态版本。只记录 params 中的 YAML 路径或 transcript.text 不足。

必须识别以下变化：同路径改规则/阈值/词表、raw_text 或路次成功态变化、quality/侧车证据刷新、音频表示变化、人工屏蔽/恢复，以及下游消费策略变化。

只改旧策略且新模式有效输入不变时，新模式的语义指纹与结果保持不变；反向亦然。无语义影响的展示排序可规范化，不把配置排列当成业务优先级。

### 7.4 发布与隔离

中断中的 run 不更新正式发布指针；正式产物绑定定义、证据和结果快照。各模式的 output、业务结果/调度缓存、checkpoint、人工状态与 publish 指针不能覆盖对方。

中性模型评分缓存允许共享，按不可变的音频/模型/预处理/参数身份寻址；不同模型或参数版本不得互相覆盖。共享评分不能携带任一模式的候选结论、tag 阈值判定或旧 category。

终态 unknown 与“尚未处理完成”区分；是否允许发布包含 unknown 的结果由新模式显式策略控制，并报告覆盖率。不得沿用旧分类的 publish_pass 假装 tag 结果已满足业务要求。

## 8. 输入发现、产物与历史迁移

### 8.1 新正式入口

原 tag_id/rule_id 不因运行策略改名而改写。旧 `selection_multi_tag_v1` 历史快照保持可读，与新状态目录隔离。

新入口必须通过一条 `audio-data pipeline run ...` 完成生产打标。CLI 与 pipeline 使用同一服务、同一输入解析契约；显式输入覆盖批次发现，冲突报错。

默认接受中性 prepared ASR/evidence 输入。现有 `prepared_asr_v3_*` 名字可以作为输入兼容别名，但读取与验证不得依赖旧分流代码。

### 8.2 显式迁移

提供可预览、可审计的迁移入口，覆盖旧 tag 配置、旧 tag 人工状态及旧 classified 产物。具体命令名由 Cursor 确定并文档化。

迁移要求：

1. 读取旧配置的**当前有效值**并生成独立 tag 配置/词表快照；输出版本、内容摘要、字段映射及差异报告。
2. 旧自动 category/type/status/queue 等保存在独立 legacy 命名空间或原始归档引用，不成为新业务输入。
3. 只导入有可信来源与音频/模型/参数绑定的中性证据；身份不足的字段标为不可验证/缺失，可显式补算。
4. 人工金标与治理字段依据来源保留。混合自动/人工含义的字段不能按名字整体删除。
5. 无法确认某项旧阻断是否源自人工决定时，保留原始记录并标记待迁移核验；tag 求值可独立进行，审核发布/训练等相关消费按共同治理阻断，不可猜测放行。
6. 迁移人工 tag 操作时保留来源、actor、reason、时间和屏蔽语义；不能自动跨音频/片段复用。
7. 不以旧唯一类别直接生成“等价的多标签”；新 tags 必须按独立规则和可信证据求值，人工 tag 明确区分来源。
8. 迁移重跑可幂等，不覆盖原文件；提供样本计数、证据可用性、人工状态变化和回滚说明。
9. 历史 tag 内联配置应迁移为新 schema；迁移器允许认识旧格式，新核心不保留隐式旧配置加载分支。

已有人工标签不应因为新策略目录变化而静默丢失，也不得默默套用到不相关的新策略。迁移时显式关联来源策略与目标策略。

## 9. 端到端双模式下游

### 9.1 明确模式与新消费策略

annotation export/import、warehouse export/freeze、dataset build 均增加或扩展明确的 `routing_mode`，语义为 `legacy` 或 `tagging`。

- 旧入口保持 legacy 行为；新入口显式使用 tagging。
- 新产物写入模式、策略、定义/结果快照和来源身份。
- 混合 manifest、参数与元数据模式冲突、来源不明时明确拒绝或要求迁移。
- 不得根据“tag 为空”回退旧分类，也不得根据“有 category”自动切成旧模式。
- 不允许先把 tags 压成旧 category，再调用旧队列/构建逻辑冒充 tagging 消费者。

tagging 下游策略独立、可版本化、可配置，至少支持：

- include_all/include_any/exclude 的候选池选择与 unknown/not_evaluated 处理。
- 审核选样、优先级、双审触发、抽检分层和预算冲突处理。
- 仓库视图、数据集候选与配比用途。
- 每个消费决定的标签命中、治理依据、策略版本和解释。

资源优先级可以出现在下游消费策略中，但不能反向改变 tag 判断或截断其他规则。没有显式训练消费策略时不自动赋予训练可信度。

交付可运行的初始 tag 消费配置：可将 `semantic_risk_text_disagreement` 用作高优先级审核候选，具体依据写入独立策略；它及其他任意 tag 均不自动等于人工语义结论。

### 9.2 旧自动字段隔离

在相同 tags、中性证据、人工确认与治理状态下，增删或修改旧自动：

`category / type / classification_bucket / risk_tag / risk_tags / status / label_tier / review_queue / review_priority / 旧 candidate 标记`

不得改变 tagging 模式的候选集合、审核优先级、双审、freeze 或训练准入。

上述隔离针对**旧自动决策来源**。人工确认的类别、训练排除或 usage block 必须迁移到明确人工/治理契约，不能为通过测试而忽略。

旧模式在相同旧输入、配置和治理状态下，应忽略新 tags、tag 规则、tag 消费策略及 tag 人工操作；旧业务结果保持一致。

### 9.3 人工金标与训练共同契约

保留有效的 annotation_state、gold_kind、gold_text、speech_scope、人工 semantic/noise/crosstalk、审核人身份、版本、双审与裁决；具体字段按现行契约复核。

以下要求持续生效：

- 缺有效逐字金标、未完审核/双审、未决冲突、人工拒绝或明确排除，不可进入相应正式训练/评测集。
- 空金标和不可辨样本按现行契约处理，不能因 tag 移除就被当作普通可训练 speech。
- `tags=["pseudo_high"]` 或任意自定义标签不等于已审计伪标签；必须有独立、可验证的审计证明和准入依据。
- 多说话人、串音、不可辨、用途排除与评测保留组等现有约束按实际契约继续执行。
- reservation、防泄漏分组、训练/验证/评测隔离不由 tag 自动绕过。
- 人工确认与模型推断分开存储，不能把 tag 当成 human_semantic 等人工字段。

共同治理模块不得以旧自动 category 为隐藏前提。需要双审的 tagging 样本由独立 tag 消费策略与共同治理明确触发。

### 9.4 审核包、仓库和数据集身份

新模式审核包、freeze alignment、build provenance 应绑定：

- mode、样本/片段与音频内容身份。
- tag 定义及结果快照、有效标签集合与来源身份。
- 实际生效的消费策略与版本。
- 所需人工/治理状态版本及审批/审计引用。

改变影响消费的 tag、快照或策略后，旧审核包和旧下游 checkpoint 不能静默复用；导入应拒绝不匹配包并解释原因。

同一样本原有合法人工金标仍绑定音频事实，可按明确身份校验和当前审核要求复用；不因 tag 重跑简单清空，也不直接宣称新要求的审核已完成。

包内保存可追溯标签和来源元数据；盲审展示遵循现行契约，不得把模型标签、候选答案或第一轮结果泄漏给应独立盲审的人。

仓库继续保持已有样本/音频唯一性；模式隔离体现在业务投影和快照身份，不要求复制原始音频或制造重复的 canonical 样本记录。
