## 1. 目标与实施范围

在源 PCM 完成登记、形成样本记录后，增加同源 FSMN VAD 切段。**保留片段必须能够溯源到未切分音频，全部进入数据归类，归类后使用对应片段进行标注。** 后续处理的样本单位由源文件转为片段，需要同步梳理索引、缓存、归类和标注契约。

```text
源 PCM 登记／入库
  → 音频格式规范化
  → FSMN VAD 生成 start / end
  → 按区间裁切，并丢弃不足 1 秒的片段
  → 片段清洗结果 Manifest
  → 全量片段多模型 ASR、结果聚合、数据归类
  → 按归类结果组织片段标注、回填及入仓
  → 后续训练数据链路
```

当前清洗入口是 `pipelines/data_cleaning_source_A.yaml`，尚无 VAD 切段。仓库已有 `audio.vad` 仅计算能量语音占比，后置分拣中的 Silero 用于质量判断；它们均不能替代此次移植的 FSMN 切段。

本次必须交付 VAD 适配、片段落盘、源与片段索引、一对多流水线、全量归类衔接、片段标注导出／回填／入仓适配及验证。允许修改 `core/` 中完成这些要求所必需的结构和逻辑，并提供历史数据兼容说明；优先复用已有能力，控制改造范围。归类业务规则和训练准入条件沿用现有指定版本，人工标注仍由人工完成。

## 2. 裁切与丢弃规则

- 每个有效 `[start, end)` 区间独立生成一个音频片段；一条源 PCM 可以得到零个、一个或多个片段。
- `start`、`end` 使用 VAD 返回的整条音频全局时间，单位为毫秒。只截取该区间内的音频，不截取到缓冲区末尾，也不额外增加首尾 padding。
- **`end - start < 1000 ms`：全部丢弃；`end - start >= 1000 ms`：保留。恰好 1 秒必须保留。**
- 完整端点 `[start, end]` 和拆分端点 `[start, -1]`、`[-1, end]` 配对后，应用同一规则。不能因事件形式不同而使用不同阈值，也不拼接多个短段来凑满 1 秒。
- 裁切换算为采样坐标：16 kHz 下，`start_sample = floor(start_ms × 16)`，`end_sample = floor(end_ms × 16)`，按半开区间读取同一份规范 PCM。越界边界需记录异常，实际片段不足 16000 个采样时也不能进入下游。
- “丢弃”指不产出供下游使用的片段、不提交 ASR；保留源 PCM，以及被丢弃区间和原因的记录。

例如：`[2000, 2990]` 为 990 ms，丢弃；`[2000, 3000]` 为 1000 ms，保留；`[2000, 4600]` 为 2600 ms，保留。

## 3. “VAD 生成规则一致”的含义

移植 `D:/Work/ph_ai_model_asr_rt_cpu` 的 FSMN 推理基线：

- **模型和配置**：使用 `fsmn-vad` 的 `model.pt`、`am.mvn` 及模型元数据，通过 FunASR `AutoModel` 在 CPU 加载 `FsmnVADStreaming`。将完整 `model_configs/fenshen_vad_config.yaml` 作为独立运行目录的 `config.yaml`，不能误用模型自带默认配置。
- **参数**：整份配置迁移，包括末端静音 1100 ms、最长单段参数 10000 ms、起点回看 200 ms、尾点前看 100 ms、`speech_noise_thres=0.85`。10000 ms 是模型参数，不另外按固定 10 秒切音频。
- **输入**：先统一为 16 kHz、单声道、PCM16 小端；VAD 和裁切使用同一份规范音频。推理输入按源公式 `int16.astype(float32) / 32767` 生成。
- **调用**：按 200 ms（3200 个采样）顺序输入，每文件独立 cache；最后一个非空块设置 `is_final=True`，同时处理完整端点和拆分端点。
- **声道（已确认，沿用源项目）**：输入按单声道处理。多声道有头文件只取第 0 声道再规范化／VAD／裁切；不按声道拆多路、不混音、不做角色识别。无头 PCM 默认单声道；可信来源配置声明多声道时先解交织再取 ch0。禁止把已知多声道交织 PCM 当成连续单声道。
- **采样率（已确认）**：全局规范输出 16 kHz mono PCM16 小端；VAD／裁切／ASR／标注共用。无头默认 `source_sample_rate=16000` 并记录约定来源；有头读真实采样率。真实 8 kHz 与规范 16 kHz 分字段记录，须明显告警后重采样，不得把 8 kHz 登记或头信息改写成 16 kHz，也不得按 16 kHz 速度解释 8 kHz 样本。
- **EOF 补尾（已确认）**：final 后仍有有效 start 无 end 时，用音频实际终点作 `inferred_end_ms`，`end_reason=eof_fallback`；≥1 s 进入 `cleaned_*`／ASR／归类／标注，不足 1 s 丢弃。无有效 start、坏输入或 VAD 失败时，不得整条录音兜底送入下游。
- **复现**：固定模型、配置、依赖版本和有效推理参数，用同一音频对比原始端点；不擅自更换为 Silero、ONNX 后端或最新依赖。

运行时模型目录和源音频参数必须可配置，不能将本机 `D:/Work/` 路径写死在生产代码。保存模型／CMVN／完整配置摘要、依赖版本、有效推理参数和输入分块信息；动态阈值等版本行为按源生产基线核实，不能静默改变。原始事件日志与过滤结果分开保存，便于验证同源端点和新增的 1 秒规则。

**1 秒过滤是此次明确新增的业务规则，替代源服务历史上不一致的 150／200 ms 短段过滤。** 不继承旧服务报告起点减 100 ms、完整端点裁切到缓冲末尾等缺陷。

## 4. 当前工程基线与实施落点

以下为已核查的现状，Cursor 开工时需与当前代码复核，不能把本节现状当作已经实现的切段能力。

- **数据主体是 Sample，Manifest 保存整批样本。** 当前入库默认以文件名 stem 生成 `id`，`source_path`、`audio.raw` 和 `sha256` 记录源文件；清洗、ASR、质量、标签及处理记录附着在同一个 Sample 上。现有结构没有明确的父录音 ID、片段边界等专用字段，参见 [Sample](../../../src/audio_engine/core/sample.py)、[入库逻辑](../../../src/audio_engine/core/manifest.py)。
- **音频路径和业务身份共同影响后续处理。** ASR 默认读取 `audio.resampled_16k`；聚合主要按 `id` 并核对音频身份；通用算子缓存依赖 `sample.sha256`、算子版本和参数。只新增一份切段文件、继续沿用父样本身份与状态，不能保证下游处理的是新片段，参见 [聚合](../../../src/audio_engine/operators/quality/aggregate_manifests.py)、[算子缓存](../../../src/audio_engine/core/operator.py)。
- **归类与标注已经有独立阶段。** 五类归类以及 040 可组合多标签都将结果写回样本。033 整批标注导出支持全部分类样本；另外也有按审核队列或 `semantic_risk` 选取待标样本的流程，选取范围不能代替“全量归类”。参见 [整批标注与入仓](../../07-操作手册/batch唯一数据仓库-人工标注入仓.md)、[多标签分流](../../07-操作手册/可组合规则与多标签分流.md)。
- **当前存在一对多的适配缺口。** 普通 `BaseOperator` 接收并更新一个 Sample，`ManifestOperator` 可以返回变化后的样本集合。使用适合集合数量变化的接口建立源样本到片段样本的一对多关系，并适配持久化、并发和断点恢复；不能把多个片段塞在同一 Sample 中而让下游仍按一条样本处理。

## 5. 索引与数据契约改造要求

建立“源音频索引 + 片段索引”的逻辑分层，继续以 Sample／Manifest 为数据契约。以下字段表达必须保留的语义，允许按现有代码统一字段名，但交付时必须给出字段映射、持久化位置和兼容方式。

- **源音频索引**：稳定的 `source_audio_id`、batch／来源、未切分文件路径和 `source_pcm_sha256`、原始格式；同时记录规范化音频路径、摘要及声道策略。源记录在切段后继续存在。
- **片段索引**：`segment_id`、父 `source_audio_id`、声道、全局毫秒边界、实际采样边界、片段路径／内容摘要／时长、规范化和 VAD 处理版本。记录足以从片段反查父音频，也能从父音频列出全部片段及丢弃区间。
- **下游工作主键**：片段作为独立 Sample，`Sample.id` 对应 `segment_id`。ID 根据父源身份、规范音频、声道、采样区间和处理版本稳定生成；同版本重试不重复产段，边界或处理版本改变后形成新身份。序号仅用于展示。
- **分开父哈希与片段哈希**：下游缓存和音频校验使用当前片段的内容身份，父 PCM 哈希放在独立血缘字段。现有 `original_audio_sha256`／`source_audio_sha256` 的读取优先级需统一适配，不能直接将父哈希填入所有兄弟片段的工作身份。
- **明确现有冲突**：通用缓存可能把共用父 `sha256` 的片段当作同一输入；仓库完成检查会将同一 `original_audio_sha256` 对应多个样本 ID 判为重复音频。应调整为区分父源共享与片段重复，并校验实际片段内容，参见 [仓库身份](../../../src/audio_engine/core/warehouse/identity.py)、[完成检查](../../../src/audio_engine/core/warehouse/completion.py)。
- **保证索引贯穿全程**：新增血缘与边界应在 Sample 读写、Parquet／JSONL、ASR 聚合、分类导出、标注包、回填和仓库快照中保留。不能只存在临时文件名或运行日志中。切段时不直接继承父音频的 ASR、分类、人工金标及已完成状态。
- **同步入口与版本**：ASR 当前默认消费 `cleaned_<batch>`，需明确该产物改存片段样本，或增加片段数据集并同步各消费入口。切段版本／片段集合变化时，应生成新快照并隔离旧分类、标注包、缓存和检查点；已冻结仓库的修订需遵循现有唯一性约束，不能覆盖历史整段记录。

片段 `Sample.sha256` 应表达当前片段输入的内容身份；兼容字段 `original_audio_sha256` 若继续用于工作样本关联，必须明确映射为该片段的未 padding 音频身份。父 PCM 摘要单独保存。ID、缓存与版本策略要同时防止兄弟片段串用和不同处理版本误复用；涉及来源或路径的缓存元数据，也必须保持对应片段的血缘。

例如，源录音 A 生成片段 A1、A2：二者共享父源 ID 和父源摘要，但具有各自的片段 ID、音频摘要、转写、类别和标注记录。A1 的回填不能覆盖 A2，二者都能定位到 A 中的原始时间区间。

## 6. 全量归类与片段标注的衔接

**“全量”指通过不足 1 秒丢弃规则后保留下来的全部片段。** 每条片段都进入现有多模型 ASR、聚合及指定的数据归类流程；VAD 不承担业务归类，也不能凭父录音类别直接给子片段赋类。原有五类或多标签规则对片段重新求值，本需求不自行切换归类规则版本。

归类阶段保留完整片段清单：ASR 失败、证据缺失、无法判定的片段也保留记录，进入对应异常／待处理状态。对已保留片段，后续质量过滤不得静默删除而造成归类覆盖缺口。应能核对“VAD 保留片段集合 = 归类输出片段集合”，异常状态有原因且可重试。

归类完成后，按归类结果组织标注任务。**播放器、候选转写、人工文本和回填主键必须对应同一个片段**；未切分录音可供上下文回听，并携带片段在父录音中的位置。标注本期以既定片段为单位；若将来允许人工修改边界，需另行定义片段及标注版本关系。

标注包和回填需要同时携带片段身份及父源血缘，按 batch、片段 ID、片段音频摘要和包版本校验，不能只凭父源 ID、父哈希或 Excel 行号回填。当前包中的 `sample_id + original_audio_sha256` 契约需明确映射或升级版本，防止旧整段标注误回填到新片段。033 整批标注包的“全部样本”应对应切段后的分类快照，按片段数核验覆盖率。

兼容适配须覆盖当前实际使用的五类、040 多标签及其标注入口；按入口实际契约处理 `category` 与 `tags`，保持二者现有语义。040 默认复用已有证据，因此必须先生成片段自己的 ASR 结果，不能仅接入 VAD 后直接沿用父音频证据。

ASR 和标注统一选取明确的片段音频键。可以适配现有 `resampled_16k` 或新增统一片段键，但路径选择、音频缺失检查及摘要校验必须同步；片段缺失时不得自动退回未切分音频。入仓保留片段、父源、分类快照和标注证据的关联；训练仍按现有审核和准入条件取数，训练／评测拆分按父录音或通话分组，可复用现有 [source_audio_id 分组能力](../../../src/audio_engine/core/dataset_v3/grouping.py)。

## 7. 产物、异常与恢复

片段可用 WAV 封装规范 PCM，供现有下游读取。切段输出需要持久化源处理结果和片段 Manifest，再交给后续流程；完成记录应能对账源文件数、候选数、短段丢弃数、保留片段数及归类／标注进度。

有效输入经 VAD 后无语音，与有候选但全部不足 1 秒，分别记录原因；两者都不向 ASR 提交样本。输入损坏、VAD 失败、非法端点单独记错，不能作为成功的零片段结果，也不能直接将整条源音频送入下游。

源处理结果必须持久化原始事件、候选区间、丢弃原因、保留片段清单、异常与处理指纹，包括零片段的源记录。发布下游可消费的片段清单前，先保证音频与索引完整；中断和重试不能发布缺文件的成功片段，也不能遗漏或重复产段。大文件保持顺序流状态；多文件／声道不能共用 cache。

无语音、全短段、坏输入、VAD 失败分别记录。保留片段的 ASR 失败可单片段重试；相同切段版本下无需重新生成全部片段。日志和恢复记录沿用现有运行目录／检查点体系，源与片段索引保存在可持续消费的产物中。

## 9. 验收标准与测试要求

- 先入库，再规范化和 VAD，最后才进入 ASR；下游读取的是片段音频。
- 同一规范 PCM、同一配置／依赖／调用序列下，VAD 原始事件与迁移基线一致；1 秒过滤单独验收。
- 990／1000／1010 ms 分别丢弃／保留／保留，完整和拆分端点结果相同。
- 裁切内容与声明的采样边界一致；静音、全短段、文件尾语音和重试均有明确结果，重试不重复产段。
- 任一片段可查到未切分音频和准确位置；同一父源的多个片段身份独立，缓存不串用，聚合与回填不串段。
- 保留片段全部出现在归类结果中，异常样本有明确状态；整批标注导出按片段分类快照核对覆盖率。
- 标注听到的音频、候选文本和回填记录属于同一片段；新旧整段／片段契约可区分，入仓后仍能追溯父源。

必须提供有意义的自动化验证和小批次链路证据，至少覆盖：

1. **切段正确性**：完整／拆分／多事件、跨块等待、重复事件、非法端点；990／1000／1010 ms 阈值；实际片段采样内容、格式、长度与边界一致，无额外 padding。
2. **结束与隔离**：200 ms 整数倍和不足一块的文件均以最后非空块 final；无语音、全短段、文件尾语音；多源 cache 隔离。EOF 补尾：990／1000／1010 ms 边界，`eof_fallback`＋`inferred_end_ms` 标记，≥1 s 进入下游。
3. **规范化**：真实 8 kHz→16 kHz 时长保持与坐标正确，控制台／日志／汇总有告警；多声道只取 ch0 且时长不因交织误读翻倍；无头 PCM 按声明采样率／声道数读取，异常字节长度报错。
4. **索引与恢复**：一源零／一／多片段，Manifest 往返读写不丢字段；兄弟片段共享父源而内容身份独立，缓存／聚合／标注不串段；重试、并发和断点续跑无重复与遗漏，版本变化隔离旧结果。
5. **归类覆盖**：用真实片段 ID 集合核对保留结果与归类输出；注入 ASR 失败或证据缺失后记录仍在，且有明确状态。
6. **标注闭环**：使用测试标注记录完成导出、回填和入仓，核查片段试听引用、父源边界及分类快照；拒绝未知 ID、片段音频不匹配、篡改元数据、旧整段包误回填；兄弟片段不因共享父哈希被误判为重复。
7. **历史兼容与分组**：历史整段 Manifest 仍可读取，既有流水线相关回归通过；同父录音片段进入同一训练／评测分组。
