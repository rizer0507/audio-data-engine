# 048｜ASR 落盘并入转写清洗（去标点 / 热词 / 控制标签）

日期：2026-10-16。状态：**代码已交付**（单元/流水线 YAML 契约测试已绿；真实 vLLM/SenseVoice 大吞吐未测）。

项目：`audio-data-engine`。交付用途：交给 Cursor 在当前公用引擎库中实现。

## 1. 我想做什么

把现行「转写文本清洗」从独立评测流水线前移到**各路 ASR 识别流水线本身**：模型识别完成后、结果写入 ASR Manifest 时，就完成去控制标签、去标点、空白折叠，以及该路应有的整句热词精确清空。

目标是：下游拿到的 `transcripts.<alias>.text` 已经是可比对纯文本；原始模型串保留在审计字段，不再依赖事后再跑一遍 `asr_metric_pipeline` 的 `normalize_transcripts` 才「洗干净」。

首版覆盖生产常用三族入口：

- Qwen：`pipelines/qwen_asr_batch.yaml`
- SenseVoice：`pipelines/sensevoice_asr_batch.yaml`
- GLM：`pipelines/glm_asr_batch.yaml`

清洗口径与现有清洗流水线 **`pipelines/asr_metric_pipeline.yaml` → `quality.normalize_transcripts`** 基本保持一致（同一套 `zh_asr_v1` 规范化 + 按族配置的 `blank_exact_*`），不是另起一套规则。

## 2. 业务范围与默认决策

1. **清洗发生在 ASR 落盘路径上**，不是①音频清洗（`audio_ingest` / `data_cleaning_source_A`）。音频规范化、VAD、DNSMOS 均不承担文本清洗。
2. 每一路 ASR 只清洗**本路写出的 transcript key**（含 `--asr-run` 别名，如 `qwen1` / `glm1`），不改写其他模型字段。
3. 默认 `keep_raw=true`：首次清洗时把模型原始串写入 `extra.raw_text`（已有则不覆盖）；对外主字段 `text` 写清洗后正文。
4. 清洗失败或配置缺失不得静默跳过并假装已清洗；预检或该行失败须可定位。
5. 整句热词清空规则与现网 `blank_exact_*` 一致：**全文精确命中**才置空，禁止按单个热词子串误杀真实短句（如「不需要」）。
6. SenseVoice 落盘必须剥掉全部 FunASR 控制标签（含白名单外的 `<|withitn|>` 等）；与 [021](./021-SenseVoice控制标签不得进入可比文本.md) 目标对齐，但本需求以「识别落盘即干净」为交付入口，不另开旁路修历史 parquet 的脚本当生产主路径。
7. 不改变 ASR 推理、分片、GPU/HTTP 并发、checkpoint 与 `--resume` 语义；只在「识别结果组装成 Sample transcript」之后增加确定性文本后处理。
8. 不把五分类 / 自由 tag 的 `classify_text` 投票逻辑搬进 ASR；本需求只做与 `normalize_transcripts` 同级的纯文本清洗。外语排除、提示词回声投票等仍由下游证据层负责（可继续读 `raw_text` / 清洗后 `text`）。

## 4. 各族清洗契约

### 4.1 共同规则（与 asr_metric_pipeline 对齐）

对每一条成功写出的转写：

1. 若 `keep_raw`：`extra.raw_text` ← 清洗前原文（已存在则保留）。
2. `text` ← `plain_transcript_text(原文)`（去全部 `<|…|>` 控制标签 + `zh_asr_v1`：NFKC、去标点、去空白等）。
3. 若该路启用 blank 且清洗后全文精确命中配置短语：`text=""`，`extra.blanked_exact_hotword=true`。
4. ASR 失败行：不伪造清洗成功文本；按现有失败 status/errors 落盘，可选保留 residual 原文到 `raw_text`，但 `text` 不得伪装成有效识别。
5. 清洗是纯函数、可幂等：对已清洗文本再跑一遍，结果不变；`raw_text` 不被二次覆盖成「已清洗串」。

规范化配置固定引用：

- `configs/normalization/zh_asr_v1.yaml`（与 metric 路径同一文件，不复制分叉）。

### 4.2 Qwen

- 入口：`pipelines/qwen_asr_batch.yaml`（045 编排通过 `production.asr_routes` 调用同一 YAML，天然等价）。
- blank 配置：默认 `configs/normalization/blank_exact_qwen_v1.yaml`。
- models 匹配必须覆盖实际落盘 key：`qwen`、`qwen1`、`qwen2` 及未来 `--asr-run` 产生的同族别名；不能只认死键 `qwen` 导致 `qwen1` 不清空。
- 热词表变更须使缓存 / checkpoint 指纹失效（`NormalizeTranscriptsOperator.compute_cache_key` + `dependency_fingerprint` 对 blank / zh_asr 文件内容哈希）。

### 4.3 SenseVoice

- 入口：`pipelines/sensevoice_asr_batch.yaml`。
- **必须**经 `clean_control_tags`（已含于 `plain_transcript_text`），保证落盘 `text` 无 FunASR 控制标签；`raw_text` 可保留带标签原串供审计。
- 首版 blank：若尚无独立 `blank_exact_sensevoice_*.yaml`，允许仅做控制标签 + `zh_asr_v1` 去标点，不强制编造热词表；一旦配置了 blank 文件则按同样精确全文规则生效。
- 与 021 的关系：本需求交付后，新跑的 SenseVoice ASR 产物应满足「可比正文无控制标签」；021 中「修历史 parquet / 候选回写」若仍缺，可保留为后续小项，但不得阻塞本需求验收。

### 4.4 GLM

- 入口：`pipelines/glm_asr_batch.yaml`。
- 默认同样走 `zh_asr_v1` 纯文本清洗 + `keep_raw`。
- 首版 blank：若无独立 GLM 热词整表配置，行为与 SenseVoice 相同（只做规范化）；提供配置文件后按族启用。
- 不在本步骤做「非中文置空」的五分类政策（那是 `classify_text` / 025 影子路径）；避免 ASR 落盘与分拣政策耦合。

### 5.1 生产入口（必须改）

### 5.2 推荐配置形态

每路 ASR 步骤（或紧随其后的 normalize 步骤）显式声明，例如：

```yaml
# 示意：具体键名以实现为准，但语义须齐全
normalize_on_write: true
normalization_path: configs/normalization/zh_asr_v1.yaml
blank_exact_hotwords_path: configs/normalization/blank_exact_qwen_v1.yaml  # 无则省略
keep_raw: true
```

允许用共享 defaults 减少复制，但各家族 blank 路径不得串用（Qwen 的整表句不得误用到 GLM）。

### 5.3 与 asr_metric_pipeline 的关系

- `pipelines/asr_metric_pipeline.yaml` **保留**：历史数据补洗、CER 前再确认、评测集仍可显式跑一遍。
- 对「已经按本需求清洗落盘」的新 ASR 产物，metric 流水线再跑 normalize 必须幂等，CER 不被二次损伤。
- 手册须写清：新生产链**不再要求**识别后必须再跑 metric 清洗才能给 join/tag 用；metric 仍是算字准的入口。

### 5.4 下游消费约定

- `evidence_join` / 自由 tag / 五分类：主比较文本继续可用清洗后的 `text`；需要审计或回声匹配英文 prompt 时读 `extra.raw_text`。
- 不得删除 `raw_text` 以「省空间」导致无法追溯模型原串。
- 旧 ASR parquet（未清洗）兼容：下游保持可运行；新跑批次默认干净。本需求不强制提供全量历史回洗命令，但实现上复用 `normalize_transcripts` 即具备补洗能力，可在手册给可选示例。

## 6. 缓存、分片与续跑

1. 清洗参数（规范化配置内容摘要、blank 文件摘要、`keep_raw`、算子/清洗版本）必须进入影响复用的指纹；改热词表或 `zh_asr_v1` 后不得命中旧脏结果。
2. `--resume`：已按**同一清洗指纹**写完的样本可跳过；指纹变化则该路转写需重洗或重跑识别后处理（若只改清洗、ASR 原串仍在 `raw_text`，允许「只重洗不重推理」的优化，但须正确、可测；做不到则安全默认重跑后处理路径并文档说明）。
3. 分片子进程、shard merge 后的最终 parquet 均须带清洗后 `text`；不能只在父进程合并时洗一次而子产物仍脏。
4. 进度统计仍以样本/源为单位，不因清洗改变进度语义。

## 7. 明确不做

- 不把文本清洗并入①音频清洗或 VAD。
- 不在本需求重做五分类、自由 tag、DNSMOS。
- 不引入按词表子串清空、模糊热词匹配。
- 不默认开启「非中文整路置空」等分拣政策。
- 不要求本机百万条压测或全仓库回归。
- 不改动无关训练/标注平台需求。
