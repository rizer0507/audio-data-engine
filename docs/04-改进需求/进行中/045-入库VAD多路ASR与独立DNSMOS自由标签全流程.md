## 2. 新生产流程

将用户原描述中的重复编号整理成四个业务阶段，其中阶段③包含两个同级、并行的生产分支：

```text
① 音频入库流水线
   原始录音登记、身份与来源固化、规范化父音频
             ↓
② VAD 切分流水线
   FSMN VAD → 源处理记录 + 独立片段音频 + 片段 Manifest
             ↓ 同一个已提交的片段输入快照
       ┌──────────────────────────────┐
       │                              │
③-A N 路 ASR 流水线              ③-B DNSMOS 评分流水线
    Qwen / GLM / 其他配置模型         独立分片、独立模型 worker
    每一路独立身份与转写产物          独立 DNSMOS 正式产物
       │                              │
       └──────────────┬───────────────┘
                      ↓
             证据对齐合并与完整性检查
                      ↓
④ 自由 tag 流水线
   消费已提交的转写与评分证据 → 多标签结果、规则审计与发布快照
```

核心要求：

1. VAD 片段快照就绪后，ASR 分支与 DNSMOS 分支同时具备启动资格，实际执行时间必须能够重叠。
2. DNSMOS 不等待 ASR 结束，不读取 ASR 文本决定是否评分，不依赖旧分类、候选队列或 tag 命中。
3. N 路 ASR 与 DNSMOS 均消费片段音频，禁止使用未切分父音频代替片段。
4. 证据合并等待本次配置要求的分支完成覆盖检查；自由 tag 消费合并后的证据。
5. 首版允许阶段级屏障：入库完成后切分、切分完成后并行分支、分支完成后合并打标。无需首版实现边切边转写的跨阶段流式 DAG，但阶段内必须分块、有界并发。

## 5. 各阶段功能要求

### 5.1 音频入库

1. 固化原始录音登记、来源与内容身份，输出可持续消费的父源 Manifest；原始数据保持可追溯，规范化不覆盖原录音。
2. 复用现有 PCM/WAV 处理、16 kHz 规范化与第 0 声道策略，记录源采样率、规范采样率、源声道数及选择依据。
3. 入库及规范化与 VAD 拆成独立阶段。重复启动能复用完整登记和规范化结果；坏输入明确记错，不能伪装成成功空音频。

### 5.2 前置 VAD 高并发流水线

1. 以父源录音为并发单位，分片策略可按时长均衡；同一源的流式音频块必须顺序执行，不能把同一录音的不同块交给无共享状态的 worker 并行判断。
2. 长驻 worker 复用已加载的模型权重，每个源独立持有/重置流式 cache、端点状态和事件记录。不同源不得共享可变推理状态；禁止通过全局推理锁把全部 worker 再串行化。
3. 完成一对多输出：源处理结果、零片段原因、片段音频、片段身份与 Manifest。有效无语音、全部短段、EOF 丢弃、解码失败、模型失败分别计数。
4. 记录父源任务检查点，支持单源/失败分片恢复；重试不能重复产段，文件损坏或缺失不能被“文件存在”缓存判断掩盖。
5. 并发改造不改变切分语义的隔离要求；**VAD 端点/裁切/短段/EOF 规则以 [049](./049-FSMN-VAD与分身实时服务完全对齐.md) 为准**（已废止本节原 675 ms 尾、统一 1 秒过滤、EOF 丢弃）。
6. 旧 041 文字曾出现不同 EOF 策略，当前算子汇总文案又含有“No minimum duration”，这些不一致不得被用来改动业务语义。Cursor 应以已确认的当前代码行为固定基线，并同步修正过时说明；本次不重新设计端点、最短时长或尾部保留规则。

### 5.3 N 路模型转写

1. 路次从配置读取，每项明确 `family`、唯一 `route_id/alias`、模型及推理参数、执行身份、输入快照、服务或本地运行资源。新主编排不能写死三家族、每家两路或总共六路。
2. Qwen、GLM 沿用现有识别实现；其他已支持模型通过既有适配器接入。N 路是模型执行路次，不等同于 N 个分片或 N 个 worker。
3. 同一家族独立双跑继续使用不同执行身份与缓存边界，禁止复制第一路结果冒充第二路。恢复同一路可复用其成功记录。
4. 不同模型/路次在资源允许时并行，同一路内部使用合适的批量、分片或 HTTP 并发。GPU 资源租约和服务会话管理继续生效，不因“机器足够强”取消预算与授权边界。
5. 每一路输出完整覆盖本次片段集合的结果记录：成功文本、成功空文本、失败、缺失/排除不能混淆。单条失败记录保留，不能为了齐备率丢行。

### 5.4 DNSMOS 独立高并发流水线

1. 独立输入片段 Manifest，独立输出正式 DNSMOS 评分 Manifest/分区数据集，与 ASR 产物同级注册。即使未运行任何 ASR、tag 或旧分类，也必须可运行、恢复和查询。
2. 正式评分对象为全部保留片段；DNSMOS 不通过 ASR 异常、旧类别或 tag 候选门控决定评分范围。
3. 复用现有 P.835 算法和固定预处理，输出 SIG、BAK、OVRL、成功/失败/不支持状态、错误、模型摘要及预处理版本。保持现有分数语义，不借并发重构修改算法、阈值或把 `calibrated` 擅自设为 true。
4. 高并发指具备分片、长驻模型 worker、批量调度、有界队列、检查点、重试、完整产物与可观测性；不要求把本地 ONNX 模型强行改成 HTTP/vLLM 服务。
5. 优先采用每进程或每工作线程独立会话，并验证其隔离；禁止未经验证地把类级单例直接暴露给多个并发配置。可复用底层 ONNX session，但可变预处理缓冲、状态及模型/配置身份必须正确隔离。
6. workers、分片数、并行分片、batch_size、max_in_flight、超时及重试可配置；原生推理库的线程数也纳入预算，避免“进程数 × ONNX/BLAS 线程数”失控。
7. 模型或配置缺失应在该节点预检阶段失败；单片段推理失败保留真实失败状态与错误，禁止写默认干净分或把失败当成静默成功。
8. 本流水线负责 DNSMOS 评分，不捆绑旧分类、阈值分流、ASR 或自由 tag。energy、Silero 等其他证据不作为本次 DNSMOS 流水线的隐藏附加阶段。

### 5.5 对齐合并与自由 tag

1. 合并是新流程的显式屏障节点，消费片段输入快照、N 路 ASR 产物和 DNSMOS 正式产物；不是“把可选质量侧车 attach 到某张表”。
2. 以片段 ID、片段内容身份、输入快照和运行身份对齐。禁止仅按行号、文件名、batch 名或父源哈希合并。
3. 必须检查重复 ID、额外 ID、缺失 ID、哈希不一致、快照不一致、缺失分片和路次冲突。任何拼错身份都不得进入正式 prepared/tag 发布结果。
4. 所有配置要求的分支必须提交完整覆盖记录后再合并。单条 ASR/DNSMOS 的显式失败记录属于合法覆盖，不等于成功证据；整个分支产物缺失或覆盖缺口不能默认为成功，也不能静默省略该路。
5. 合并保留所有有效 VAD 片段及各证据状态，不以“所有模型均成功”作为全局过滤。无法满足某规则的证据按规则返回 unknown，仍能执行其他有足够证据的规则。
6. 自由 tag 正式链使用已有证据模式，消费 DNSMOS 已提交结果；不得在 tag 阶段再次隐式启动全量 DNSMOS。修复评分必须恢复/重跑独立 DNSMOS 节点，再重新合并并使受影响 tag 结果失效重判。
7. FSMN 切分与 Silero 人声判定是不同能力，不能把前置 FSMN 端点直接冒充 `vad_speech_present` 的既有 Silero 证据。当前部分 tag 还依赖 energy/Silero：若没有显式生产这些证据，保留缺失状态并按三态求值，不能伪造、删除规则或隐藏启动额外流水线。需要补充这些能力时，作为后续明确配置的独立证据流水线接入同一合并机制。
8. 每条规则继续独立使用自己的词表、阈值和条件；复用音频身份、ASR 原始结果与 DNSMOS 分数，不引入跨规则判定结果缓存。

## 6. 数据身份与正式产物

建议采用以下新的正式分层。允许为实际存储布局做等价调整，但必须在交付文档中写明唯一权威位置和命名规则：

- 父源登记与规范音频：`datasets/stage1/ingested/ingested_<batch>.parquet`。
- VAD 片段：`datasets/stage1/segments/segments_<batch>.parquet` 及版本化源处理索引。
- 每一路 ASR：`datasets/stage1/asr/<route_id>_asr_<batch>.parquet`。
- DNSMOS：**`datasets/stage1/quality/dnsmos_<batch>.parquet`**，不得继续命名为 `quality_sidecar_*`。
- 合并证据：`datasets/stage1/derived/prepared_evidence_<batch>.parquet`。
- 自由 tag：`datasets/stage1/derived/tagged_free_tags_v2_<batch>.parquet`，保留规则审计与标签发布快照。

大批次可使用同等语义的分区 Parquet 与产物清单，单文件导出只作显式可选投影。更新 `source_naming`、输入解析、产物注册和消费者，避免新入口又自动解析回 `cleaned_*`、`prepared_asr_v3_*`、旧 classified 或旧侧车路径。

身份契约：

- 保留 `source_audio_id`、父源哈希、规范化哈希、片段 ID、采样边界、切分版本与模型/配置指纹。
- 当前片段 `Sample.sha256`、`original_audio_sha256` 使用片段 PCM 内容身份，`segment_wav_sha256` 是 WAV 文件身份；这两类哈希不能互相替代，父源哈希更不能充当片段哈希。
- 各节点产物同时绑定输入快照 ID/摘要与实际运行身份。同一个 batch 使用不同 VAD 版本得到的片段不能混合消费。
- 指纹覆盖实际输入音频、模型权重摘要、有效配置内容、预处理/算子版本及 ASR 路次身份，不能只记录文件路径。
- 正式逻辑产物通过不可变版本目录与原子清单/指针提交；示例中的稳定文件名不能成为不同 run 并发覆写的公共暂存文件。

## 7. 并发、百万级容量与恢复

1. 总编排真正并行启动已满足依赖的节点：至少能够证明同一片段快照上的 ASR 与 DNSMOS 时间区间重叠。仅有 DAG 文件、提交日志或多个配置文件不算并发落地。
2. 节点内复用现有分片/进程/线程/HTTP 执行工具，按引擎特点选择资源模型；不要为每个 tag 另建推理池。
3. 在总节点并行、分片并行、worker 并行、模型原生线程及 HTTP 请求之间设清晰预算，记录实际生效值；同一资源不能被多个层级重复无上限放大。
4. 并发队列与结果收集有界，任务传递优先使用音频路径和身份元数据，避免把整段 PCM/全部转写证据反复复制到进程队列。
5. 新的百万级主链必须逐批读取 Manifest/Parquet、逐块提交结果、增量合并或按 ID 分区对齐。不能同时加载全部父源、全部片段、N 路结果和所有规则审计树。
6. 对现有 `prepare_full_manifest`、`merge_shard_outputs` 及下游整批 API 做必要的局部改造或增加新的分区路径；保留小数据调用兼容即可，不要求重写无关流水线。
7. VAD 一对多不能因父源处理成功就假定所有片段音频完整；提交源检查点前必须确认片段文件和索引均已持久化。成功零片段也必须有源终态记录。
8. 各节点支持只恢复未完成工作和只重试失败分片/样本；已有有效 ASR 不因 DNSMOS 失败重跑，已有 DNSMOS 不因单路 ASR 失败重算。
9. 音频、切分版本、模型或有效预处理变化只失效相关节点及其下游；修改 tag 词表/规则只重判 tag，不重跑入库、VAD、ASR 或 DNSMOS。
10. 原子提交、运行锁、进程退出后的锁释放、临时文件与失败记录复用现有治理能力。记录错误不等于产物完整，文件存在不等于缓存有效。

## 8. 统一 runs、日志和可见执行过程

总流程有一个父 run，各独立流水线有可追溯子 run。参考目录形态如下，具体目录可沿用现有 runs 规范：

```text
runs/<parent-run>/
  run.json / state.json / config_snapshot/ / events.jsonl / metrics.json
  nodes/
    ingest/
    vad/
    asr/<route_id>/
    dnsmos/
    evidence_join/
    tagging/
```

必须做到：

- 任一阶段都能找到实际生效配置、输入产物、输出产物、子运行和恢复位置；独立运行 DNSMOS/VAD 时同样具备完整运行目录。
- 结构化事件携带父 run、子 run、节点、引擎、分片、父源/片段 ID、路次、尝试次数、耗时与错误，不只依赖终端 print。
- 展示 pending/running、提交/完成/失败/重试/复用/在途数量、吞吐、ETA、最后心跳及检查点。进度和模型调用统计必须来自实际执行，不能按计划数量虚增。
- VAD 分开显示父源进度、候选片段、保留片段及各类零输出/丢弃原因；ASR 按配置路次显示覆盖；DNSMOS 显示评分覆盖与失败；join 显示身份与覆盖缺口；tag 显示处理/提交进度。
- 挂起、服务不可用、进程退出和证据失败可以从统一视图定位。执行完成与全部证据成功分别展示，不得把含失败记录的运行描述成全部推理成功。
- 复用并扩展 `audio-data pipeline progress <parent-run> --follow` 或同等现有查询入口，能从父 run 看到 ASR 和 DNSMOS 同时运行，以及哪个节点正在阻塞合并；不能要求用户逐个寻找散落日志。
- 心跳独立于模型完成事件，长文件/长推理时仍周期性更新；无法直接观察的内部运行数量如实显示未知，不编造 worker 活跃度。

通用调度、监控与结果存储能力可以从 tag 下沉至公共运行/证据层，由 VAD、DNSMOS、ASR 编排及 tag 复用。依赖方向必须保持：公共运行/模型层不反向依赖 tag 规则、词表或旧 selection 业务。

## 9. 实施顺序与完整交付

1. 复核当前代码和未提交改动，给出简短的新 DAG、节点输入输出及计划改动清单，随后直接实施。
2. 拆开音频入库与 VAD，完成前置 VAD 有界并发、身份隔离和一对多恢复。
3. 建立独立 DNSMOS 生产流水线，接入模型常驻、分片并行、检查点和完整 runs。
4. 将模型路次改为配置驱动，完成 ASR 与 DNSMOS 的真实并行编排、资源预算和独立恢复。
5. 完成身份校验的证据合并、自由 tag 已有证据消费，以及百万级分块持久化和增量输出。
6. 接通统一父子 runs 与进度查询，清理新链中的旧侧车、旧分类和固定路次假设。
7. 完成最小验证，更新现行架构/操作手册、`单条流水线执行命令.txt` 和需求实施状态，交付实际可执行的首次运行、独立运行、查询、续跑及失败重试命令。

本需求明确授权为以上目标修改必要的 `core/`、算子、CLI、YAML、模型运行配置、输入命名/合并、测试与文档。保留已有未提交改动、规则语义和历史数据；不自动提交、推送或结束用户正在使用的模型服务。

必须交付所有节点的实际实现与完整接线，不能只提交设计、并发 YAML、空适配器、启动脚本或仅能 mock 的生产路径。真实模型资产/环境缺失时完成可实现代码并明确报告验证限制，不伪造服务器通过结果。

## 10. 最小验收

优先复用现有针对性测试，并增加少量能覆盖关键新行为的测试；不要求全仓库回归、长时间压测或真实百万条运行。

至少证明：

1. **真实并发调度**：小固定输入上，两个父源可同时执行 VAD；ASR 与 DNSMOS 分支能够重叠运行；设置的在途上限生效，源状态/模型会话不串用。可使用可控 mock 后端与同步屏障证明工程并发。
2. **身份与合并**：一源零/多片段；同父源不同片段、不同模型路次不串结果；DNSMOS 分数属于对应片段；重复、缺失、额外、哈希或快照不一致被识别。
3. **失败与恢复**：中途终止或注入一处失败后只重做未提交/失败工作；不重复产段；DNSMOS 失败不重跑成功 ASR，反向同理；父 run 可见故障和恢复位置。
4. **自由 tag 消费**：有完整 DNSMOS 证据时不再调用 DNSMOS；失败/缺失保持三态；不同词表规则独立；旧 classified/侧车文件不会被新链自动发现为输入。
5. **最小链路**：用少量父源完成入库 → VAD → 多路 ASR 与 DNSMOS 并行 → join → tag，核对源数、片段集合、各路覆盖和最终样本集合；检查统一进度与日志。

VAD 边界及分数语义优先复用已有固定样本测试。真实模型可用时补充少量实际片段的串行/并发评分对照，容差沿用当前配置；不可用时清楚标记“工程验证通过，真实模型一致性/吞吐未验证”。不要以机器足够强为由承诺未经实测的固定加速倍数。
