# 数据清洗与标注双流水线

Manifest 为唯一真相源，Pipeline YAML 编排 Operator DAG，支持断点续跑与 cache。

**前置条件**：原始 wav / pcm 须先通过 [批次资产入库](./构建思路.md#二数据批次资产从物理文件到可引用数据源) 登记为 **数据源**（如 `数据源A`）。清洗与标注流水线的输入均为数据源 manifest，而非直接扫描 raw 目录。

```text
物理文件 batch_A  →  batch ingest  →  数据源 A  →  数据清洗流水线  →  cleaned_source_A
物理文件 batch_B  →  batch ingest  →  数据源 B  →  数据清洗流水线  →  cleaned_source_B
```

## A. 数据清洗流水线（只做音频质量，不做标注决策）

### 目标

- 输入：**数据源**（如 `source_A` / `数据源A`），即 `datasets/sources/source_A.yaml` 指向的批次 manifest
- 输出：`datasets/manifests/cleaned_source_A_YYYYMMDD.parquet`

### 流程

0. **前置：批次入库（batch ingest，在清洗流水线之外执行）**
   - 扫描 `data/batches/batch_A/` 下 wav / pcm
   - 写入 `datasets/batches/batch_A/manifest.parquet` + `batch_meta.yaml`（含入库时间、来源）
   - 注册 `datasets/sources/source_A.yaml` → 形成 **数据源 A**

1. **标准化**
   - 从数据源 manifest 读取样本，`id` = 文件名 stem；`sha256` 用于去重与 cache key
   - pcm 先经 `audio.pcm_to_wav` 转码（配置 sample_rate / channels）

2. **重采样**
   - `audio.resample` 统一到 16k（输出 key：`resampled_16k`）

3. **质量检测**
   - 损坏：`probe_audio` 失败 → `labels.broken = true`
   - 空白：`duration == 0` 或 `audio.vad` 的 `speech_ratio` 低于阈值
   - `quality.filter` 标记 `labels.audio_pass`

4. **导出清洗结果**
   - 仅保留 `audio_pass == true` 样本进入 `cleaned_source_A_YYYYMMDD.parquet`
   - manifest 继承 `batch_id`、`source_id`、`ingested_at`、`origin` 血缘字段

### YAML 草案

```yaml
name: data_cleaning_source_A

input:
  source: source_A                              # 数据源 A，非 raw 目录
  # 解析为 manifest: datasets/batches/batch_A/manifest.parquet

output:
  manifest: datasets/manifests/cleaned_source_A_20260820.parquet

pipeline:
  - { operator: audio.pcm_to_wav, params: { sample_rate: 8000 } }
  - { operator: audio.resample, params: { sample_rate: 16000, input_audio_key: raw, output_audio_key: resampled_16k } }
  - { operator: audio.vad, params: { input_audio_key: resampled_16k } }
  - { operator: quality.filter, params: { expr: "label_broken != True and quality_speech_ratio > 0.1", label_key: audio_pass } }
```

数据源 B 同理，复制为 `data_cleaning_source_B.yaml`，改 `input.source` 与 `output.manifest` 即可。

## B. 标注流水线（只做文本生成与标注融合）

### 目标

- 输入：`datasets/manifests/cleaned_source_A_YYYYMMDD.parquet`（或 `cleaned_source_B_*`）
- 输出：`data/exports/train_source_A.jsonl`

### 流程

1. **双模型 ASR（可并行）**
   - `asr.sensevoice` + `asr.qwen`，输入音频 key 为 `resampled_16k`
   - 输出到 `transcripts.sensevoice.text` / `transcripts.qwen.text`

2. **文本归一化**
   - 两路文本统一走 `zizhun.py` 的 `clean_text`（去标签、口语词归一、数字转汉字）

3. **一致性筛选（伪金标）**
   - 计算归一化后的编辑距离 / 字准率（`word_acc = 1 - dis / len(ref)`）
   - `word_acc >= 阈值`（如 0.95）→ `labels.pseudo_gold = true`

4. **标注融合**
   - 一致样本：归一化后文本写入 `labels.gold_text`
   - 不一致样本：接入边际距离脚本（`quality.transcript_merge`）融合
   - 差异过大：`labels.needs_review = true`

5. **业务过滤（语音信箱）**
   - 对 `gold_text` 正则匹配：`您拨打的电话|无法接通|留言|语音信箱`
   - 命中：`labels.voicemail = true`，导出时排除

### YAML 草案

```yaml
name: labeling_source_A

input:
  manifest: datasets/manifests/cleaned_source_A_20260820.parquet

output:
  export: data/exports/train_source_A.jsonl

pipeline:
  - { operator: asr.sensevoice, params: { input_audio_key: resampled_16k } }
  - { operator: asr.qwen, params: { input_audio_key: resampled_16k } }
  - { operator: quality.transcript_diff, params: { model_a: qwen, model_b: sensevoice } }  # 待扩展为 clean_text + word_acc
  - { operator: quality.transcript_merge }  # 待实现，接入边际距离脚本
  - { operator: quality.filter, params: { expr: "label_voicemail != True and label_pseudo_gold == True", label_key: export_pass } }
```

## 交付物

| 阶段 | 产物 |
|------|------|
| 批次入库 | `datasets/batches/batch_*/batch_meta.yaml` + `manifest.parquet` |
| 数据源注册 | `datasets/sources/source_*.yaml` |
| 清洗 | `datasets/manifests/cleaned_source_*_YYYYMMDD.parquet` |
| 标注 | `data/exports/train_source_*.jsonl` |
| 每轮 run | `runs/<timestamp>/manifest.parquet` + `metrics.json` |
