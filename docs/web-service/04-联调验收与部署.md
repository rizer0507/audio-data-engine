# 04｜联调、插件扩展验收与部署

日期：2026-10-19。状态：验收计划，尚未执行。前置：[00](00-总需求与实施顺序.md) 至 [03](03-前端操作台.md)。

## 1. 完成标准

交付可运行的前端、API、Worker 和统一插件接入机制。用户只配置真实数据源与已启动的 GLM/Qwen 连接，即可通过页面处理、查看并导出实际结果。

“页面有内容”“接口返回 200”“离线 mock 通过”“服务能启动”都不能单独代表完整验收。分别记录离线、协议测试、浏览器和真实服务器证据，完成结论与实际验证范围一致。

## 2. 测试组织

优先复用当前空骨架 `tests/web/test_api.py`、`test_jobs.py`、`test_engine.py`，新增 `tests/test_plugins.py`。必要时按职责少量拆分，不为目录占位编写测试，不对简单样式和实现细节大量重复断言。

### 2.1 插件契约与扩展测试

至少覆盖：

1. pipeline/tag 共用契约和注册表；普通 YAML、production DAG、tag 定义正确适配。
2. 重复 ID、版本冲突、非法 schema、未知 adapter、循环引用、缺词表、禁用/归档、tag 文件名不符产生定位错误。
3. 查看目录、describe、validate、plan 零推理调用，无关重型依赖缺失不阻断目录。
4. 现有算子组合新增流水线，只加定义和登记即可发现、规划和执行；无需修改路由、Worker 和页面。
5. 新增 tag 文件刷新即可发现，未显式选择不影响原任务；选择后按既有证据产生预期三态和来源。
6. 两个 tag 共享同模型同参数声学证据时只计算一次；existing、纯文本 tag 和 preview plan 不补算。
7. 递归快照包含真实子 YAML、词表正文和参数；排队后修改源文件不污染旧任务，代码实现漂移不能静默恢复。

扩展测试的示例插件放在测试临时目录，不污染正式库、不把测试规则启用到生产配置。

### 2.2 HTTP 协议与模型端口测试

使用测试代码启动的两个本地 HTTP 测试服务捕获请求，不需要启动真实大模型：

- 两个连接使用不同端口，验证任务实际访问各自端口，没有默认端口替代。
- GLM 的 transcription URL、multipart、model 和 Qwen 的 chat URL、音频、model/语言参数符合现有适配。
- base_url 的主机形式与 /v1 形式均不重复拼接，超时、401、404、模型名不符、无效响应有具体错误。
- 同家族多 route 不同端口不会串配置；API/Worker 继承的旧环境变量不能覆盖冻结连接。
- 一个任务配置变更或失败不会影响另一个任务的模型地址。

这些是“HTTP 契约测试”，报告中不得标为“真实 GLM/Qwen 推理已通过”。

### 2.3 任务与故障测试

至少覆盖提交幂等、双 Worker 原子领取、重复取消、排队取消、运行取消、取消后保留断点、API 重启、Worker/执行子进程崩溃、租约过期、PID 复用保护、失租者迟到更新与发布、发布后数据库更新前崩溃对账。

验证：没有两个活动 attempt 共同覆盖输出；不能仅凭 lease 过期重复启动旧进程仍在运行的任务；恢复只读取兼容断点；终态有完整事件与错误；取消只停止服务创建的任务进程树。

使用小型测试插件和临时目录触发故障，避免为状态机测试启动昂贵推理。

### 2.4 业务兼容与数据查询测试

- 用固定证据比较现有 tag 的三态、重叠、多规则来源和人工添加/屏蔽结果。
- 保持片段 ID、父源血缘、ASR 原文/清洗文本、证据失败/缺失/真实空文本的区别。
- 测试审核 revision 冲突、重复请求幂等、正式 Gold 门禁和人工状态持久化。
- 验证分页/筛选与导出一致，分母和失败口径正确；不可变发布产物不被人工操作直接覆盖。
- 测试日志 cursor、UTF-8、轮换、attempt 切换、响应上限，音频 Range 及错误路径范围。
- 生产主链使用实际编排适配器验证子节点连接传递、输出隔离和取消，而不只 mock 最外层调用。

按改动范围运行现有回归，例如 `test_core.py`、`test_production_045.py`、`test_tagging_library_042.py`、`test_tagging_decoupling_044.py`、`test_free_tags_v2_entry_044.py`、`test_tagging_concurrency.py`、`test_annotation_v3.py`、`test_eval_decoupled.py`、`test_vllm_asr.py`。依赖缺失或原有失败应列出证据，不删除测试或修改预期以制造通过。

## 3. 前端与浏览器验收

完成前端类型检查、生产构建和一条浏览器核心流程。项目 package.json 需提供实际可执行的 dev、build、typecheck 和适用测试命令。

核心流程：登记源 → 配置并检查连接 → 刷新插件 → 选择插件和 tags → 动态参数 → 规划 → 提交 → 查看进度日志 → 刷新页面 → 查看产物 → 试听 → 筛选导出。

额外覆盖：

- 新插件在前端不改源代码即可出现并生成字段。
- 配置冲突、目录漂移、错误端口、离线模型、unknown、空数据和任务中断有可理解状态。
- 取消显示 cancelling 后等待真实结束，外部测试 HTTP 服务继续存活。
- 深层路由刷新正确，未知 /api 路径返回 JSON 错误而非 SPA 页面。
- 大日志和较多样本时使用增量和分页；页面不重复请求全量数据。

截图/录屏和自动化结果要说明测试使用的是协议测试服务还是真实服务器，不能混淆。

## 4. 真实服务器小批次验收

### 4.1 前提

由用户填写或提供：真实源 ID/路径与格式参数、项目部署路径、需要使用的 GLM 或 Qwen base_url、served-model-name、model_revision；如主链包含 VAD/DNSMOS，提供实际可用的本地依赖配置。

不得从历史服务器配置推断当前端口可用，也不得启动或停止用户 vLLM。若真实环境不在当前执行主机可访问范围，交付具体命令和待验收项，不宣称真实环境通过。

### 4.2 小批次边界

先使用明确限制的约 10 条实际音频，包含正常音频与可确认的异常/缺失路径案例；测试临时样本索引保留来源映射，不能改写原始目录。若流水线没有受限样本选择能力，先通过其声明的输入接口生成受限测试输入，不直接对整个真实目录执行生产全量处理。

真实小批次验收记录至少包含：

1. 数据源检查通过的时间、抽样数量和音频格式。
2. 模型目录检查与真实短音频转写分别记录；实际请求地址保留端口，密钥脱敏。
3. 至少一个用户已启动的 GLM 或 Qwen 完成页面提交的实际 ASR 任务，产生真实 Manifest、原文/清洗文本和日志。
4. 使用已有证据运行显式选中的 tags，展示 matched/not_matched/unknown 和来源；缺某家族时依契约显示 unknown，不捏造转写填满证据。
5. 若本期主链依赖已齐全，完成入库/VAD/ASR/DNSMOS/join/tag 主链小批次；否则单独列出尚未验证的主链节点，不能将 ASR 子任务成功当整链通过。
6. 页面可试听实际音频、查看样本、按标签筛选并下载实际导出文件。
7. 运行中刷新/关闭页面后任务继续；取消另一个受限任务后用户 vLLM 仍可访问。
8. 保存一个受控中断任务的断点，恢复时校验快照并保留历史 attempt；代码或输入发生不兼容变化时明确拒绝。

没有合法正式 Gold 的小样本仅用于处理链验证，不要求产生正式准确率。评测验收使用已有合法 Gold 数据，否则记录门禁拒绝符合预期，正式评测成功项留待验证。

## 5. 部署与运行要求

### 5.1 部署产物

保留根 pyproject.toml 作为 Python 依赖入口，以可选 Web 依赖组或等价清晰方式增加必要依赖；不再创建冲突的 requirements 文件。前端保留一个包管理器及其 lockfile。

提供实际可运行且已验证的两个启动入口，推荐目标为：

```text
audio-data-web --config <项目绝对路径>/configs/web.yaml
audio-data-worker --config <项目绝对路径>/configs/web.yaml
```

这是待实现的启动入口约定，不代表当前已经存在。若选择 `python -m`，必须同步给出清晰、等价且经过验证的命令，避免文档命令与 pyproject 入口不一致。

前端构建产物由 API 通过配置的静态目录提供。服务从不同工作目录启动、重新启动后，数据源、模型配置、任务和产物可持续访问。

### 5.2 进程与端口

Web 和 Worker 各自独立常驻，退出时释放自身资源。Linux 部署说明可给出 systemd 配置示例，Windows 本地开发给出两个终端启动方式；不强制引入 Docker 或 Nginx。

部署说明区分 Web 服务端口与外部模型端口。Web 绑定地址采用显式配置，默认本机访问；外部模型地址仅用于 HTTP 客户端调用。服务重启不触发任何 vLLM 启动/关闭脚本。

### 5.3 持久化与维护

说明 SQLite、配置、runs、数据集和导出物的实际位置；SQLite 保存在本机磁盘。备份包括配置、SQLite 一致性备份及必要任务快照，不能只复制前端代码。

清理策略只覆盖服务生成且明确过期的未引用临时文件/已过期计划，不能自动删除源音频、历史人工记录、已发布产物或仍被恢复任务引用的断点。
