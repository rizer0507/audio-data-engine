# Web 服务部署与运行

日期：2026-10-19。对应需求：[04 联调验收与部署](04-联调验收与部署.md)。

交互修订（内部 ID 自动生成、流水线/tag 启用/归档）已按 [05 增量提示词](05-Cursor执行提示词.md) 落地；离线协议与前端构建见 [验收记录.md](验收记录.md) §0。下述登记与分类按当前实现说明。真实服务器/vLLM 仍待用户环境验收。

## 1. 依赖与构建

```text
# 仓库根目录
pip install -e ".[web]"
# 开发/测试另加
pip install -e ".[dev]"

cd frontend
npm ci
npm run build
```

前端产物：`frontend/dist/`。API 通过 `configs/web.yaml` 的 `static_dir` 同源托管。

## 2. 配置

编辑 `configs/web.yaml`（相对路径相对 `project_root`）：

| 项 | 说明 |
|----|------|
| `bind_host` / `bind_port` | Web 监听；默认 `127.0.0.1:5599`（可由 nginx 反代） |
| `project_root` | 建议启动参数 `--project-root` 显式指定 |
| `sqlite_path` | 任务状态 SQLite，默认 `var/web.sqlite3` |
| `runs_dir` | 计划快照、日志、任务工作目录 |
| `plugins_config` | `configs/plugins.yaml` |
| `sources_manifest` | `resources/manifest.yaml`（唯一数据源登记） |
| `allowed_source_roots` | 源路径必须落在这些根下 |
| `models[]` | GLM/Qwen：`base_url`（含端口）、`model`、`model_revision`、`provider`、`api_key_env` |

模型密钥只通过环境变量引用（如 `GLM_ASR_API_KEY`），API/日志不回传密钥。

**外部 vLLM 由用户自行启动。** 本服务不启动、不停止、不杀 GPU 进程；取消任务只停本服务创建的任务进程树。

## 3. 启动入口（已验证）

两个独立进程。任选其一对：

### A. console scripts（`pip install -e ".[web]"` 后）

```text
# 终端 1 — Web
audio-data-web --config D:/Work/audio-data-engine/configs/web.yaml --project-root D:/Work/audio-data-engine

# 终端 2 — Worker
audio-data-worker --config D:/Work/audio-data-engine/configs/web.yaml --project-root D:/Work/audio-data-engine
```

### B. 等价 `python -m`（阶段五冒烟已验证）

```text
set PYTHONPATH=src
python -m audio_engine.web.app --config D:/Work/audio-data-engine/configs/web.yaml --project-root D:/Work/audio-data-engine
python -m audio_engine.web.worker --config D:/Work/audio-data-engine/configs/web.yaml --project-root D:/Work/audio-data-engine
```

浏览器打开：`http://127.0.0.1:<bind_port>/`（默认 5599）。开发时可另开 `cd frontend && npm run dev`（Vite 代理 `/api` 到 5599）。

服务器建议：`bind_host=127.0.0.1`，nginx 反代到 `127.0.0.1:5599`；勿占用/暴露 8080。Web 端口与外部模型端口（如 8001/8002）相互独立。

## 4. 停止自身服务

- 在两个终端对 Web/Worker 发送 Ctrl+C（或结束对应进程）。
- **不要**运行历史 vLLM 启动/杀进程脚本；停止 Web/Worker 不会也不应停止用户 vLLM。

## 5. 日常操作步骤

### 5.1 登记数据源

1. 页面「数据源」→ 填写 batch、服务器可读路径、格式参数 → 保存；后端自动分配 source_id，无需手填  
2. 「检查」：确认路径存在、可读、抽样文件数  

或写 `resources/manifest.yaml` 后刷新列表（SQLite 不维护第二套源主数据）。

### 5.2 配置模型连接

1. 「模型」→ 编辑 `base_url`（含端口）、`model`（served-model-name）、`provider`、`model_revision`  
2. 「检查（models）」：目录/模型名  
3. 「检查（transcription）」：需选短音频样本；真实推理依赖用户已启动的 vLLM  

connection_id 由后端首次保存自动生成，显示名称可自动取 provider 与主机:端口；连接可跨 batch 复用，编辑时不换 ID。任务页面按名称/地址选择，不要求复制粘贴 ID。

### 5.3 新增插件（不改 API/Worker/前端）

见 [插件接入说明.md](插件接入说明.md)。摘要：

1. 流水线：新增 `pipelines/<id>.yaml` + `configs/plugins.yaml` 登记  
2. Tag：新增 `configs/tagging/library/<tag_id>.yaml`（文件名=tag_id）  
3. 页面「插件」→ 刷新目录 → 出现在列表与任务表单  

阶段五证明用插件：`web_stage5_ext_demo` / `web_stage5_ext_text_tag`。

流水线和 tag 列表/详情均有“归档/启用”按钮，按在用(enabled)/归档(archived)/全部筛选，经 `PATCH /api/v1/plugins/{kind}/{id}/status` 写回原配置并刷新目录。归档不删除历史标签/产物，不停止已提交任务；新规划/提交不可选归档项，重新启用后再规划。

### 5.4 提交任务

1. 「任务」→ 选 pipeline 或 tagging → 动态参数（SchemaForm）→ 绑定 route → 规划  
2. 规划成功后提交（幂等键）；「任务详情」看进度与增量日志  
3. 刷新页面后状态从 SQLite 恢复，不丢 attempt  

### 5.5 取消

任务详情点取消 → 状态 `cancelling` → 终态 `cancelled`。仅杀本任务子进程树；用户 vLLM 应仍可访问。

### 5.6 恢复 / 重跑

- 兼容断点：`resume`（读取冻结快照；定义漂移会拒绝）  
- 不兼容或需全量：`rerun`（新 attempt、隔离输出）  

重启 Web/Worker 后，未完成任务可被 Worker 按租约重新领取（见状态机测试）。

### 5.7 结果 / 导出 / 评测

1. 「数据集」→ 筛选 → 试听（Range）→ 规则解释（不推理）  
2. 人工标签 / 审核写入工作态，不覆盖已发布 Manifest  
3. 导出：冻结当前筛选 → 插件任务 → 下载 artifact  
4. 评测：先 Gold 门禁；无正式金标应被拒绝（`FORMAL_GOLD_GATE`）  

## 6. 持久化位置

| 内容 | 默认位置 |
|------|----------|
| SQLite | `var/web.sqlite3` |
| 计划/日志/attempt 工作区 | `runs/web/` |
| 源登记 | `resources/manifest.yaml` |
| 模型连接 | `configs/web.yaml` |
| 插件目录 | `configs/plugins.yaml` + `pipelines/` + `configs/tagging/library/` |
| 业务产物 | 既有 `datasets/` 等路径（任务隔离输出在 runs 下按 attempt） |

备份：配置 + SQLite 一致性拷贝 + 仍被恢复引用的 runs 快照；不要只备份前端。

清理：仅清理服务生成且过期的未引用临时文件/过期计划；不得自动删除源音频、人工记录、已发布产物、恢复仍引用的断点。

## 7. Linux systemd 示例（可选）

```ini
# /etc/systemd/system/audio-data-web.service
[Unit]
Description=audio-data-engine Web
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/audio-data-engine
Environment=PYTHONPATH=src
ExecStart=/usr/bin/audio-data-web --config /opt/audio-data-engine/configs/web.yaml --project-root /opt/audio-data-engine
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Worker 单元同理，将 `ExecStart` 换为 `audio-data-worker`。不强制 Docker/Nginx。
