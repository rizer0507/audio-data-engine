# 03｜前端操作台需求

日期：2026-10-19。状态：待实现。前置：[00](00-总需求与实施顺序.md)、[01](01-统一插件接口.md)、[02](02-后端与任务执行.md)。

## 1. 目标与实现边界

提供面向实际音频处理工作的中文管理台。用户无需手改脚本即可配置真实资源、选择插件、提交任务、查看日志与结果、操作标签并导出。

复用已有 React/TypeScript 空骨架，保持单一 api.ts 和必要公共组件。可以采用一个稳定的组件方案，不叠加多个 UI 框架，不为每个插件创建页面。页面连接真实后端，测试 fixture 只能用于测试，不能成为生产页面默认数据。

开发阶段 Vite 将 `/api` 代理至后端；生产阶段使用同源相对路径。不能把 localhost 开发地址、模型端口或数据集路径写死在前端 bundle。

## 2. 导航与通用体验

导航使用：数据源、模型连接、插件库、任务、数据集、评测。

对应页面：Sources、Models、Plugins、Jobs、JobDetail、Datasets、DatasetDetail、Evaluations；必要详情使用抽屉或当前页展开，不预建大量页面目录。

所有页面都需要明确的加载态、空态、错误态和可重试操作。没有数据时说明下一步，例如“先登记服务器数据源”，不能使用虚构行填充表格。

- 页面 URL 可直接访问，浏览器刷新不丢失当前资源位置。
- 列表筛选、分页及所选任务/数据集尽量写入 URL；任务表单可保留草稿，但模型密钥不进入浏览器存储。
- 时间按用户时区显示，持续时间与执行状态分开展示。
- 展示后端 error.code、可读 message、字段错误和 request_id；用户能复制诊断信息。
- 请求失败保留已输入表单，重复点击提交使用同一个幂等键，明确成功后再清空。
- 页面只根据后端报告展示状态和能力，不通过定时器制造进度或自行猜测任务完成。

## 3. 数据源页面 Sources

列表展示 source_id、名称、服务器路径、格式、必要音频参数、最近检查时间和结果。

用户可以登记和修改数据源、执行真实受限检查、查看抽样结果，并从该行进入新建任务。

- 路径输入说明是服务器路径；不使用用户电脑的文件选择器冒充服务器目录选择。
- 输入格式及 PCM 参数的必填规则来自后端能力与 schema。
- 检查结果区分目录存在、权限、抽样文件数、解码结果、是否完成全量扫描。
- “未检查”“抽样可用”“检查失败”单独展示；不把 file_count 默认值当真实全量统计。
- revision 冲突提示加载最新配置，保留当前输入供用户比较。
- 第一版不提供删除原始音频按钮。

## 4. 模型连接页面 Models

列表和表单包含连接 ID、显示名称、provider、base_url、model、model_revision、超时、并发、密钥环境变量引用。

提供两个明确操作：

1. 检查连接与模型名：展示真实返回身份、延迟和时间。
2. 试转写：用户选择已登记数据源/产物中的实际短音频样本，展示本次真实请求的转写和结果状态。

未提供样本时不能显示“转写验证通过”。检查过程不能显示“正在启动模型”；连接不可用时告诉用户访问的地址与端口及具体错误。

base_url 输入提供格式说明但不固定端口。provider 可选项从后端能力读取；任务可使用同一 provider 的多个连接。api_key 只显示配置引用和是否可解析，不回显密钥。

保存配置与测试连接是独立操作；用户修改模型配置不改变历史任务的快照。页面提示 model_revision 用于标记同名模型部署修订，不宣称它是远端权重哈希。

## 5. 插件库页面 Plugins

使用“流水线 / tag”两个分区或页签，共用搜索、状态筛选、详情和刷新目录操作。

### 5.1 列表和详情

列表包含 kind、ID、名称、业务版本、状态、purpose、适配器、定义来源、当前可执行性和诊断。详情展示：

- 流水线：业务目的、输入类型、实际步骤/DAG、模型角色、输出类型、参数说明、tag 选择支持、取消/恢复能力。
- tag：业务定义、规则条件、版本、片段与词表、证据需求、命中/不命中/unknown 示例、是否需要声学计算。
- 当前 generation 和定义摘要；诊断可定位到文件及字段。

查看、刷新和打开详情不触发 ASR/DNSMOS。页面不得把未知依赖显示为已满足，也不能因一个插件无效让整个目录白屏。

### 5.2 新插件接入后的体验

操作者新增定义文件并登记后，点击刷新即可发现新插件；新增 tag 不会自动勾选到已有任务草稿或所有批次。

disabled/archived 可查看但不能新选。页面不提供上传 Python、安装包、输入 import 路径或任意执行命令的功能；定义维护继续使用代码与配置文件。

## 6. 新建任务与 Jobs

任务列表展示任务 ID/名称、任务类型、输入源或数据集、根插件、选中 tag 数量、状态、真实进度、创建和运行时间。支持状态筛选、分页、详情和新建。

### 6.1 新建任务流程

1. 选择任务方式：运行流水线，或对已有数据集执行选定 tags。
2. 从后端插件目录选择当前可用版本；输入类型由 descriptor 限定。
3. 选择 source_id 或 dataset/artifact ID；不能手填后端输出路径。
4. 依据插件模型角色生成 route 绑定表，选择已配置连接。
5. 根据 parameters_schema 生成参数表单，填写并发、语言、证据模式等声明项。
6. 仅在支持时展示 tag 选择，明确版本、依赖和计数；不默认启用全库。
7. 发起校验与规划，查看规范化参数、节点、模型地址/端口、tag、缺失依赖和可能补算的证据。
8. 用户点击“提交任务”后按 plan_id/plan_digest 入队，成功跳转详情。

字段修改后旧计划立即标记过期并禁用提交，要求重新规划；后端返回版本漂移 409 时重新加载目录和规划，不悄悄换成新定义。规划界面说明“尚未执行推理”。

### 6.2 动态参数表单

前端不允许维护 `pipeline_id -> 专用表单`、`tag_id -> 特殊字段` 映射。

第一版通用表单至少支持 JSON Schema 的 object、string、number、integer、boolean、enum、array、required、default、minimum/maximum、minItems/maxItems 和嵌套对象，并根据 title/description 显示中文标签和帮助。

`additionalProperties: false` 与后端保持一致。对于有效但暂不能用普通控件表达的复杂 schema，允许提供受 schema 校验约束的 JSON 参数编辑区；后端字段错误仍能定位。不得把高级参数文本当 shell 或任意 YAML 执行。

模型路次绑定是通用结构化控件，支持动态增加/删除 schema 允许的 route，唯一 route_id 与 provider 兼容性由后端验证。不写死 GLM/Qwen 各一路或固定三族六路。

## 7. 任务详情 JobDetail

页面展示：

- 当前 job 与 attempt 状态，开始/结束时间，心跳和异常信息。
- 阶段、节点及并行状态；已处理/成功/失败/缓存命中/unknown 等实际计数。
- 本次输入、所用插件和 tag 版本、模型地址端口、模型修订、证据模式与配置快照。
- 增量日志，支持节点选择、自动滚动开关、复制诊断。
- 产物列表，成功后可以跳转数据集、查看报告或下载已登记文件。
- 历史 attempts，保留失败、取消与恢复链路。

运行中默认每 2 秒查询状态和增量日志，可配置；切换页面或组件卸载停止轮询，后台页面可降低频率。终态停止高频轮询；网络断开只提示连接中断，不改变任务状态。

日志按 cursor 增量追加，客户端保留有限缓冲并提供查看/下载实际日志入口；attempt 切换重新建立 cursor，不能拼接成同一次执行的假连续日志。

动作由后端能力控制：

- 取消：显示 cancelling，直到后端确认停止才显示 cancelled。
- 恢复：显示使用原冻结计划、可复用断点和阻塞原因；不支持时禁用并说明。
- 重新运行：明确创建新任务；默认使用原计划，可另选“按最新定义重新规划”。

没有可靠 total 时显示阶段与计数，不画伪精确百分比。并行主链分别显示 ASR 路次和 DNSMOS，不把其中一个完成视为全部完成。

## 8. 数据集列表与详情

### 8.1 Datasets

列表展示数据集/产物 ID、版本、来源任务/批次、样本数量及统计状态、创建时间和可用产物。已有旧数据集能够浏览，缺元数据时显示未登记/无法完整追溯的具体限制。

### 8.2 DatasetDetail

使用服务端分页和筛选。样本表支持样本 ID、时长、选中路次转写、质量指标、有效 tags、规则三态和失败状态；复杂详情在展开区展示，避免一次将所有字段挤入表格。

筛选项至少包括：tag 包含/排除与 all/any 组合、matched/not_matched/unknown、路次状态、已存在质量指标区间、审核状态。缺失指标显示“未计算/失败/缺失”真实状态，不显示 0。

音频播放器请求后端资产接口，支持拖动播放；样本详情展示原始音频或片段、父源、时间区间和 lineage。不能用浏览器本地路径直接读取服务器文件；PCM 无法解释时展示原因。

规则解释展示实际使用的规则/版本、证据、缺失依赖、人工来源与结果快照；当前定义改变时明确提示，旧结果仍按旧定义解释。

### 8.3 人工标签与审核

标签操作提供人工添加、屏蔽自动标签、恢复自动规则和撤回人工来源。显示与保存 operator_id、reason、revision；冲突保留编辑内容并提示刷新。

审核表单遵守现有 Gold/标注协议：如金标文本、speech_scope、gold_kind、审核阶段以及该阶段所需其他字段。页面可使用后端提供的审核字段定义或明确映射现有合法字段，不凭空设计更宽松的协议。

一次修改不能伪装完成双人审核；正式 Gold 不通过时显示具体缺项，不能仅靠勾选“已审核”绕过。未发布人工工作状态与不可变发布版本要有可识别标记，导出明确使用哪一版本。

### 8.4 导出

用户选择服务声明支持的导出类型和当前筛选范围，查看输入版本、筛选条件与范围后创建导出任务。批量导出经统一任务/插件链执行，不在点击按钮的 HTTP 请求中生成全量文件。

按钮显示等待、运行、完成或失败，完成后从注册 artifact 下载；过滤条件和数据集版本冻结，不随继续浏览而变。

## 9. 评测页面 Evaluations

选择评测数据集版本、purpose=evaluation 的流水线插件与模型连接，通过同一规划和任务提交过程执行。

展示真实评测任务状态、模型/修订、数据范围、总量/有效量/失败量、指标及分母口径、分组结果与报告。正式 Gold 不满足时阻止正式评测并展示原因；探索性结果必须按现有引擎能力明确标识，不能包装成正式准确率。

模型对比只对可比较的同一输入版本和同一指标口径进行。无数据时显示无结果；柱状图、排名和指标不能由前端随意生成。与其他处理任务共享任务详情及日志组件。

## 10. 前端验收

1. 生产构建、类型检查通过；所有导航与深层 URL 刷新正常。
2. 从登记真实数据源、配置外部模型、选择插件、规划、提交到查看结果的核心流程可操作。
3. 新增合法流水线/tag 后，刷新目录即可展示并生成参数表单，不修改前端源文件。
4. 计划过期、目录漂移、端口错误、任务失败、unknown、空列表、轮询断开、配置冲突都有明确展示。
5. 刷新/关闭页面不影响任务，重新打开能定位相同 job 与 attempt。
6. 查看目录、规则详情和已有结果不发起推理；补算与重跑必须是明确任务操作。
7. 样本分页、标签解释、音频拖动、人工操作与导出使用实际后端；测试截图不冒充真实服务器验证。

浏览器自动化优先覆盖核心提交链、插件动态发现和状态恢复，不为纯布局编写大量镜像测试。
