# 02｜后端、真实资源接入与任务执行

日期：2026-10-19。状态：待实现。前置：[00](00-总需求与实施顺序.md)、[01](01-统一插件接口.md)。

## 1. 目标与代码职责

FastAPI 负责配置、查询与任务管理；Worker 负责执行；所有处理任务通过 01 的插件接口调用现有引擎。HTTP 请求中不得直接跑全量扫描、ASR、声学评分或导出。

- `web/app.py`：应用工厂、生命周期、错误处理、路由、前端静态文件。
- `web/settings.py`：显式项目根路径、配置加载、路径规范化、运行依赖。
- `web/schemas.py`：HTTP 请求/响应，不复制插件契约含义。
- `web/store.py`：SQLite 初始化、事务、任务领取、状态与操作幂等。
- `web/worker.py`：心跳、领取、隔离子进程、退出与遗留任务处理。
- `web/services/engine.py`：调用统一插件规划/执行，适配结果。
- `web/services/jobs.py`：提交、状态流转、取消、恢复、重新运行。
- `web/services/results.py`：复用现有产物、Manifest、tag/审核和导出服务。
- `web/api/`：薄路由；按资源分文件，不按每个插件拆路由。

不得另建与现有 core 平行的标签引擎、数据集执行框架或评测公式实现。

## 2. 配置与真实数据源

### 2.1 通用配置

`configs/web.yaml` 至少包含 Web 绑定地址/端口、项目根目录、SQLite 路径、runs 目录、插件清单路径、源数据允许根目录、模型连接与 Worker 限制。

根目录通过显式启动参数或环境变量指定并校验，不依赖当前 shell 工作目录。配置文件内的相对路径统一相对于项目根目录解析；历史配置有不同规则的，通过已有加载器或冻结阶段明确转换，不能双重猜测。

提供带说明的配置示例，实际地址和密钥由部署者填写。空配置要有可定位错误；不以仓库中的历史机器绝对路径冒充当前服务器配置。

### 2.2 数据源登记

沿用 `resources/manifest.yaml`，至少支持 source_id、source_name、path、format、必要音频参数和备注。PCM 缺少采样率、位宽、通道数等必要解释参数时不能假定为 WAV。

- 后端检查路径为服务器本地绝对路径、在配置允许根目录下、实际存在且可读。
- 保存采用跨进程文件锁、版本/ETag 检查和原子替换；不能用两个独立的读改写覆盖彼此操作。
- 严格 YAML 加载器发现重复键须报错并指出位置。当前 `resources/manifest.yaml` 含重复 `sources` 键，不能用普通解析器静默丢掉其中一段；先保留备份并明确无损规范化方案，遇到同 ID 不同内容要报冲突。
- 新建同 source_id 返回冲突；修改不改变已提交任务的冻结来源信息。
- 快速检查只进行受限枚举与抽样解码，明确“抽样可读”，不伪造全量可用结论。
- 全量登记/扫描作为插件任务执行。目录内容可能变化，任务保存实际输入样本索引、文件身份和适用的内容摘要，恢复时验证。
- 第一版不提供删除服务器原始数据功能；取消/失败不清理用户源数据。

## 3. 外部 vLLM 连接

### 3.1 连接配置

每项至少包含：`connection_id/name/provider/base_url/model/model_revision/api_key_env/timeout_seconds/concurrency`。

- provider 本期提供 glm、qwen；将来其他已注册适配器可声明支持的 provider，前端通过能力信息取得选项。
- base_url 为完整 HTTP(S) 地址，包含实际端口；端口范围 1～65535。`0.0.0.0` 是监听地址，不能作为默认客户端目标；同机示例使用 `127.0.0.1`。
- model 必须与服务的 served-model-name 一致；同一个连接可由不同 ASR route 引用。
- model_revision 是操作者维护的部署修订标识，用于避免同名换权重后错误复用缓存。无法验证远端权重时据实标注。
- API key 仅配置环境变量名；前端只看到是否已配置，不能读取真实值。
- 保存不要求模型此刻在线；用于提交处理任务时，所需连接必须通过本次运行条件检查。

示意配置（地址与端口为占位示例）：

```yaml
models:
  - connection_id: glm_main
    name: GLM ASR
    provider: glm
    base_url: http://127.0.0.1:8001/v1
    model: glm-asr
    model_revision: deployment_001
    api_key_env: GLM_ASR_API_KEY
    timeout_seconds: 120
    concurrency: 4
  - connection_id: qwen_main
    name: Qwen ASR
    provider: qwen
    base_url: http://127.0.0.1:8002/v1
    model: qwen3-asr
    model_revision: deployment_001
    api_key_env: QWEN_ASR_API_KEY
    timeout_seconds: 120
    concurrency: 4
```

### 3.2 检查与协议

复用 `operators/asr/vllm.py` 及现有 GLM/Qwen 适配，不能因统一插件而强行使用相同请求体。

- GLM ASR：当前仓库走 `/v1/audio/transcriptions`。
- Qwen ASR：当前仓库走 `/v1/chat/completions`，保留音频输入、语言及所需 chat template 参数。
- 规范化 base_url 时不能丢端口或拼出重复 `/v1/v1`；已有 URL 构建工具应复用。
- 模型检查分“连接与模型名检查”和“真实短音频转写”两级。TCP 通不能宣称转写成功；`/v1/models` 成功也只代表模型目录检查通过。
- 真实转写检查使用已登记源/产物中的明确样本引用，限制音频长度和超时；无样本时显示尚未转写验证。
- 检查记录时间、访问的脱敏地址、HTTP 状态、返回模型身份、延迟与错误；不返回密钥或整段敏感请求头。
- Worker 开始任务时再次检查所需模型身份及可用性。检查后服务仍可能下线，实际请求失败必须反映到任务和样本状态。

任务使用自己的解析结果。覆盖优先级固定为“任务冻结的显式连接参数 > 插件默认参数”；任务执行进程中的旧 GLM/Qwen 环境变量不得覆盖已经选择的连接。必要时清除旧 `GLM_ASR_API_BASES` 等冲突变量后按任务注入；保留其他无关环境变量。

每个 route 单独绑定，使用任务生成配置或节点私有 env 传入。禁止仅设置一个全局 QWEN/GLM 变量后假定多端口路次自动隔离。不得在任何错误分支回退启动本地模型权重。

## 4. HTTP 基础契约

统一前缀 `/api/v1`。JSON 字段使用 snake_case，时间存储为带时区的 UTC ISO 8601；前端按用户时区展示。成功返回实际资源结构；列表使用 `items/next_cursor/total`，total 无法廉价取得时允许 null。

错误统一：

```json
{
  "error": {
    "code": "MODEL_NAME_MISMATCH",
    "message": "服务未提供所配置的模型名",
    "details": {"connection_id": "glm_main", "field_path": "model"},
    "request_id": "<request-id>"
  }
}
```

请求结构错误为 422；资源缺失 404；版本、状态、幂等键冲突为 409；依赖服务不可用为 503 或明确的检查失败结果；未知内部错误为 500。FastAPI 默认验证错误也要转换为一致结构，堆栈写脱敏服务日志。

### 4.1 基础与配置 API

- `GET /health`：进程存活、版本和服务状态，不启动模型。
- `GET /capabilities`：配置项可选值、支持的模型 provider、执行选项边界等，由适配器/服务能力派生。
- `GET/POST /sources`，`GET/PATCH /sources/{source_id}`。
- `POST /sources/{source_id}/check`：受限真实检查。
- `GET/POST /models`，`GET/PATCH /models/{connection_id}`。
- `POST /models/{connection_id}/check`：传 `level=models|transcription`，后者必须给合法样本引用。

源/模型 PATCH 通过 If-Match 或等价 revision 条件更新，防止并发覆盖。模型保存与检查分开，错误模型配置不能静默替换历史任务里的连接。

### 4.2 插件 API

- `GET /plugins?kind=pipeline|tag&purpose=...&status=...`：分页目录及 generation。
- `GET /plugins/{kind}/{plugin_id}?version=...`：详情、schema、定义与诊断。
- `POST /plugins/refresh`：原子刷新；返回新 generation 或定位错误。
- `POST /plugins/validate`：接收 01 的任务请求，返回定义与参数校验报告。
- `POST /plugins/plan`：接收同一请求，返回不可变 plan_id、plan_digest、到期时间、选择与依赖摘要。

计划在服务端短期保存，默认 15 分钟有效。规划只读，提交时执行所需资源检查和定义摘要复核；若目录选择已漂移，返回 409 要求重新规划。计划到期或不匹配不能静默使用新定义。

### 4.3 任务 API

- `POST /jobs`：接收 `plan_id/plan_digest`，配合 `Idempotency-Key`，返回 202 和 job_id。
- `GET /jobs?status=...&cursor=...&limit=...`：真实列表。
- `GET /jobs/{job_id}`：状态、当前 attempt、进度、输入、插件/模型快照摘要、产物、能力与错误。
- `GET /jobs/{job_id}/logs?cursor=...&limit_bytes=...&node_id=...`：增量日志。
- `POST /jobs/{job_id}/cancel`：幂等取消。
- `POST /jobs/{job_id}/retry`：显式 `mode=resume|rerun`，返回新 attempt 或新 job。
- `GET /jobs/{job_id}/snapshot`：脱敏快照；可选择查看子节点定义。

同幂等键、相同计划重复提交返回同一个 job_id；相同键、不同计划返回 409。提交响应丢失后重试不会重复创建任务。幂等信息持久化，不能只保存在 API 内存。

日志 cursor 包含 attempt、日志文件标识与偏移，支持重启、截断、轮换和 UTF-8 边界；每次响应默认最多 64 KiB，可配置合理上限。没有新日志返回空增量；不能每两秒重新发送整份 run.log。节点日志使用已知 node_id，不能接受任意文件路径。

### 4.4 数据集、样本与人工操作 API

- `GET /datasets`：现有已注册 Manifest 和本服务发布的数据集版本。
- `GET /datasets/{dataset_id}`：来源、版本、统计、实际产物和审核状态。
- `GET /datasets/{dataset_id}/samples`：分页，支持声明的标签、三态、ASR 路次状态和质量区间筛选。
- `GET /datasets/{dataset_id}/samples/{sample_id}`：转写、指标、父源/片段血缘、有效与人工标签。
- `GET /datasets/{dataset_id}/samples/{sample_id}/audio?asset=...`：后端解析登记资产，支持实际格式与 Range。
- `GET /datasets/{dataset_id}/samples/{sample_id}/explain`：读取已有规则结果、快照与证据，不触发推理。
- `POST /datasets/{dataset_id}/samples/{sample_id}/tag-actions`：manual_add/manual_block/restore_auto/retract_manual，复用现有人工状态接口。
- `POST /datasets/{dataset_id}/samples/{sample_id}/review`：按现有审核/Gold 契约提交，不用一个 reviewed=true 替代真实字段。
- `POST /datasets/{dataset_id}/exports`：创建经插件执行链运行的导出任务，返回 job_id。
- `GET /artifacts/{artifact_id}/download`：仅下载已注册、校验存在且允许下载的产物。

解释中同时展示运行时快照规则与当前库规则是否不同；不能用最新规则解释旧命中。单纯读取解释不能启动 ASR/DNSMOS。

手工操作要求 operator_id、reason、预期状态 revision 和操作幂等 ID。单操作者可使用部署配置的 operator_id，但不得伪装成独立第二审核人。冲突返回 409；遵守现有 append log、来源与发布机制，不原地覆盖不可变数据集。API 成功后后续查询和导出必须看到已确认的状态版本；尚未发布时明确显示工作状态与发布版本差异。

全量 export 进入任务系统，可提供 manifest/parquet/xlsx 等当前已支持类型；格式由导出插件 schema 声明。筛选条件与输入版本冻结，不能导出过程中跟随页面或源数据变化。

### 4.5 评测 API

- `POST /evaluations`：以目的为 evaluation 的 pipeline 插件创建规划/任务；使用相同任务服务，不能另建无插件的推理入口。
- `GET /evaluations`，`GET /evaluations/{evaluation_id}`：实际任务、评测集版本、模型修订、范围与指标。

评测请求支持与普通任务相同的显式规划确认和幂等语义。先通过通用 plugins/plan 取得计划；POST /evaluations 接收与 POST /jobs 相同的 plan_id/plan_digest 和幂等键，仅额外验证 root 插件 purpose=evaluation，返回 202 和同一 job_id，evaluation_id 可直接使用 job_id。也可直接通过通用 jobs 提交；评测路由作为薄查询/提交 facade，不重复持久化一套任务状态。

复用现有 metrics 与正式 Gold 检查；无合法 Gold 时不生成虚构准确率。说明 CER/字准率的公式来源、单位、分母、失败样本口径，是否可直接比较。训练不是评测前置条件。

## 5. 持久化与任务状态

### 5.1 SQLite 最小信息

使用本机磁盘 `var/web.sqlite3`，启用必要的事务、busy timeout、外键和适用的 WAL 配置。初始化可重入，保存 schema version，不每次启动删表。

可使用 jobs、job_attempts、job_events、plans 表及必要幂等记录：

- jobs：job_id、请求/计划摘要、快照路径、状态、当前 attempt、创建/更新时间、幂等键及请求摘要。
- attempts：attempt_id/序号、状态、worker_id、唯一 lease token、lease 到期/心跳、子进程身份、开始/结束时间、输出/断点引用、错误。
- events：有序事件 ID、任务/attempt、时间、状态事件和有限大小的脱敏详情。
- plans：到期时间、完整计划与快照引用，提交后的关联任务。

大文件日志、全量样本、原始音频和整份规则结果不放 SQLite。产物索引存引用，现有 catalog/Manifest 仍为业务数据权威来源。

### 5.2 状态机

任务状态：queued → running → succeeded/failed/cancelling；cancelling → cancelled。queued 可直接取消为 cancelled。执行进程意外丢失且无法确认结果时进入 interrupted，不伪装为 failed 或重新入队。

- 终态：succeeded、failed、cancelled；interrupted 需要明确恢复/重跑选择。
- resume：仅 failed/cancelled/interrupted 且插件支持、快照和断点兼容时，同 job 新增 attempt，旧 attempt 保留。
- rerun：创建新 job 和新工作区，使用明确选定的计划。默认复用原冻结计划；要使用最新定义必须重新规划并在页面说明。
- succeeded 不直接 resume；可创建新 rerun job。
- 状态更新必须验证预期状态及 lease token；旧 Worker 回调不能覆盖新 attempt 状态。

默认不无限自动重试。可配置有限的单请求网络重试；任务级失败保留诊断，由用户决定 resume/rerun。任务和样本层重试统计分别展示。

### 5.3 领取、租约与异常恢复

默认单个 Web 任务并行，但仍必须事务领取，避免误启动第二 Worker 时重复消费。领取采用事务/CAS，写入唯一 lease token，建议每 5 秒心跳、30 秒租约，具体参数可配置。

租约过期不等于执行进程必定退出。恢复流程检查任务子进程身份（PID 加启动身份），停止或确认旧执行实例已不再写入后，才能开启新 attempt；不能仅凭 PID 杀掉复用该 PID 的其他进程。

每个 attempt 使用独立暂存输出；正式发布前复核当前 lease 和 attempt，并用单发布锁/原子提交机制防止失租旧执行者迟到发布。多个 attempt 不共同写同一活动 Parquet/状态文件。发布与 SQLite 终态更新之间若崩溃，重启后据可验证的发布记录对账，不能重复发布或直接判成功。

API 重启不影响独立 Worker 的任务；Worker/执行子进程崩溃则显示 interrupted 或已验证终态。第一版允许人工确认后恢复，不要求盲目自动重启昂贵任务。

## 6. 执行隔离、取消与进度

- 每个任务 attempt 在独立子进程运行，输入为冻结计划和私有上下文。
- 默认 task 工作区示意为 `runs/web/<job_id>/attempt_<n>/`，其下允许现有引擎创建自己的父/子 run；保存准确映射。
- 适配器把输出定向到该任务的专属产物/暂存目录，成功后沿用现有注册机制发布。禁止依赖相同 source_name 的固定默认输出覆盖历史结果。
- Worker/适配器必须覆盖生产编排的所有后代执行进程。Linux 使用受控进程组等机制；Windows 开发环境提供等价进程树管理或清晰的能力错误。
- 取消先记录 cancelling 并发出协作信号，停止调度新节点，等待可配置宽限期后终止本任务进程树。只在确认退出且停止发布后记 cancelled。
- 外部 vLLM 不属于任务进程树；不得按模型端口、GPU 号或进程名批量杀进程。
- 已发布结果不因取消删除；不完整结果标记为未发布，断点保留以供兼容恢复。
- 如果某适配器暂时无法可靠取消或恢复，应声明能力为 false，并在完成该能力前不得标为满足本期生产主链验收。

进度包含阶段、节点、已处理、成功、失败、缓存命中、未知与总量。未知总量返回 null；多分支并行显示各节点状态，不假装线性百分比准确。页面通过增量查询读取真实事件和当前进度。

## 7. 样本查询、音频与文件范围

样本默认分页 50，单页上限 200，筛选使用后端查询。Parquet 尽量使用投影、谓词下推和按需读取；没有合适索引时可构建派生查询索引，但不能把它变成另一份可编辑样本真相源。禁止每次翻页将全量 Parquet 转为 Python 列表。

音频与下载接口从 dataset/sample/artifact 引用解析真实路径，并在允许根目录中解析符号链接后检查范围。支持 HTTP Range 及 206/416，返回实际 Content-Type。浏览器不能解码的原始 PCM 可通过已有音频能力生成明确标记的试听 WAV，不覆盖原文件；缺少 PCM 参数时显示不能试听的原因。

SPA 静态回退放在 API/资源路由之后，未知 `/api` 应返回 JSON 404，不能返回 index.html。浏览器刷新深层页面必须正常。

## 8. 后端验收

1. 数据源和模型配置写入唯一来源，重启后仍存在，重复键和并发修改有明确错误。
2. HTTP 测试服务捕获实际请求，确认任务选中的端口、model、协议、route 和语言参数正确；旧进程环境变量不能串入另一任务。
3. 提交幂等、双 Worker 领取、取消、崩溃、失租迟到回调、发布对账、断点不兼容均有行为测试。
4. API 进程重启时任务继续，浏览器刷新能查回同一任务；Worker 丢失时状态真实可解释。
5. 所有执行通过统一插件接口；查看目录、规划、解释不会启动推理。
6. 查询/试听/筛选/审核/导出来自真实已登记数据；手工操作和 Gold 门禁沿用现有业务契约。
7. 对生产主链验证实际子进程 env、输出隔离和取消，不仅验证最外层 Worker 的函数调用。

具体真实服务器验收与测试分层见 [04](04-联调验收与部署.md)。
