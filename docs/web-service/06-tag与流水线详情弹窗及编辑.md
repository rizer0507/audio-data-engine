# 06｜tag 与流水线详情：只看解释、只改解释

日期：2026-10-19。状态：已实现（只看解释、只改解释）。

## 1. 要做什么

点击 tag 或流水线名称，弹出一个简单窗口，只显示：**名称、解释、最近修改时间**，以及“编辑”“关闭”按钮。

本版替代本文件之前的设计。删除规则编辑、参数编辑、高级设置、技术详情和单独校验按钮的要求，不再继续扩展这些功能。

## 2. 解释怎么写

请逐条阅读现有 tag 的规则和流水线配置，把每一项解释重新写成普通人能直接看懂的话，不能只换弹窗样式或修改一个示例。

- tag：直接说清“什么情况下打这个标签”。有多个条件，写清“都满足才打”或“满足其中一个就打”。必要时补一句“不包括什么”或“缺什么就无法判断”。
- 流水线：直接说清“处理什么、做哪些事、最后得到什么”。
- 用短句，通常一小段或两三条即可。复杂规则可以多写几条，但不能省略真正影响判断的条件。
- 用“识别出的文字”“两次结果一致”“没有检测结果”等日常表达，避免“代表文本、家族状态、证据模式、能力节点”等术语。模型名称、实际数值和比较范围需要时保留。
- 不展示 JSON、规则代码或长篇背景，也不重复堆叠用途、业务定义、依赖等栏目。
- 必须忠于真实规则；不能为了好懂改变判定条件。规则没有规定的例子或门槛不要自行添加。

例如“严格全零静默”的解释可以写成：

```text
只有整段录音中每个声道的采样值都为 0，才打这个标签。
声音很小但不为 0，不算；没有检测结果时，无法判断。
```

流水线的解释可以写成，具体以实际步骤为准：

```text
把原始录音切成片段，识别说话内容并检查音质，再按规则打标签，
最后生成可以查看和导出的数据清单。
```

弹窗底部显示“最近修改：YYYY-MM-DD HH:mm:ss”。没有可靠的修改记录时显示“最近修改：尚未记录”。

## 3. 编辑只改解释

点击“编辑”后，窗口里只有**一个多行文本框**，用于修改当前解释，以及“保存”“取消”两个按钮。名称和最近修改时间保持只读。

不出现名称输入框、规则、阈值、参数、版本、表单 schema、高级配置或校验按钮。修改解释不会修改实际打标条件、流水线执行过程、启用/归档状态，也不会启动推理或重新打标。

保存成功后立即显示新解释和实际保存时间；取消保留原解释。保存失败保留输入内容并给出简短错误提示。解释不能为空。

## 4. 保存要求

- 优先统一使用现有 `description` 字段作为弹窗正文，不再拼接其他字段或自动摘要覆盖用户保存的文字。
- 在同一原配置位置保存 `description_updated_at`：tag 保存在自己的定义文件，流水线保存在自己的插件登记中。复用现有读取、保存接口和原子写入机制，不增加数据库表、版本发布或独立校验流程。
- 保存接口只允许更新解释，时间由后端记录，不能由浏览器随意填写；修改时间和文字一起保存。文字没有变化时不刷新时间，取消、打开弹窗、启用/归档也不刷新时间。
- 本次重新编写解释并实际落盘时，记录真实写入时间；不能将打开页面的时间或随意选择的日期当作修改时间。
- 时间存储为 UTC，页面按用户时区显示。刷新页面、重启服务后，文字和时间保持不变。
- 不修改 tag/流水线 ID、业务版本、执行规则、模型连接或历史结果；沿用已有并发保护，避免说明保存覆盖同时发生的归档操作。

## 5. 怎么验收

1. 点击任意 tag/流水线，只出现名称、通俗解释、最近修改时间和必要按钮。
2. 所有现有条目的解释已按真实规则改写；tag 的判定条件不用读代码就能理解。
3. 编辑态只有一个解释文本框和保存/取消按钮。
4. 保存后文字与时间更新，刷新/重启后仍保留；取消、未改内容、查看或归档不改变时间。
5. 修改解释不会改变规则、参数、状态或业务版本，不触发推理，不影响正在运行的任务和历史标签。

完成必要的保存接口检查、前端类型检查/构建和浏览器验证，记录真实结果即可，不为此增加额外设计。
