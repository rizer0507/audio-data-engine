# 插件接入说明（三个最小示例）

日期：2026-10-19。对应需求：[01 统一插件接口](01-统一插件接口.md)。

统一原则：新增已有能力组合的流水线或 tag，只改定义与登记，刷新目录即可；**不修改** `web/api`、`web/worker`、前端业务分发。

---

## 示例 A：新增复用现有算子的 YAML 流水线

### 要改的文件

1. 新建 `pipelines/<your_id>.yaml`（`name` 与登记 `id` 一致；步骤只引用已注册算子）
2. 在 `configs/plugins.yaml` 的 `pipelines:` 下追加一项：

```yaml
  - id: <your_id>
    version: "1"
    adapter: yaml_pipeline
    name: 中文显示名
    definition: pipelines/<your_id>.yaml
    status: enabled
    purpose: processing
    input_kinds: [dataset]   # 或 [source]，按真实前置输入
    supports_tag_selection: false
    parameters_schema:
      type: object
      additionalProperties: false
      properties: {}
```

### 不必改的文件

- `src/audio_engine/web/**`
- `frontend/src/**`
- `src/audio_engine/plugins/registry.py` / `adapters.py`（已有 `yaml_pipeline`）

### 验证

```text
python -m audio_engine.plugins list --kind pipeline
python -m audio_engine.plugins show --kind pipeline --id <your_id>
python -m audio_engine.plugins plan --request <request.json>
```

仓库内演示文件：

- 阶段五正式扩展示例（已登记、可刷新后规划）：`pipelines/web_stage5_ext_demo.yaml` + `configs/plugins.yaml` 中 `web_stage5_ext_demo`
- 单元测试临时目录（不污染正式库）：`tmp/plugin_ext_test/ext_demo_pipeline.yaml`（由 `tests/test_plugins.py` 生成）

## 示例 B：新增组合已有能力的 tag

### 要改的文件

1. 复制 `configs/tagging/library/_example_new_tag.yaml`
2. 去掉文件名开头的 `_`，改成 `<tag_id>.yaml`
3. 填写真实 `tag_id` / `version` / `rules`（`tag_id` 必须等于文件名 stem）
4. **不要**在 `configs/plugins.yaml` 里逐条登记 tag；刷新时从 `tag_libraries.path` 自动发现

### 不必改的文件

- Web API / Worker / 前端
- 除非引入全新证据能力，否则不改 Python

### 验证

```text
python -m audio_engine.plugins list --kind tag
python -m audio_engine.plugins show --kind tag --id <tag_id>
```

仅当任务 `tags` 显式选中该 id/version 时才参与打标；不会因发现而自动全库启用。

阶段五正式扩展示例：`configs/tagging/library/web_stage5_ext_text_tag.yaml`（复用 `family_state`；页面选 tagging 任务并勾选该 tag 即可规划）。

## 示例 C：新增处理算子或执行适配器

### 新增算子（算法能力）

1. 在 `src/audio_engine/operators/...` 按现有 `OperatorRegistry` 契约实现并注册
2. 在流水线 YAML 中引用 `category.name`
3. 按示例 A 登记流水线

无需改插件注册表（`yaml_pipeline` 已包装 `PipelineRunner`）。

### 新增执行后端（adapter）

1. 实现符合 `describe/validate/plan/execute` 的适配器类
2. 在受信模块中调用 `register_adapter("<adapter_id>", factory)`
3. 将模块路径写入 `configs/plugins.yaml` 的 `extension_modules`
4. 流水线登记使用新的 `adapter: <adapter_id>`

浏览器不能上传代码或传入任意 import 路径。

---

## 能力声明注意

适配器必须据实声明 `supports_cancel` / `supports_resume` / `supports_isolated_output`：

| 适配器 | resume | cancel | 任务私有数据集输出 |
|--------|--------|--------|-------------------|
| yaml_pipeline | 是（checkpoint） | 否 | 是（`--output-manifest` 定向到任务目录） |
| production_pipeline | 是 | 否 | 否（stage1 仍按 source_name 共享；runs 可定向） |
| tag_definition | 是 | 否 | 是（TaggingService work_root） |
