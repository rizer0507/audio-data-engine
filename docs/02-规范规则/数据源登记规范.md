# 数据源登记规范

## 概述

本工程 **不持有物理音频**，只管理由外部物理资产映射而来的 **逻辑数据源**。

所有逻辑数据源统一在 `resources/manifest.yaml` 中登记——记录每批数据 **何时落入、体系内叫什么名字、外部物理路径在哪**。

## 登记位置

```
resources/
└── manifest.yaml      ← 逻辑数据源清单（本仓唯一登记入口）
```

## manifest.yaml 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source_id` | string | 是 | 体系内唯一标识，如 `source_A`、`source_B` |
| `source_name` | string | 是 | 可读名称，如 `数据源A` |
| `ingested_at` | datetime | 是 | 落入（登记）时间，ISO 8601 格式 |
| `origin` | string | 是 | 来源描述：供应商、项目、采集方式等 |
| `path` | string | 是 | **工程外**物理根路径（只读引用，文件不进本仓） |
| `format` | string | 否 | 主要音频格式：`wav` / `pcm` / `mp3` 等 |
| `sample_rate` | int | 否 | 主要采样率，如 `8000`、`16000` |
| `file_count` | int | 否 | 文件总数 |
| `note` | string | 否 | 备注 |

## 登记示例

```yaml
sources:
  - source_id: source_A
    source_name: 数据源A
    ingested_at: "2026-08-20T10:30:00+08:00"
    origin: "某供应商-第一批客服外呼录音"
    path: "D:/Data/batch_A"
    format: wav
    sample_rate: 8000
    file_count: 15000
    note: "8k 单声道"

  - source_id: source_B
    source_name: 数据源B
    ingested_at: "2026-08-20T14:00:00+08:00"
    origin: "内部采集-回访录音"
    path: "D:/Data/batch_B"
    format: wav
    sample_rate: 16000
    file_count: 8000
    note: ""
```

## 操作流程

1. 外部物理批次已就绪（供应商交付盘、NAS 目录等，**不拷进本仓**）
2. 确认该外部路径可读，边界清晰（一批对应一个根 path）
3. 打开 `resources/manifest.yaml`，在 `sources` 列表末尾追加一条记录
4. 填写 `source_id`（唯一）、`source_name`、`ingested_at`、`origin`、`path`（外部路径）
5. 提交 git，完成逻辑资产登记

详细步骤见 [数据源落入流水线](../03-流水线/数据源落入流水线.md)。

## 与下游流水线的关系

数据清洗流水线（见 [数据清洗流水线](../03-流水线/数据清洗流水线.md)）输入的是已登记的 **逻辑** `source_id`，不是物理目录：

```yaml
input:
  source: source_A    # 对应 resources/manifest.yaml 中的逻辑数据源
```

解析：`source_id` → 取登记的外部 `path` → 运行时只读读物理文件 → 产出仍是本仓内的逻辑 manifest。
