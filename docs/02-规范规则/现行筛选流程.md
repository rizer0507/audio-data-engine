## A. 全链路总流程

```text
1、数据源登记
  → 2、清洗落库
  → 3、多家族 ASR（N≥3×双跑）
  → 4、聚拢 / 附着（prepared / prepared_asr）
  → 5、ASR 预分流 → 按需 Silero / energy / DNSMOS(SIG)
  → 6、五类自动分拣（classify · v3）
  → 7、导出汇总 / 可选人审 / Release
```

### 1、数据源登记

- 在 `resources/manifest.yaml` 登记逻辑数据源（`source_id`、外部物理 `path` 等）。
- 工程不持有物理音频；下游只认已登记的逻辑源。

### 2、清洗落库

只做音频质量，不做业务分类：

```text
2.1 读源 → pcm/wav 标准化
  → 2.2 重采样到 16k（resampled_16k）
  → 2.3 probe（损坏 → broken）
  → 2.4 filter（非 broken 且 duration > 0 → audio_pass）
  → 2.5 select（仅保留 audio_pass）→ cleaned_*.parquet
```

要点：

- 输入已是上游切分段；本步**不跑 VAD、不重切**。
- 噪声评分、语速判定**不在本步**。

### 3、多家族 ASR

```text
3.1 默认三族：Qwen / GLM / SenseVoice
  → 3.2 每族双跑（共六路）
  → 3.3 产出各路 ASR parquet
```

契约：`N≥3` 家族 × 每族双跑即可；四族为可选增强。

### 4、聚拢 / 附着

```text
4.1 prepare / attach
  → 4.2 对齐到可分类样本集（prepared / prepared_asr）
```

### 5、证据计算（分拣前置算子）

```text
5.1 quality.audio_energy（全量可读样本）
  → 5.2 quality.dnsmos_v2_2_candidates（仅规则候选子集）
```

| 证据 | 回答的问题 |
| --- | --- |
| 家族四态 | 各 ASR 家族听成了什么、是否稳定 |
| `audio_energy` | 有没有物理可闻声音 |
| DNSMOS（v2.2） | 候选上的 noisy / clean / moderate，用于联合判噪与置信度 |

### 6、五类自动分拣

见下方 **B. 分拣决策顺序**（命中即结束）。

### 7、导出 / 人审 / Release

```text
7.1 export-summary（XLSX）
  → 7.2 可选人审（hardcase / semantic_risk 等）
  → 7.3 Release / 评测集登记
```

## B. 分拣决策顺序（命中即结束）

成功进入决策的样本，**必落五类之一**；顺序固定：

```text
1、前置排除
  → 2、voicemail（语音信箱）
  → 3、semantic_risk（语义风险）
  → 4、environment_noise（环境噪声，含 DNSMOS 联合）
  → 5、gold_candidate（金标候选）
  → 6、hardcase（唯一业务兜底）
```

### 1、前置排除 → `excluded`

- 物理无效，或全部路次被前置规则排除（如外语 / 全文回声等）。
- 出口：`outcome=excluded`，`category=null`（**不是**第六业务类）。

### 2、语音信箱 → `voicemail`

- 任一有效成功路次命中信箱正则 → 入本类，结束。
- DNSMOS **不得**改主类。

### 3、语义风险 → `semantic_risk`

- ≥2 个 `stable_text` 家族对同一命题明确冲突 → 入本类，结束。
- 「空转写 vs 有字」**不算**语义风险。
- DNSMOS **不得**改主类。

### 4、环境噪声 → `environment_noise`

按子类依次收敛（未先命中信箱 / 语义风险）：

```text
4.1 energy_state=too_short
      → noise_kind=audio_too_short

4.2 全部家族 stable_empty + inaudible
      → silence

4.3 全部家族 stable_empty + audible
      → 4.3a DNSMOS=noisy     → background（high）
      → 4.3b moderate / clean（非 strong speech）→ background（medium）
      → 4.3c clean + strong speech → 改走 hardcase（矛盾）
      → 4.3d DNSMOS 不可用    → background（medium，回退 v2）

4.4 全部家族 stable_empty + borderline + DNSMOS=noisy
      → background（medium）

4.5 ≥2 稳定空 + 恰好 1 稳定有字 + 可闻（或 borderline+noisy）
      + 无 unstable/unavailable 冒充空
      + 唯一文本非关键短应答
      → human_noise
      （若已有可信串音确认 → crosstalk）
```

**禁止自动入噪**（改走后续金标 / hardcase）：

- 已有 ≥2 家族同文支持
- 族内 `unstable` / 失败冒充空
- `energy_state=failed`
- `borderline` 且 DNSMOS 非 `noisy`
- 唯一文本为关键短应答（要/不要/可以/不行等）

### 5、金标候选 → `gold_candidate`

- ≥2 个 `stable_text` 家族支持同一无害等价文本 → 入本类，结束。
- 第三家族 `stable_empty` 可审计，不否决；任一相关 `unstable` 否决。
- DNSMOS=`noisy` 时**只**打 `quality_tag=background_noisy`，**不得**改主类。

### 6、疑难兜底 → `hardcase`

- 前五步都未命中 → 唯一业务兜底，并写明 `hardcase_reason`。
- `needs_review` 只是附属动作，不是独立出口。

## C. 家族四态（分拣证据基底）

每个配置家族的双跑先归并为恰好一态：

```text
1、stable_text   两路成功、有字、相等或仅无害差异
  → 2、stable_empty  两路成功、清洗后均为空
  → 3、unstable      一空一有字 / 实质冲突 / 仅一路成功等
  → 4、unavailable   两路失败、缺失、无法形成证据
```

推理失败、缺失、外语/回声排除 **不得**计为 `stable_empty`。

## D. 样本出口（互斥）

| 出口 | outcome | category | 含义 |
| --- | --- | --- | --- |
| 业务分类 | `classified` | 五类之一 | 成功决策必落一类 |
| 前置排除 | `excluded` | `null` | 物理无效或全路排除 |

禁止：`category=null` 的业务分类；把 `excluded` / `manual_annotation` / `pending_evidence` 当成业务第六类。

## F. 一眼决策图

```text
样本进入
  │
  ├─ 物理无效 / 全路排除 ──────────────► excluded
  │
  ├─ 信箱正则命中 ─────────────────────► voicemail
  │
  ├─ ≥2 稳定有字严格语义冲突 ──────────► semantic_risk
  │
  ├─ 可自动判噪（能量 + 家族 + DNSMOS）─► environment_noise
  │     └─ 全空+audible+clean+strong ─► hardcase（矛盾）
  │
  ├─ ≥2 稳定同文 ──────────────────────► gold_candidate
  │
  └─ 其余 ─────────────────────────────► hardcase
```
