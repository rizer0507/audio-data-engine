面向幻觉转写与语义反转的五类数据筛选方案
日期：2026-09-22｜建议版，未进行本方案实验
修订重点：所有数据必须有唯一主类；人审与入训不是分类出口。
参考：同目录《数据筛选规则(现行0922).txt》与本次讨论。
本文件只提出方案，未修改现行分类代码和流水线。

一、最终产物：五类互斥，全量归总
================================

每条音频最终且只能进入一个主类：
1. gold：符合已采用共识规则的文本金标。
2. semantic_risk：命中已明确启用的业务语义风险规则。
3. 噪声（environment_noise）：满足联合判噪条件，再区分子类。
4. 语音信箱（voicemail）：满足语音信箱准入条件。
5. hardcase：以上四类均不满足时的唯一兜底。

总量 N = gold + semantic_risk + 噪声 + 语音信箱 + hardcase。
噪声子类之和 = 噪声总量。每条数据只在一个主类中计数。

“待审核”“暂存”“候选池”“推理失败”都不是额外主类。
同一条数据可以带多个原因标签，但不能同时占用多个主类名额。
分类不要求先完成标注；标注状态、正确转写和是否入训是独立字段，不参与上述总量分母。

本方案默认 N 为本次输入的去重音频记录数。损坏、零时长、全路失败、全部业务过滤等记录均归 hardcase，并保留原因，保证输入记录不消失。
如果工程沿用前置 excluded，则另报：原始输入 = excluded + 五类分类输入。必须固定报表口径，不能将 excluded 隐藏后仍声称五类覆盖原始总量。

二、最少证据与明确含义
======================

A. 四模型家族各双跑：提供主要文本证据。
每族归并成四态：
- stable_text：双跑成功，规范化后为同一非空文本。
- stable_empty：双跑成功，真实输出均为空。
- unstable：两次成功但有实质差异、一空一有字，或只有一次成功。
- unavailable：两次都没有可使用的成功结果。

失败、外语排除、热词回声排除不能转成 stable_empty。
按家族计票，八次推理不等于八个独立家族。
保留所有成功原始输出；不稳定家族的一次极性冲突也可以触发风险。
规范化只去除明确无害的格式差异，不删除“不”、数字、单位等内容，不靠宽松语义相似度合并文本。

下面使用三个直接从结果得到的条件：
- C：至少两个 stable_text 家族支持唯一同文文本。
- E：stable_empty 家族的数量。
- D：成功的非空输出之间存在无法按无害差异合并的实质分歧。

C 与 D 可以同时为真，例如两个家族同文，第三个家族输出不同内容。
两组各有两族支持不同文本时，C 不成立，D 成立。
只要有成功非空输出，就不属于“全部输出为空”；失败和缺失不提供空输出证据。

B. Silero VAD：有语音 / 无语音 / 失败。
这里是模型检测结果，不是音频真值。它不能证明某个词存在，也不能区分可辨语言与不可辨人声。[来源1]

C. DNSMOS：保留三个原始分数，第一版只考虑 SIG 这一个分类辅助量。
SIG 是语音质量，BAK 是背景噪声质量，OVRL 是整体质量；不等于文本正确率。[来源2]
BAK、OVRL 暂不增加准入条件，避免堆叠阈值。
低 SIG 不单独判噪，高 SIG 不单独判 gold。

定义 Q 为“SIG 落入已在该来源验证的低语音质量区间”。
不凭空写 SIG<2 等数值。该来源尚未校准时，Q=unknown，对应人声噪声规则暂不启用，其样本落 hardcase。
这是一个明确的配置依赖，不需要每条数据等人审后才能分类。
已有分数直接复用；需补算时，只对下述人声噪声候选计算，不增加全量评分要求。

不新增 EfficientAT 必经环节，不增加综合加权评分器。

三、固定决策顺序：命中即结束
============================

0. 音频物理无效 → hardcase / invalid_audio。
1. 命中已启用的语义风险规则 → semantic_risk。
2. 命中语音信箱准入规则 → voicemail。
3. 命中噪声准入规则 → environment_noise，并确定 noise_kind。
4. 命中普通文本共识准入规则 → gold。
5. 其余全部 → hardcase，并记录原因。

这个顺序刻意将业务语义风险放在前面：
同一条数据既有“要/不要”风险又疑似噪声时，主类仍是 semantic_risk，附 noise_suspected 标签。
这样不会把最高关注的语义样本埋进噪声或 gold。
不存在“任意有字 + VAD 无语音 = 已确认幻觉”的强声学否决。

四、semantic_risk：只收明确启用的业务风险
=======================================

本建议版启用两个入口：

S1. 明确极性冲突。
至少两次成功非空输出，在同一命题上表达相反含义，如“需要/不需要”“可以/不可以”。
可以来自跨家族，也可以来自同一家族双跑；后者同样是有价值的不稳定性证据。
不要求双方都双跑稳定，不用多数票覆盖风险。
“空输出 vs 有字”不属于极性冲突；“两句都出现否定词”也不自动构成冲突。
无法可靠对齐到同一命题时，不能强判反转，落 hardcase。

S2. 存在歧义的业务关键极性短应答。
必须同时满足：成功的非空转写之间存在实质差异，且至少一个相关输出命中已配置白名单中的独立短应答，例如“要/不要、需要/不需要、可以/不可以”。
这里的歧义不包括已经消除的无害格式差异；空输出、失败、缺失本身也不构成语义歧义。只有命中名单，没有非空文本实质分歧，不触发S2。
如果所有成功非空输出均为“不要”，即使涉及关键极性，也继续按gold、噪声、信箱和hardcase各自条件分类；满足gold准入即可进gold，不因名单命中而拦截。
若多数家族同文但仍有成功非空输出实质不同，歧义仍然存在；命中名单时触发S2。明确极性对立则优先按S1记录。
匹配的是完整短应答或明确规则，不能用“包含‘不’字”匹配任意长句。
该入口按用户纠正后的“存在歧义 AND 命中名单”启用，不将一致的关键短应答或所有否定句升级。
Qwen 是否参与只作为模型维度记录，不改变通用分类规则。

S2 与 S1 用不同 reason：critical_polarity_response（关键极性短应答歧义）/ polarity_conflict。
semantic_risk 表示值得关注的业务风险，不宣称已经发生错误。

第一版暂不默认启用：金额分歧、日期分歧、专名差异、一般意图变化、未在白名单内的其他短句。
这些如果因实质分歧不满足 gold，全部进入 hardcase，并保留具体 reason。
后续按业务验证扩充 S3、S4……，只从匹配新规则的 hardcase 中转入 semantic_risk。
不是发现任何差异就不断放大 semantic_risk。

五、语音信箱：避免单路模板误识别直接定类
======================================

准入条件全部满足：
- 未命中 S1/S2。
- 至少两个 stable_text 家族的文本命中同一明确语音信箱模板。
- 成功非空输出间没有实质冲突，即 D=false。
- 没有 stable_empty 家族，即 E=0。
- VAD 检出语音。

满足 → voicemail。
仅一路或仅一个家族命中模板、VAD 无语音/失败、或其他家族稳定空 → 不直接进入 voicemail。
在后续规则中若满足噪声条件则归噪声；否则归 hardcase / voicemail_evidence_insufficient。
这些存在信箱模板疑点但未满足准入的样本，不再退回 gold。

这比现行“任一有效路次命中正则”更谨慎，准入放宽需要后续证据支持。
模板匹配仅用于信箱识别，不额外增加模型调用。

六、噪声：联合证据准入，明确三个子类
==================================

噪声主类是筛选系统对音频的判定，不等同于逐条已经证明正确的空转写标签。
保留 noise_kind 和 noise_rule，后续可以衡量每条规则的准确性；不因此增加一个“噪声候选”主类。

N0. silence（严格数字静音）。
音频可读且时长大于零，全部采样值为零，VAD 未检出语音。
满足且未被前序业务风险命中 → 噪声 / silence。
只使用严格零值检查，不把“振幅较小”武断当静音。没有这项已计算证据时可跳过本子规则。
存在任一路非空输出时附 nonempty_on_noise 标签，表示噪声规则与转写矛盾，不直接写成已确认模型幻觉。

N1. background_suspected（非语音背景噪声疑似）。
全部满足：
- VAD 未检出语音。
- E >= 2。
- 没有任何 stable_text 家族；或者仅一个 stable_text 家族，且其文本不是前述关键短应答。
- 已通过前序 semantic_risk 检查。

满足 → 噪声 / background_suspected。
不稳定家族可以有字，这正是发现噪声误转写的一个入口。
有任何成功非空输出时附 nonempty_on_noise；全部成功输出为空时附 all_empty。
此子类可能包含弱人声或近静音，是当前证据支持的筛选归类，不能声称 VAD 已证明它一定是纯环境声。
尤其注意：至少两个稳定文本家族即使互相不同，也不走 N1，进入后续 hardcase；避免空输出票数简单压过已有稳定语言证据。

N2. human_noise_suspected（不可辨人声噪声疑似）。
全部满足：
- VAD 检出语音。
- E >= 2。
- 没有任何 stable_text 家族。
- Q=true，即 SIG 位于该来源已验证的低语音质量区间。
- 已通过前序 semantic_risk 和 voicemail 检查。

满足 → 噪声 / human_noise_suspected。
可以是所有家族空，也可以是部分家族不稳定地输出零散文字。
若出现一个稳定文本家族，或 Q 未校准/不满足，则不强判人声噪声，落 hardcase。
这是一条保守的起始规则，可能漏掉真实人声噪声，但给出了可验证的扩展边界。

必须直说的限制：VAD + DNSMOS + 家族结果不能无误地区分“不可辨人声”和“模型共同没听懂的真实语音”。因此采用 suspected 子类名，不用命名掩盖不确定性。
如果当前没有任何来源的 SIG 校准，本版 N2 的输出量就是零，相关样本全部进入 hardcase / human_noise_unresolved；分类仍然全量闭合。

七、gold：保留共识主线，排除明确风险与矛盾
======================================

准入条件全部满足：
- 未被前序规则分类，且不带未解决的信箱模板疑点。
- C=true：至少两个家族各自双跑同文，且同文组唯一。
- D=false：其他成功非空结果均与共识无害等价。
- E=0：没有其他家族稳定空。
- VAD 检出语音，或 VAD 失败/缺失；VAD 明确未检出语音则不进入 gold。

满足 → gold，目标文本为共识文本。
VAD 失败/缺失仅标记 acoustic_missing，不伪装成“无语音”；此处沿用已验证的文本共识基础，而非要求声学全齐。
其他家族缺失不构成反对票；其他家族一空一有字且有字与共识相同，也不整体否决共识。
DNSMOS 低分不否决 gold，保留带噪但可转写的数据。

存在实质歧义且命中名单的关键短应答在semantic_risk出口结束；不存在歧义的关键短应答可按本节条件进入gold。
“至少两家族稳定同文但另有稳定空”暂落 hardcase；如果已有实验已验证这类共识也足够可靠，可作为后续 gold 准入扩充，不能在本版同时给出两个去向。

八、hardcase：其余一切都有明确落点
==================================

不满足上述准入条件的记录全部归 hardcase，reason 至少标明主要原因：
- invalid_audio：损坏、零时长等。
- no_usable_asr：全路失败、缺失或全部被业务过滤；保留细分原因。
- insufficient_family_evidence：只有一家族稳定文本，缺少共识且不满足噪声条件。
- ordinary_text_divergence：实质文本分歧，但未命中已启用语义风险规则。
- consensus_empty_conflict：已有文本共识，另有家族稳定空。
- consensus_vad_conflict：已有文本共识，但 VAD 未检出语音。
- human_noise_unresolved：疑似人声噪声，但不满足 N2。
- empty_evidence_insufficient：空输出证据不足，或所需 VAD 证据缺失。
- voicemail_evidence_insufficient：存在信箱模板疑点但信箱及噪声准入均未满足。
- fallback：其他未覆盖情况，保留原始证据以便补充规则。

允许记录多个 reason，但主类仍只有 hardcase。
未来扩充语义规则时，从 ordinary_text_divergence 等相关原因中查找，不必重新处理全部原始音频。

九、代表性组合的最终去向
========================

以下均以未命中更早规则为前提；若同时命中，按第三节固定顺序取唯一主类。

1. 两族双跑“不要”，其余缺失，VAD 有语音。
→ gold。非空文本没有实质分歧，不触发S2；其余缺失不构成反对票。Qwen是否参与不改变该结论。

2. 两族双跑“不要”，另一路为“要”。
→ semantic_risk / polarity_conflict。

3. 同一家族一次“需要”、一次“不需要”，其他家族都缺失。
→ semantic_risk / polarity_conflict，不因缺少跨家族共识而漏掉。

4. 两族双跑“明天下午三点见”，其余缺失，VAD 有语音，无模板疑点。
→ gold。

5. 两族同文普通句，另一个家族稳定空，VAD 有语音。
→ hardcase / consensus_empty_conflict。

6. 三族同文普通句，VAD 无语音。
→ hardcase / consensus_vad_conflict，不直接判噪声，也不进 gold。

7. 一个家族双跑“谢谢”，其他至少两族稳定空，VAD 无语音。
→ 噪声 / background_suspected，附 nonempty_on_noise。

8. 四族稳定空，VAD 无语音。
→ 噪声 / background_suspected；若满足严格数字静音条件则为 silence。

9. 四族稳定空，VAD 有语音，Q=true。
→ 噪声 / human_noise_suspected。

10. 四族稳定空，VAD 有语音，SIG 未校准或 Q=false。
→ hardcase / human_noise_unresolved。

11. 两族稳定空，其余家族输出不稳定，VAD 有语音，Q=true，没有关键短应答和稳定文本。
→ 噪声 / human_noise_suspected，附 nonempty_on_noise。

12. VAD 有语音、多族各说各话、SIG 低，但不足两族稳定空。
→ hardcase / ordinary_text_divergence；低 SIG 不能单独定噪声。

13. 两族稳定输出相同信箱播报，其他结果无冲突且无稳定空，VAD 有语音。
→ voicemail。

14. 只有一个家族命中信箱模板，其他缺失。
→ hardcase / voicemail_evidence_insufficient。

15. 普通文本有两族稳定共识，无其他文本冲突和稳定空，VAD 失败。
→ gold，附 acoustic_missing。

16. 全路失败，VAD 无语音。
→ hardcase / no_usable_asr，不把推理失败当噪声证据。

17. 金额、日期或人名存在实质差异，但尚未启用对应语义风险规则。
→ hardcase / ordinary_text_divergence；业务规则启用后，匹配样本才能迁入 semantic_risk。

18. 文件不可读或时长为零。
→ hardcase / invalid_audio，保证本方案输入口径下总量不丢失。

十、规则扩充：在同一总量上减少 hardcase
======================================

每次扩充都指定：原 hardcase 原因、新增准入条件、目标主类、规则版本。
例如：
- 已确认的金额冲突规则：hardcase → semantic_risk。
- 验证通过的不可辨人声联合条件：hardcase → 噪声 / human_noise_suspected。
- 验证通过的文本共识与稳定空并存条件：hardcase → gold。
- 验证通过的单家族稳定信箱模板条件：hardcase → voicemail。

固定输入集合，且只新增覆盖 hardcase 的准入规则时：
新 hardcase = 旧 hardcase - 本次迁出数。
其他四类增加数之和 = 本次迁出数，总量不变。

若一条新规则同时符合多个目的类别，仍按既定优先级决定一次迁出，不能重复计数。
这种扩充不回扫已归类的其他四类；如要改变旧分类，属于单独的规则修订，需要报告迁移量，不能再声称只是压缩 hardcase。
去重口径、输入范围和数据批次必须固定；增加新音频时不能直接比较 hardcase 的绝对数量判断规则是否改进。

十一、分类输出与最小验证
======================

每条记录输出：
- sample_id、source_id。
- category：五选一，不能为空。
- noise_kind：仅噪声类填写。
- reason：命中规则及补充原因。
- consensus_text：存在共识时保留，即使当前主类不是 gold。
- family_states 与原始结果引用、VAD 状态、可用 DNSMOS 分数。
- rule_version；N2 启用时记录对应来源的 SIG 配置版本。

Qwen 相关错误倾向可做附属模型标签；主分类不依赖某个固定品牌。

落地先检查三个问题：
1. 结构正确：每条恰好一个主类、五类数量之和等于 N、噪声子类之和等于噪声数量。
2. 规则有用：分规则检查 gold 文本是否可靠、噪声是否混入可辨语音、semantic_risk 是否命中业务关注点。
3. 扩充有效：新增准入从 hardcase 迁出了多少，迁出后的准确性是否保持。

标注团队的结果用于验证和改进准入规则、生成最终训练目标，但“需要标注”不能成为类别名称或决定分类的替代答案。
噪声分类结果也不自动等于空标签金标；分类质量验证和训练目标确认仍应分别记录。本方案重点解决五类最终流向，不把训练发布规则混入分类顺序。
