# GitHub 语音数据工程对标

核查日期为 2026-11-17。项目基线为 `v4.1` 的本地工作树，HEAD `f11ae27`，包含当时未提交的入库与评测改动。项目组织按代码分层、数据契约和上下游职责比较。

## 结论

- **可复用引擎最接近的是 NVIDIA NeMo Curator 的 Granary v2 配方。** 它有 Manifest 驱动的独立音频阶段、配方与模型实现分离、阶段清单落盘、两种分布式后端实测、公开测试和版本发布。语音产物用于 Nemotron 3.5 Transcribe 的训练。[Granary v2 配方及跑批记录](https://github.com/NVIDIA-NeMo/Curator/blob/bb670416eebb67011c2fc649e8df85db9572ce0e/tutorials/audio/granary_v2/README.md) · [NVIDIA 技术报告](https://research.nvidia.com/labs/nemotron/Granary-v2/)
- **工序一业务路线最接近的是 WenetSpeech-Yue 的 WenetSpeech-Pipe。** 它在同一片段上做三路 ASR、DNSMOS 和其他声学质检、转写融合，并发布人工标注的独立 ASR 评测集。语料规模和评测已公开，端到端的流水线源码与入口未在所核文件树找到。[论文 §3–4](https://arxiv.org/html/2509.03959#S3) · [公开源码目录](https://github.com/ASLP-lab/WenetSpeech-Yue/tree/bea884c67f03f73f2d2d94557457a5849dd61090/WenetSpeech-Yue)
- **在已核查的候选中，以下治理环节尚无同一套公开实现可供一对一对应。** 按片段身份、音频摘要与快照对齐证据，带双审或仲裁的金标回填，按组拆分并冻结语料版本，再面向固定评测集独立跑多模型。源音频与标注平台的外部交接是其中的重要边界。[证据合并](../../src/audio_engine/operators/quality/evidence_join.py) · [复核导入](../../src/audio_engine/core/annotation_v3/import_workflow.py) · [v3 发布](../../src/audio_engine/core/dataset_v3/release.py) · [评测门禁](../../src/audio_engine/core/eval_ready.py)

## 当前项目的比较基线

- 045 的配置入口把入库、VAD、多路 ASR、独立 DNSMOS、证据合并和自由标签串起来。ASR 与 DNSMOS 在同一波并行，ASR 路次可配置。所核默认文件配置 Qwen 和 GLM 两路，另有支持至少三家族双跑的五类分拣入口。当前 045 标签入口为 `tag_dataset_free_tags_v2`。[045 配置](../../pipelines/audio_ingest_vad_asr_dnsmos_tags.yaml) · [五类分拣配置](../../pipelines/classify_dataset_five_class_v3.yaml) · [工序总览](../01-项目架构/工序总览.md)
- ASR 与质量证据在 Manifest 中保留来源。合并算子按样本 ID 与原始音频摘要核对，ASR 清单还检查输入的 VAD 快照。父任务支持并行子节点及续跑。自由标签复用已落盘证据。[合并算子](../../src/audio_engine/operators/quality/evidence_join.py) · [总编排](../../src/audio_engine/core/production/orchestrator.py) · [自由标签配置](../../pipelines/tag_dataset_free_tags_v2.yaml)
- 标注平台接收片段身份、音频和上下文关联键，轻量听写与正式 v3 双审是不同契约。正式 v3 Gold 有审核证据，v3 发布做分组划分与同版本内容校验，正式评测拒绝伪金标。评测和训练解耦，训练由外部项目承担。[标注平台分片契约](../01-项目架构/标注平台对接上下文-audio-label-master-VAD分片.md) · [训练平台契约](../01-项目架构/训练平台对接上下文-Qwen3-ASR.md) · [评测门禁](../../src/audio_engine/core/eval_ready.py)

## 各项目的公开实现和证据

### NVIDIA NeMo Curator / Granary v2

- **目的和路径。** 从长录音制作可用于训练的多语种语音与标签。公开教程拆成录音元数据与切片、Indic ASR 或 Qwen3-Omni、文本处理三个部分，各阶段可分别验证，通过 JSONL 衔接。切片阶段有重采样、VAD、说话人、声事件和语言证据。Indic 配方保存 Canary 与 Parakeet 的预测字段，按幻觉检查结果选择转写、记录选文来源并计算参考 WER。[元数据 YAML](https://github.com/NVIDIA-NeMo/Curator/blob/bb670416eebb67011c2fc649e8df85db9572ce0e/tutorials/audio/granary_v2/metadata/pipeline.yaml) · [Indic ASR YAML](https://github.com/NVIDIA-NeMo/Curator/blob/bb670416eebb67011c2fc649e8df85db9572ce0e/tutorials/audio/granary_v2/indic_asr/pipeline.yaml)
- **组织和成熟度。** `ProcessingStage`、输入输出 schema、YAML、执行后端和测试分别组织。主分支实现了阶段间的 JSONL 元数据 checkpoint，可供下游重用评分。另有源分区完成状态，用于重跑时跳过已完成分区。项目有 `v1.4.0` 发布、音频测试和 Granary v2 在同一批输入上的 Xenna / Ray Data 跑批记录。这里的配方和 checkpoint 按主分支提交核查。[版本发布](https://github.com/NVIDIA-NeMo/Curator/releases/tag/v1.4.0) · [checkpoint 实现](https://github.com/NVIDIA-NeMo/Curator/blob/bb670416eebb67011c2fc649e8df85db9572ce0e/nemo_curator/stages/audio/common/manifest_checkpoint.py#L33-L47) · [音频测试](https://github.com/NVIDIA-NeMo/Curator/tree/bb670416eebb67011c2fc649e8df85db9572ce0e/tests/stages/audio)
- **对应边界。** Indic 示例基于主路和备路选文。官方音频质检配方有 UTMOS、SIGMOS 等独立算子；本仓库按 DNSMOS 分支、片段快照和自由标签合并证据。Curator 的阶段清单用于可恢复计算，本仓库的 v3 Release 还冻结分区、审核依据与内容指纹。部分公开示例依赖特定的模型或推理引擎，须以各配方文档为准。[质检文档](https://docs.nvidia.com/nemo/curator/latest/curate-audio/process-data/quality-filtering) · [元数据教程及依赖](https://github.com/NVIDIA-NeMo/Curator/blob/bb670416eebb67011c2fc649e8df85db9572ce0e/tutorials/audio/granary_v2/metadata/README.md) · [本仓库 v3 发布](../../src/audio_engine/core/dataset_v3/release.py)

### WenetSpeech-Yue / WenetSpeech-Pipe

- **工序一相似度。** 长音频经 VAD 切段，记录说话人与声学属性。SenseVoice、Whisper 和商业 TeleASR 分别转写。同一片段的 SNR、DNSMOS 和带宽形成质检证据。三路文本规范化后用编辑距离剔除离群结果，ROVER 对齐投票得到选文与置信度，再做 Qwen3-4B 最小纠错和字级强制对齐。与本项目最接近的是同片段异构证据的组合。ROVER 的产物是融合文本，本项目的 045 先保留各路证据、再按规则打标签，正式评测使用经核验的参考。[论文 §3](https://arxiv.org/html/2509.03959#S3) · [045 证据合并](../../pipelines/evidence_join.yaml)
- **成熟度和开源范围。** 作者报告 21,800 小时粤语语料，公布带人工转写的 WSYue-ASR-eval、多个模型成绩与数据修订记录。仓库 README 描述完整流程，实际工序目录只有公开的文本后处理脚本，本次未找到其中的 VAD 调度、ROVER 实现或可运行的总入口。川渝话、吴语、闽南语项目提供类似的方言语料和评测做法。[论文 §4](https://arxiv.org/html/2509.03959#S4) · [文本后处理脚本](https://github.com/ASLP-lab/WenetSpeech-Yue/blob/bea884c67f03f73f2d2d94557457a5849dd61090/WenetSpeech-Yue/text_postprocessing.py) · [川渝话](https://github.com/ASLP-lab/WenetSpeech-Chuan) · [吴语](https://github.com/ASLP-lab/WenetSpeech-Wu-Repo) · [闽南语](https://github.com/ASLP-lab/WenetSpeech-Min-Repo)

### NeMo Speech Data Processor / 第一代 Granary

适合对照本仓库的 `operators/` 与 `pipelines/` 组织。Hydra YAML 串联可扩展的 Python processor，每一步消费和写出语音 Manifest，支持按索引选跑阶段。Granary 配方包含重采样、切段、两遍转写、幻觉过滤、规范化与分片打包，保留中间清单用于核查。仓库有端到端测试工作流。其编排以相邻文件逐步衔接为主，对应本仓库的分步 CLI 和中间产物。[runner](https://github.com/NVIDIA/NeMo-speech-data-processor/blob/27c5e635fa27d41b6aacdaee5cd1fdd2708b3bc6/sdp/run_processors.py#L146-L233) · [Granary 配方](https://github.com/NVIDIA/NeMo-speech-data-processor/blob/27c5e635fa27d41b6aacdaee5cd1fdd2708b3bc6/dataset_configs/multilingual/granary/README.md#pipeline-stages) · [测试工作流](https://github.com/NVIDIA/NeMo-speech-data-processor/blob/27c5e635fa27d41b6aacdaee5cd1fdd2708b3bc6/.github/workflows/tests.yml)

### SpeechColab / GigaSpeech 2

适合对照训练集、人工评测集与基线的组织。论文描述近 3 万小时自动转写、Whisper 初转写、MMS 强制对齐、过滤与迭代伪标签精炼。数据按来源频道分组隔离 TRAIN、DEV 和 TEST，并人工核查跨频道说话人重叠。泰语、印尼语、越南语各有专业标注的 DEV 和 TEST，训练数据有 raw/refined 两版，附 Icefall、ESPnet 基线。仓库公开采集、转写、对齐、过滤和切段脚本。对本项目而言，分组隔离和独立人工评测集最有可比性。[公开流水线](https://github.com/SpeechColab/GigaSpeech2/tree/098171b675f4b7c923bf6fd523dac6ee76b7d5bf/pipeline) · [数据与基线](https://github.com/SpeechColab/GigaSpeech2/blob/098171b675f4b7c923bf6fd523dac6ee76b7d5bf/README.md#leaderboard) · [ACL 论文的拆分方法](https://aclanthology.org/2025.acl-long.135.pdf#page=4)

### NAVER Sommelier 与 Amphion Emilia-Pipe

- **Sommelier** 面向全双工语音模型的多方对话数据，公开入口有可直接核对的三模型 ROVER。切段和说话人处理之后，获得 Whisper、Parakeet、Canary 的结果，按段融合并同时输出各路原文。产物以单录音目录、JSON 和片段音频组织。作者报告了融合 WER 和分阶段耗时。DNSMOS 模块在仓库中，所核主入口只找到导入和统计工具引用，未确认以独立质检阶段执行。该仓库无 GitHub Releases，工程组织以研究脚本为主。[论文实验](https://arxiv.org/pdf/2603.25750#page=7) · [三路推理与落盘](https://github.com/naver-ai/sommelier/blob/4d94098abfed6fc3202db46faf11eb1f4a4cd416/podcast-pipeline/main_original_ASR_MoE.py#L1683-L1713) · [输出契约](https://github.com/naver-ai/sommelier/blob/4d94098abfed6fc3202db46faf11eb1f4a4cd416/README.md#output)
- **Emilia-Pipe** 公开真实可查的规整、分离、说话人分段、Silero VAD、WhisperX 和 DNSMOS P.835 代码。工程入口集中在 `preprocessors/Emilia`，处理目标是语音生成训练语料。可对应本项目的音频预处理和质检算子，单路转写与生成语料的质量筛选是它的主要用法。[配方与用法](https://github.com/open-mmlab/Amphion/blob/26f6883110181f1dbfe95c70a7c7dbaf4de5f42a/preprocessors/Emilia/README.md) · [DNSMOS 执行代码](https://github.com/open-mmlab/Amphion/blob/26f6883110181f1dbfe95c70a7c7dbaf4de5f42a/preprocessors/Emilia/main.py#L343-L387)

## 检索与验证边界

通过 GitHub 仓库检索跑了 29 组关键词组合，覆盖语料筛选、Manifest/YAML 编排、多路 ASR/ROVER、DNSMOS、人工复核和分组发布。返回结果去重后涉及 263 个仓库，包含弱匹配和复刻。对主要候选核对了默认分支、文件树、运行配置、论文或官方报告，以及可见的测试、发布和使用证据。成熟度按这些可核项目判断，未做 GPU 运行或准确率复测。

另外核对了几个局部参照。Data-Juicer 对应通用算子与配置组织，Lhotse 对应录音、片段与监督信息的 Manifest，Common Voice 对应采集端投票及语料打包，The People’s Speech 对应强制对齐、过滤和拆分。这些项目覆盖的环节不同，较适合作为单环节参照。[Data-Juicer](https://github.com/datajuicer/data-juicer) · [Lhotse 数据契约](https://github.com/lhotse-speech/lhotse/blob/master/docs/corpus.rst) · [Common Voice 打包](https://github.com/common-voice/CorporaCreator) · [The People’s Speech 对齐](https://github.com/mlcommons/peoples-speech/blob/main/galvasr2/align/spark/align_cuda_decoder.py)
