当前我的数据引擎工序是：
①数据清洗、落库流水线(data_cleaning_source_A.yaml) --------> ②同源多结果 ASR + 聚拢 + 字准：任意 `--asr-run` 别名识别（同 `--source-name`）→ `multi_asr_aggregate`（`--aggregate-base` + `--join-manifest`）→ `asr_metric_pipeline`（`--agreement-base`，vs_base agreement CER） -------> ③自动分拣 + 金标聚拢 +（可选）人工审核冻结 Dataset：classify_dataset → review export-gold →（可搁置）review export/import → release build --------> ④训练流水线(当前尚未实现，在另一套框架中，未集成进来)  --------> ⑤评测流水线（与④完全解耦）：`eval register` → 各模型独立 vLLM 跑批（`--eval-name` + `--asr-run`）→ `eval_aggregate`（按 id 对齐）→ `eval_metric_pipeline`（相对 gold_text 多模型字准 + 按 type 导出）

工序②要点：
- 同一 `--source-name` 下可多次跑任意模型/批次，用 `--asr-run <alias>` 区分产物（`{alias}_asr_<BATCH>.parquet` + transcript 键）
- 聚拢不绑模型清单：`--aggregate-base qwen1 --join-manifest qwen2 --join-manifest sensevoice1 ...`
- 字准：其余结果相对 base 算 agreement CER，并写出 `max_vs_base_agreement_cer`（工序②指标；工序③分拣不再依赖该 CER 进桶）

工序③要点：
- classify 使用 `configs/selection/zh_asr_v1.yaml`（`selection_zh_asr_v1_6` / `selection_v1.1`）：`type` + `decision` + `label` 三分开
- 分桶：`noise` / `voicemail` / `semantic_inversion` / `hallucination` / `qwen_missing` / `auto_gold` / `consensus_gold` / `hardcase`
- 一致度用 **transcript_similarity**（非字准率）；阈值 `0.95` / `0.90`；金标取 **medoid**（禁止随机）
- 模型族感知：同族多跑不算独立票；`semantic_inversion` 在相似度判断之前执行
- `audio-data review export-gold` 默认导出 `auto_gold` + `consensus_gold`
- 待审样本可搁置；`--allow-unresolved-review` 允许仅用已有金标冻结 Release
- `audio-data review export-summary`：导出全量汇总 xlsx，`type` 列=分拣桶
- 细则见 [数据挑选规则](../02-规范规则/数据挑选规则.md)

工序⑤要点：
- **与④训练无依赖**：只要评测集与各推理结果 id 对齐即可，不强制 Model Registry
- `audio-data eval register <summary|gold> --name eval_$BATCH` → 准入检查并落盘评测集快照
- 各权重独立起 vLLM，用 `--eval-name eval_$BATCH --asr-run <alias>` 跑批（例：`qwen` / `qwen-sft-epoch10` / `qwen-sft-epoch100`）
- `eval_aggregate`：评测集为底表，`--join-manifest` 左连接（允许推理侧多出 id；评测集缺 id 失败）
- `eval_metric_pipeline --eval-model ...`：相对 `gold_text` 算 CER/字准率，按 `type` 汇总，导出 evaluation.xlsx
- 若 summary 已含原模型文本，可只 join SFT 别名；`--eval-model` 选定报告维度
