# 工序总览（三大工序）

> **现行组织方式：三大工序。** 下文「①–⑤」仅为大工序内部步骤编号，日常执行与手册分册以「工序一 / 二 / 三」为准。
>
> 可执行命令见仓库根目录 `手册/dev/`、`手册/local/`。

---

## 总览

```text
工序一 数据清洗落库打标
  ①清洗落库 → ②多 ASR + 聚拢 + agreement 字准 → ③分拣 / 金标 /（可选）人审 / Release
        │
        ▼（可选）
工序二 训练（外部框架，本引擎未完整集成）
  ④ Dataset Release → 外部训练 → Model Registry（可选）
        │
        ▼（与②解耦，可不经训练直接评）
工序三 评测
  ⑤ eval register → 各模型独立跑批 → eval_aggregate → eval_metric_pipeline
```

| 大工序 | 名称 | 覆盖引擎步骤 | 状态 |
| --- | --- | --- | --- |
| **工序一** | 数据清洗落库打标 | ① + ② + ③ | 已落地 |
| **工序二** | 训练 | ④ | 外部框架；引擎侧 adapter / Registry 可选 |
| **工序三** | 评测 | ⑤ | 已落地；**与工序二完全解耦** |

## 两条数据入评测主路径

按**是否自带金标**分流；两条都先经数据源登记与清洗，**都要跑多模型识别**（分拣依赖转写，不能跳过 ASR）。

```text
【路径 A · 带金标外源数据】
  外部音频 + 外源金标 xlsx
       │
       ▼
  数据源登记（逻辑数据源）
       │
       ▼
  数据清洗流水线（①）
       │
       ▼
  不同模型识别流水线（②：多 ASR → 聚拢）
       │
       ▼
  分类分拣（③：classify_external_gold）
  · 金标以外源为准（注入 gold_text）
  · 产生 type / decision / 标签
       │
       ▼
  classified_*  →  评测集（eval register）  →  工序三评测
```

```text
【路径 B · 不带金标数据】
  外部音频（无金标）
       │
       ▼
  数据源登记（逻辑数据源）
       │
       ▼
  数据清洗流水线（①）
       │
       ▼
  不同模型识别流水线（②：多 ASR → 聚拢）
       │
       ▼
  分类分拣（③：classify_dataset / consensus）
  · 跨模型共识「匹配」候选金标
  · 产生 type / decision / 标签（现行多为 auto_gold / consensus_gold 等）
       │
       ▼
  summary_ / gold_ / classified_*  →  评测集（eval register）  →  工序三评测
```

| | 路径 A（带外源金标） | 路径 B（不带金标） |
| --- | --- | --- |
| 金标从哪来 | 外源 xlsx 注入，**不以**模型共识覆盖 | 多模型共识 medoid（候选/自动金标） |
| 分拣入口 | `classify_external_gold.yaml` | `classify_dataset.yaml` |
| 策略配置 | `external_gold_v1` | `zh_asr_v1`（默认 `selection_v1.1`）；可选 `zh_asr_v2` |
| 典型产物 | `classified_*` | `classified_*` / `gold_*` / `summary_*` |
| 进工序三 | `eval register` → 跑批 → 聚合 → 指标 | 同左 |

> **v2 已并行落地**：路径 B 可用 `classify_dataset_v2` / `selection_v2.0`，模型共识为 `pseudo_gold_*`；正式评测集须人审或可信外源升为真金标后再 `eval register`（默认 `--formal` 拒伪金标）。细则见 [数据挑选规则_v2.0](../02-规范规则/数据挑选规则_v2.0.md)、[011](../04-改进需求/已完成/011-数据挑选规则v2落地.md)。生产默认仍为 v1.1。

前置登记：[数据源落入流水线](../03-流水线/数据源落入流水线.md)。分拣细则：[数据挑选规则](../02-规范规则/数据挑选规则.md)。评测命令：[评测流水线](../03-流水线/评测流水线.md)。

## 工序一：数据清洗落库打标

从原始 wav/pcm 到可评测 / 可训练的金标与汇总表。

### 内部步骤

| 步骤 | 做什么 | 主要流水线 / CLI |
| --- | --- | --- |
| ① | 数据清洗、落库 | `pipelines/data_cleaning_source_A.yaml` |
| ② | 同源多结果 ASR → 聚拢 → agreement CER | 见下表 ASR / 聚合 / 字准 |
| ③ | 自动分拣 → 金标导出 →（可搁置）人审 → Release | `classify_dataset` + `review *` + `release build` |

### 对齐流水线

| 阶段 | Pipeline / 命令 | 说明 |
| --- | --- | --- |
| 清洗 | `data_cleaning_source_A.yaml` | `--source-name` + `--source-dir` → `cleaned_${BATCH}` |
| ASR（任选多次） | `qwen_asr_batch.yaml` | vLLM；`--asr-run <alias>` |
| | `sensevoice_asr_batch.yaml` | 本地 GPU；`--asr-run <alias>` |
| | `doubao_asr_batch.yaml` / `doubao_asr_single.yaml` | 豆包 API |
| | `kimi_asr_batch.yaml` | Kimi vLLM（内部按时长桶 pad）→ join 名 `kimi`；pad 音频不进 Release / 评测集真值 |
| | `kimi_audio_asr_batch.yaml` | Kimi 本地 → join 名 `kimi_audio` |
| | `glm_asr_batch.yaml` | GLM vLLM（transcription HTTP，无 pad）→ join 名 `glm` |
| 聚拢 | `multi_asr_aggregate.yaml` | `--aggregate-base` + 重复 `--join-manifest` |
| 字准（模型间） | `asr_metric_pipeline.yaml` | `--agreement-base`；写出 `max_vs_base_agreement_cer` |
| 分拣 | `classify_dataset.yaml` | `configs/selection/zh_asr_v1.yaml`（默认） |
| | `classify_dataset_v2.yaml` | `zh_asr_v2` / `selection_v2.0`（伪金标 + 风险闸） |
| | `classify_external_gold.yaml` | 外源 xlsx 注入 + `external_gold_v1` 四桶 → 同名 `classified_*` |
| 金标 / 汇总 | `audio-data review export-gold` | 默认 `auto_gold` + `consensus_gold` |
| | `audio-data review export-summary` | 全量 xlsx，`type`=分拣桶 |
| 人审（可选） | `review export` / `review import` | 可搁置；不阻塞金标评测 |
| 冻结 | `audio-data release build` | 可加 `--allow-unresolved-review` |

### 工序一要点（原②③）

**ASR / 聚拢 / 字准**

- 同一 `--source-name` 下可多次跑任意模型，用 `--asr-run <alias>` 区分产物：`{alias}_asr_<BATCH>.parquet`
- 聚拢不绑死模型清单：`--aggregate-base qwen1 --join-manifest qwen2 --join-manifest sensevoice1 ...`
- agreement CER 是工序一内部指标；**分拣进桶不再依赖该 CER**

**分拣 / 金标**

- 策略：默认 `configs/selection/zh_asr_v1.yaml`（`selection_v1.1`）；可选 `zh_asr_v2.yaml`（`selection_v2.0`）
- 字段三分开：`type` + `decision` + `label`（v2 另有 `label_tier` / `label_source` 等）
- 分桶（v1）：`noise` / `voicemail` / `semantic_inversion` / `hallucination` / `qwen_missing` / `auto_gold` / `consensus_gold` / `hardcase`
- 分桶（v2）：`pseudo_gold_*` / `invalid_audio` / `true_silence` / `possible_vad_miss` / `model_missing` / 语义风险桶等，见 [数据挑选规则_v2.0](../02-规范规则/数据挑选规则_v2.0.md)
- 一致度用 **transcript_similarity**（非字准率）；阈值 `0.95` / `0.90`；金标取 **medoid**（禁止随机）
- 模型族感知：同族多跑不算独立票；语义风险在相似度判断之前执行（v2 禁止多数票自动接受 semantic_inversion）
- **外源金标路径（B2）**：`classify_external_gold` + `external_gold_v1`；`gold_text` 来自 xlsx，四桶 `voicemail`/`noise`/`auto_gold`/`hardcase`；见 [006](../04-改进需求/已完成/006-工序一清洗引擎拆分需求.md)
- 细则：[数据挑选规则](../02-规范规则/数据挑选规则.md)（默认 v1.1）

## 工序三：评测

与工序二**无依赖**：只要评测集与各推理结果 **id 对齐** 即可，不强制 Model Registry。

评测集上游按是否自带金标分两条（完整图见上文「两条数据入评测主路径」）：

| 路径 | 金标 | 工序一出口 | 状态 |
| --- | --- | --- | --- |
| **A · 带外源金标** | 外源 xlsx 注入 | `classify_external_gold` → `classified_*` | 正式主路径已落地。[006](../04-改进需求/已完成/006-工序一清洗引擎拆分需求.md) |
| **B · 不带金标** | 工序一多模型共识 | `summary_` / `gold_` / `classified_*` | 正式主路径已落地 |

两条在工序三汇合后步骤相同：`eval register` → 独立跑批 → `eval_aggregate` → `eval_metric_pipeline`。

### 对齐流水线

| 阶段 | Pipeline / 命令 | 说明 |
| --- | --- | --- |
| 注册评测集 | `audio-data eval register` / `eval check` | 常用 `summary_` / `gold_` / `classified_` → `eval_$BATCH` |
| 推理跑批 | `qwen_asr_batch.yaml` / `glm_asr_batch.yaml`（等） | `--eval-name` + `--asr-run <alias>`；各权重独立 vLLM |
| 聚拢 | `eval_aggregate.yaml` | 评测集为底表，`--join-manifest` 左连接 |
| 字准 / 报告 | `eval_metric_pipeline.yaml` | 相对 `gold_text`；`--eval-model` 定报告维度；按 `type` 导出 |
| 外源 → classified_ | `classify_external_gold.yaml` | 工序一 B2；再 `eval register`（与场景 1 相同） |
| 外源 xlsx（旁路·过渡） | `scripts/run_eval_from_label_xlsx.py` | 不产出正式 `classified_*`；优先改用上一行 |
| 兼容旧入口 | `evaluate_registered_models.yaml` | Registry + 双端口串行；**不推荐** |

### 工序三要点（原⑤）

- `eval_aggregate`：允许推理侧多出 id；评测集缺 id 失败
- 若 summary 已含原模型文本，可只 join SFT 别名
- 配置：`configs/metrics/model_eval.yaml`（`vs_gold`）
- 同 family 多阶段对比：base + 各 SFT 用不同 `--asr-run` / `--eval-model`
