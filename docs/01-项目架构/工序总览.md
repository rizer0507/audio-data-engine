# 工序总览（三大工序）

> **现行组织方式：三大工序。** 下文「①–⑤」仅为大工序内部步骤编号，日常执行与手册分册以「工序一 / 二 / 三」为准。
>
> 可执行命令见仓库根目录 `手册/dev/`、`手册/local/`。

---

## 总览

```text
工序一 数据清洗落库打标
  ①清洗落库 → ②多 ASR + 聚拢 + agreement 字准 → ③分拣 / 金标 /（可选）人审 / Release
        │
        ▼（可选）
工序二 训练（外部框架，本引擎未完整集成）
  ④ Dataset Release → 外部训练 → Model Registry（可选）
        │
        ▼（与②解耦，可不经训练直接评）
工序三 评测
  ⑤ eval register → 各模型独立跑批 → eval_aggregate → eval_metric_pipeline
```

| 大工序 | 名称 | 覆盖引擎步骤 | 状态 |
| --- | --- | --- | --- |
| **工序一** | 数据清洗落库打标 | ① + ② + ③ | 已落地 |
| **工序二** | 训练 | ④ | 外部框架；引擎侧 adapter / Registry 可选 |
| **工序三** | 评测 | ⑤ | 已落地；**与工序二完全解耦** |

## 两条数据入评测主路径

按**是否自带金标**分流；两条都先经数据源登记与清洗，**都要跑多模型识别**（分拣依赖转写，不能跳过 ASR）。

```text
【路径 A · 带金标外源数据】
  外部音频 + 外源金标 xlsx
       │
       ▼
  数据源登记（逻辑数据源）
       │
       ▼
  数据清洗流水线（①）
       │
       ▼
  不同模型识别流水线（②：多 ASR → 聚拢）
       │
       ▼
  分类分拣（③：classify_external_gold）
  · 金标以外源为准（注入 gold_text）
  · 产生 type / decision / 标签
       │
       ▼
  classified_*  →  评测集（eval register）  →  工序三评测
```

```text
【路径 B · 不带金标数据】
  外部音频（无金标）
       │
       ▼
  数据源登记（逻辑数据源）
       │
       ▼
  数据清洗流水线（①）
       │
       ▼
  不同模型识别流水线（②：多 ASR → 聚拢）
       │
       ▼
  五类分拣（③：默认 five_class_v2_2；N≥3×双跑）
  · 家族四态 + 音频能量 + DNSMOS 联合判定
  · 产物 classified_five_class_v2_2_auto_noise_*（v2/v1/v3 仅对照）
       │
       ▼
  summary_ / gold_ / classified_five_class_v2_2_auto_noise_*  →  评测集（eval register）  →  工序三评测
```

| | 路径 A（带外源金标） | 路径 B（不带金标 · **默认五类 v2.2**） |
| --- | --- | --- |
| 金标从哪来 | 外源 xlsx 注入，**不以**模型共识覆盖 | 多家族双跑共识（候选 / 伪金标；正式 eval 须人审或外源） |
| 分拣入口 | `classify_external_gold.yaml` | **`classify_dataset_five_class_v2_2_auto_noise.yaml`**（v2/v1 对照，v3 legacy） |
| 策略配置 | `external_gold_v1` | **`selection_five_class_v2_2_auto_noise`（N≥3）** |
| 典型产物 | `classified_*` | **`classified_five_class_v2_2_auto_noise_*`**（勿覆盖 v1/v2/v3） |
| 进工序三 | `eval register` → 跑批 → 聚合 → 指标 | 同左（formal 拒伪金标） |

> **正式分拣**：`classify_dataset_five_class_v2_2_auto_noise` / `selection_five_class_v2_2_auto_noise`（[028](../04-改进需求/已完成/028-五分类自动噪声归类与互斥准入修复.md)、[029](../04-改进需求/已完成/029-五分类v2.2-DNSMOS联合判定修复.md)）。完整说明见 [五类分拣规则与决策流程](../02-规范规则/五类分拣规则与决策流程.md)；DNSMOS 增量见 [数据挑选规则 v2.2](../02-规范规则/数据挑选规则_v2_2_auto_noise.md)。**新批次默认走五类 v2.2。**
>
> **对照/回退**：v2 自动能量规则用于无 DNSMOS 联合语义的对照，五类 v1 与 `classify_dataset_v3_asr_anomaly_noise` 仅作历史复现。
>
> **噪声判定**：v2.2 在 ASR attach 后先计算音频能量，再只对候选复用/计算 DNSMOS，最后联合家族状态、能量和版本化 DNSMOS 状态分类。DNSMOS 单项不能证明目标人声或背景噪声；不可用时审计回退 v2 强规则。`audio_quality_sidecar` 只作研究或复用分数来源。操作见完整服务器手册及 `单条流水线执行命令.txt` §2f-v3-029 / §2f-noise。
>
> 契约经 [015](../04-改进需求/已完成/015-v3分拣支持三族及以上.md)：**N≥3 族 × 每族双跑**即可，四族为可选增强。文本相似度热路径已用 `rapidfuzz`（[019](../04-改进需求/已完成/019-Levenshtein原生加速.md)）。伪标签自动进训 / 业务门禁 `publish_status=pass` 仍须校准。语义容错 [022](../04-改进需求/已完成/022-v3语义容错分拣与金标选文落地.md)、业务语义 [024](../04-改进需求/已完成/024-业务语义优先分类与三万条人审收敛策略.md)、中文-only [025](../04-改进需求/已完成/025-标点非中文字符等筛除.md) 均为显式影子，不替换正式五类入口。

前置登记：[数据源落入流水线](../03-流水线/数据源落入流水线.md)。分拣细则：[五类分拣规则与决策流程](../02-规范规则/五类分拣规则与决策流程.md)。评测命令：[评测流水线](../03-流水线/评测流水线.md)。

从原始 wav/pcm 到可评测 / 可训练的金标与汇总表。

### 工序一要点（原②③）

**ASR / 聚拢 / 字准**

- 同一 `--source-name` 下可多次跑任意模型，用 `--asr-run <alias>` 区分产物：`{alias}_asr_<BATCH>.parquet`
- 聚拢不绑死模型清单：`--aggregate-base qwen1 --join-manifest qwen2 --join-manifest sensevoice1 ...`
- agreement CER 是工序一内部指标；**分拣进桶不再依赖该 CER**

**分拣 / 金标**

- **默认策略**：`selection_five_class_v2_2_auto_noise`（通用或批次专用配置）；细则 [五类分拣规则与决策流程](../02-规范规则/五类分拣规则与决策流程.md)；v2/v1 为对照，旧 v3 为 legacy
- 契约：**N≥3** 族 × 每族双跑；同族最多一票；全量共识相对配置内全族
- 相似度热路径：`rapidfuzz`（[019](../04-改进需求/已完成/019-Levenshtein原生加速.md)）；公式/阈值不变；分拣并发仍见 [017](../04-改进需求/进行中/017-v3分拣加速.md)
- 产物：正式 `classified_five_class_v2_2_auto_noise_*`；v2/v1/v3 分别独立命名，禁止互相覆盖
- **噪声判定**：家族四态 + `audio_energy_v1` + `dnsmos_decision_v2_2` 联合；DNSMOS unavailable 时回退 v2 强规则并留痕，全量 `audio_quality_sidecar` 仅研究/复用
- **语速不可能（018）**：分拣前短路超限转写；不在①清洗。打开 025 `chinese_only_v1` 后按 `classify_text` 计字，置空路不参与 chars/sec
- legacy：`zh_asr_v1` / `zh_asr_v2` 仅复现；字段与分桶见旧规则文档
- **外源金标路径（B2）**：`classify_external_gold` + `external_gold_v1`；见 [006](../04-改进需求/已完成/006-工序一清洗引擎拆分需求.md)

## 工序三：评测

与工序二**无依赖**：只要评测集与各推理结果 **id 对齐** 即可，不强制 Model Registry。

评测集上游按是否自带金标分两条（完整图见上文「两条数据入评测主路径」）：

| 路径 | 金标 | 工序一出口 | 状态 |
| --- | --- | --- | --- |
| **A · 带外源金标** | 外源 xlsx 注入 | `classify_external_gold` → `classified_*` | 正式主路径已落地。[006](../04-改进需求/已完成/006-工序一清洗引擎拆分需求.md) |
| **B · 不带金标** | 工序一多模型共识 | `summary_` / `gold_` / `classified_*` | 正式主路径已落地 |

两条在工序三汇合后步骤相同：`eval register` → 独立跑批 → `eval_aggregate` → `eval_metric_pipeline`。

### 对齐流水线

| 阶段 | Pipeline / 命令 | 说明 |
| --- | --- | --- |
| 注册评测集 | `audio-data eval register` / `eval check` | 常用 `summary_` / `gold_` / `classified_` → `eval_$BATCH` |
| 推理跑批 | `qwen_asr_batch.yaml` / `glm_asr_batch.yaml`（等） | `--eval-name` + `--asr-run <alias>`；各权重独立 vLLM |
| 聚拢 | `eval_aggregate.yaml` | 评测集为底表，`--join-manifest` 左连接 |
| 字准 / 报告 | `eval_metric_pipeline.yaml` | 相对 `gold_text`；`--eval-model` 定报告维度；按 `type` 导出；**012-E** 写入 `business_metrics` / `publish_status` |
| 外源 → classified_ | `classify_external_gold.yaml` | 工序一 B2；再 `eval register`（与场景 1 相同） |
| 外源 xlsx（旁路·过渡） | `scripts/run_eval_from_label_xlsx.py` | 不产出正式 `classified_*`；优先改用上一行 |
| 兼容旧入口 | `evaluate_registered_models.yaml` | Registry + 双端口串行；**不推荐** |

### 工序三要点（原⑤）

- `eval_aggregate`：允许推理侧多出 id；评测集缺 id 失败
- 若 summary 已含原模型文本，可只 join SFT 别名
- 配置：`configs/metrics/model_eval.yaml`（`vs_gold`）；业务风险：`configs/metrics/business_risk_v1.yaml`（012-E）
- 同 family 多阶段对比：base + 各 SFT 用不同 `--asr-run` / `--eval-model`
- **当前五分类生产入口**：v2.2（028/029）；家族数下限沿用 N≥3×双跑。伪标签自动进训 / 业务门禁 `publish_status=pass` 仍须独立验收后才宣称放行。
