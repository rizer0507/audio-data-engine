# 工序总览（三大工序）

> **现行组织方式：三大工序。** 下文「①–⑤」仅为大工序内部步骤编号，日常执行与手册分册以「工序一 / 二 / 三」为准。
>
> 可执行命令见仓库根目录 `手册/dev/`、`手册/local/`。

---

## 总览

```text
工序一 数据清洗落库打标
  ①清洗落库 → ②多 ASR + 聚拢 + agreement 字准 → ③分拣 / 金标 /（可选）人审 / Release
        │
        ▼（可选）
工序二 训练（外部框架，本引擎未完整集成）
  ④ Dataset Release → 外部训练 → Model Registry（可选）
        │
        ▼（与②解耦，可不经训练直接评）
工序三 评测
  ⑤ eval register → 各模型独立跑批 → eval_aggregate → eval_metric_pipeline
```

| 大工序 | 名称 | 覆盖引擎步骤 | 状态 |
| --- | --- | --- | --- |
| **工序一** | 数据清洗落库打标 | ① + ② + ③ | 已落地 |
| **工序二** | 训练 | ④ | 外部框架；引擎侧 adapter / Registry 可选 |
| **工序三** | 评测 | ⑤ | 已落地；**与工序二完全解耦** |

## 两条数据入评测主路径

按**是否自带金标**分流；两条都先经数据源登记与清洗，**都要跑多模型识别**（分拣依赖转写，不能跳过 ASR）。

```text
【路径 A · 带金标外源数据】
  外部音频 + 外源金标 xlsx
       │
       ▼
  数据源登记（逻辑数据源）
       │
       ▼
  数据清洗流水线（①）
       │
       ▼
  不同模型识别流水线（②：多 ASR → 聚拢）
       │
       ▼
  分类分拣（③：classify_external_gold）
  · 金标以外源为准（注入 gold_text）
  · 产生 type / decision / 标签
       │
       ▼
  classified_*  →  评测集（eval register）  →  工序三评测
```

```text
【路径 B · 不带金标数据】
  外部音频（无金标）
       │
       ▼
  数据源登记（逻辑数据源）
       │
       ▼
  数据清洗流水线（①）
       │
       ▼
  不同模型识别流水线（②：多 ASR → 聚拢）
       │
       ▼
  分类分拣（③：默认 classify_dataset_v3 / consensus_v3；N≥3×双跑）
  · 跨家族共识候选 / 伪金标与风险标签
  · 产物 classified_v3_*（legacy classified_* 仅复现）
       │
       ▼
  summary_ / gold_ / classified_v3_*  →  评测集（eval register）  →  工序三评测
```

| | 路径 A（带外源金标） | 路径 B（不带金标 · **默认 v3**） |
| --- | --- | --- |
| 金标从哪来 | 外源 xlsx 注入，**不以**模型共识覆盖 | 多家族双跑共识（候选 / 伪金标；正式 eval 须人审或外源） |
| 分拣入口 | `classify_external_gold.yaml` | **`classify_dataset_v3.yaml`**（legacy：`classify_dataset` / `_v2`） |
| 策略配置 | `external_gold_v1` | **`zh_asr_v3` / `zh_asr_v3_three_family`（N≥3）**；legacy：`zh_asr_v1` / `zh_asr_v2` |
| 典型产物 | `classified_*` | **`classified_v3_*`**（勿覆盖无前缀 `classified_*`） |
| 进工序三 | `eval register` → 跑批 → 聚合 → 指标 | 同左（formal 拒伪金标） |

> **正式分拣**：`classify_dataset_five_class_v1` / `selection_five_class_v1`（[027](../04-改进需求/进行中/027-五类分拣重构正式需求.md)）。细则见 [数据挑选规则_v1](../02-规范规则/数据挑选规则_v1.md)。**新批次默认走五类 v1。**
>
> **legacy 回退**：`classify_dataset_v3_asr_anomaly_noise` / `selection_v3.0`（[014](../04-改进需求/进行中/014-分拣生产默认切换至v3.md)）；更旧的 v2/v1 仅复现。
>
> **噪声打分**：DNSMOS 落在工序一③、ASR attach 之后。主路径为分拣 YAML 内嵌按需诊断（[023](../04-改进需求/进行中/023-ASR异常触发噪声诊断与全局质量门禁移除.md) / 027 §9），正常中文 `not_required`；`audio_quality_sidecar` 只作研究或历史复现。未校准不得自动定 `environment_noise`。操作步骤：`手册/*/01` §3b、`手册/*/00` §5b、`单条流水线执行命令.txt` §2f-noise；侧车需求 [009](../04-改进需求/已完成/009-噪声评分流水线接入.md)。
>
> 契约经 [015](../04-改进需求/进行中/015-v3分拣支持三族及以上.md)：**N≥3 族 × 每族双跑**即可，四族为可选增强。文本相似度热路径已用 `rapidfuzz`（[019](../04-改进需求/已完成/019-Levenshtein原生加速.md)）。伪标签自动进训 / 业务门禁 `publish_status=pass` 仍须校准。语义容错 [022](../04-改进需求/进行中/022-v3语义容错分拣与金标选文落地.md)、业务语义 [024](../04-改进需求/进行中/024-业务语义优先分类与三万条人审收敛策略.md)、中文-only [025](../04-改进需求/进行中/025-标点非中文字符等筛除.md) 均为显式影子，不替换正式五类入口。

前置登记：[数据源落入流水线](../03-流水线/数据源落入流水线.md)。分拣细则：[数据挑选规则_v1](../02-规范规则/数据挑选规则_v1.md)。评测命令：[评测流水线](../03-流水线/评测流水线.md)。

## 工序一：数据清洗落库打标

从原始 wav/pcm 到可评测 / 可训练的金标与汇总表。

### 内部步骤

| 步骤 | 做什么 | 主要流水线 / CLI |
| --- | --- | --- |
| ① | 数据清洗、落库 | `pipelines/data_cleaning_source_A.yaml` |
| ② | 同源多结果 ASR → 聚拢 → agreement CER | 见下表 ASR / 聚合 / 字准 |
| ③ | 按需噪声诊断 → 自动分拣 →（可选）人审 → Release | **正式** `classify_dataset_five_class_v1`（内嵌 DNSMOS）；**legacy** `classify_dataset_v3_asr_anomaly_noise`；研究全量 `audio_quality_sidecar`。人审/Release：`review --protocol v3` / `build_dataset_v3`。**语速不可能栏在本步（ASR 之后），不在①清洗。** |

### 工序一要点（原②③）

**ASR / 聚拢 / 字准**

- 同一 `--source-name` 下可多次跑任意模型，用 `--asr-run <alias>` 区分产物：`{alias}_asr_<BATCH>.parquet`
- 聚拢不绑死模型清单：`--aggregate-base qwen1 --join-manifest qwen2 --join-manifest sensevoice1 ...`
- agreement CER 是工序一内部指标；**分拣进桶不再依赖该 CER**

**分拣 / 金标**

- **默认策略**：`selection_five_class_v1`（`configs/selection/zh_asr_five_class_v1.yaml` / 批次专用配置）；细则 [数据挑选规则_v1](../02-规范规则/数据挑选规则_v1.md)；legacy 回退 `zh_asr_v3*.yaml` + `classify_dataset_v3_asr_anomaly_noise`
- 契约：**N≥3** 族 × 每族双跑；同族最多一票；全量共识相对配置内全族
- 相似度热路径：`rapidfuzz`（[019](../04-改进需求/已完成/019-Levenshtein原生加速.md)）；公式/阈值不变；分拣并发仍见 [017](../04-改进需求/进行中/017-v3分拣加速.md)
- 产物：正式 `classified_five_class_v1_*`；legacy `classified_v3_*`；勿覆盖历史无前缀 `classified_*`
- **噪声打分**：分拣内嵌按需 DNSMOS（正常中文 `not_required`）；全量 `audio_quality_sidecar` 仅研究。未校准不得自动定 `environment_noise`；操作见 `手册/*/01` §3b、`单条流水线执行命令.txt` §2f-noise
- **语速不可能（018）**：分拣前短路超限转写；不在①清洗。打开 025 `chinese_only_v1` 后按 `classify_text` 计字，置空路不参与 chars/sec
- legacy：`zh_asr_v1` / `zh_asr_v2` 仅复现；字段与分桶见旧规则文档
- **外源金标路径（B2）**：`classify_external_gold` + `external_gold_v1`；见 [006](../04-改进需求/已完成/006-工序一清洗引擎拆分需求.md)

## 工序三：评测

与工序二**无依赖**：只要评测集与各推理结果 **id 对齐** 即可，不强制 Model Registry。

评测集上游按是否自带金标分两条（完整图见上文「两条数据入评测主路径」）：

| 路径 | 金标 | 工序一出口 | 状态 |
| --- | --- | --- | --- |
| **A · 带外源金标** | 外源 xlsx 注入 | `classify_external_gold` → `classified_*` | 正式主路径已落地。[006](../04-改进需求/已完成/006-工序一清洗引擎拆分需求.md) |
| **B · 不带金标** | 工序一多模型共识 | `summary_` / `gold_` / `classified_*` | 正式主路径已落地 |

两条在工序三汇合后步骤相同：`eval register` → 独立跑批 → `eval_aggregate` → `eval_metric_pipeline`。

### 对齐流水线

| 阶段 | Pipeline / 命令 | 说明 |
| --- | --- | --- |
| 注册评测集 | `audio-data eval register` / `eval check` | 常用 `summary_` / `gold_` / `classified_` → `eval_$BATCH` |
| 推理跑批 | `qwen_asr_batch.yaml` / `glm_asr_batch.yaml`（等） | `--eval-name` + `--asr-run <alias>`；各权重独立 vLLM |
| 聚拢 | `eval_aggregate.yaml` | 评测集为底表，`--join-manifest` 左连接 |
| 字准 / 报告 | `eval_metric_pipeline.yaml` | 相对 `gold_text`；`--eval-model` 定报告维度；按 `type` 导出；**012-E** 写入 `business_metrics` / `publish_status` |
| 外源 → classified_ | `classify_external_gold.yaml` | 工序一 B2；再 `eval register`（与场景 1 相同） |
| 外源 xlsx（旁路·过渡） | `scripts/run_eval_from_label_xlsx.py` | 不产出正式 `classified_*`；优先改用上一行 |
| 兼容旧入口 | `evaluate_registered_models.yaml` | Registry + 双端口串行；**不推荐** |

### 工序三要点（原⑤）

- `eval_aggregate`：允许推理侧多出 id；评测集缺 id 失败
- 若 summary 已含原模型文本，可只 join SFT 别名
- 配置：`configs/metrics/model_eval.yaml`（`vs_gold`）；业务风险：`configs/metrics/business_risk_v1.yaml`（012-E）
- 同 family 多阶段对比：base + 各 SFT 用不同 `--asr-run` / `--eval-model`
- **v3 生产切换**：分拣默认切 v3 见 [014](../04-改进需求/进行中/014-分拣生产默认切换至v3.md)；家族数下限见 [015](../04-改进需求/进行中/015-v3分拣支持三族及以上.md)。伪标签自动进训 / 业务门禁 `publish_status=pass` 仍须校准后才宣称放行。
