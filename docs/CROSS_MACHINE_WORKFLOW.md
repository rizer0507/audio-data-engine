# 跨电脑接续工作

此流程同步项目知识，不同步 Codex 原始聊天、自动记忆数据库或正在运行的进程。

## 换机器前

1. 更新 `docs/PROJECT_CONTEXT.md` 中有变化的事实：当前任务、决策原因、相关文件、验证结果、未完成项。长篇结果放专门文档，再从上下文链接过去。
2. 记录实验的数据版本、代码 commit、配置、运行身份和证据位置。区分已验证、仅本机通过、待服务器验证；不要把计划写成完成。
3. `git status -sb` 检查分支和改动；只提交任务相关文件，再 push 当前分支。不要顺带提交数据、模型、凭据或个人聊天原文。

## 家里开始工作

在对应仓库执行以下命令（替换分支名）：

```bash
git fetch origin
git switch <分支名>
git pull --ff-only origin <分支名>
git status -sb
```

首次尚无本地分支时，使用 `git switch --track origin/<分支名>`。如果本地有改动或分支发生分叉，先检查并保留本地工作，再处理；不要强制覆盖。

在 Codex 中打开这个本地仓库，开新对话即可。推荐首条消息：

> 请先阅读 AGENTS.md、docs/PROJECT_CONTEXT.md 和相关运行手册，核对当前分支及代码。告诉我已确认的状态与尚缺的外部资源，再继续我指定的任务。

仓库可放在不同盘符。项目文档采用仓库相对路径；训练 YAML、JSONL 中的服务器绝对路径必须另行核对。音频、模型、忽略的数据集、运行日志和 checkpoint 不会因 git pull 自动出现，需要从受控存储另行恢复。输入路径改变时按数据版本规范留痕。

## 日常维护

完成有实质变化的任务后，同步上下文与对应专项文档。没有进度变化时无需制造更新记录。两个仓库各自提交、各自 push；涉及接口变更时，在两边记录兼容的分支/commit 和数据契约。自动记忆可辅助回忆，但不替代这里的版本化知识。
